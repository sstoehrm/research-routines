# Agent Harness (Local) — 2026-07-25

## Summary

May–July 2026 was the "backend catch-up" cycle for local agents. The
**MCP `2026-07-28` spec** (RC locked 2026-05-21, ships 2026-07-28)
formalizes stateless-first transport, removes the `Mcp-Session-Id`
and `initialize` handshake, and hardens OAuth 2.1 — self-hosted MCP
servers no longer need sticky sessions or shared session stores.
**vLLM 0.24 / 0.25** and **SGLang 0.5.12–0.5.16** both landed a wave
of tool-call parsers and day-0 support for the summer's model
releases (MiniMax M3, Nemotron 3 Ultra, GLM-5.2, Ring-2.6-1T, DeepSeek
V4, Kimi K2.5–K2.7, Inkling 975B). **llama.cpp** added a controversial
`--tools all` flag that executes file/shell primitives directly on the
server host (explicitly "not for untrusted environments") but still
does not ship a native C++ MCP client. **Ollama 0.32** made bare
`ollama` drop into an interactive coding agent. On harnesses,
**Hermes Agent** shipped a major "Quicksilver" release (~2,245
commits), **Jan** got inline MCP tool approvals and native
web-search/-fetch tools, **Crush** (Charmbracelet) is the emerging
successor to the archived Roo Code, and **Continue.dev** wound down
its OSS product after being acquired by Cursor. For model+harness
combos the standout new pick is **GLM-5.2 (753B / 40B active) +
SGLang NVFP4** at 500+ tok/s/user on 8×B300 for long-horizon coding
agents; on the tiny end **Gemma 4 E4B + Ollama** and **Qwen3.5-4B +
LM Studio** cover the "runs on a laptop" slot.

## MCP for local stacks

- **MCP `2026-07-28` (RC 2026-05-21)** — stateless-first
  (SEP-2567 removes `Mcp-Session-Id` and protocol-level session;
  SEP-2575 removes the `initialize` handshake). Adds MCP Apps
  (server-rendered iframes), Tasks (long-running work), Server
  Cards. Hardened OAuth 2.1 (RFC 9207 `iss` validation,
  `application_type` on registration). Practical impact: local
  MCP servers can sit behind a plain round-robin load balancer;
  `tools/list` can be cached.
  Blog: <https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/>
- **llama.cpp** — web-UI MCP host since March; no native C++ MCP
  client. `--webui-mcp-proxy` provides an optional CORS bridge.
- **Ollama** — no first-party MCP client; `mcp-client-for-ollama`
  (Python, PyPI 2026-07-10) is the community bridge.
- **LM Studio** — MCP Host + OAuth for MCP servers; most complete
  MCP surface among GUI local runners.
- **Jan** — inline MCP tool approval + citation cards (v0.8.0);
  v0.8.4 native web_search/web_fetch tools that replace the most
  common external MCP needs.
- **SGLang, vLLM, TensorRT-LLM** — MCP integration remains
  client-side, through harnesses (Crush, OpenCode, Hermes,
  OpenHarness).
- **candle-vllm** — documented MCP + OpenAI-compatible tool calling.
- **OpenHarness v0.1.8** — explicit "MCP stability enhancements."
- **Crush + Docker MCP** — Charm's documented pattern for MCP tools
  in containers.

## Model + Harness Combinations That Work Well

Only combos with a published source are listed.

### Tiny (≤4B)

- **Qwen3.5-4B + LM Studio** — 97.5% on jdhodges tool-calling eval.
  Source:
  <https://jdhodges.com/blog/local-llms-on-tool-calling-2026-pt1-local-lm>
- **Gemma 4 E2B (2.3B) / E4B (4.5B) + Ollama** — Google Gemma 4
  launched 2026-04-02 under Apache 2.0; strong tool calling for its
  class. Secondary: aurigait.com.

### Small (4B–14B)

- **Gemma 4 E4B (4.5B) + Ollama / llama.cpp** — natively
  multimodal; benefited from the 2026-07-15 Google community update
  (FA4 on Hopper, chat-template smoothing, tool-call reliability
  fixes). Secondary: explainx.ai.

### Medium (14B–32B)

- **Gemma 4 26B-A4B-it (Q4_K_M / UD-IQ4_XS) + llama.cpp
  `--jinja`** — 12.65 GiB GGUF fits with **65k context on a 16GB
  RTX 5070 Ti**; **89% BFCL v4 non-live function-calling**, 95% on
  the `simple_python` subset. Source:
  <https://huggingface.co/unsloth/gemma-4-26B-A4B-it-GGUF/discussions/42>
- **Gemma 4 27B / 31B Dense + Ollama or llama.cpp** — τ2-bench
  Retail **86.4%** (vs Gemma 3 27B at 6.6%). 24 GB VRAM class.
  Secondary: promptquorum.com, insiderllm.com, explainx.ai.
- **Qwen3-Coder 30B + vLLM / Ollama / llama.cpp** — 93–96%
  well-formed call rate; strong on code-shaped tool work.
  Secondary: promptquorum.com "Best Local Models for Tool Calling
  2026".
- **Qwen3 32B + vLLM / SGLang** — cited alongside above as reliable
  tool caller. Secondary: promptquorum.com.

### Large (32B–70B)

- **GLM-4.7 32B + SGLang (`--tool-call-parser glm47
  --reasoning-parser glm47`)** — 128k native context; best-in-class
  on long-context agent tasks in the 32-class per the May 2026
  promptquorum.com roundup. Setup:
  <https://docs.sglang.io/basic_usage/glm45.html>
- **GLM-4.7-Flash (30B total / 3B active) + vLLM / SGLang / Ollama /
  llama.cpp** — 60–80+ tok/s on RTX 3090 / 4090 or M-series per
  unsloth.ai docs.
- **Devstral Small 2 (24B, MIT) + Mistral Vibe CLI** — **68.0%
  SWE-bench Verified**, deployable on consumer hardware. Source:
  <https://mistral.ai/news/devstral-2-vibe-cli/>
- **Devstral 2 (123B) + Vibe CLI** — **72.2% SWE-bench Verified**,
  256K context. Same source.
- **Llama 3.3 70B + vLLM / llama.cpp** — ~97% well-formed call rate
  on MCP schema validation per promptquorum.com; 48 GB+ VRAM.

### XL / MoE (>70B total, including 100B+ MoE)

- **Qwen3-Coder-Next 80B-A3B (3B active) + vLLM continuous batching
