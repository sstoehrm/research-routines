# Agent Harness (Local) — 2026-05-23

## Summary

Between 2026-04-23 and 2026-05-23 the local-agent stack consolidated
around what the March 2026 llama.cpp MCP merge set up. **MCP is now
table stakes**: llama.cpp natively, LM Studio with OAuth (v0.4.10+),
LocalAI (MCP Apps + client), Hermes Agent, OpenHarness, Goose, Cline,
Roo Code — Ollama remains the holdout that still needs a bridge. On
the harness side, **OpenCode (SST)** shipped v1.15.6/v1.15.7
(May 20–21) adding a TUI diff viewer, on-demand subagent picker, and
Grok OAuth; **OpenHarness** (HKUDS) reached v0.1.9 with bundled
skill-creator and user-invocable slash commands; **Hermes Agent**
(Nous Research) crossed ~95.6K stars and shipped 0.13 / 0.14
("Tenacity" / "Foundation") with a 180× faster browser CDP and
LM Studio as a first-class provider. On backends, **vLLM v0.21.0**
(May 15) landed XGrammar 0.2.0 structural tags + new Cohere/LFM2
tool parsers and a TOKENSPEED_MLA backend tuned for DeepSeek-R1 /
Kimi-K2.6 on Blackwell; **SGLang v0.5.11** (May 5) hit ~3× faster
constrained decoding than vLLM with XGrammar-2 plus day-0 support
for Gemma 4, GLM-5.1, Qwen3.6 and Kimi K2.6. Model launches
dominated: **Kimi K2.6** (Apr 20, 1T-A32B), **Qwen3.6** (incl.
35B-A3B and 27B dense), **DeepSeek V3.2** with thinking-integrated
tool use, **MiniMax M2/M2.7**, plus **Nemotron 3 Nano 4B** and
**Gemma 4 e2b/26B-A4B** at the small end. The community's recurring
observation this month: *the harness improves the model more than
fine-tuning does* — covered by HN ("Improving 15 LLMs at Coding in
One Afternoon, Only the Harness Changed") and The Register's
OpenClaw piece (May 17).

## Harnesses

### OpenCode (SST)

- Source: <https://opencode.ai/changelog>,
  <https://github.com/opencode-ai/opencode>
- License: MIT.
- Status: Active. v1.15.6 (May 20, 2026) — TUI diff viewer, shell
  mode in the run prompt, on-demand subagent picker, desktop tabs,
  native Windows app menu, Ukrainian locale. v1.15.7 (May 21, 2026) —
  Grok OAuth/device-code sign-in, PDF attachments, restored OpenAI
  reasoning streams, hardened V2 session APIs against corrupt-message
  errors. Auto-Compaction (introduced in v0.1.6 line) keeps
  multi-day sessions viable.
- Good at: provider-agnostic (~75 providers including Ollama,
  LM Studio, llama.cpp endpoints), fully offline operation, mature
  TUI, multi-day session support.
- Known issues: local-endpoint config is still hand-wired; tool-call
  quality is bottlenecked by the chosen model rather than the harness.
- MCP / parallel tool calls: MCP supported through provider config;
  parallel tool calls supported when the model/parser supports them.

### OpenHarness + ohmo (HKUDS)

- Source: <https://github.com/HKUDS/OpenHarness>
- License: open-source (verify SPDX on repo).
- Status: Very active. v0.1.6 (Apr 10), v0.1.7 (Apr 18), v0.1.8
  (May 6), v0.1.9 (May 7). v0.1.8 added NVIDIA NIM, ModelScope, Qwen
  providers, isolated failing MCP servers, fixed subprocess stderr
  deadlocks. v0.1.9 added a bundled skill-creator and user-invocable
  slash commands.
- Good at: multi-agent coordination, IM gateway agents (ohmo lives in
  Feishu / Slack / Telegram / Discord), auto-compaction, MCP HTTP
  transport with auto-reconnect, swarm polling.
- Known issues: young project (first release 2026-04-01); fast-changing
  surface area.
- MCP / parallel tool calls: first-class MCP (HTTP transport, JSON
  Schema type inference, swarm polling). Multi-agent swarm
  coordination.

### Hermes Agent (Nous Research)

- Source: <https://github.com/NousResearch/hermes-agent>,
  <https://hermes-agent.nousresearch.com>,
  MCP docs
  <https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp>
- License: open-source (see repo).
- Status: Explosive growth — ~95.6K GitHub stars by April 2026.
  v0.12.0 "Curator" (Apr 30), v0.13.0 "Tenacity" (May 7), v0.14.0
  "Foundation" (May 16).
- Good at: self-improving learning loop, persistent memory, 22
  messaging platforms, native voice / video, browser CDP (180× faster
  after v0.14), ComfyUI v5 and TouchDesigner-MCP bundled in v0.12.
  LM Studio is a first-class local provider since v0.12.
- Known issues: docs themselves warn that the "reflection phase can be
  shallow" on small local models; agent-quality scales with model.
- MCP / parallel tool calls: native MCP with four plugin hooks
  (`pre_llm_call`, `post_llm_call`, `on_session_start`,
  `on_session_end`).

### Aider

- Source: <https://github.com/Aider-AI/aider>,
  <https://aider.chat/HISTORY.html>
- License: Apache 2.0.
- Status: Maintenance-heavy in this window. Last tagged release as of
  Feb 12 was v0.86.2; no new tag during 2026-04-23 to 2026-05-23 —
  confirm whether `main` has diverged before quoting.
- Good at: pair-programming workflow, atomic git commits, works with
  any OpenAI-compatible local endpoint (Ollama, llama.cpp server,
  LM Studio).
- Known issues: edit-mode tool calls are mostly diff-via-prompt rather
  than schema-driven; smaller local models struggle with edit-block
  fidelity.
- MCP / parallel tool calls: no first-class MCP; tooling is the
  built-in edit/run loop. No native parallel tool calls.

### Plandex

- Source: <https://github.com/plandex-ai/plandex>
- License: AGPL-3.0.
- Status: Slower cadence. Last tagged release `cli/v2.2.1` (Jul 16,
  2025); no new tag during the window. Plandex Cloud was wound down
  2025-10-03; project is now self-host first.
- Good at: long-horizon plans, large repos, parallel branching of
  edits. JSON model-config system added in v2.
- Known issues: no new release in window. Tool-calling primarily via
  diff/edit blocks, similar to Aider.
- MCP / parallel tool calls: no MCP yet. Ollama is the only built-in
  local provider, via `ollama-oss` and `ollama-daily` model packs.

### Pi / little-coder

- Source: <https://github.com/earendil-works/pi>,
  <https://github.com/itayinbarr/little-coder>
- License: Pi appears MIT/permissive; little-coder MIT (verify).
- Status: Actively used in May 2026 community benchmarks (r/LocalLLaMA
  "Pi + Qwen 3.5 on M1 Pro" write-ups).
- Good at: minimal 4-tool core (Read, Write, Edit, Bash) — explicitly
  designed for small local LLMs. little-coder tunes Pi for 4–14B
  models and posts SOTA local Aider Polyglot scores at that size.
- Known issues: tiny tool surface limits long-horizon workflows.
- MCP / parallel tool calls: no MCP; parallel tool calls depend on the
  underlying model.

### Goose (Block)

- Source: <https://github.com/block/goose>
- License: Apache 2.0.
- Status: Active, integrated with Ollama in docs.ollama.com.
- Good at: 15+ providers, recipes, scheduler, sub-agents, MCP-based
  extensions.
- MCP / parallel tool calls: MCP is the canonical extension mechanism.

### Cline / Roo Code (VS Code agent extensions)

- Source: <https://github.com/cline/cline>,
  <https://github.com/RooVetGit/Roo-Code>
- License: Apache 2.0 (both).
- Status: Cline CLI 2.0 shipped early 2026 with parallel/headless
  workflows. Both work against local Ollama / LM Studio.
- Good at: BYO-key, mature IDE integration, agentic edits with diff
  preview.
- MCP / parallel tool calls: both ship MCP client support.

## Backends

### llama.cpp

- Source: <https://github.com/ggml-org/llama.cpp>
- License: MIT.
- Status: daily builds; build b9294 on 2026-05-23. Recent May builds
  focus on OpenCL/Adreno MoE, SYCL MoE prefill throughput, Vulkan
  fusions, Level Zero detection, and a VRAM-leak fix in
  `server destroy()` for MTP/speculative draft contexts.
- Landmark just outside the window: PR #18655 (allozaur, merged
  2026-03-06) added a full MCP client to `llama-server` with agentic
  loop, MCP Prompts UI, MCP Resources file browser, server-side CORS
  proxy. 15,285 LOC across 147 files.
- Good at: native MCP without a bridge, GGUF inference on any
  hardware, hybrid attention models, agentic loop in `llama-server`'s
  WebUI.
- Known issues: the WebUI is the canonical MCP surface — programmatic
  MCP wiring still relies on the chat-completions API.
- MCP / parallel tool calls: MCP native since March 2026. Qwen XML
  tool-call format fixed in the March release notes. Parallel tool
  calls work through the OpenAI-style chat API.

### vLLM

- Source: <https://github.com/vllm-project/vllm>,
  releases <https://github.com/vllm-project/vllm/releases/tag/v0.21.0>
- License: Apache 2.0.
- Status: heavy cadence. v0.20.1 (May 4), v0.20.2 (May 10), v0.21.0
  (May 15, 2026). v0.21.0 highlights: XGrammar 0.2.0 with structural
  tags for strict tool calling + reasoning; new tool parsers for
  Cohere and LFM2/2.5; streaming tool/function calling with `required`
  and named-choice; speculative decoding respects reasoning/thinking
  budgets; new TOKENSPEED_MLA backend for DeepSeek-R1 / Kimi-K2.6 on
  Blackwell; C++20 build requirement.
- Good at: production throughput, parallel tool calling, structured
  outputs via guided decoding, async scheduling on by default
  (v0.19+).
- Known issues: C++20 toolchain bump in v0.21 broke some downstream
  builds; Transformers v4 deprecated.
- MCP / parallel tool calls: parallel tool calls supported and the
  parser cleanly separates content from calls. No native MCP server;
  MCP is layered above via the harness.

### SGLang

- Source: <https://github.com/sgl-project/sglang>,
  release notes
  <https://github.com/sgl-project/sglang/releases/tag/v0.5.11>,
  structured outputs docs
  <https://docs.sglang.io/advanced_features/structured_outputs.html>
- License: Apache 2.0.
- Status: v0.5.10.post1 (Apr 9), v0.5.11 (May 5, 2026). v0.5.11 lands
  XGrammar-2 (~80× faster grammar compilation), CUDA 13 + Torch 2.11,
  Speculative Decoding V2 default, day-0 support for Gemma 4,
  GLM-5.1, Qwen3.6, Kimi K2.6; LoRA for DeepSeek-V3 and Kimi-K2.
  v0.5.3 already had streaming MCP tool calls in the OpenAI router.
- Good at: ~3× faster constrained decoding than vLLM on structured
  outputs; `FunctionCallParser` with detectors for DeepSeekV3, Llama3,
  Qwen2.5, Qwen3-Coder; RadixAttention prefix cache wins on agent
  loops with repeated system prompts.
- Known issues: heavy CUDA dep tree; smaller community than vLLM.
- MCP / parallel tool calls: streaming MCP tool calls via the OpenAI
  router (since v0.5.3). Per-model tool-call parsers selectable via
  `--tool-call-parser`.

### TensorRT-LLM

- Source: <https://github.com/NVIDIA/TensorRT-LLM>
- License: Apache 2.0.
- Status: Active. Latest stable Apr 20, 2026 (RC cadence through
  2026). Recent changes: fixed Harmony and tool-calling parsers for
  agentic-coding use cases; K2 tool-calling examples added.
- Good at: lowest latency on NVIDIA hardware (H100/B200), KV-cache
  drop, batch scheduling tuned for agent workloads.
- Known issues: NVIDIA-only; build complexity; smaller open-model
  coverage than vLLM.
- MCP / parallel tool calls: tool-call parsers fixed for agentic
  flows; no native MCP server.

### Ollama

- Source: <https://github.com/ollama/ollama>
- License: MIT.
- Status: v0.21.0 (Apr 17, 2026) with `ollama launch` integrations,
  Gemma 4 fixes, Metal cross-compile patches. Earlier 2026: streaming
  chat content + tool calls.
- Good at: easiest local server, model registry, M-series Macs,
  streaming tool-call API.
- Known issues: no built-in MCP — needs an external bridge (MCPHost,
  ollama-mcp-bridge, mcp-client-for-ollama). MCPHost has been called
  "deprecation-prone" in May 2026 community reports.
- MCP / parallel tool calls: no native MCP. Parallel tool calls
  dependent on model.

### LM Studio

- Source: <https://lmstudio.ai>, April 2026 update coverage
  <https://www.toolmintx.in/blog/lm-studio-april-2026-update-mcp-oauth-qwen-3-6-locally-ai>
- License: proprietary (free for personal use; commercial requires a
  license).
- Status: v0.4.10 added OAuth for MCP servers (Apr 2026), v0.4.11
  (Apr 10), v0.4.12 (Apr 17 — Qwen 3.6 support, fixed Windows
  OAuth-MCP issue).
- Good at: desktop UX, GGUF + MLX, runs as both MCP client and MCP
  server, OAuth-backed MCP (rare for local).
- Known issues: closed source; less scriptable than llama.cpp / vLLM.
- MCP / parallel tool calls: MCP since 0.3.17 — first-class for local.
  Both client and server roles.

### LocalAI (mudler)

- Source: <https://github.com/mudler/LocalAI>,
  features <https://localai.io/features/mcp/>
- License: MIT.
- Status: heavy 2026 cadence. Feb: realtime audio + tool calling.
  Mar: agent management, React UI, WebRTC, MLX-distributed via
  P2P/RDMA, MCP Apps, MCP client-side. Apr: voice/face recognition,
  Ollama API compat, video gen in `stable-diffusion.ggml`; new
  backends `sglang`, `ik-llama-cpp`, `TurboQuant`, `sam.cpp`, Kokoros,
  `qwen3tts.cpp`.
- Good at: one-stop "engine-of-engines" wrapping llama.cpp + sglang +
  ik-llama; in-process MCP server exposes LocalAI's own admin surface
  as tools.
- Known issues: heavy surface area; some backends still alpha.
- MCP / parallel tool calls: MCP Apps + MCP client; LocalAI Assistant
  is wired to its own MCP server.

## Model + Harness Combinations That Work Well

### Tiny (≤4B)

- **Gemma 4 e2b (Apache 2.0) — Q4_K_M @ Ollama → little-coder / Pi.**
  Hardware: laptop CPU + 8 GB GPU. Notable: route/execute/respond
  split makes a 2B model reliable for tool-call routing. Sources:
  <https://www.kdnuggets.com/easy-agentic-tool-calling-with-gemma-4>,
  <https://jcbl.ws/gemma-4-tool-calling>.
- **NVIDIA Nemotron 3 Nano 4B (NVIDIA Open Model License) — vLLM or
  SGLang → Goose / OpenHarness.** Hardware: single consumer GPU.

  <https://huggingface.co/blog/nvidia/nemotron-3-nano-4b>.

## Cross-cutting observations (Apr–May 2026)

- **MCP is now table stakes for local stacks** — every active harness
  and most backends ship it; Ollama remains the holdout requiring a
  bridge.
- **Tool-call quality is model-bound at 27B+.** Five local models
  cleared ~95% well-formed-call rates this month: Gemma 4 27B,
  GLM-5.1 32B, Qwen3 32B, Qwen3-Coder 30B, Llama 3.3 70B (97% ceiling).
- **Speed matters as much as accuracy in agent loops.** A coding
  agent doing 20–50 tool calls per task makes Qwen3-Coder-Next-80B-A3B's
  ~44 tok/s decisively better-feeling than a 10 tok/s dense 32B.
- **"The harness improves the model more than fine-tuning"** —
  community-wide realization this month, see HN's "Improving 15 LLMs
  at Coding in One Afternoon. Only the Harness Changed" thread
  (<https://news.ycombinator.com/item?id=46988596>) and The Register's
  OpenClaw piece (<https://www.theregister.com/ai-ml/2026/05/17/how-ai-agent-harnesses-like-openclaw-are-changing-llms-inference-and-cpus/5241530>).
- **Security exposure is real.** Kaspersky (2026-05-12) reports broad
  LLMjacking against exposed Ollama / LM Studio / AutoGPT endpoints —
  affects anyone running a local stack on a routable interface
  (<https://www.kaspersky.com/blog/llmjacking-2026-private-ai-server-security/55768/>).
