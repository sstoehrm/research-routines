# Agent Harness (Local) — 2026-04-25

## Summary

Two-week delta since 2026-04-23. Three big shifts: (1) **Kimi K2.6 GA on
2026-04-20** supersedes K2 Thinking as the headline open-weight agentic
model — 1T total / 32B active MoE, SWE-Bench Pro 58.6%, designed for
12-hour autonomous sessions with up to 300-agent swarms; (2) **Hermes
Agent v0.11.0 (2026-04-23)** is a full React/Ink CLI rewrite with a
pluggable transport layer and native AWS Bedrock; (3) **mem0 v2.0.0**
dropping Neo4j (see the LLM-memory report) combined with **Cline v3.26.6
(2026-04-15)** pitching itself as a laptop-first harness for LM Studio +
Qwen3-Coder-30B finally gives mid-range single-GPU users a named, working
combo. On backends, **vLLM v0.19.0** turned the async scheduler on by
default and shipped a CVE-2026-0994 patch; **LM Studio 0.4.12 (2026-04-17)**
added Qwen 3.6 and improved parallel tool-call handling on the streaming
API (partial answer to the prior follow-up); **Ollama v0.21.2 (2026-04-24)**
integrates Kimi CLI and bundles its web-search plugin into OpenClaw;
**SGLang** absorbed CVE-2026-5760 (CVSS 9.8, GGUF-parsing RCE) — upgrade
required. New BFCL v3 numbers (2026-04-21) put **GLM-4.5 at 76.7** and
**Qwen3-32B at 75.7** — the first time open-weight models top that board.

## Harnesses

### Hermes Agent v0.11.0 (Nous Research)

- Source: <https://github.com/NousResearch/hermes-agent/releases/tag/v2026.4.23>
- Prior: <https://github.com/NousResearch/hermes-agent/releases/tag/v2026.4.16>
- License: Apache-2.0.
- Date: 2026-04-23 (shipped the same day as the prior report).

native AWS Bedrock, five new inference paths, GPT-5.5 via Codex OAuth,

make local **LM Studio + Qwen3-Coder-30B** viable as the only model. Also

## Backends

### vLLM v0.18.0 → v0.19.0

- Source: <https://github.com/vllm-project/vllm/releases>
- Coverage: <https://fazm.ai/blog/vllm-update-april-2026>
- License: Apache-2.0.
- Date: latest published 2026-04-18.

gRPC serving (`--grpc`), GPU NGram speculative decoding, KV-cache
offloading, full Gemma 4 (E2B / E4B / 26B-A4B / 31B), async scheduler **on
by default**. **CVE-2026-0994** patch on the Completions API for ≥0.10.2
— upgrade required if exposed externally.

### llama.cpp (build b8838, nightly 2026-04-24)

- Source: <https://github.com/ggml-org/llama.cpp/releases>
- Coverage: <https://buttondown.com/weekly-project-news/archive/weekly-github-report-for-llamacpp-april-06-2026/>

### Ollama v0.21.1 / v0.21.2

- Source: <https://github.com/ollama/ollama/releases>

- Date: 0.21.2 on 2026-04-24.

Kimi CLI integration (run Kimi K2.6 via Ollama) and bundling of Ollama's

### LM Studio 0.4.10 / 0.4.12

- Source: <https://lmstudio.ai/changelog>
- License: proprietary, free for personal use.
- Date: 0.4.10 on 2026-04-09; 0.4.12 on 2026-04-17.

Gemma 4 tool-call reliability fixes; OAuth for MCP servers (plus a

### SGLang (security + roadmap)

## Model + Harness Combinations That Work Well (delta only)

### Tiny (≤4B)

- **Gemma 4 E2B / E4B + Ollama or llama.cpp + llama-agent**. Day-0
  vLLM / SGLang / Ollama support, native tool-use. License: Gemma terms.
  Source: <https://blog.google/innovation-and-ai/technology/developers-tools/gemma-4/>.

### Small (4B–14B)

- No named new combos in the last two weeks beyond what 2026-04-23
  covered.

### Medium (14B–32B)

- **Qwen3-Coder-30B + LM Studio 0.4.12 + Cline v3.26.6** — the first
  explicitly vendor-endorsed fully-local laptop coding combo at this size,
  as of 2026-04-15.
  Source: <https://cline.bot/blog/cline-v3-26-6-three-ways-to-code-for-free>.
- **Qwen3-32B + any harness** — BFCL v3 result **75.7** as of 2026-04-21,
  second-best open-weight tool-caller. License: Apache-2.0.
  Source: <https://pricepertoken.com/leaderboards/benchmark/bfcl-v3>.
- **Gemma 4 26B / 26B-A4B + vLLM v0.19** for agent serving.
  Source: <https://fazm.ai/blog/vllm-update-april-2026>.

### Large (32B–70B)

- **Qwen3.6-35B-A3B + OpenCode or OpenHarness via vLLM** — released
  April 2026, agentic-coding focus. License: Apache-2.0.
  Source: <https://qwen.ai/blog?id=qwen3.6-35b-a3b>.
- **GLM-4.5 + any OpenAI-compatible harness** — **#1 on BFCL v3 at 76.7**
  as of 2026-04-21.
  Source: <https://pricepertoken.com/leaderboards/benchmark/bfcl-v3>.

### XL / MoE (>70B total, incl. 100B+ MoE)

- **Kimi K2.6 (1T total / 32B active, MoE) + OpenHarness or Kimi CLI via
  Ollama 0.21.x** — GA 2026-04-20. **SWE-Bench Pro 58.6%**, **HLE-with-
  tools 54.0%**, **DeepSearchQA 92.5% F1**. Designed for 12-hour
  autonomous sessions with up to 300-agent swarms / 4,000 coordinated
  steps. Modified MIT license (per HF card).
  Sources: <https://huggingface.co/moonshotai/Kimi-K2.6>,
  <https://www.marktechpost.com/2026/04/20/moonshot-ai-releases-kimi-k2-6-with-long-horizon-coding-agent-swarm-scaling-to-300-sub-agents-and-4000-coordinated-steps/>.
- **GLM-5.1 (754B MoE) + Cline or OpenCode** — released 2026-04-07, MIT
  license, **58.4 SWE-Bench Pro**; runs via vLLM and SGLang FP8 recipes.
  Source: <https://www.testingcatalog.com/zhipu-ai-launches-open-source-glm-5-1-model-for-coding-tasks/>.
- **Qwen3-Coder-Next 80B / 3B + OpenCode or Plandex via vLLM ≥0.15** —
  `--enable-auto-tool-choice --tool-call-parser qwen3_coder` is now the
  canonical recipe; **58.7% SWE-Bench Verified** per Alibaba's April
  publication. License: Apache-2.0.
  Sources: <https://huggingface.co/Qwen/Qwen3-Coder-Next>,
  <https://docs.vllm.ai/projects/recipes/en/latest/DeepSeek/DeepSeek-V3_2.html>.
- **DeepSeek-V3.2 + SGLang** — new recipe reports **3.1× throughput vs.
  vLLM on H100s** for DSV3-class models via FlashMLA / CutlassMLA. Useful
  counterpoint to the earlier "Plandex + vLLM" pairing.
  Sources: <https://docs.vllm.ai/projects/recipes/en/latest/DeepSeek/DeepSeek-V3_2.html>,
  <https://particula.tech/blog/sglang-vs-vllm-inference-engine-comparison>.

## Open questions / follow-ups

- **OpenCode + Qwen3-Coder-Next / Kimi K2 on vLLM vs. llama.cpp** — still
  no first-party benchmark publication in the last two weeks. The community
  `llm-coding-benchmark` repo runs OpenCode end-to-end and notes Llama 4
  Scout fails because llama.cpp does not yet parse pythonic tool calls —
  confirms vLLM remains the safer backend for pythonic-format models.
  Source: <https://github.com/akitaonrails/llm-coding-benchmark>.
- **SGLang agent story** — not landed. CVE-2026-5760 absorbed bandwidth;
  agent-friendly session-cache work is on the Q2 2026 roadmap.
  Source: <https://github.com/sgl-project/sglang/issues/22949>.
- **LM Studio parallel tool-calls** — 0.4.12 explicitly improves streaming-
  API parallel tool-call handling (partial fix). MLX parallel-request work
  is still recent (Feb 2026). Source: <https://lmstudio.ai/changelog>.
- **Native MCP in vLLM, Ollama, SGLang** — still none. llama.cpp remains
  the only backend with a merged MCP server-side path.
- **BFCL v3 open-weight movement** — GLM-4.5 (76.7) and Qwen3-32B (75.7)
  now top the leaderboard — verify whether GLM-5.1 and Kimi K2.6 will be
  added; if so the "best open-weight tool-caller" claim may shift again
  before the next report.
- **Hermes Agent v0.11.0** — shipped same day as the prior report; depth
  review of the new pluggable transport layer for local backends is still
  outstanding.
  Source: <https://github.com/NousResearch/hermes-agent/releases/tag/v2026.4.23>.
