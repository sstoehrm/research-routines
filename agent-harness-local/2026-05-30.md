# Agent Harness (Local) — 2026-05-30

## Summary

Between 2026-04-23 and 2026-05-30 the most consequential changes for
local-LLM agent harnesses landed on the **model and backend** layer:
**DeepSeek V4** (Apr 24, MIT) shipped with day-0 vLLM and SGLang
recipes, plus an SGLang `deepseekv4` tool parser; **Kimi K2.6** (Apr
20, modified MIT) arrived as a 1T-MoE / 32B-active agent model with
INT4 quantization; **Qwen 3.6** (27B dense, 35B-A3B MoE, Apache 2.0)
became the open-weights model people are actually pairing with local
harnesses; and **llama.cpp** finally landed MTP speculative decoding
(PR #22673, May 16) which speeds Qwen 3.6 by ~1.4–2.2× (vendor
figures). On the harness side **OpenCode** (SST) and **Charm Crush**
pushed steady weekly releases with MCP hardening; **Hermes Agent**
shipped a Foundation Release (v0.14.0, May 16) adding a `pip install`
path and an OpenAI-compatible local proxy, then a Velocity Release
(v0.15.0, May 28) with an MCP catalog picker. **OpenHarness** 0.1.8 /
0.1.9 added Docker sandboxing, Ollama as a first-class provider, and
skill slash-commands. **Roo Code** shipped its final release (May 15)
and went read-only — migrate to **Cline** or **Kilo Code**. SGLang
v0.5.12 added auto-detection of tool-call / reasoning parsers from the
chat template.

- Status: updated (v1.15.3 → v1.15.12 across May 16–28, 2026)

What changed:

## Backends

### llama.cpp

- Source: <https://github.com/ggml-org/llama.cpp/releases>
- License: MIT
- Status: updated (build numbers past **b9415** by May 29, 2026)

Tool-calling / MCP / parallel-tool-call notes:

- The big MCP-client work (PR #18655) was the **March 2026 merge** and
  remains the foundation; nothing comparable landed Apr 23 – May 30.
- **PR #22673 (merged May 16, 2026)**: added **MTP (Multi-Token
  Prediction) speculative decoding heads** used by Qwen 3.6 and
  Gemma 4 MTP variants — ~1.4–2.2× faster generation per Unsloth.
- **b9411 (May 29)**: added DeepseekV32 architecture (generic
  DeepSeek Sparse Attention).
- llama-server now parses thinking content and tool calls (per Qwen
  docs).
- **Discussion #22640 (May 6)**: llama-server does **not** implement
  MCP `sampling` — host-side `sampling/createMessage` is unsupported,
  so MCP servers that require it will not work end-to-end without a
  wrapper.
- Reported ~18 tok/s on a single RTX 6000 96GB with the (non-upstream)
  DeepSeek-V4-Flash community patch.

## Model + harness combinations that work well

### Tiny (≤4B)

- **Gemma 4 E2B / E4B** (Apache 2.0; Mar 31, 2026): native
  function-calling with system instructions. Works locally via Ollama
  + Continue.dev or LM Studio + Crush. Good for on-device tool-calling
  agents. Source:
  <https://blog.google/innovation-and-ai/technology/developers-tools/gemma-4/>
- Carry-over from prior report: **Llama-3.2-3B / Qwen2.5-3B +
  llama-agent** on llama.cpp still the cited baseline.

### Small (4B–14B)

- **Qwen 3.6 Coder variants** (Apache 2.0): per Unsloth and community
  testing, tool calls succeed even at 2-bit GGUF on llama.cpp; works
  with **OpenCode + Ollama** and **qwen-code + vLLM**. Source:
  <https://unsloth.ai/docs/models/qwen3.6>
- **Gemma 4 E4B + qwen-code / OpenHarness via Ollama**: documented in
  Gemma 4 function-calling docs —
  <https://ai.google.dev/gemma/docs/capabilities/text/function-calling-gemma4>.
  Reliable JSON arguments and stop behavior.

### Medium (14B–32B)

- **Qwen 3.6 27B (Apache 2.0) + llama.cpp + OpenCode / Crush /
  qwen-code**: scored 71.78 Coding Avg on LiveBench's May 12, 2026
  snapshot per
  <https://medium.com/@arvisionlab/qwen-3-6-reviewed-the-open-weight-coder-that-just-crashed-the-frontier-party-3b2e3e37ba34>
  (secondary source — verify on LiveBench directly).
  r/ollama May 8 thread called it the best local "tool-using coding
  agent." MTP heads via llama.cpp PR #22673 give 1.4–2.2× speedup.
- **Qwen 3.6 27B + SGLang v0.5.12**: auto-detected tool-call /
  reasoning parsers from chat template, removes per-model flag
  config.
- Substack write-up (May 2026) documents a working **Qwen 3.6 +
  OpenCode + Hermes Agent + Codex** local pipeline:
  <https://augmentedmind.substack.com/p/building-a-reliable-local-coding-agent>.

### Large (32B–70B)

- **Qwen 3.6 35B-A3B MoE (Apache 2.0) + llama.cpp / Ollama**: 3B
  active, fits tighter VRAM than the 27B dense; tool-calling via the
  `qwen3_coder` parser in SGLang / vLLM. Source:
  <https://huggingface.co/unsloth/Qwen3.6-35B-A3B-MTP-GGUF>
- **Gemma 4 31B Dense + vLLM (Gemma 4 recipe)** (Apache 2.0): native
  function-calling. Source:
  <https://docs.vllm.ai/projects/recipes/en/latest/Google/Gemma4.html>

### XL / MoE (>70B)

- **DeepSeek V4 Flash (284B / 13B-active, MIT, Apr 24, 2026)** + vLLM
  ≥ 0.7.0 or SGLang v0.5.12 with
  `--tool-call-parser deepseekv4`. Fits a single 80GB GPU when
  quantized; runs on 2×48GB with Unsloth GGUFs. Community llama.cpp
  WIP branch reports ~18 tok/s on a single RTX 6000 96GB. Sources:
  <https://api-docs.deepseek.com/news/news260424>,
  <https://github.com/ggml-org/llama.cpp/discussions/22376>.
- **DeepSeek V4 Pro (1.6T / 49B-active, MIT)**: vLLM / SGLang day-0;
  **not practical to GGUF-quantize** (Q2_K ~400GB) — stick to Flash
  for local. SWE-bench Verified 80.6 reported for the V4-Pro-Max
  variant per
  <https://benchlm.ai/models/deepseek-v4-flash>.
- **Kimi K2.6 (1T MoE, 32B-active, modified MIT, Apr 20, 2026)** +
  Hermes Agent or OpenCode: native INT4 quantization; Agent Swarm
  primitive (300 sub-agents, 4,000 coordinated steps); ties GPT-5.5
  on SWE-bench Pro per Artificial Analysis
  (<https://artificialanalysis.ai/articles/kimi-k2-6-the-new-leading-open-weights-model>).
  Local execution needs ~240GB unified memory for >10 tok/s.
- **Qwen3-Coder-Next (80B / 3B-active, Apache 2.0)** continues as the
  cost-effective MoE coding option via OpenCode + LM Studio
  (<https://unsloth.ai/docs/models/qwen3-coder-next>).
