# Agent Harness (Local) — 2026-06-06

## Summary

Six weeks of dense activity since the 2026-04-23 report. The headlines:

- **llama.cpp** landed MTP (Multi-Token Prediction) speculative decoding
  on master (PR #22673, merged 2026-05-16), giving Qwen3.6-27B a ~1.7×
  generation speedup on RTX 3090 — a big practical win for local agents
  that pay for every token. MCP support shipped in March continues to
  mature; tool-call approval dialogs are now inline rather than modal.
- **vLLM v0.21.0** (2026-05-15) shipped with full DeepSeek V4 tool-call
  parser, Gemma 4 day-0 support, KV Offload + HMA, and switched the
  default wheel to CUDA 13.0.
- **SGLang v0.5.11** (2026-05-05) added Kimi K2.5 tool-call parser and
  tighter DeepSeek V4 integration; XGrammar-2 dropped a day earlier and
  is the new default structured-output backend.
- **LM Studio** shipped three releases in May (0.4.12 → 0.4.14), adding
  OAuth for MCP servers, Qwen 3.6 support, MLX parallel predictions for
  VL models, and stable MTP speculative decoding.
- **OpenHands 1.7.0** (2026-05-01) is now first-class for local:
  Qwen3.6-35B-A3B is their officially recommended local-first model,
  with documented LM Studio / Ollama / vLLM / SGLang paths.
- **DeepSeek V4 preview** (2026-04-24, MIT) is open-weight; runnable on
  dual 4090s or a single 5090, with vLLM and SGLang tool-call parsers
  in tree.
- **Qwen 3.6** family (April 2026) — 27B dense and 35B-A3B MoE — is the
  new local-coding default per OpenHands, ai.rs, and codersera. The 27B
  dense closes the gap with Claude Opus 4.6 on SWE-Bench Verified.
- **Kimi K2.6** (2026-04-20, 1T total / 32B active) is open-weight and
  tops BFCL among open models when paired with SGLang's K2.5 parser
  (note: SGLang issue #18086 flags occasional parser failures).
- **MiniMax-M2.7** is now in the picture; M2 already had day-0
  SGLang/vLLM support.

What did NOT change materially: Plandex (still 2.2.1; no v2.3 cut),
Aider (no May release after v0.86.x line), llama-agent (no new tagged
release).

## Backends

### llama.cpp (ggml-org/llama.cpp)

- License: MIT
- Status: Master branch continues daily activity.

What's new since April:

- **MTP speculative decoding merged 2026-05-16** (PR #22673). Flag is
  `--spec-type draft-mtp`. Qwen3.6-27B: 38 → 65 tok/s on RTX 3090
  (1.71×). Qwen3.6-27B MTP: 160 tok/s, Qwen3.6-35B-A3B MTP: 240 tok/s
  on RTX PRO 6000. Tradeoff: MTP heads eat KV-cache VRAM, so context
  window shrinks on 16 GB cards.
- MCP client work from the March PR #18655 continues; tool-call
  approval is now inline in each tool card (no modal interruption).

Tool-calling matrix: Documented in `docs/function-calling.md`.
`parallel_tool_calls: true` is opt-in on the completion endpoint and
works on a subset of models.

Good at: Single-binary local serving, MCP client built into WebUI.

Known issues: Per OpenHarness issue #199, multimodal `ImageBlock` +
compaction interacts badly with `n_ctx` on llama-server.

Source: <https://github.com/ggml-org/llama.cpp/pull/22673>,
<https://huggingface.co/froggeric/Qwen3.6-27B-MTP-GGUF>,
<https://jarvislabs.ai/blog/qwen36-mtp-llamacpp-rtxpro6000>,
<https://github.com/ggml-org/llama.cpp/blob/master/docs/function-calling.md>.

## Model + Harness Combinations That Work Well

### Tiny (≤4B)

- **Gemma 4 e2b (edge variant), Apache-2.0** — Ollama / LM Studio
  backend → llama-agent or any OpenAI-compatible harness. Runs on
  8 GB laptop. Good at: First-class structured-JSON tool calls without
  grammar constraints; trained for tool-use as a primary objective.
  Source:
  <https://www.kdnuggets.com/easy-agentic-tool-calling-with-gemma-4>,
  <https://android-developers.googleblog.com/2026/04/gemma-4-new-standard-for-local-agentic-intelligence.html>.

### Small (4B–14B)

- **Gemma 4 12B, Apache-2.0** — Ollama → Hermes Agent. Hardware:
  12–16 GB VRAM. Good at: Privacy-first local agent with reliable
  JSON tool calls; documented Hermes Agent recipe. Source:
  <https://lushbinary.com/blog/run-hermes-agent-with-gemma-4-12b-local-guide/>.

### Medium (14B–32B)

- **Qwen 3.6-27B (dense), Apache-2.0** — llama.cpp with MTP
  (`--spec-type draft-mtp`) → OpenCode / Cline / Roo Code / Aider.
  Hardware: RTX 3090 (38 → 65 tok/s with MTP) or 18 GB consumer card.
  Good at: Best local coding model per ai.rs and codersera May 2026
  tests; within 4 points of Claude Opus 4.6 on SWE-Bench Verified.
  Tradeoff: MTP shrinks usable context on 16 GB cards. Source:
  <https://ai.rs/ai-developer/qwen-3-6-27b-local-coding-model>,
  <https://qwen.ai/blog?id=qwen3.6-27b>,
  <https://mer.vin/2026/05/run-qwen-3-6-mtp-in-llama-cpp-faster-local-inference-with-built-in-speculative-decoding/>.
- **Devstral Small 2 (24B), Apache-2.0** — llama.cpp / vLLM →
  Mistral Vibe CLI. Hardware: Single RTX 4090 or 32 GB Mac. Good at:
  256K context, fully private SWE agent; runs in Vibe with ACP IDE
  integration. Source: <https://mistral.ai/news/devstral-2-vibe-cli/>.

### Large (32B–70B)

- **Qwen3.6-35B-A3B (MoE), Apache-2.0** — LM Studio (preferred) /
  Ollama / vLLM / SGLang → **OpenHands 1.7.0 (officially recommended
  local-first combo as of 2026-05-21)**. Hardware: 12 GB VRAM
  possible at small quants; full precision wants 24+ GB. Good at:
  Agentic coding with the active-parameter-efficient MoE; documented
  OpenHands setup paths. With MTP on RTX PRO 6000: 240 tok/s. Source:
  <https://www.openhands.dev/blog/openhands-product-update---may-2026>,
  <https://docs.openhands.dev/openhands/usage/llms/local-llms>,
  <https://carteakey.dev/blog/running-qwen3-6-mtp-locally/>.

### XL / MoE (>70B total, incl. 100B+ MoE)

- **Qwen3-Coder-Next (80B total / 3B active), Apache-2.0** — vLLM /
  SGLang → SWE-Agent / Mini-SWE-Agent / OpenHands. Hardware: 64 GB
  MacBook, RTX 5090, or AMD Radeon 7900 XTX. Good at: SWE-Bench
  Verified 70.6% with SWE-Agent, 71.1% with Mini-SWE-Agent, 71.3%
  with OpenHands; SWE-Bench Pro 44.3%. 256K context. Still the
  standout small-active-param coder. Source:
  <https://qwen.ai/blog?id=qwen3-coder-next>,
  <https://explore.n1n.ai/blog/qwen3-coder-next-architecture-performance-analysis-2026-05-22>.
- **MiniMax-M2 (230B total / 10B active), open-weight** — SGLang
  (day-0) or vLLM → harness of choice. Good at: Multi-file edits,
  code-run-fix loops, Terminal-Bench and (Multi-)SWE-Bench style
  tasks; long-horizon planning across shell/browser/retrieval/code
  runners. Source: <https://github.com/MiniMax-AI/MiniMax-M2>,
  <https://www.minimax.io/news/minimax-m2>.
- **Kimi K2.6 (1T total / 32B active), open-weight (modified MIT)** —
  SGLang with Kimi K2.5 parser (note caveats) or via Unsloth quants
  for llama.cpp → Hermes / OpenHands / Roo Code. Hardware: 1-bit
  quant fits in 247 GB total disk+RAM+VRAM; 1.8-bit fits in 24 GB GPU
  + RAM offload (~1–2 tok/s). Good at: Currently leads open-source on
  coding (78.57) and agentic coding (58.33) per MindStudio's
  leaderboard cut; `preserve_thinking` mode helps multi-turn coding.
  Source: <https://www.kimi.com/blog/kimi-k2-6>,
  <https://unsloth.ai/docs/models/tutorials/kimi-k2-thinking-how-to-run-locally>,
  <https://www.mindstudio.ai/blog/best-open-source-llms-agentic-coding-2026>.
- **DeepSeek V4-Flash (284B) and V4-Pro (1.6T), MIT** — vLLM 0.20+ or
  SGLang with in-tree V4 tool-call parser → OpenCode (with
  `interleaved: { field: "reasoning_content" }` for thinking mode).
  Hardware: Dual RTX 4090 or single RTX 5090 viable for Flash. Good
  at: 1M-token context at 27% of single-token FLOPs and 10% of KV
  cache vs DeepSeek V3.2 (CSA + HCA hybrid attention). Source:
  <https://api-docs.deepseek.com/news/news260424>,
  <https://huggingface.co/deepseek-ai/DeepSeek-V4-Flash>.

## Open questions / follow-ups

- **Kimi K2.5/K2.6 tool-call parser reliability in SGLang** (issue
  #18086). Track whether the parser fix lands by the next report;
  meanwhile harnesses need retry logic for K2-family tool calls.
- **llama.cpp MCP image + compaction bug** (OpenHarness #199).
  Multimodal sessions still hit `n_ctx` errors; check whether the fix
  lands in the next llama.cpp release.
- **Plandex** — no v2.3, no obvious roadmap, hosted offering winding
  down. Consider whether to keep covering it.
- **llama-agent** — the Rust-based agent harness around llama.cpp had
  no tagged release this cycle. Is it still actively maintained?
- **MCP stateless transport and discovery** are targeted at the June
  2026 spec cycle; confirm what shipped vs. slipped by next report.
- **BFCL-V4** still has only 9 evaluated models as of June 2026. Need
  to find a broader, openly-reproduced tool-calling benchmark that
  includes Qwen 3.6, Kimi K2.6, MiniMax M2.7, Devstral 2.
- **TensorRT-LLM** agent-application scheduling work (proactive
  KV-cache drop, batch scheduling for multi-agent) is unique — worth
  a deeper follow-up to see if any harness has integrated it.
- **MTP VRAM/context tradeoff** quantification: the May benchmarks
  show throughput wins but the context-shrinkage cost on 16 GB cards
  needs a real agent-loop test (not just tok/sec).
- **OpenHarness v0.2** — still no minor-version bump after two months
  of v0.1.x patching. Watch for it.
