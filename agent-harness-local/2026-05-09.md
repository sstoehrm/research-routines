# Agent Harness (Local) — 2026-05-09

## Summary

This cycle was driven by **DeepSeek V4** (Apr 24) and the backend
scramble to support it. **vLLM 0.20.0** (Apr 27, 752 commits / 320
contributors) shipped Day-0 DeepSeek V4 + Hunyuan v3 preview support,
moved to CUDA 13 / PyTorch 2.11 / Transformers v5, made FA4 the default
MLA prefill, introduced TurboQuant 2-bit KV (4× capacity), and bumped to
Python 3.14; v0.20.1 (May 3) stabilised the V4 path with multi-stream
pre-attention GEMM and fixed RTX Blackwell SM120 NVFP4 MoE. **SGLang**
shipped a Day-0 V4 serving + RL post (Apr 25). On harnesses,
**Hermes Agent** had three releases (v0.11 Interface, v0.12 Curator,
v0.13 Tenacity — adding durable multi-agent Kanban and persistent
goal tracking); **OpenCode** ran a continuous v1.14.x train; and
**Charm Crush** was open-sourced May 6 as a polished post-OpenCode-fork.
On models the headline open-weight releases for agents are
**Qwen3.6-27B** (Apr 22, 77.2% SWE-bench Verified — direct competitor
to Qwen3-32B), **Qwen3.6-35B-A3B** (Apr 16 MoE with 3B active),
**Kimi K2.6** (Apr 20, 1T MoE / 32B active, 80.2% SWE-bench Verified,
agent-swarm scaling to 300 sub-agents), and **GLM-5.1** (Apr 7, first
open model to lead SWE-Bench Pro at 58.4%). MCP support in **Ollama**
remains absent (issue #7865); **LM Studio** patched MCP-OAuth on
Windows.

## Harnesses

### OpenCode (SST) — v1.14.x train

- Source: <https://github.com/sst/opencode>; release notes via Product
  Hunt launches: <https://www.producthunt.com/products/opencode/launches>
- License: MIT.

Continuous v1.14.x releases through Apr 29 / May 1, 2026. v1.14.30
(Apr 29) added **Mistral Medium 3.5 with reasoning support**, fixed
missing Desktop sessions, improved Azure responses and DeepSeek
compatibility. May 1 update added Azure setup prompts, preserved parent
permissions in task child sessions, surfaced **explicit errors for
invalid remote MCP URLs** (meaningful for agent debugging), and fixed
crashes restoring messages with missing models.

### Hermes Agent (Nous Research) — v0.11 → v0.13

- Source: <https://github.com/NousResearch/hermes-agent/releases>
- License: Nous source-available (verify in repo).

Three releases in window:

- **v0.11.0 "Interface"** (Apr 23): full React/Ink CLI rewrite,
  pluggable transport architecture, native AWS Bedrock, five new
  inference paths, GPT-5.5 via Codex OAuth, 17th messaging platform
  (QQBot).
- **v0.12.0 "Curator"** (Apr 30): 1,096 commits / 550 PRs,
  self-maintaining Curator, smarter self-improvement loop, new
  providers, bundled Spotify / Google Meet integrations.
- **v0.13.0 "Tenacity"** (May 7): **durable multi-agent Kanban**,
  persistent `/goal` tracking, stronger session recovery, Google Chat
  as 20th platform.

The transport rewrite plus persistent goal/Kanban are the meaningful
agentic upgrades — Hermes is now competitive with OpenHarness for
long-horizon multi-agent orchestration.

### Charm Crush — open-sourced May 6, 2026

- Source: <https://github.com/charmbracelet/crush>
- License: see repo (FSL/MIT).

Charm's post-OpenCode-fork, open-sourced this window. First-class
support for **Hyper** (a coding-focused inference service), MCP over
stdio / HTTP / SSE, LSP-augmented context, multi-provider with
**mid-session model switching**, cross-OS (Linux / macOS / Windows /
Android / BSD). Functionally equivalent to OpenCode for local-LLM use;
differs on UX polish and Charm's Bubble Tea TUI stack. Worth running
side-by-side with OpenCode for users who prefer Charm's aesthetic.

### Aider, Plandex, OpenHarness, llama-agent

No new releases in window. OpenHarness latest is v0.1.7 (Apr 18,
pre-window). Aider v0.86.x lineage continues but no new minor.

## Backends

### vLLM v0.20.0 (Apr 27) and v0.20.1 (May 3)

- Source: <https://github.com/vllm-project/vllm/releases/tag/v0.20.0>
- License: Apache 2.0.

The biggest backend release of the window.

- **v0.20.0**: 752 commits / 320 contributors. Day-0 **DeepSeek V4 +
  Hunyuan v3** preview support. CUDA 13 / PyTorch 2.11 / Transformers
  v5 baseline. **FA4 as default MLA prefill**, **TurboQuant 2-bit KV**
  (4× capacity), introduction of vLLM IR. Python 3.14 added.
- **v0.20.1**: DeepSeek V4 stabilization (multi-stream pre-attention
  GEMM, BF16 / MXFP8 all-to-all over FlashInfer), **RTX Blackwell
  SM120 NVFP4 MoE fixes**, faster FP32→FP4 conversion via PTX cvt.

### SGLang — Day-0 DeepSeek V4 (Apr 25)

- Source: <https://www.lmsys.org/blog/2026-04-25-deepseek-v4/>
- License: Apache 2.0.

Joint LMSYS + Miles post: SGLang shipped Day-0 serving + RL for
DeepSeek V4's hybrid sparse attention, mHC, and FP4 expert weights.
Benchmark setup: B200 Pro (1.6T) at TP=8 and H200 Flash (285B) at
TP=4, single-batch decode, OSL=4096 on a 30K-token prefix. SGLang
EAGLE-3 spec-decode (`num-steps=3`, `eagle-topk=1`,
`num-draft-tokens=4`) reaches **accept length ~2.5** on both Pro and
Flash. Numerical tok/sec values are rendered only as figures in the
post — read directly for the chart values.

## New model releases relevant for agents

### DeepSeek V4 Pro (1.6T MoE / 49B active) and V4 Flash (284B / 13B active) — Apr 24

- Source: <https://huggingface.co/deepseek-ai/DeepSeek-V4-Pro>,
  <https://api-docs.deepseek.com/news/news260424>
- License: MIT.
- Bucket: **XL / MoE**.

Hybrid Compressed Sparse Attention (CSA) + Heavily Compressed
Attention (HCA), **1M-token context**, up to 384K output tokens. At 1M
context V4-Pro uses **~27% of single-token inference FLOPs** and **~10%
of KV cache** vs. V3.2. V4-Flash (284B / 13B active) is the practically
deployable variant for self-hosters with 8×H200 / B200; V4-Pro is
multi-node-only (BF16 weights ~3.2 TB). Official llama.cpp / Ollama
GGUF support pending.

### Qwen3.6-27B (dense, Apr 22) and Qwen3.6-35B-A3B (MoE, Apr 16)

- Sources: <https://huggingface.co/Qwen/Qwen3.6-27B>,
  <https://huggingface.co/Qwen/Qwen3.6-35B-A3B>
- License: Apache 2.0.
- Buckets: **Medium** (27B dense), **Large** (35B-A3B with 3B active).

Qwen3.6-27B reports **77.2% SWE-bench Verified** and **59.3%
Terminal-Bench 2.0**; native multimodal, 262K context extensible to
1M, new "**Thinking Preservation**" mechanism for retaining reasoning
across messages. The 27B dense model is now the strongest open coding
model in the Medium bucket and a direct competitor for the
Qwen3-32B + OpenCode + vLLM combo from the prior report.

### Kimi K2.6 — Apr 20

- Sources: <https://huggingface.co/moonshotai/Kimi-K2.6>,
  <https://artificialanalysis.ai/articles/kimi-k2-6-the-new-leading-open-weights-model>
- License: Modified MIT.
- Bucket: **XL / MoE**.

1T total / 32B activated MoE, 262K context, ships natively in INT4.
Reports **80.2% SWE-bench Verified** and **58.6% SWE-Bench Pro**.
Agent-swarm scaling to **300 sub-agents over 4,000 coordinated steps**
(vs. 100 / 1,500 for K2.5). Direct successor to the Kimi K2 Thinking
entry in the prior report; the new Agent Swarm + Skills infrastructure
is the main reason to re-test in OpenHarness / OpenCode / Crush.

### GLM-5.1 — Apr 7 (vLLM + SGLang recipes landed in window)

- Source: <https://huggingface.co/zai-org/GLM-5.1>
- vLLM recipe: <https://docs.vllm.ai/projects/recipes/en/latest/GLM/GLM5.html>
- License: MIT.
- Bucket: **XL / MoE**.

754B MoE / 40B active, 200K context, 128K max output. **58.4%
SWE-Bench Pro** — first open-source model to lead that leaderboard,
edging GPT-5.4 (57.7%) and Claude Opus 4.6 (57.3%). Reports **8-hour
autonomous execution**. FP8 deployment via vLLM
`--enable-expert-parallel` or SGLang `--enable-moe-ep`.

## Model + Harness Combinations That Work Well

Updates / additions only — combos already in the prior report still
apply unless a backend-specific regression is noted.

### Tiny (≤4B)

- **Gemma 4 E2B / E4B (Q4_K_M) + llama-agent on Ollama 0.21**.
  Native function calling + audio; benefits from the in-window Gemma 4
  flash-attention fix in Ollama 0.21. Source:
  <https://ollama.com/library/gemma4:e4b>.

### Small (4B–14B)

- No new high-confidence in-window combos. Prior recommendations
  unchanged (Qwen2.5-Coder-7B/14B + Aider; Llama-3.1-8B + OpenCode).

### Medium (14B–32B)

- **Qwen3.6-27B (BF16 or AWQ) + vLLM 0.20.x + OpenCode 1.14.30 (or
  Crush)** on a single H100 / H200. Direct upgrade path from the
  Qwen3-32B + OpenCode + vLLM combo in the prior report; 77.2%
  SWE-bench Verified per
  <https://huggingface.co/Qwen/Qwen3.6-27B>.

### Large (32B–70B)

- **Qwen3.6-35B-A3B (MoE) + llama-agent on llama.cpp**, 64 GB Apple
  Silicon or 1×4090. Bucket-Large model that activates only 3B,
  tractable on prosumer HW. Source:
  <https://huggingface.co/Qwen/Qwen3.6-35B-A3B>.

### XL / MoE (>70B)

- **DeepSeek-V4-Flash (FP8 / MXFP8) + vLLM 0.20.1 + OpenCode 1.14.30**,
  8×H200. First backend with stabilized V4 path and OpenCode now
  surfaces remote MCP errors. Source: vLLM 0.20.1 release notes,
  OpenCode launches.
- **DeepSeek-V4-Pro (FP4 expert weights) + SGLang Day-0 + Hermes
  Agent v0.13.0**, B200 TP=8. For agents that need multi-day Kanban
  workflows; Hermes 0.13 adds durable goal tracking. Source:
  <https://www.lmsys.org/blog/2026-04-25-deepseek-v4/>.
- **Kimi K2.6 (INT4 native) + SGLang + OpenHarness 0.1.7**, 8×H200.
  Agent-swarm scaling makes this the headline upgrade vs. the Kimi
  K2 Thinking + OpenHarness combo in the prior report. Source:
  <https://artificialanalysis.ai/articles/kimi-k2-6-the-new-leading-open-weights-model>.
- **GLM-5.1 (FP8) + vLLM (`--enable-expert-parallel`) or SGLang
  (`--enable-moe-ep`) + Crush / OpenCode**, 8×H200. First open model
  leading SWE-Bench Pro and the only one with a claimed 8-hour
  autonomous-execution number. Source:
  <https://docs.vllm.ai/projects/recipes/en/latest/GLM/GLM5.html>.

## Inference engine head-to-head — May 2026 roundups

- Source: <https://leetllm.com/blog/llm-inference-engine-comparison-2026>,
  <https://www.spheron.network/blog/vllm-vs-tensorrt-llm-vs-sglang-benchmarks/>

- **SGLang 16,200 tok/s vs. vLLM 12,500 tok/s** on H100 for 7B–8B
  models (~29% lead). The gap collapses to **3–5% on 70B+ models**.
- On H100 80 GB **Llama-3.3-70B-Instruct FP8**, **TensorRT-LLM is 8%
  faster than vLLM at 1 concurrent request and 13% faster at 50**.
- 8×B200 SXM serving **gpt-oss-120B peaks at 92,909 output tok/s**.

## MCP gap status (no change in window beyond LM Studio fix)

- **Ollama**: still no native MCP support (issue #7865 open); use
  MCPHost / ollama-mcp-bridge / ollmcp.
- **LM Studio**: leading GUI MCP client; OAuth on Windows fixed Apr 17.
- **llama.cpp**: leading CLI / server MCP client (since the Mar 6
  merge).
- **SGLang**: no first-party MCP client.
- **Parallel tool calls in llama.cpp**: confirmed disabled by default;
  enable via `"parallel_tool_calls": true` per
  <https://github.com/ggml-org/llama.cpp/blob/master/docs/function-calling.md>.
