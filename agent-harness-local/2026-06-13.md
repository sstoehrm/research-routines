# Agent Harness (Local) — 2026-06-13

## Summary

Since the April baseline, the cycle's biggest move is on the model
side: **Qwen3.6 / Qwen3.6-35B-A3B** (Apr 16) and **Kimi K2.6** (Apr 20)
shipped within a four-day window, and **DeepSeek-V4** (Apr 24) followed
— all under Apache 2.0 with native tool-calling, plus a fresh
**Qwen3.6 Coder** family in 4B / 14B / 32B sizes. Backends caught up
fast: **SGLang 0.5.11/0.5.12** (May 5, May 16) made Speculative
Decoding V2 the default and added day-one DeepSeek-V4 support;
**vLLM v0.22.0** (May 29) and **v0.22.1** (Jun 5) hardened
DeepSeek-V4 and shipped EAGLE 3.1; **Ollama** churned through
0.23.x → 0.24 → 0.30 in May–June, replacing its custom runner with
llama.cpp on NVIDIA and an MLX runner on Apple Silicon. **LM Studio
0.4.13** (May 22) finally fixed dropped-chunk parallel tool calls and
streamed empty-function-name bugs — the GUI is now a usable agent
backend in a way it was not in April. On harnesses, **Hermes Agent**
(Nous) tripled its release cadence — three named releases in May
(Foundation 0.14, Velocity 0.15.1, Patch 0.15.2) plus the Surface
desktop release in early June — and a TechTimes piece claims it has
overtaken OpenClaw on monthly contributor counts. **OpenHands 1.7/1.8**
added LLM Profiles, sub-agent delegation, and KVM-accelerated
sandboxes; **Goose** went through v1.34–1.37 with a hooks system and
PreToolUse denial; **OpenCode** crossed v1.17 with native local-MCP
`cwd` support. The biggest pending event is the **MCP 2026-07-28
specification** whose release candidate locked on **May 21, 2026**:
it removes sessions entirely (any request can land on any server),
adds `Mcp-Method`/`Mcp-Name` routing headers, batches tool calls in a
single JSON-RPC request, and tightens OAuth.

## Backends

### llama.cpp

- Source: <https://github.com/ggml-org/llama.cpp>; releases:
  <https://github.com/ggml-org/llama.cpp/releases>.
- Tutorial: <https://github.com/ggml-org/llama.cpp/discussions/14758>.

The March 2026 MCP-client merge (PR #18655) into the llama-server
web UI remains the structural change of the year. Through May/June
the build line moved from b9000 → b9616 with frequent ships: notable
items include **EAGLE3 speculative decoding** (b9606, Jun 12),
**Qwen 3.6 MTP** support (b9196 era), Adreno mobile-GPU q5_0/q5_1
kernels, and a CUDA "concat for scalar types" backend addition
(b9605). Tool-call routing in the web UI gained polish but
**parallel tool calls remain server-side via `--parallel N`** on
llama-server — model-level parallel tool calls depend on the
template
(<https://github.com/ggml-org/llama.cpp/discussions/22132>).
Measured: Qwen3.6-35B-A3B Q4_K_M runs **~30 tok/s on 6 GB VRAM** with
heavy CPU offload
(<https://mychen76.medium.com/run-qwen3-6-35b-a3b-on-6gb-vram-using-llama-cpp-30-tps-a89032e5a60c>),
and a single RTX 3090 benchmark of llama.cpp speculative decoding on
Qwen3.6-35B-A3B found **no variant achieves net speedup** on Ampere
+ A3B MoE post-PR #19493 (Apr 19)
(<https://github.com/thc1006/qwen3.6-speculative-decoding-rtx3090>).

## MCP — protocol developments

- **2026-07-28 specification, release candidate locked May 21, 2026**
  (<https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/>).
  Key changes vs. the spec that landed in March:
  - **Sessions removed**: any request can land on any server instance
    — the `initialize` / `initialized` handshake is gone; client info
    travels via `_meta` on each request.
  - **Routing headers required**: `Mcp-Method` and `Mcp-Name` so load
    balancers/gateways can route without inspecting the body.
  - **List/read caching**: `ttlMs` and `cacheScope` on responses,
    HTTP-Cache-Control-style.
  - **Tool-call batching**: clients can send multiple tool invocations
    in a single JSON-RPC request — directly relevant to parallel
    tool-call semantics.
  - **Auth tightened**: clients must validate `iss` per RFC 9207,
    declare OpenID Connect `application_type` at registration.
- The 2026 MCP roadmap (March) keeps streaming results, skills,
  extensions, server discovery, long-running tasks, and event-driven
  triggers on the radar
  (<https://chatforest.com/guides/mcp-2026-roadmap-whats-coming/>,
  <https://tedt.org/MCPs-2026-Roadmap/>).
- **Agentic AI Foundation** (Linux Foundation, 2026) — Goose, MCP,
  AGENTS.md as founding projects
  (<https://www.paperclipped.de/en/blog/goose-block-open-source-ai-agent/>).
  Useful as a stability signal for the protocol's governance.
