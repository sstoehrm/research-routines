# Agent Harness (Local) — 2026-05-02

## Summary

The April 20 → May 2 window is a **model + backend** window, not a
harness window. On the harness side, OpenCode, Aider, OpenHarness,
Plandex, Cline, and llama-agent had no verified releases in the
window; only Goose (now under the AAIF / Linux Foundation umbrella)
and Hermes Agent (Nous Research) shipped in-window UX work. By
contrast, three frontier-class open weights landed: **DeepSeek V4**
(Apr 24, MIT, 1.6T-total Pro and 284B / 13B-active Flash, 1M
context), **Poolside Laguna XS.2** (Apr 29, Apache-2.0, 33B-total /
3B-active MoE specialised for local agentic coding), and
**Qwen3.6-27B** (Apr 22, Apache-2.0 dense, 262K context). Backends
moved in lockstep: **vLLM v0.20.0** (Apr 27) added day-one DeepSeek
V4 support, FlashAttention 4 default for MLA prefill, TurboQuant 2-bit
KV cache, CUDA 13.0, PyTorch 2.11, Python 3.14; **Ollama** shipped
seven tags (v0.21.1 → v0.22.1) including native catalog entries for
Nemotron 3 Nano Omni and Laguna XS.2; **llama.cpp** crossed b8987 →
b8999 with Vulkan asymmetric flash-attention coopmat2, WebGPU vector
shaders, and Hexagon non-contiguous tensor support. **LM Studio** had
no in-window release that changes parallel-tool-call behaviour. No
new MCP spec revision; the March 5, 2026 roadmap still governs.

## Backends

### llama.cpp — Vulkan, WebGPU, Hexagon improvements (b8987 → b8999)

- Source: <https://github.com/ggml-org/llama.cpp/releases>
- License: MIT.
- Cadence: builds **b8987 → b8999 between 2026-04-30 and 2026-05-01**
  (verified via the releases atom feed).

In-window changes (verified from release titles):

- Vulkan asymmetric flash-attention in coopmat2 (b8995).
- WebGPU vectorization fix and upscale shader (b8994 / b8996).
- Hexagon backend non-contiguous row-tensor support for unary ops
  (b8998).
- 32-bit WASM / large-model file I/O fix using ftello / fseeko
  (b8992).
- `--tensor-type` override fix (b8999).

No MCP-client follow-on visible since the March PR #18655 merge, but
Vulkan and Hexagon paths keep improving for non-CUDA local rigs
(Apple, AMD, Qualcomm).

### vLLM v0.20.0 + v0.20.1 — DeepSeek V4 day-one, FA4, TurboQuant

Tool-calling and parallel-function-call story unchanged from prior

## New open-weight models in window

### Tiny (≤4B): no fresh launches

The April 2 Gemma 4 E2B / E4B (Apache-2.0) remains the freshest
practical pick; multimodal, tool-use-friendly, runs on CPU / edge.
Source: <https://blog.google/innovation-and-ai/technology/developers-tools/gemma-4/>

### Small (4B–14B): no fresh launches

Gemma 4 E4B (Apache-2.0) and the prior-cycle Qwen 3.5 small dense
models remain best in class.

### Medium (14B–32B): Qwen3.6-27B (2026-04-22)

- Source: <https://github.com/QwenLM/Qwen3.6>
- Coverage:
  <https://www.marktechpost.com/2026/04/22/alibaba-qwen-team-releases-qwen3-6-27b-a-dense-open-weight-model-outperforming-397b-moe-on-agentic-coding-benchmarks/>
- License: Apache-2.0.

Dense 27B; native 262K context (extensible to ~1M); multimodal
text/image/video; "Thinking Preservation" across multi-turn; claimed
77.2 on SWE-bench Verified. Top open dense pick for a single
24–32 GB GPU running an agent loop. Branding caveat: the "Qwen3.6"
label is heavily reported but worth treating with mild skepticism;
verify weights on Hugging Face under the QwenLM org before
committing.

### Large (32B–70B): Poolside Laguna XS.2 (2026-04-29)

- Source: <https://poolside.ai/blog/introducing-laguna-xs2-m1>
- Coverage:
  <https://venturebeat.com/technology/american-ai-startup-poolside-launches-free-high-performing-open-model-laguna-xs-2-for-local-agentic-coding>
- License: Apache-2.0.

33B-total / 3B-active MoE, agentic-coding-specialised, runs on a
36 GB Mac (Ollama, OpenRouter, HF). Reported scores: 68.2
SWE-bench Verified, 44.5 SWE-bench Pro. First credible open-weight
model from a US frontier lab specifically tuned for local agentic
coding loops.

### XL / MoE (>70B): DeepSeek V4 (2026-04-24)

- Source: <https://api-docs.deepseek.com/news/news260424>
- Coverage: <https://simonwillison.net/2026/Apr/24/deepseek-v4/>
- License: MIT.

Two open-weight variants: **V4-Pro** (1.6T total / 49B active) and
**V4-Flash** (284B / 13B active), 1M context, switchable
thinking / non-thinking modes. V4-Flash is realistic to self-host
on a single 8×H100 / 8×MI300 box and will be the most-cited backbone
in May. V4-Pro takes 1.6T-class infrastructure but is the largest
open weights ever shipped. Day-one supported by vLLM v0.20.

Adjacent: NVIDIA Nemotron 3 Nano Omni (Apr 28, 30B / 3B-active
hybrid Mamba-Transformer MoE, NVIDIA Open Model Agreement —
**not OSI-approved** but commercial use allowed; multimodal incl.
audio/video). Source:
<https://blogs.nvidia.com/blog/nemotron-3-nano-omni-multimodal-ai-agents/>.

## Model + Harness combinations that work well (this window)

### Tiny (≤4B)

- **Gemma 4 E2B / E4B + OpenHarness 0.1.7** on Ollama 0.22.x. No
  window-fresh alternative.
- Prior recommendations (Llama-3.2-3B / Qwen2.5-3B + llama-agent on
  llama.cpp) still apply for tool-use minimalism.

### Small (4B–14B)

- **Gemma 4 E4B + Aider** (or OpenCode) on Ollama for tool calls;
  if you need pure code, stick with **Qwen2.5-Coder-7B/14B + Aider**
  from prior research.

### Medium (14B–32B)

- **Qwen3.6-27B + OpenHarness or Cline** on llama.cpp (recent
  b899x) or vLLM v0.20. Best new pick of the window for a single
  high-end GPU. Source: see Qwen3.6 launch coverage above.
- Prior pick **Qwen3-32B + OpenCode + vLLM** still valid.

### Large (32B–70B)

- **Poolside Laguna XS.2 + Hermes Agent or OpenHarness** on
  Ollama 0.22.0 (native catalog entry) or vLLM v0.20. First-choice
  for a single high-end Mac / workstation. Source: Poolside launch
  blog.
- Prior pick **Llama-4 Scout / Maverick + OpenCode + vLLM** still
  valid.

### XL / MoE (>70B)

- **DeepSeek V4-Flash + any MCP-aware harness on vLLM v0.20.1**.
  Top choice this window if you have 8×H100-class hardware. Source:
  DeepSeek API docs / Simon Willison writeup.
- **DeepSeek V4-Pro** if you have 1.6T-class infra (multi-node).
- Prior picks **Qwen3-Coder-Next (80B / 3B-active) + OpenCode or
  Plandex** and **Kimi K2 Thinking + OpenHarness / OpenCode** still
  valid for workstation-scale.

## Caveats

Several "Qwen3.6", "DeepSeek V4", "Nemotron 3", "GPT-5.5" mentions
come from secondary AI-summary blogs surfaced via WebSearch; primary
sources exist (DeepSeek API docs, Google blog, Poolside blog,
NVIDIA newsroom), but **exact benchmark numbers should be
re-verified on Hugging Face model cards before quoting in
production**. The "OpenClaw" terminology that appears in some
Ollama / Hermes search summaries does **not** correspond to a
verified primary project and is likely a search-engine confusion of
"OpenCode" — no claim above relies on it.
