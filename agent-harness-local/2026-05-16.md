# Agent Harness (Local) — 2026-05-16

## Summary

This window was dominated by a wave of frontier open-weights model
releases (DeepSeek V4-Pro/Flash on Apr 24, Xiaomi MiMo-V2.5 / V2.5-Pro
on Apr 27, Moonshot Kimi K2.6 on Apr 20, Qwen3.6-27B on Apr 22) and
inference backends scrambling to add day-0 support. **SGLang v0.5.11**
(May 5) and **vLLM v0.21.0** (May 15) both shipped day-0 recipes; vLLM
also tightened tool calling (XGrammar 0.2.0 structural tags, LFM2/2.5
and Cohere parsers, streaming tool calls in the Responses API). On the
harness side, **Hermes Agent v0.13.0 "Tenacity"** (May 7) added a
durable multi-agent Kanban + `/goal` Ralph loop; **OpenHarness v0.1.8/
v0.1.9** (May 6–7) added more provider profiles, a Docker sandbox, and
a skill-creator; **oh-my-openagent v4.x** introduced a multi-agent
"Team Mode"; **OpenCode** kept its weekly cadence (v1.14.46–v1.14.50).
MCP coverage continues to spread — **LM Studio 0.4.13** (May 13)
polished MLX 1.8.1 on top of April's MCP OAuth work — but **Ollama
still has no native MCP**, and the MCPHost / ollama-mcp-bridge /
jonigl TUI remain the workaround. The standout new model+harness
combo of the cycle is **Qwen3.6-27B + OpenCode + SGLang/llama.cpp**
(dense, fits 24 GB at Q4_K_M, 77.2 SWE-bench Verified evaluated *via*
OpenCode).

## Harnesses

### Hermes Agent (Nous Research)

- Source: <https://github.com/NousResearch/hermes-agent>
- License: open-source (per Nous; verify in repo)
- Status: **major release in window**

What's new since 2026-04-23: **v0.13.0 "Tenacity"** released
2026-05-07 (tag `v2026.5.7`). 864 commits, 588 merged PRs since
v0.11. Adds durable multi-agent Kanban with heartbeat, zombie
detection, auto-block on incomplete exit, per-task retries, and
hallucination recovery; new `/goal` command (Ralph loop) to keep the
agent locked on a target across turns; gateway auto-resume after
restart; Checkpoints v2 with real pruning; eight P0 security fixes
with redaction on by default; Google Chat as the 20th messaging
platform; localization to seven languages. v0.12.0 "Curator" landed
2026-04-30 with an autonomous skill-library curator, four new
providers, 57% faster cold start.

Notes / caveats: works with any OpenAI-compatible endpoint
(DeepSeek, Kimi, MiniMax, z.ai, OpenRouter, or self-hosted vLLM /
SGLang / Ollama).

### OpenHarness (HKUDS)

- Source: <https://github.com/HKUDS/OpenHarness>
- License: per repo (open source)
- Status: **updated**

What's new since 2026-04-23: **v0.1.8** (May 6) and **v0.1.9** (May
7). v0.1.8 adds first-class provider profiles (NVIDIA NIM, Qwen
DashScope, MiniMax, Google Gemini), plugin tool auto-discovery for
`BaseTool` subclasses, a **Docker sandbox backend** for stronger
execution isolation, an OpenAI-compatible client supporting DeepSeek
/ GitHub Models / Groq / Ollama, a `--dry-run` settings preview,
and a `diagnose` skill. v0.1.9 ships a `skill-creator` for
verifying skills, plus user-invocable skills as slash commands.
Memory is now isolated between `ohmo` and `OpenHarness` project
memory.

Notes / caveats: **CVE-2026-40502** disclosed for the project;
check security advisories before pinning.

### oh-my-openagent (omo)

What's new since 2026-04-23: **v4.0.0 "Team Mode"** launched May 7

### Pi (earendil-works)

- Source: <https://github.com/earendil-works/pi>

## Backends

### llama.cpp

- Source: <https://github.com/ggml-org/llama.cpp>
- License: MIT

What's new since 2026-04-23: daily build cadence (b9151–b9173,
May 14–15). Notable: **PR #23041 added Codex CLI support** (May
14); "RDNA3 mma FA, faster AMD transpose" (PR #22880); extended
head-size 256 support for CDNA; MTMD chunked preprocessing for
Qwen3a multimodal (PR #23073). **Beta MTP (Multi-Token Prediction)
support** with `--speculative-config method:'mtp'
num_speculative_tokens:2`; argument changed from `--spec-type mtp`
to `--spec-type draft-mtp` on May 13. FlashAttention 4 and Qwen3.5
family work continued. Sparse MoE handling expanded for the
MiMo-V2.5 family.

Tool-calling / MCP notes: March 2026's PR #18655 (full MCP client
+ agentic loop in llama-server WebUI) remains the headline; this
window saw mostly stability and hardware-acceleration polish, no
major MCP feature adds.

## Model + harness combinations that work well

Only listing **new** combos or combos with new evidence in this
window. April combos still hold unless contradicted.

### Tiny (≤4B)

- **Gemma 4 E2B / E4B + Pi + Ollama** — phones/edge devices; native
  function-calling tokens, configurable thinking modes; good for
  fully local research-summary agents like the "brief" CLI demoed
  in May. Source: <https://parallel.ai/blog/free-CLI-agent>.

### Small (4B–14B)

- **Qwen2.5-7B + Pi + Ollama on 8 GB cards** — minimal Pi setup
  per InsiderLLM's May guide. Source:
  <https://insiderllm.com/guides/pi-agent-local-models-ollama/>.
- **WebWorld-8B (Qwen) + browser-agent harness** — open-web
  world-model series for training/evaluating web agents (8B for
  fast simulation, 14/32B for fidelity). Source:
  <https://huggingface.co/Qwen/WebWorld-8B>.

### Medium (14B–32B)

- **Qwen3.6-27B (dense) + OpenCode + SGLang or llama.cpp** — new
  flagship dense coder, released Apr 22. **77.2 on SWE-bench
  Verified, 53.5 SWE-bench Pro, 48.2 SkillsBench**, evaluated *via
  OpenCode*. Run with SGLang `--tool-call-parser qwen3_coder`.
  ~16.8 GB at Q4_K_M; fits 24 GB cards. Sources:
  <https://qwen.ai/blog?id=qwen3.6-27b>,
  <https://huggingface.co/Qwen/Qwen3.6-27B>.
- **Qwen3.6-27B + Pi + Ollama** (`ollama run qwen3.6:27b`,
  17 GB / 256K ctx) — recommended for 24 GB GPUs per InsiderLLM.
- **Gemma 4 26B-MoE (3.8B active) + Pi + LM Studio** — Philipp
  Schmid's demo: `pi` against `gemma4:26b` served from LM Studio
  on `localhost:1234`, fully YOLO local. Source:
  <https://x.com/_philschmid/status/2048719354905108623>.
- **Qwen3.6-35B-A3B + llama.cpp on 6 GB VRAM (~30 t/s)** with
  `--cpu-moe` offload. Community recipe:
  <https://mychen76.medium.com/run-qwen3-6-35b-a3b-on-6gb-vram-using-llama-cpp-30-tps-a89032e5a60c>.

### Large (32B–70B)

- No new 32–70B open-weights releases this window; the action
  moved to the MoE classes above and below.

### XL / MoE (>70B total)

- **Kimi K2.6 (1T total / 32B active) + Kimi Code CLI on vLLM or
  SGLang** — released Apr 20. **96.6%** tool-invocation success
  on Moonshot's benchmark; SWE-bench Pro **50.7 → 58.6** vs. K2.5;
  ties GPT-5.5 at 5–6× lower cost. Modified-MIT, native INT4
  quant. Day-0 vLLM recipe:
  <https://recipes.vllm.ai/moonshotai/Kimi-K2.6>; SGLang LoRA
  support added in v0.5.11. Agent Swarm scales to 300 sub-agents /
  4,000 steps. Source:
  <https://huggingface.co/moonshotai/Kimi-K2.6>.
- **DeepSeek V4-Flash (284B / 13B active) + Hermes Agent or
  OpenCode on vLLM or SGLang** — MIT, 1M-token context, day-0
  vLLM/SGLang recipes
  (<https://github.com/vllm-project/vllm-project.github.io/blob/main/_posts/2026-04-24-deepseek-v4.md>).
  Local on 2× H100-80GB FP8 or 1× H200-141GB. llama.cpp support
  still experimental (antirez fork:
  <https://github.com/antirez/llama.cpp-deepseek-v4-flash>).
- **DeepSeek V4-Pro (1.6T / 49B active) + cluster + SGLang or
  vLLM** — MIT, 1M-token context, **80.6% SWE-Bench Pro** per
  Codersera. Self-host needs 8–16× H200 or 8× B200.
- **MiMo-V2.5 (310B / 15B active) + vLLM or SGLang** — Xiaomi
  open-sourced Apr 27; "frontier-level agentic capability" claim.
  Day-0 vLLM v0.21 + SGLang v0.5.11. Source:
  <https://huggingface.co/XiaomiMiMo/MiMo-V2.5>.
- **MiMo-V2.5-Pro (1.02T / 42B active, hybrid attention, 1M
  ctx) + vLLM or SGLang** — for research labs with the GPU pool.
- **GLM-5.1 (744B MoE) + OpenCode / Cline + vLLM or SGLang** —
  released Apr 7 (just before window) but combos firmed up in
  May. MIT-licensed weights; ~595 GB at INT4, ~220–236 GB via
  Unsloth Dynamic 2-bit GGUF; needs ~8× H100. Sources:
  <https://lushbinary.com/blog/glm-5-1-claude-code-opencode-kilo-roo-cline-setup-guide/>,
  <https://unsloth.ai/docs/models/glm-5.1>.
- **Qwen3-Coder-Next (80B MoE / 3B active) + OpenCode or Aider +
  llama.cpp** — established combo; new evidence in May shows
  ~38–40 t/s generation on a single 48 GB GPU with MXFP4, ~7.7
  t/s on Ryzen AI 9 HX 96 GB CPU-only (ggml-org/llama.cpp issue
  #19480); ik_llama.cpp fork ~1.9× faster on MoE. Aider:
  `aider --model openai/qwen3-coder-next --openai-api-base http://localhost:8080/v1`.

  just client) by next window? Ollama issue tracker is the
  bellwether.
- Whether llama.cpp gains a full Qwen3-Next (80B-A3B) sparse-MoE
  fast-path; current performance lags expectations (issues
  #15940 / #19480).
- Real-world tool-call success rates for Kimi K2.6, DeepSeek
  V4-Flash, and MiMo-V2.5 when wired into OpenCode / Hermes — most
  numbers so far come from model authors.

  — needs hands-on verification.
- Roo Code's mid-May shutdown: how the Cline / Continue.dev /
  oh-my-openagent ecosystem absorbs Roo's user base, and whether
  any new local-first agent forks emerge from the wreckage.
- Status of vLLM RFC #26703 ("Any MCP Server Tools") and #30115
  (non-Harmony MCP) — both still open as of mid-May.
- Whether **OpenHarness CVE-2026-40502** has a clean patched
  version users should pin to.
