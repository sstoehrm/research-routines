# Agent Harness (Local) — 2026-08-29

## Summary

The five weeks since the last report were dominated by four things:
(1) **MCP 2026-07-28 moved from RC to Standard on July 28**, forcing
every local-agent tool to plan a migration away from the
`initialize` / `initialized` handshake, session IDs, and the
deprecated Roots / Sampling / Logging features; (2) DeepSeek
open-sourced its agent harness **dsh** on 2026-08-13, and **Ollama**
shipped a first-class launcher for it (`ollama launch dsh`) the
following day; (3) inference backends absorbed a wave of day-0
support for **Kimi K3** (2.8T MoE, open-weight 2026-07-26/27) and
**Ling-3.0-Flash** (BailingMoE3, merged into llama.cpp 2026-08-17),
plus NVIDIA's **Nemotron 3.5 Lightning** (30B MoE, 2026-08-11), which
is targeted specifically at local agentic workloads; and (4) **Hermes
Agent** shipped its biggest release yet — v0.20.0 "The Herald
Release" (2026-08-03) — adding A2A v1.0, real-time voice, and a full
desktop platform layer. On the harness side, **Crush**, **OpenCode**,
and **Hermes Agent** shipped in a steady weekly cadence; **OpenHarness
(HKUDS)** remained stalled at v0.1.9 from May.

## Model Context Protocol (MCP)

- **Spec 2026-07-28 is now Standard** (was RC 2026-05-21 in the
  last report). <https://blog.modelcontextprotocol.io/posts/2026-07-28/>
- Key rework: stateless request / response core;
  `initialize` / `initialized` handshake and `Mcp-Session-Id`
  header removed; new `server/discover` RPC; `Mcp-Method` and
  `Mcp-Name` HTTP headers for gateway routing; cacheable list
  results with `ttlMs` / `cacheScope`; **MRTR** (multi-round-trip
  requests) replaces server-initiated elicitation / sampling.
- Deprecations (12-month minimum window before removal): Roots,
  Sampling, Logging; HTTP+SSE transport reclassified Deprecated;
  DCR → Client ID Metadata Documents (CIMD). RFC 9207 issuer
  validation is now mandatory.
- Tasks extension moved out of experimental core into
  `io.modelcontextprotocol/tasks`.
- SDK status: TS, Python, Go, C# on 2026-07-28; Rust in beta.
  C# SDK v2.0 announced 2026 (Microsoft DevBlog).
- Local-agent impact: **Crush v0.91.2** explicitly turned on
  "GitHub MCP sessionless mode" — the first in-window harness
  release that visibly aligns with the new stateless model.

## Model + harness combinations that work well

### Tiny (≤4B params)

- **Gemma 4 E2B / E4B + Ollama** — still the tiny-agent default;
  150M+ Gemma 4 downloads by 2026-08; ships in Ollama's `gemma4`
  library. Use case: on-device chat, cheap agent side-cars.
  <https://ollama.com/search?q=gemma4>
- **Qwen3.5 / Qwen3.6 sub-4B + LM Studio (MLX on Apple Silicon)** —
  tool calling verified after Qwen chat-template fixes flowed
  through llama.cpp / Ollama / LM Studio / OpenWebUI / Jan.
  <https://qwen.readthedocs.io/en/latest/framework/function_call.html>

### Small (4B–14B)

- **Nemotron 3.5 Lightning 30B MoE (~3B active) + vLLM or Ollama**
  — released 2026-08-11 under OpenMDW-1.1 for local-agent workloads
  on RTX / DGX Spark / Jetson. vLLM and Ollama both supported at
  launch (Ollama v0.32.9).
  <https://blogs.nvidia.com/blog/nemotron-lightning-switchyard-rtx-dgx/>
- **Ling-3.0-Flash 124B MoE (5.1B active) + llama.cpp + any
  OpenAI-compatible harness** (OpenCode, Crush, Claude Code, Kilo,
  Hermes Agent) — with only 5.1B active, generation feels
  small-model even though weights are 124B. On a 24 GB GPU + 64–
  96 GB DDR5, Q4_K_M runs at usable rates via llama.cpp's
  offloaded-experts path. inclusionAI documents strong SWE-Bench
  Pro / Multilingual / Tau3-banking-AA / MCP-Atlas / SkillsBench
  results and lists compatible harnesses.
  <https://huggingface.co/inclusionAI/Ling-3.0-flash>

### Medium (14B–32B)

- **Qwen3.8-27B + Ollama (MLX on Apple Silicon)** — first-class
  MLX-optimized support landed in Ollama v0.32.12 on 2026-08-14.
  Tool-calling works after Qwen3-Coder chat-template fix; typical
  setup: `ollama pull qwen3.8:27b`, then any OpenAI-compatible
  harness. <https://ollama.com/oamazonasgabriel/qwen3.8-27b> ·
  <https://qwen.readthedocs.io/en/latest/framework/function_call.html>
- **Qwen3.6-27B (UD-Q4_K_XL) + Pi harness** — this pairing hit
  **16/16 perfect** on the harness-bench 16-task SWE eval
  (Python / PyTorch / JAX / C / C++ / Rust / SQL), running on a
  single M3 Max / 128 GB laptop. Currently the top small / medium
  local combo in the harness-bench sweep.
  <https://neuralnoise.com/2026/harness-bench-wip/>
- **Qwen3.6-27B MTP on RTX 6000** — reported 160 tok/s.
  <https://unsloth.ai/docs/models/qwen3.6>

### Large (32B–70B)

- **Qwen3.6-35B-A3B + llama.cpp / Ollama / LM Studio** — 240 tok/s
  reported on RTX 6000 per Unsloth's Qwen3.6 doc; 30+ tool-calls
  demonstrated (search sites, exec Python).
  <https://unsloth.ai/docs/models/qwen3.6>

### XL / MoE (>70B total)

- **GLM-5.2 (744B, 40B active) + SGLang NVFP4** — remains the
  "GLM you can self-host" standout from the last report. GLM-5.3
  was announced 2026-08-14 but weights are still under safety-hold
  ("two weeks" per Z.ai). Unsloth's 2-bit dynamic GGUF fits in
  ~239 GB, running on 4×RTX 3090 (192 GB sys RAM) or a Mac Studio
  with 256 GB+.
- **DeepSeek-V4-Pro (1.6T) / DeepSeek-V4-Flash (285B) + SGLang
  v0.5.18** — TP LMHead all-to-all dropped decode from 320 µs →
  169 µs on V4-Pro; SGLang reports **383.7 tok/s at accept-length
  ~5** on V4-Pro with DSpark speculative decoding. Tool parser
  `deepseek_v4` documented for both vLLM and SGLang.
  <https://docs.sglang.io/cookbook/autoregressive/DeepSeek/DeepSeek-V4> ·
  <https://recipes.vllm.ai/deepseek-ai/DeepSeek-V4-Flash>
- **Kimi K3 (2.8T MoE, 16/896 experts) + vLLM v0.27+ or SGLang
  v0.5.17+** — day-0 support in both engines when the weights
  dropped 2026-07-26/27. Practically it is not a "local" model in
  the workstation sense — MXFP4 weights alone are ~1.56 TB;
  Moonshot recommends 64+ accelerators. You point a local harness
  (OpenCode, Crush, Claude Code) at a self-hosted multi-node
  cluster or an API.
  <https://vllm-project.github.io/2026/07/27/k3.html> ·
  <https://www.kimi.com/code/docs/en/third-party-tools/opencode.html>
- **MiniMax M3 (229.9B, 9.8B active) + llama.cpp** — GGUFs
  available; MSA (Sparse Attention) not yet supported, so keep
  context modest.
- **Qwen3.8-Flash-Next (125B / 6B active, 262K native / 1M with
  YaRN)** — released 2026-08-26 as an experimental preview of the
  Qwen4 architecture. Ollama shipped support in v0.33.1
  (2026-08-26); Crush picked it up in v0.91.2 (2026-08-26). No
  independent large-model local-tool-use benchmarks yet.
