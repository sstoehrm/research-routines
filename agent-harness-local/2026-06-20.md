# Agent Harness (Local) — 2026-06-20

## Summary

The eight weeks since the last report were dominated by **MCP plumbing
in front-ends** rather than backend churn. Headlines: **Jan v0.8.0
(May 22)** wraps llama.cpp in a single router process and adds a real
`/v1/orchestrations` MCP endpoint with inline tool-approval — the
first reproducible "MCP via llama.cpp" desktop setup we've seen. **LM
Studio** finally shipped **streaming parallel tool-calls**, answering
one of the previous report's open questions. **Databricks open-sourced
Omnigent** (June 16) — a meta-harness that sits above Claude Code /
Codex / custom agents and is local-friendly via on-prem clusters.
**Hermes Agent** added a native desktop app (v0.15.2, June 2) and
crossed ~180K GitHub stars in under four months. On the backend,
**vLLM** went v0.18 → v0.20 (CUDA 13, FlashAttention 4, TurboQuant
2-bit KV) and **SGLang's** Qwen3-Coder-Next tool parser landed,
finally giving SGLang real agent-stack credibility. Model side:
**DeepSeek V4-Pro/Flash (Apr 24)**, **Qwen 3.6 27B / 35B-A3B
(mid-Apr)**, **GLM-5.1 (Apr 7)** then **GLM-5.2 (Jun 13)**, **MiniMax
M3 (early Jun)**, **Kimi K2.7-Code (Jun 12)** — the open-weight
frontier moved decisively into 1M-context, agentic-by-default
territory. **Roo Code shut down in May**; its users migrated mostly to
Cline (whose 2.0 SDK landed) and Goose.

## Harnesses

### OpenCode (Charm)

- Source: <https://github.com/sst/opencode> (maintenance under Charm)
- License: MIT
- Changelog summary: <https://releasebot.io/updates/sst/opencode>,
  <https://www.developersdigest.tech/blog/opencode-developer-guide-2026>

OpenCode kept compounding: ~172K GitHub stars and reportedly ~8M MAUs
by May 2026, the most-starred open-source coding agent. May–June
shipped workflow polish rather than architecture changes: safer edit
operations, more reliable Bedrock sessions, richer diff navigation,
**backgroundable subagents**, **persistent session context**, Snowflake
Cortex support, collapsed thinking-view in the TUI, pinned-session
quick-switching, improved tool-schema metadata and prompt history.
Local-LLM support still goes through Ollama / LM Studio / llama.cpp /
any OpenAI-compatible endpoint. Practical local recommendation has
shifted: pair OpenCode with **GLM-5.1/5.2** or **Qwen3-Coder-Next**
rather than small models — the harness now assumes longer agentic
loops that brittle small-model tool-calling can't sustain.

### Aider

- Source: <https://aider.chat/>, releases
  <https://github.com/Aider-AI/aider/releases>
- License: Apache 2.0

Still the reference single-turn coding agent. May–June updates: watch
mode, GPT-5 reasoning support, new model defaults. The Polyglot
leaderboard <https://llm-stats.com/benchmarks/aider-polyglot> is now
the more interesting evaluation surface — GPT-5 leads at 0.880; open
models cluster behind GLM-5 and Kimi K2.7. Aider's lightweight loop
remains the most forgiving harness when running smaller local models
that can't carry a multi-step plan reliably.

### Plandex

- Source: <https://github.com/plandex-ai/plandex>
- License: MIT

No major release this cycle — current line is **2.2.x**, not 3.0.
**MCP is still not natively supported**; the team is shipping
MCP-like behaviors (browser launching, console-log capture)
internally rather than wiring a real MCP client. Ollama is built-in
for custom models; any OpenAI-compatible local endpoint works via
`baseUrl`. Best paired with a model strong at structured planning
(Qwen3-Coder-Next, GLM-5.1). Source:
<https://docs.plandex.ai/models/custom-models/>.

### OpenHarness (HKUDS)

- Source: <https://github.com/HKUDS/OpenHarness>, releases
  <https://github.com/HKUDS/OpenHarness/releases>
- License: open source (see repo)

Tagged release line stalled at **v0.1.7 (April 18)** — `main` has
continued moving (commits as recently as June 4) but no new tagged
release in the window. v0.1.4 added Moonshot/Kimi provider auth with
reasoning-content support. Still primarily a research/teaching
artifact rather than a daily driver.

### Hermes Agent (Nous Research)

- Source: <https://github.com/NousResearch/hermes-agent>
- Changelog: <https://hermes-ai.net/changelog/>
- NVIDIA RTX AI Garage:
  <https://blogs.nvidia.com/blog/rtx-ai-garage-hermes-agent-dgx-spark/>

Biggest single-harness story of the cycle. **Hermes Desktop** launched
**June 2 (v0.15.2)** with native macOS/Windows/Linux builds, finally
giving non-terminal users a path in. Repo crossed **180K stars in
under four months**. The May "Velocity Release" refactored
`run_agent.py` into focused agent modules, turned Kanban into a
multi-agent platform, added a Nous-approved **MCP catalog**,
**OpenHands orchestration**, lighter installs (PyPI packaging),
Windows beta, and an OpenAI-compatible local proxy for OAuth-backed
providers. The "self-improving" claim is concrete: agents with 20+
self-created skills reportedly complete similar future tasks 40%
faster than fresh instances. The six-backend story (local / Docker /
SSH / Daytona / Modal / serverless) remains a differentiator.

### Goose (Block)

- Source: <https://github.com/block/goose>, releases
  <https://github.com/block/goose/releases>
- License: Apache 2.0

Steady weekly-release cadence — **v1.30.0 (April 8) → v1.38.0
(June 17)**. Local-first by design; works with any LLM via Ollama;
supports MCP servers as first-class extensions. ~27K GitHub stars.
Practical sweet spot is destructive-action workflows where Goose's
"on-machine" framing matches Hermes's sandboxing story but with less
ceremony. See <https://www.openaitoolshub.org/en/blog/goose-ai-agent-block-review>,
<https://www.vishnudileesh.com/bench/goose-agent-local-llm>.

### Continue.dev / Cline

- Continue: <https://github.com/continuedev/continue>,
  <https://changelog.continue.dev/>
- Cline 2.0 SDK announcement:
  <https://cline.bot/blog/introducing-cline-sdk-the-upgraded-agent-runtime>
- License: Apache 2.0 (both)

Continue and Cline both **opened up their runtimes as SDKs** in this
cycle (`continue-sdk`, `cline-sdk`), reframing each product as one
build on top of an underlying agent runtime rather than the only one.
Agent mode supports MCP via the simplified `.continue/mcpServers/`
folder structure, plus new MCP transports (SSE, Streamable HTTP) for
remote MCP hosting. Strong fit for IDE-bound users who want local
models via Ollama / LM Studio with permissioned tool use.
See <https://docs.continue.dev/customize/deep-dives/mcp>.

### Omnigent (Databricks) — NEW

- Source: <https://www.databricks.com/blog/introducing-omnigent-meta-harness-combine-control-and-share-your-agents>
- Coverage: <https://www.heise.de/en/news/Meta-Harness-for-AI-Agents-Databricks-Releases-Omnigent-as-Open-Source-11335496.html>,
  <https://www.developersdigest.tech/blog/omnigent-meta-harness-agent-orchestration>
- License: Apache 2.0
- Released: 2026-06-16

A "meta-harness" — explicitly designed to sit *above* Claude Code,
OpenAI Codex, and custom agents and make them interoperable in a
single control plane. Doesn't ship its own LLM; routes through
existing credentials including on-prem clusters, so a local
llama.cpp / vLLM / SGLang endpoint can back it. Installable via
pip / Homebrew / shell. The first serious mainstream OSS attempt at
agent-of-agents orchestration with local-friendly auth.

### llama-agent

- Source: <https://github.com/gary149/llama-agent> (fork:
  <https://github.com/TuringWorks/llama-agent>)
- License: see repo

No new release in the window. Still the right baseline when
evaluating whether a heavier harness is actually needed for small
local models. With llama.cpp's MCP client now upstream, the gap
between "llama-agent" and "llama-server + MCP" has narrowed enough
that llama-agent is becoming a teaching artifact more than a tool.

### Jan v0.8.0 — NEW notable

- Source: <https://github.com/janhq/jan>
- License: AGPL-3.0
- Released: 2026-05-22

Wraps llama.cpp in a single router process with `POST /models/load` /
`POST /models/unload` for multi-model agent setups, and exposes a
real `/v1/orchestrations` MCP endpoint with inline tool-approval —
**the cleanest reproducible "MCP via llama.cpp" desktop setup we've
seen this cycle**. Directly addresses the previous report's
follow-up about documenting an MCP-via-llama.cpp setup.

### Roo Code — DECEASED

Roo Code **shut down in May 2026** at roughly 3M installs. The team
pivoted to **Roomote** (Slack-based operational agent). Most users
moved to **Cline** or **Goose**; the local-LLM router project
`locallama-mcp` (<https://github.com/Heratiki/locallama-mcp>) is
still maintained but explicitly out-of-date for Roo's slot.
Recorded so the previous report's tooling map is up-to-date.

## Backends

### llama.cpp

- Source: <https://github.com/ggml-org/llama.cpp>
- Function-calling docs:
  <https://github.com/ggml-org/llama.cpp/blob/master/docs/function-calling.md>
- WebUI guide:
  <https://github.com/ggml-org/llama.cpp/discussions/16938>
- LlamaHub discussion:
  <https://github.com/ggml-org/llama.cpp/discussions/17952>

The March 2026 MCP merge is now bedded down. **Parallel tool calling
is supported on suitable models but disabled by default** — opt in by
passing `"parallel_tool_calls": true` in the chat-completion payload.
New WebUI built on SvelteKit 5 ships with MCP integration baked in.
Community effort **LlamaHub** is layering a richer local-first GUI +
MCP + RAG on top. Performance gap to vLLM is real and well-documented:
GitHub issue #19345 measures Qwen3-Coder-Next FP8 at **~70–80 tok/s on
llama.cpp vs ~120 tok/s on vLLM** with 100% CPU pegged — and issue
#19480 reports ~5× slower-than-expected CPU inference on consumer
hardware for the same model. The router/load-on-demand workflow that
**Jan v0.8.x** exposes is the cleanest single-host path for
multi-model agent setups.

### vLLM

- Source: <https://github.com/vllm-project/vllm>
- Tool-calling docs:
  <https://docs.vllm.ai/en/latest/features/tool_calling/>

Active release cycle: **v0.18.0, v0.19.0, v0.19.1rc0** inside a 14-day
window in April, then **v0.20.0 (Apr 30, ROCm 7.2.1)**, plus the
**v0.19.17** patch (Transformers v5.5.4) fixing Gemma4 streaming and
tool calls. v0.20 defaulted to **CUDA 13.0 / PyTorch 2.11**, brought
back **FlashAttention 4** as default prefill backend, added
**TurboQuant 2-bit KV cache**. A scheduler change makes scheduling
and execution overlap rather than serialize — measurable TTFT win,
which matters because agents emit many short tool calls in a loop.
Native function-calling supports `auto`, `required`, `none`
tool_choice. **No first-class MCP client** in core vLLM — Issue
#30115 ("MCP Support for Non Harmony Models") is open; community
projects like `vllm-playground` (v0.1.1, agentic-ready with MCP and
human-in-the-loop) cover the gap. **vllm>=0.15.0 required for
Qwen3-Coder-Next** with the new tool parser.

### SGLang

- Source: <https://github.com/sgl-project/sglang>
- Tool-calling docs:
  <https://sgl-project-sglang-93.mintlify.app/advanced/tool-calling>

This is the cycle SGLang got serious about agents. The
Qwen3-Coder-Next **`--tool-call-parser qwen3_coder`** flag is now
part of the recipe (also `kimi_k2` for K2). Day-0 support for new
open models continued (gpt-oss-20b/120b, Llama-3.1-8B-Instruct,
DeepSeek-R1 added to NVIDIA's June 2026 release). v0.5.12 / v0.5.13
extended DeepSeek-V4 to context-parallel serving with sparse-attention
kernels. **Known wart**: Qwen3.5 9B / 35B-A3B reportedly emits
**XML-style tool calls** instead of JSON under SGLang's parser —
agent harnesses built for JSON will silently fail. Still **no native
MCP client** — SGLang remains an inference engine; MCP is the
harness's job. Heterogeneous CPU+GPU EPD disaggregation (Intel)
showed ~1.3× P99 TTFT and request-throughput improvements under load.

### Ollama

- Source: <https://github.com/ollama/ollama>, updates
  <https://releasebot.io/updates/ollama>
- Streaming-with-tools: <https://ollama.com/blog/streaming-tool>

Steady incremental releases through the window, latest
**v0.30.9-rc1 (June 17 2026)** adding Cohere2Moe support and fixing
the "single-token output" bug that broke `ollama launch claude` and
similar coding-agent flows. Now correctly errors when a single
message exceeds the context window instead of failing silently.
**Still no built-in MCP client** as of mid-June 2026; users bridge
via `mcp-client-for-ollama`
(<https://github.com/jonigl/mcp-client-for-ollama>) or `MCPHost`.
Tool-call streaming works for the supported model families.
Continues to dominate single-user desktop ergonomics; vLLM/SGLang
still beat it under concurrent load.

### LM Studio

- Changelog: <https://lmstudio.ai/changelog>
- API changelog:
  <https://github.com/lmstudio-ai/docs/blob/main/1_developer/api-changelog.md>

**This answers the April open question**: LM Studio shipped
**streaming parallel tool calls** in the API. Argument tokens are now
streamed as generated; the bug where parallel tool calls split across
chunks were dropped is fixed; root-level `$defs` in tool schemas are
no longer stripped; Mistral tool-call parsing fixed. `stream_options`
on OpenAI-compatible endpoints supported. MLX engine v1.8.1 added
**parallel predictions for vision-capable models** (Qwen 3.5/3.6,
Gemma 4). LM Studio is now a credible agent backend, not just a GUI
experimentation tool — with the caveat that the closed-source
UI/runtime split still makes it a worse fit than llama.cpp for
sovereign-stack setups. See
<https://x.com/lmstudio/status/2019872805521674563>.

### MLX (Apple Silicon) — promoted to a backend in its own right

- Apple Foundation Models integration (June 8 beta): MLX is now
  Apple's first-class on-device runtime, with tool-calling +
  structured output + streaming unified across model backends.
- vllm-mlx: <https://github.com/waybarrios/vllm-mlx> —
  OpenAI/Anthropic-compatible server with continuous batching,
  **MCP tool calling**, multimodal; reports ~400 tok/s on Apple
  Silicon; works with Claude Code.
- Rapid-MLX: <https://github.com/raullenchai/Rapid-MLX> — claims
  4.2× faster than Ollama, 100% tool-calling, 17 tool parsers,
  drop-in OpenAI replacement; works with Claude Code, Cursor, Aider.
- vMLX: <https://vmlx.net/> — MCP tool-binding configuration, prefix
  caching, continuous batching.

Mac users now have at least three credible MLX inference servers
with real MCP/tool-call support and OpenAI-compatible APIs — a
genuine new category since April.

### LocalAI

- Source: <https://localai.io/>

No major news in the window. Still the lowest-friction way to swap a
cloud OpenAI agent to local with a single base-URL change.

### TensorRT-LLM

For NVIDIA data-center hardware; still operationally heavier than
vLLM/SGLang. NVIDIA's NIM continues to be the productized envelope
with documented MCP integration:
<https://docs.nvidia.com/nim/large-language-models/latest/advanced-use-cases/tool-calling-and-mcp.html>.
Not a workstation play.

## Model + Harness Combinations That Work Well

### Tiny (≤4B)

- **Llama-3.2-3B / Qwen2.5-3B + llama-agent on llama.cpp.** Single-shot
  tool use; multi-step plans still derail. Source:
  <https://github.com/gary149/llama-agent>,
  <https://unsloth.ai/docs/basics/tool-calling-guide-for-local-llms>.
- **Phi-4-mini + Aider on Ollama.** Fine for small diffs; brittle on
  multi-file reasoning.
- **Gemma 4 (small) + LM Studio (MLX engine v1.8.1).** New this cycle
  — parallel predictions for vision-capable models make this viable
  as a desktop helper agent on Apple Silicon. Source:
  <https://lmstudio.ai/changelog>.

### Small (4B–14B)

- **Qwen2.5-Coder-7B/14B + Aider on Ollama or vLLM.** Still the laptop
  default for single-turn edits.
- **Llama-3.1-8B-Instruct + OpenCode on llama.cpp.** Adequate for
  light agentic loops with strict tool-call schema.
- **Llama-3.1-8B-Instruct + SGLang.** New in the SGLang day-0 lineup
  as of the June 2026 NVIDIA release; sensible for multi-user agent
  serving when 8B is enough. Source:
  <https://docs.nvidia.com/deeplearning/frameworks/pdf/SGLang-Release-Notes.pdf>.

### Medium (14B–32B)

- **Qwen3-Coder-Next 32B variants + OpenCode + vLLM.** As of June 2026,
  reportedly **the highest-scoring locally-runnable coding model**.
  Source: <https://kilo.ai/open-source-models>.
- **Qwen 3.6-27B (dense) + OpenCode or Aider on vLLM.** Released
  **April 22 2026**; reportedly beats Qwen3.5-397B-A17B on coding
  benchmarks at 27B dense; Apache 2.0; 256K context. Source:
  <https://insiderllm.com/guides/qwen-3-6-local-ai-guide/>.
- **Qwen 3.6-35B-A3B (MoE) + OpenCode on llama.cpp / MLX.** Mid-April
  release; ~101.7 tok/s short-prompt decode and ~80.9 tok/s at 65K
  context on RTX 3090. Source:
  <https://antekapetanovic.com/blog/qwen3.5-apple-silicon-benchmark/>,
  <https://huggingface.co/Qwen/Qwen3.6-35B-A3B>.
- **DeepSeek-Coder-V2-Lite (16B MoE) + Plandex on vLLM.** Still
  recommended for plan-heavy tasks.

### Large (32B–70B)

- **Llama-4 Scout / Maverick class + OpenCode + vLLM.** Stable
  general-purpose agent driver. Source:
  <https://www.spheron.network/blog/deepseek-vs-llama-4-vs-qwen3/>.
- **GLM-5.1 + OpenCode / Cline / Goose on vLLM or SGLang.** Released
  **April 7 2026**; explicitly optimized for long-horizon agentic
  coding (claims of 8-hour autonomous task runs). Weights on
  HuggingFace `zai-org/GLM-5.1`. Currently top of Artificial Analysis
  Intelligence Index for open weights. Source:
  <https://docs.z.ai/guides/llm/glm-5.1>,
  <https://lushbinary.com/blog/glm-5-1-developer-guide-long-horizon-agentic-coding/>.
- **Nemotron 3 Super (120B hybrid Mamba-Transformer, ~12B active) +
  Goose or OpenCode on vLLM/SGLang.** New June 9 release; 1M context.
  NVIDIA Nemotron Open Model License. Source:
  <https://research.nvidia.com/labs/nemotron/files/NVIDIA-Nemotron-3-Ultra-Technical-Report.pdf>.

### XL / MoE (>70B total)

- **Qwen3-Coder-Next (80B total, 3B active) + OpenCode / Plandex /
  SGLang.** Still the cycle's reference combo for "real coding agent
  on a single workstation". **Concrete numbers now public**:
  **~120 tok/s on vLLM (FP8); ~70–80 tok/s on llama.cpp** for the
  same FP8 model (issue #19345), confirming vLLM as the right engine
  if you have the GPU for it. SGLang gained `--tool-call-parser
  qwen3_coder` this cycle. Apache 2.0; 256K context. Sources:
  <https://github.com/ggml-org/llama.cpp/issues/19345>,
  <https://docs.vllm.ai/projects/recipes/en/latest/Qwen/Qwen3-Next.html>,
  <https://huggingface.co/Qwen/Qwen3-Coder-Next>.
- **Kimi K2.7-Code (1T total, 32B active) + Kimi Code CLI or Hermes
  Agent.** Released **June 12 2026**; 256K context, multimodal,
  always-thinking; **~30% fewer reasoning tokens vs K2.6**, which
  materially helps agent loop cost. Setup guide:
  <https://lushbinary.com/blog/kimi-k2-7-code-hermes-agent-autonomous-coding-setup-guide/>.
  Local viability: Mac Studio 512 GB unified runs Q2/Q3 (slow);
  256 GB Mac runs heavily quantized with degraded quality. Top of
  AA Coding Index for open models (78.57 coding / 58.33 agentic).
  Sources:
  <https://devops.com/moonshot-ais-kimi-k2-7-code-targets-token-efficiency-in-agentic-coding/>,
  <https://www.kimi.com/blog/kimi-k2-6>.
- **DeepSeek V4-Pro (1.6T) / V4-Flash (284B) + vLLM + OpenCode.**
  Released **April 24 2026** as preview; MIT; 1M-token context via
  API. Pro tier needs serious multi-GPU; Flash is the
  workstation-feasible variant if you have multi-GPU. Source:
  <https://simonwillison.net/2026/apr/24/deepseek-v4/>,
  <https://api-docs.deepseek.com/news/news260424>.
- **Qwen 3.5 397B-A17B + vLLM.** Apache 2.0; 256K native context;
  201-language support; vision-capable. Multi-GPU server territory
  only. Source:
  <https://particula.tech/blog/deepseek-v4-qwen-open-source-ai-disruption>.
- **GLM-5.2 + vLLM or SGLang.** Released **June 13 2026**;
  MIT-licensed open weights; 1M context; two reasoning-effort modes
  (high/max). Currently described as the top open-weights frontend
  coding model. Source:
  <https://codersera.com/blog/glm-5-2-release-1m-context-coding-2026/>,
  <https://www.latent.space/p/ainews-glm-52-the-top-frontend-coding>.
- **MiniMax M3 + OpenCode or Hermes on vLLM.** Released early June
  2026; 1M context, native multimodality, MiniMax Sparse Attention.
  Source:
  <https://www.minimax.io/blog/minimax-m3>,
  <https://venturebeat.com/technology/minimax-m3-debuts-eclipsing-gpt-5-5-and-gemini-3-1-pro-on-key-benchmark-performance-for-just-5-10-of-the-cost>.

## Open questions / follow-ups

- **MCP v2.1 sandboxing** is now a mandatory spec requirement
  (response to command-injection findings in ~43% of v2.0
  implementations). Track which local backends (llama.cpp, Jan,
  vllm-mlx) actually implement the sandbox vs. just the wire
  protocol — this is the security cliff the local ecosystem is about
  to fall off if no one looks. Source:
  <https://pipelab.org/blog/nsa-mcp-security-guidance/>.
- The reproducible **MCP via llama.cpp** setup is now de-facto
  **Jan v0.8.x** (`llama-server --models-preset router.preset.ini
  --no-webui` + `/v1/orchestrations`). Document end-to-end next
  cycle and diff against a raw llama.cpp + WebUI baseline.
- **SGLang's XML-tool-call quirk** under Qwen3.5 — confirm whether
  it also affects Qwen 3.6 / 3.7 (3.7 Max landed mid-June, see
  <https://codingfleet.com/blog/qwen-3-7-max-vs-kimi-k2-6/>) and
  document workarounds for JSON-expecting harnesses.
- **vLLM still has no first-class MCP client** (issue #30115 open).
  Track whether the v0.21/v0.22 line adopts MCP natively or the
  community settles on `vllm-playground`-style wrappers as the
  canonical path.
- **Kimi K2.7-Code agentic tool-call success rate** on Hermes Agent
  vs OpenCode vs Kimi Code CLI — published claim of 30% fewer
  reasoning tokens needs an independent agentic-task replication.
- **Apple Foundation Models + MLX** (June 8 beta) opens a real
  on-device agent path on macOS/iOS. Watch which harnesses ship an
  Apple FM backend in Q3.
- **Omnigent meta-harness** — measure end-to-end overhead vs.
  running the same agent directly. If Omnigent can route between a
  local llama.cpp endpoint and a hosted Claude Code instance
  per-task, the "local + remote, same loop" story finally becomes
  real.
- **Roo Code's user migration** — confirm whether Cline 2.0 SDK or
  Goose absorbed the bulk of the ~3M installs, and what that does
  to the relative weights of the harness ecosystem.
