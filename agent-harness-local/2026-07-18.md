# Agent Harness (Local) — 2026-07-18

## Summary

The three-month window since 2026-04-23 is dominated by consolidation
rather than new invention. Biggest shifts:

- **llama.cpp shipped an MCP client** inside the bundled SvelteKit web
  UI, meaning any GGUF model served by `llama-server` can now drive MCP
  tool servers (file, web, DB) without an external bridge. The MCP
  piece lives in the web UI plus an optional CORS proxy
  (`--webui-mcp-proxy`), not in the C++ server itself.
- **vLLM v0.20.x** (late April – June) unified tool-call and reasoning
  parsing behind a single `Parser.parse()` interface, added parsers for
  Kimi K2.6 / K2 Thinking, DeepSeek V4, MiniMax M2, GLM-5.x and
  Nemotron V3, and made the async scheduler on by default.
- **SGLang v0.5.13** (Jun 13) made Spec V2 speculative decoding the
  default and added day-0 DeepSeek V4 serving.
- **Ollama v0.30** (May 13) introduced the **MLX engine for Apple
  Silicon** and an `ollama launch` shortcut that plumbs a GGUF's
  tool-calling capability through to a chosen coding agent; v0.31
  tightened Gemma 4 and Qwen tool-call parsing.
- **LM Studio** shipped OAuth for MCP servers (0.4.10 / 0.4.11, April),
  Qwen 3.6 support (0.4.12), and stable MTP speculative decoding
  (0.4.14, May 29).
- **Harness churn:** Continue.dev was acquired by Cursor on June 19,
  2026; the repo is now read-only after v2.0.0. Roo Code was archived
  in May 2026. Plandex is de-facto in maintenance mode. OpenCode,
  OpenHands, Aider, Goose, OpenHarness (HKUDS) and Nous's Hermes Agent
  remain actively developed.
- **New models in-window:** Kimi K2.6 (Apr 20, Modified MIT), Qwen3.6
  35B-A3B (Apr 16) / Qwen3.6-27B dense (Apr 22), Llama 4 Scout &
  Maverick (Apr 5), DeepSeek V4 (Apr 24), and GLM-5.2 (Jun 16, MIT).
  Qwen3-Coder-Next (80B-A3B MoE, Feb 2026) remains the reference for
  "runs an agent loop on modest hardware."
- **Tool-call reliability rankings** (single-call well-formed rate,
  from a third-party writeup — treat as directional, not
  authoritative): Llama 3.3 70B ~97%, Qwen3-Coder 30B ~96%, Gemma 4 27B
  ~95%, GLM-5.1 32B ~94%, Qwen3 32B ~93%.

## Harnesses

### OpenCode

- Source: <https://github.com/sst/opencode> (site
  <https://opencode.ai>).
- License: MIT.
- Status: actively developed; the most-starred coding agent on GitHub
  as of mid-2026 (~150K+ stars per third-party writeups — not
  verified against the repo directly).
- Good at: OpenAI-compatible endpoint → local LLM in one config;
  `/init` AGENTS.md flow; LSP integration; 75+ provider adapters via
  the AI SDK / models.dev.
- Known issues: quality strongly gated by the local model. On Qwen 3.6
  35B-A3B a naked (non-tool-format) tool call in the console has been
  reported to stall progress (issue #24316 on the `anomalyco/opencode`
  fork).
- Source: [Explainx guide 2026](https://www.explainx.ai/blog/how-to-run-open-source-models-locally-opencode-2026),
  [opencode.ai](https://opencode.ai/).

### Aider

- Source: <https://github.com/Aider-AI/aider>.
- License: Apache-2.0.
- Status: v0.86.2 (Feb 12, 2026) is the most recent visible stable per
  third-party writeups; release cadence has slowed vs. 2025. Still one
  of the most cited local-friendly coding harnesses.
- Good at: diff-block "tool" format that works with weakly
  JSON-native models; git-first workflow.
- Known issues: newer models expect JSON/XML tool calls; on some local
  model + tool combos, diff-block conflicts with harness-side MCP
  wrappers.
- Source: [Aider LLM docs](https://aider.chat/docs/llms.html).

### OpenHands (formerly OpenDevin)

- Source: <https://github.com/All-Hands-AI/OpenHands>.
- License: MIT.
- Status: v1.6.0 (Mar 30, 2026) added Kubernetes support and Planning
  Mode beta; May 2026 blog now recommends **Qwen3.6 35B-A3B** as the
  first local model to try. LM Studio / Ollama / vLLM / SGLang all
  listed as supported backends.
- Good at: sandboxed Docker runtime, GitHub issue → PR loop, matches
  Devin on SWE-bench with a swappable model.
- Known issues: dockerised runtime is heavy; small (<14B) local models
  still trip on multi-turn tool loops.
- Source: [OpenHands product update May 2026](https://www.openhands.dev/blog/openhands-product-update---may-2026),
  [Local LLMs doc](https://docs.openhands.dev/openhands/usage/llms/local-llms).

### Goose (Agentic AI Foundation, ex-Block)

- Source: <https://github.com/block/goose>.
- License: Apache-2.0.
- Status: active; Rust CLI + desktop app; MCP-native since inception.
- Good at: MCP is the extension model, so drop-in for any MCP server;
  Ollama provider tested by maintainers.
- Known issues: as everywhere, tool-call reliability is bottlenecked
  by 7–14B local models.
- Source: [Goose + Ollama guide](https://localaimaster.com/blog/goose-ollama-local-agent),
  [Ollama Goose docs](https://docs.ollama.com/integrations/goose).

### OpenHarness (HKUDS)

- Source: <https://github.com/HKUDS/OpenHarness>.
- License: MIT.
- Status: v0.1.9 (May 7, 2026); ~14.9K stars per direct WebFetch of
  the repo.
- Good at: transparent, CLI-first agent runtime with 43+ built-in
  tools, streaming tool-call cycles, `MEMORY.md` persistence, three
  permission modes (default / auto / plan), MCP over HTTP with
  auto-reconnect. Configurable directly at Ollama's
  `http://localhost:11434/v1`.
- Known issues: **name collision** — not "OpenHarness by MaxGfeller"
  (unrelated interop SDK); also distinct from `zhijiewong/openharness`
  CLI. Mind which repo you clone.
- Source: [HKUDS/OpenHarness](https://github.com/HKUDS/OpenHarness),
  [MarkTechPost design writeup Jun 24 2026](https://www.marktechpost.com/2026/06/24/how-to-design-an-openharness-style-agent-runtime-with-tools-memory-permissions-skills-and-multi-agent-coordination/).

### Hermes Agent (Nous Research)

- Source: <https://github.com/NousResearch/hermes-agent>.
- License: MIT.
- Status: v0.18.2 (Jul 8, 2026); v0.9.0 "the everywhere release"
  shipped Apr 13, 2026. Star claims in the 200K range from third-party
  fetches look inflated versus typical Nous repos — treat as unverified;
  release cadence is real.
- Good at: skills auto-generated from successful trajectories; FTS5
  session search with LLM summarization; Honcho dialectic user
  modeling; MCP integration to bolt in external tools.
- Known issues: search results don't confirm first-class Ollama /
  llama.cpp support in current release notes; "any endpoint" is
  documented but a canonical local-model recipe wasn't in the docs
  reached.
- Source: [hermes-agent repo](https://github.com/NousResearch/hermes-agent),
  [Hermes Atlas guide Jul 2026](https://hermesatlas.com/guide/).

### llama-agent (single-binary llama.cpp harness)

- Source: <https://github.com/gary149/llama-agent> (fork:
  <https://github.com/TuringWorks/llama-agent>).
- License: MIT.
- Status: 270 stars; last release `b9718` on Jun 2, 2026; active.
- Good at: inference + agent loop in one binary, zero external deps,
  JSONL session persistence, HTTP API + SSE, MCP via `mcp.json`.
  Recommended models include GLM-4.7-Flash and Gemma 4 E4B / 26B-A4B /
  31B.
- Known issues: tiny community; not audited; use with care in
  production.
- Source: [llama-agent repo](https://github.com/gary149/llama-agent).

### Continue.dev (now read-only)

- Source: <https://github.com/continuedev/continue> (read-only).
- License: Apache-2.0.
- Status: v2.0.0 (Jun 19, 2026) — final polished release; **Continue
  acquired by Cursor** in June 2026; VS Code / JetBrains extensions
  still install and run.
- Good at: BYO-LLM path (Ollama, LM Studio, llama.cpp, any

- Known issues: no future roadmap; the local path exists but won't

- Source: [Continue Ollama setup](https://localaimaster.com/blog/continue-dev-ollama-setup),
  [MCP with local LLMs on HF](https://huggingface.co/learn/mcp-course/en/unit2/continue-client).

### Cline

- Source: <https://github.com/cline/cline>.
- License: Apache-2.0.
- Status: Cline CLI 2.0 shipped earlier in 2026 with parallel /
  headless support; remains actively maintained. **Roo Code** (Cline
  fork) was archived in May 2026.
- Good at: default VS Code local-LLM path, per-task model routing
  (Ollama default, cloud escalation on threshold).
- Known issues: `apply_diff` reliability on 7–14B local models varies;
  users often prefer Aider's diff blocks for very small models.
- Source: [Cline local models docs](https://docs.cline.bot/running-models-locally/overview),
  [Frontman comparison](https://frontman.sh/blog/best-open-source-ai-coding-tools-2026/).

### Plandex

- Source: <https://github.com/plandex-ai/plandex>.
- License: MIT.
- Status: effectively in maintenance mode; a third-party review notes

  `git log`).
- Good at: large-context refactors via 2M-token cumulative-diff

- Known issues: only `ollama` for local providers; not the harness to

- Source: [Plandex custom models docs](https://docs.plandex.ai/models/custom-models/),

## Backends

### llama.cpp

- Source: <https://github.com/ggml-org/llama.cpp>.
- License: MIT.
- Status: extremely active; observable release tags in July include
  `b9829` (Jun 28) and July build stream `b10052`–`b10066` (Jul 16-17),
  plus MTP speculative decoding, Kimi Linear-style prompt-processing
  speedup, and MUL_MAT / Hexagon backend work.
- Tool-calling / MCP: **MCP client is in the bundled web UI**
  (SvelteKit interface, not the C++ server). **PR #18059** landed a
  client-side tool-calling implementation with two built-in tools.
  Optional `--webui-mcp-proxy` CORS proxy on the backend side. Native
  tool-call parsers include the Qwen3 XML format (fixed in-window for
  malformed argument cases).
- Known issues: reports of SIGSEGV in `llama-server` on
  Qwen3-Coder-Next during consecutive tool calls; premature EOS in
  some tool loops.
- Sources: [llama.cpp releases](https://github.com/ggml-org/llama.cpp/releases),
  [PR #18059](https://github.com/ggml-org/llama.cpp/pull/18059),
  [jasonmoon.dev Apr 15 2026 writeup](https://jasonmoon.dev/blog/2026-04-15-mcp-v21-llama-cpp-local-agents),
  [Local AI Master llama.cpp MCP](https://localaimaster.com/blog/llama-cpp-mcp-server).

### vLLM

- Source: <https://github.com/vllm-project/vllm>.
- License: Apache-2.0.
- Status: v0.19.0 (Apr 3), v0.20.0 (Apr 27; CUDA 13.0 / PyTorch 2.11
  default, TurboQuant 2-bit KV cache, FlashAttention 4 re-enabled as
  prefill default), v0.20.1–v0.20.2 (DeepSeek V4 / Qwen3-VL / gpt-oss
  patches).
- Tool-calling / MCP: **new streaming Parser engine** unifies tool-call
  + reasoning parsing behind `Parser.parse()`. Parsers ship for Qwen3,
  MiniMax M2, GLM-4.7 / 5.1 / 5.2, Nemotron V3, Kimi K2.5 / K2.6 /
  K2.7, DeepSeek V4. Q3 2026 roadmap explicitly promises
  "production-ready refactored tool-calling" and better
  structured-output robustness. No first-class MCP client — MCP is a
  harness-side concern.
- Known issues: PR #35347 was needed to fix malformed JSON in Qwen3.5
  tool calls (dedicated `Qwen35CoderToolParser`).
- Sources: [vLLM releases](https://github.com/vllm-project/vllm/releases),
  [fazm.ai vLLM April 2026 writeup](https://fazm.ai/t/vllm-release-april-2026-release-notes),
  [PR #35347](https://github.com/vllm-project/vllm/pull/35347),
  [Q3 roadmap #48168](https://github.com/vllm-project/vllm/issues/48168).

### SGLang

- Source: <https://github.com/sgl-project/sglang>.
- License: Apache-2.0.
- Status: v0.5.13 shipped Jun 13, 2026; Spec V2 tree drafting is now
  the default (Spec V1 deprecated); DeepSeek V4 context-parallel
  serving, sparse FlashMLA, FP4 indexer; new model support Nemotron 3
  Ultra, Step-3.7-Flash, Command A+, Kimi K2.5. LMSYS blog Jul 2, 2026
  documented KDA-Pilot–derived optimizations upstreamed via
  agent-assisted development.
- Tool-calling: `--tool-call-parser` supports Qwen / Llama / DeepSeek
  / others; OpenAI function-calling wire-compatible.
- Known issues: parsers for very new models sometimes lag mainline
  vLLM by a release.
- Sources: [SGLang releases](https://github.com/sgl-project/sglang/releases),
  [LMSYS agent-assisted dev blog Jul 2 2026](https://www.lmsys.org/blog/2026-07-02-agent-assisted-sglang-development/),
  [SGLang tool-call docs](https://docs.sglang.io/advanced_features/tool_parser.html).

### Ollama

- Source: <https://github.com/ollama/ollama>.
- License: MIT.
- Status: v0.30.0 (May 13) added **MLX engine on Apple Silicon** (GGUF
  from Hugging Face + Vulkan / NVIDIA path via llama.cpp); v0.31
  improved Gemma 4 and Qwen tool-call parsing (ignore braces inside
  JSON strings when detecting tool-call end); July release includes
  MLX cache-leak fix and interactive-agent CWD passthrough.
- Tool-calling / MCP: Ollama itself is a model server; a separate MCP
  client (`jonigl/mcp-client-for-ollama`, ChatForest guide) or a
  harness (Cline, OpenCode, OpenHarness) does the MCP legwork.
  `ollama launch` shortcut wires a GGUF's tool-calling into a chosen
  agent.
- Known issues: earlier Qwen 3.5 calls were misrouted through a
  Hermes-style JSON parser; fixed in v0.17.3 (thinking-mode subset)
  and v0.17.6 (remaining cases). Silent CPU fallback if `num_ctx`
  overshoots VRAM.
- Sources: [Ollama version history](https://localaimaster.com/blog/ollama-version-history),
  [Ollama v0.30 on Apple Silicon writeup](https://runaihome.com/blog/ollama-v030-mlx-stable-upgrade-2026/),
  [mcp-client-for-ollama](https://github.com/jonigl/mcp-client-for-ollama).

### LM Studio

- Site: <https://lmstudio.ai/> (proprietary UI; SDK MIT).
- Status: 0.4.10 (Apr 9) OAuth for MCP servers; 0.4.11 (Apr 10)
  improved Gemma 4 tool-call reliability; 0.4.12 (Apr 17) Qwen 3.6
  support + Windows OAuth-MCP fix; **0.4.14 (May 29)** stable MTP

- Tool-calling / MCP: acts as an MCP **client**; documented via

- Known issues: closed-source UI; not scriptable at scale — use its

- Sources: [LM Studio changelog](https://lmstudio.ai/changelog),
  [LM Studio MCP docs](https://lmstudio.ai/docs/developer/core/mcp).

### MLX / mlx_lm.server (Apple Silicon)

- Sources: <https://github.com/ml-explore/mlx-lm> (MLX, MIT);
  <https://github.com/ddalcu/mlx-serve> (community server with
  tool-call, MIT).
- Status: MLX matured in 2026 with a Swift-native backend,
  OpenAI-compatible server, distributed inference; Apple's Jan 2026
  research showed **M5 Neural Accelerators at 4.06× TTFT vs. M4** on
  Qwen3-14B-4bit. WWDC 2026 session 232 covered local agentic AI on

- Tool-calling / MCP: `mlx_lm.server` speaks OpenAI chat completions
  with structured tool calls; `mlx-serve` adds an Anthropic-compatible
  surface plus native chat / agent app.
- Known issues: model coverage lags llama.cpp; new architectures often
  need Swift-side plumbing.
- Sources: [WWDC26 session 232](https://developer.apple.com/videos/play/wwdc2026/232/),
  [mlx-serve](https://github.com/ddalcu/mlx-serve),
  [Apple M5 research](https://machinelearning.apple.com/research/exploring-llms-mlx-m5).

### TensorRT-LLM

## Model + Harness Combinations That Work Well

Entries cite the source that made the claim; "hardware tested" is what
the linked source reported, not a fresh verification.

### Tiny (≤ 4B)

- **Qwen3-4B (Apache-2.0)** — Q4, Ollama / llama.cpp, harness: Cline
  / OpenCode. Hardware: 4 GB VRAM GPU. Good for local dev with tool
  calling + 128K context; 97.5% pass rate at 3.4 GB in one third-party
  eval. Source:
  <https://unsloth.ai/docs/models/qwen3.5>,
  <https://www.jdhodges.com/blog/local-llms-on-tool-calling-2026-pt1-local-lm/>.
- **Gemma 4 E4B** (~5 GB quant) — llama.cpp, harness: llama-agent /
  Ollama chat. Hardware: 8 GB laptop. Good for multimodal (images /
  screenshots / diagrams) with tool calling. Source:
  <https://github.com/gary149/llama-agent>.

### Small (4B – 14B)

- **Qwen3 8B** — Q4_K_M (~8 GB), Ollama, harness: Aider / Cline /
  OpenCode. Hardware: mid-range 12–16 GB GPU. Called out as "best
  Ollama model for agents" in a third-party mid-2026 shortlist; native
  tool calling. Source:
  <https://localaimaster.com/blog/best-ollama-models-for-agents>.
- **Qwen3 14B** — Q4_K_M, Ollama, harness: Hermes Agent. Hardware:
  12–16 GB GPU. Recommended "best pick for a single 12–16 GB card"
  for fully-local Hermes. Source:
  <https://localaimaster.com/blog/hermes-agent-ollama>.
- **DeepSeek V4-Flash (13B active / 284B total)** — FP4 (vLLM), vLLM
  / SGLang day-0, harness: OpenCode / OpenHands. Hardware: multi-GPU.
  Preserves reasoning content across user turns for long agent
  sessions. Source:
  <https://api-docs.deepseek.com/news/news260424/>.

### Medium (14B – 32B)

- **Qwen3.6-27B dense (Apache-2.0, Apr 22 2026)** — Q4_K_M (~17 GB),
  vLLM (`--tool-call-parser qwen`) / llama.cpp, harness: Cline /
  OpenCode / OpenHands. Hardware: 1× RTX 5090 / 24 GB card. Source
  claims 77.2% SWE-bench Verified and Terminal-Bench parity with
  Claude 4.5 Opus (unverified vs. leaderboard). Source:
  <https://localaimaster.com/models/qwen-3-6-27b>,
  <https://www.buildfastwithai.com/blogs/qwen3-6-27b-review-2026>.
- **Qwen3-Coder 30B** — Q4_K_M, llama.cpp / vLLM, harness: Aider /
  Cline. Hardware: 24 GB VRAM. ~96% well-formed tool-call rate on
  code MCP tools per one benchmark writeup. Source:
  <https://www.promptquorum.com/power-local-llm/best-local-models-tool-calling-2026>.
- **Gemma 4 27B (Gemma license)** — Q4_K_M, Ollama / LM Studio,
  harness: Cline / Continue. Hardware: 24 GB VRAM. Called out as
  best general-purpose tool-caller on 24 GB (~95%) in the same
  benchmark writeup. Source: same URL above.
- **Hermes 4.3 36B (Nous)** — Q4, Ollama, harness: Hermes Agent.
  Hardware: 24 GB GPU. Best local pick for the vendor's own harness.
  Source: <https://localaimaster.com/blog/hermes-agent-ollama>.

### Large (32B – 70B)

- **Qwen3.6-35B-A3B (MoE, 3B active)** — Q4, vLLM / SGLang / LM Studio
  / Ollama, harness: OpenHands (default recommendation) / OpenCode.
  Hardware: 22 GB RAM min; ~120 tok/s on RTX 4090 Q4 per one report.
  Good for long-horizon agentic coding; OpenHands' recommended first
  local model as of May 2026. Source:
  <https://www.openhands.dev/blog/openhands-product-update---may-2026>,
  <https://unsloth.ai/docs/models/qwen3.6>.
- **GLM-5.2 (MIT, Jun 16 2026)** — Q4, llama.cpp, harness: Aider /
  Cline / Claude Code (via compat endpoint) / Roo Code. Hardware:
  single high-end GPU per Unsloth guide. 1M context via `glm-5.2[1m]`
  id; useful sub-agent role in multi-model setups. Source:
  <https://github.com/zai-org/GLM-5>,
  <https://unsloth.ai/docs/models/tutorials/glm-5>,
  <https://www.datacamp.com/blog/glm-5-2>.
- **GLM-5.1 32B** — Q4_K_M, llama.cpp / vLLM, harness: Aider / Cline.
  Hardware: 24 GB VRAM. ~94% well-formed call rate in the same
  benchmark writeup. Source:
  <https://www.promptquorum.com/power-local-llm/best-local-models-tool-calling-2026>.
- **Llama 3.3 70B** — Q4_K_M, vLLM / llama.cpp, harness: any.
  Hardware: 2× 24 GB or 1× 48 GB. Highest ceiling in the tool-call
  bench (~97%). Source: same URL above.

### XL / MoE (>70B total)

- **Qwen3-Coder-Next (80B total / 3B active, Apache-2.0, Feb 2026)** —
  GGUF Q4–Q6 (Unsloth), llama.cpp / LM Studio / vLLM. Harnesses:
  Qwen Code / Claude Code / Cline / Kilo / Trae / OpenCode. Hardware:
  24 GB VRAM works at Q4 per Unsloth. Long-horizon reasoning, complex
  tool use, recovery from execution failures; 256K context. Source:
  <https://qwen.ai/blog?id=qwen3-coder-next>,
  <https://unsloth.ai/docs/models/qwen3-coder-next>,
  <https://github.com/QwenLM/Qwen3-Coder>.
- **Llama 4 Scout (17B active / 109B total MoE, Apr 5 2026)** — 4-bit,
  llama.cpp / Ollama, harness: Cline / OpenCode. Hardware: ~32 GB
  system RAM at 4-bit per source; 2× H100 BF16. 10M-token context;
  single-GPU-class MoE. Source:
  <https://ai.meta.com/blog/llama-4-multimodal-intelligence/>,
  <https://insiderllm.com/guides/llama-4-guide-scout-maverick/>.
- **Llama 4 Maverick (17B active / 400B total MoE)** — 4-bit heavy
  quant, vLLM / SGLang, harness: OpenHands. Hardware: 4–8× H200 range.
  Highest-quality Llama 4 tier; agent workloads with lots of compute.
  Same source as above.
- **Kimi K2.6 (1T total / 32B active, Modified MIT, Apr 20 2026)** —
  native INT4 (K2 Thinking variant), vLLM / SGLang / TRT-LLM. Harness:
  OpenHands / OpenClaw-style. Hardware: 8× H100 80 GB INT4 min for
  practical speed per one review. K2.6 documents an Agent Swarm
  scaling to **300 sub-agents / 4,000 coordinated steps** (vendor
  claim). Source:
  <https://github.com/MoonshotAI/Kimi-K2>,
  <https://www.marktechpost.com/2026/04/20/moonshot-ai-releases-kimi-k2-6-with-long-horizon-coding-agent-swarm-scaling-to-300-sub-agents-and-4000-coordinated-steps/>.
- **DeepSeek V4-Pro (1.6T total / 49B active)** — FP4 MoE, vLLM /
  SGLang day-0, harness: OpenCode / OpenHands with an OpenAI-compat
  frontend. Hardware: multi-node H100 / H200. Long agent chains;
  reasoning content preserved across user turns. Source:
  <https://api-docs.deepseek.com/news/news260424/>,
  <https://www.runpod.io/blog/deepseek-v4-in-the-wild-and-how-to-run-it-on-runpod>.
- **MiniMax M2 (230B / 10B active, open weights)** — vLLM / SGLang
  recipes, harness: any OpenAI-compat. Hardware: multi-GPU. Long-horizon
  shell / browser / retrieval / code-runner chains. Source:
  <https://www.minimax.io/news/minimax-m2>,
  <https://github.com/MiniMax-AI/MiniMax-M2>.

Caveat on the benchmark numbers above: the sub-100% percentages come
from third-party writeups (Prompt Quorum, Local AI Master). The primary
numbers (vendor benchmarks, GitHub release counts) are directly from
vendors. Treat percent-tool-call-success as directional, not

## Open questions / follow-ups

- **The Neural Noise benchmark is likely the most reliable head-to-head
  available**, but the page was unreachable (403). Worth fetching
  manually or via `curl` next execution.
  URL: <https://www.neuralnoise.com/2026/harness-bench-wip/>.
- **Parallel tool calls**: vLLM's roadmap explicitly targets improving
  parallel / structured-output robustness in Q3 2026; llama.cpp's
  webUI MCP client doesn't yet document parallel tool invocation
  semantics. Verify against `llama.cpp/tools/server/README.md` on
  master.
- **Actual star / release counts for a few repos looked inflated in
  third-party writeups** (Hermes Agent "216K stars", OpenCode
  "150K–160K stars"). Confirm via `gh repo view` next cycle.
- **Continue.dev's post-Cursor future** is unclear — the OSS repo is
  read-only but community forks may emerge. Worth watching for forks
  in the next 30–60 days.
- **Roo Code's archival in May 2026** — ecosystem impact isn't yet
  visible in downstream harnesses; some benchmark scripts still
  assume it exists.
- **MCP-Bench and MCP-Universe as reproducible benches for local
  models** — the papers exist but the local-model-vs-cloud tables
  they publish weren't verified.
  URLs: <https://github.com/Accenture/mcp-bench>,
  <https://mcp-universe.github.io/>.
- **llama.cpp MCP integration is in the web UI, not the C++ server
  itself.** This matters for headless production. No confirmed native
  C++ MCP client yet as of this window.
- **Qwen3-Coder-Next stability under `llama-server`** — multiple
  issues report SIGSEGV during consecutive tool calls. If picking
  this model for a production loop, verify against the current
  llama.cpp head, not the `b8xxx` line.
- **Terms consistency**: several sources conflated model release names
  (Qwen3.5 vs. Qwen3.6 vs. Qwen3-Coder-Next; GLM-4.7-Flash vs.
  GLM-5.x). Anchor future entries on Hugging Face model IDs, not
  blog nicknames.
