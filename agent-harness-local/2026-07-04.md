# Agent Harness (Local) — 2026-07-04

## Summary

Since April 2026, the local-agent stack has been reshaped by three simultaneous forces: (1) a wave of new open-weight agentic-coding models — DeepSeek-V4 (April 24), Kimi K2.6 (April 20), Qwen3.6-27B/35B (April 16-22), MiniMax-M3 (June 1), Nemotron-3-Ultra (June 4), Qwen 4 Coder 32B-A3B (June 2), and GLM-5.2 MIT (June 13-16); (2) inference backend maturity — vLLM 0.24.0 landed DeepSeek-V4 hardening and a unified reasoning/tool-call parser, SGLang shipped day-0 Nemotron-3 support, Ollama's v0.30.x line added better tool-call JSON parsing and MLX speedups, and LM Studio 0.4.10+ gained OAuth-backed MCP; and (3) harness consolidation — Nous released a native Hermes Desktop (June 2), Continue.dev was acquired by Cursor with v2.0 as final release (June 19), and OpenCode/Crush kept iterating on MCP + local backends. The most consequential shift is that a Mac-runnable 32B MoE (Qwen 4 Coder) now clears 80% on SWE-Verified, closing much of the local/frontier gap for daily coding.

## Harnesses

### OpenCode (sst/opencode)

- Source: <https://github.com/sst/opencode>
- License: MIT

Terminal-native coding agent, ~160k GitHub stars as of mid-2026. June 2026 updates added a Scout subagent for external-docs research, background subagents, auto-compact context management, `fff`-backed faster file search, WSL-backed Desktop support, and a "Go" $10/mo open-weight-model plan alongside BYOK. Fully supports MCP (stdio, HTTP, SSE) and connects to 75+ providers including Ollama and any OpenAI-compatible endpoint (source: <https://opencode.ai/docs/mcp-servers/>, <https://opencode.ai/docs/models/>).

### Crush (Charm)

- Source: <https://github.com/charmbracelet/crush>
- License: FSL-1.1-MIT (converts to MIT over time)

Charm's Go TUI coding agent, ~25k stars. Supports MCP over stdio/HTTP/SSE, LSP integration, session workspaces keyed by working directory (shared LSP/MCP/permission state), and any OpenAI/Anthropic-compatible endpoint. Runs as a single binary on macOS/Linux/Windows/BSD/Android. Documented DeepSeek integration path; local via Ollama/LM Studio (source: <https://charmbracelet-crush.mintlify.app/>, <https://api-docs.deepseek.com/quick_start/agent_integrations/crush>).

### Hermes Desktop / Hermes Agent (Nous Research)

- Source: <https://github.com/NousResearch/hermes-agent>
- License: MIT

Hermes Desktop launched in public preview on June 2, 2026 as a native macOS/Linux/Windows GUI for Hermes Agent v0.15.2, adding streaming tool output, one-click install, in-app self-update, inline model picker, concurrent profiles, a remote gateway sign-in, and a fuller web admin panel. The underlying Hermes Agent (Feb 2026) has a built-in learning loop that persists skills across sessions. Ollama v0.30.7 (June 7) added `ollama launch hermes-desktop` (source: <https://www.marktechpost.com/2026/06/03/nous-research-releases-hermes-desktop-a-native-cross-platform-front-end-for-hermes-agent-v0-15-2-with-streaming-tool-output/>, <https://github.com/ollama/ollama/releases>).

### Mistral Vibe 2.0 CLI

- Source: <https://github.com/mistralai/mistral-vibe>
- License: Apache 2.0 (CLI)

Terminal-native coding CLI purpose-built around the Devstral 2 family. Vibe 2.0 shipped Jan 27, 2026; runs against any OpenAI-compatible endpoint so local Devstral Small 2 (24B, Apache 2.0, ~15GB Q4_K_M) works out of the box. Uses the Agent Communication Protocol for IDE integration (source: <https://mistral.ai/news/mistral-vibe-2-0/>, <https://docs.mistral.ai/mistral-vibe/local>).

### Aider

- Source: <https://github.com/Aider-AI/aider>
- License: Apache 2.0

40k+ stars, still 0.x versioning with ~biweekly releases. Runs against Ollama and any OpenAI-compatible API. Most common local pairing in 2026 is `aider --model ollama/qwen3-coder` or Devstral Small 2. Still no MCP-client integration in Aider itself as of late June 2026 (source: <https://aider.chat/docs/llms.html>).

### Plandex & opencode-ai fork

- Plandex source: <https://github.com/plandex-ai/plandex> — License: MIT
- opencode-ai source: <https://github.com/opencode-ai/opencode>

Plandex's 2026 line focused on the model-provider config system and shipping built-in Ollama support, with hosted Cloud being wound down in favor of self-hosted/local. Ships two adaptive local packs (`ollama-oss` and `ollama-daily`) that route light roles to local Ollama and heavy roles to remote (source: <https://docs.plandex.ai/models/ollama/>).

### Cline

- Source: <https://github.com/cline/cline>
- License: Apache 2.0

VS Code agent, ~59k GitHub stars, 1.5M+ installs by April 2026. Cline CLI 2.0 (early 2026) added parallel + headless flows. Full MCP client, direct Ollama/LM Studio pickers in the UI. Well-known caveat: Ollama's default `num_ctx` (2K-4K) truncates agent context — must be raised for real agentic use (source: <https://docs.cline.bot/running-models-locally/overview>).

### OpenHands

- Source: <https://github.com/OpenHands/OpenHands>
- License: MIT

v1.7.0 (May 1, 2026) moved the Tavily search key to MCP settings and proxied MCP-to-Tavily through the app server for enterprise deployments. Local-LLM support documented for Ollama/vLLM backends; SDK provides a typed tool system + MCP integration with deterministic replay (source: <https://github.com/OpenHands/OpenHands/releases>).

### OpenHarness (HKUDS)

- Source: <https://github.com/HKUDS/OpenHarness>
- License: MIT

Reference "open agent harness" implementation with an agent loop, 43 tools, skills, plugins, permissions, hooks, commands, MCP support, memory, and multi-agent coordination. v0.1.7 (April 18, 2026) polished packaging and TUI, and linked `oh`, `ohmo`, and `openharness` into `~/.local/bin`. `oh --dry-run` previews all resolved runtime settings including MCP servers without executing the model (source: <https://github.com/HKUDS/OpenHarness/blob/main/CHANGELOG.md>).

## Backends

### vLLM

- Source: <https://github.com/vllm-project/vllm>
- Latest release: v0.24.0 (June 30, 2026); v0.22.0 EAGLE 3.1 shipped in May/June; v0.21 stabilized DeepSeek V4 on Blackwell

Unified reasoning + tool-call parsing behind a single `Parser.parse()` interface (Streaming Parser Engine); DeepSeek-V4 hardened with sparse-MLA metadata decoupled from V3.2, TRTLLM-gen attention kernel, EPLB support for Mega-MoE, selective prefix-cache retention for sliding-window KV; Rust frontend gained new endpoints. Note: MiniMax-M3 is not yet supported as of v0.24.0. A public blog series covered debugging Kimi K2 tool-calling accuracy (chat-template compatibility, `add_generation_prompt`, schema validation). MCP integration via the vLLM Semantic Router. Supports parallel tool calls via OpenAI-compatible API (source: <https://github.com/vllm-project/vllm/releases>, <https://blog.vllm.ai/>).

### SGLang

- Source: <https://github.com/sgl-project/sglang>
- Latest release: NVIDIA-packaged release notes indexed as v26.06 (June 2026)

Day-0 support for Nemotron 3 Ultra, Nemotron 3 Super, Higgs Audio v3 TTS. New hardware support for GB300/B300, RTX PRO 6000 Blackwell Server, DGX Spark, Jetson Thor; FP8 on Hopper+. Tool-call parsers per-model family: `qwen25`, `qwen3_coder` (also used for Qwen3.5/3.6), plus reasoning-parser flags. SGLang router provides observability across HTTP/router/worker/circuit-breaker/retry/discovery/MCP/database layers. Parallel tool calls supported via OpenAI function-calling spec (source: <https://docs.nvidia.com/deeplearning/frameworks/sglang-release-notes/index.html>, <https://docs.sglang.io/advanced_features/tool_parser.html>).

### llama.cpp

- Source: <https://github.com/ggml-org/llama.cpp>
- Latest release: b9870 (July 3, 2026); b9838 (June 29, 2026)

Continuous build-tag releases. MCP client remains in the bundled SvelteKit web UI (merged March 2026) — the C++ server itself is not an MCP client, but `llama-server --webui-mcp-proxy` provides an optional CORS proxy so browsers can reach MCP servers. Recent commits: CUDA topk-MOE fusion for 288 experts, Hexagon flash-attention rework, SSE-stream pings to prevent web-UI timeout disconnects, StepFun parser trimming to fix long reasoning loops, OpenCL binary-kernel loading, Qwen3.6 MTP support out of experimental, and a pending GLM-5.2 support issue (#24730). Tool calling supported for Qwen 3.x, Qwen Coder, and other trained-for-tools GGUFs (source: <https://github.com/ggml-org/llama.cpp/releases>).

### Ollama

- Source: <https://github.com/ollama/ollama>
- Latest release: v0.31.1 (June 30, 2026) — ~90% faster Gemma 4 on Apple Silicon via MLX; MTP auto-tuning

Rapid-fire June cadence: v0.30.4 Nemotron-3-Ultra + multimodal GPU optimization on Apple Silicon (June 3); v0.30.6 Gemma 4 QAT weights + Oh My Pi (June 5); v0.30.7 `ollama launch hermes-desktop` (June 7); v0.30.9 Cohere2Moe architecture (June 15); v0.30.10 Command A + North family via MLX (June 17); v0.30.11 extended-thinking detection + Claude Code auto-install + speculative decoding (June 25); v0.30.12 tool-call parser fix to ignore braces inside JSON strings (June 29). Streaming tool calls and parallel tool calls supported. Persistent gotcha: `num_ctx` still defaults small — agents must set it explicitly (source: <https://github.com/ollama/ollama/releases>).

### LM Studio

- Source: <https://lmstudio.ai/>
- Latest release: 0.4.18 (Mac Apple Silicon)

0.3.17 introduced MCP; 0.4.10 (April 9, 2026) added OAuth for MCP servers — the first mainstream local runner with an authenticated MCP path; 0.4.12 (April 17) added Qwen 3.6 support and fixed OAuth-MCP on Windows. Local + remote MCP configured via `mcp.json` or an "Add to LM Studio" button (source: <https://lmstudio.ai/blog/lmstudio-v0.3.17>, <https://lmstudio.ai/docs/app/mcp>).

### TensorRT-LLM

- Source: <https://github.com/NVIDIA/TensorRT-LLM>
- Latest release: April 20, 2026

K2 tool-calling examples added; "MCP Agent Ready" documented with MCP module verification in Docker builds. Base images bumped to `nvcr.io/nvidia/pytorch:25.10-py3`; PyTorch 2.9.0, ModelOpt 0.37, transformers 4.56.0. C++ TRTLLM sampler enabled by default with a new `sampler_type` argument on SamplingConfig (source: <https://nvidia.github.io/TensorRT-LLM/release-notes.html>).

## Model + Harness Combinations That Work Well

### Tiny (≤4B)

- **Gemma 4 E2B/E4B + Ollama + OpenCode/Crush** — On-device Android/laptop agent; native function-calling with structured JSON output, Apache 2.0. Quantized variants run on consumer GPUs (source: <https://ai.google.dev/gemma/docs/capabilities/text/function-calling-gemma4>).
- **Phi-4-mini + llama.cpp + Aider** — Still the small-footprint code-completion default until Phi-5 Mini lands; MIT license (source: <https://azure.microsoft.com/en-us/products/phi/>).

### Small (4B–14B)

- **Gemma 4 12B + Ollama + OpenCode** — Released June 3, 2026; sits in the "big enough to reason, small enough for a laptop" slot with native function calling (source: <https://haimaker.ai/blog/gemma-4-12b-ollama-opencode-setup/>, <https://github.com/ollama/ollama/releases>).
- **Qwen2.5-Coder-7B/14B + llama.cpp + Aider** — Still the go-to sub-16GB local coder; unchanged since prior report but continues to appear in mid-2026 recommendation lists (source: <https://insiderllm.com/guides/best-local-coding-models-2026/>).

### Medium (14B–32B)

- **Devstral Small 2 24B + Mistral Vibe CLI / Cline** — Apache 2.0, 256K context, ~15GB Q4_K_M, runs on a single RTX 4090 or 32GB Mac; explicitly optimized for agentic coding (source: <https://mistral.ai/news/devstral-2-vibe-cli/>, <https://ollama.com/library/devstral>).
- **Qwen3.6-27B (dense) + SGLang (parser `qwen3_coder`) + OpenCode** — April 22, 2026 release; dense multimodal, flagship-level agentic coding, beats prior Qwen3.5-397B-A17B MoE (source: <https://qwen.ai/blog?id=qwen3.6-27b>, <https://sgl-project-sglang-93.mintlify.app/advanced/tool-calling>).
- **Gemma 4 26B A4B + vLLM + OpenHands** — Leads on LiveCodeBench (99.1%) per artificialanalysis; strong tool calling (source: <https://blog.google/innovation-and-ai/technology/developers-tools/gemma-4/>).

### Large (32B–70B)

- **Qwen 4 Coder 32B-A3B (MoE) + Ollama or vLLM + Aider/Crush** — Released June 2, 2026; 82% SWE-Verified, Apache 2.0, 256K context; RL post-trained against executable tests. First open-weight Mac-runnable coder to clear 80% SWE-Verified (source: <https://llmcheck.net/blog/qwen-4-coder-review/>).
- **Qwen3.6-35B-A3B + SGLang + OpenCode/Cline** — Apache 2.0, 262K native context (~1M via YaRN), MoE with 3B active; strong for long-context repository work (source: <https://huggingface.co/Qwen/Qwen3.6-35B-A3B>).
- **Nemotron-3 Nano Omni 30B-A3B (hybrid MoE) + SGLang + OpenHarness** — Day-0 SGLang support, multimodal, NVIDIA Open Model License; targets efficient multimodal sub-agents (source: <https://developer.nvidia.com/blog/nvidia-nemotron-3-nano-omni-powers-multimodal-agent-reasoning-in-a-single-efficient-open-model/>).
- **Llama 3.3 70B + vLLM + Cline/OpenHands** — Still the highest well-formed-call rate at ~97% across MCP servers per the tool-calling benchmark round-ups; needs 48GB+ VRAM (source: <https://www.promptquorum.com/power-local-llm/best-local-models-tool-calling-2026>).

### XL / MoE (>70B total)

- **Qwen3-Coder-Next 80B/3B-A + Ollama or vLLM + OpenCode/Aider** — 70.6% SWE-Verified, 256K context, ~52GB VRAM at Q4_K_M (2× RTX 5090 / 1× H100 / M3 Ultra 96GB); 60-120 tok/s on H100 because only 3B is active (source: <https://ollama.com/library/qwen3-next:80b>, <https://localaimaster.com/models/qwen-3-coder-next>).
- **DeepSeek-V4-Flash 284B/13B-A + vLLM 0.24 + OpenHands** — 160GB weights, runnable on 128GB M5 MacBook with light quantization or 2×GPU + `--tensor-parallel-size 2`; 1M context. Custom `ds4` engine ships KV-cache persistence for 1M context on a MacBook (source: <https://www.lmsys.org/blog/2026-04-25-deepseek-v4/>, <https://flowtivity.ai/blog/deepseek-v4-flash-ds4-local-inference-128gb-mac/>).
- **Kimi K2.6 1T/32B-A + vLLM + Crush/OpenCode** — Released April 20, 2026, open-weight, ties GPT-5.5 on coding per artificialanalysis; vLLM debugged K2 tool-call accuracy in blog series (source: <https://artificialanalysis.ai/articles/kimi-k2-6-the-new-leading-open-weights-model>, <https://blog.vllm.ai/>).
- **GLM-5.2 ~744-753B / 40B-A + llama.cpp (RPC) or vLLM + OpenCode/Crush** — MIT license (June 13-16), 1M context, top of Artificial Analysis Intelligence Index (51), 62.1 SWE-Bench Pro, 74.4% FrontierSWE. llama.cpp support tracked in issue #24730; realistic local run needs a 256GB Mac or multi-4090 box at 2-bit (source: <https://simonwillison.net/2026/Jun/17/glm-52/>, <https://ofox.ai/blog/glm-5-2-run-locally-gguf-2026/>).
- **MiniMax-M3 428B/22B-A + SGLang / AMD Instinct + custom harness** — Released June 1, 2026, 1M context via MiniMax Sparse Attention (~1/20 the cost of prior gen at 1M), native multimodal. Day-0 AMD Instinct support; not yet in vLLM 0.24.0. Exposes `<mm:think>` chain-of-thought + auto tool selection over OpenAI API (source: <https://www.amd.com/en/developer/resources/technical-articles/2026/day-0-support-for-minimax-m3-on-amd-instinct-gpus.html>, <https://openrouter.ai/minimax/minimax-m3>).
- **Nemotron-3 Ultra 550B/55B-A + SGLang + OpenHands** — Released June 4, 2026; NVIDIA Open Model License is permissive incl. commercial; targets long-horizon agentic orchestration (source: <https://developer.nvidia.com/blog/nvidia-nemotron-3-ultra-powers-faster-more-efficient-reasoning-for-long-running-agents/>).

## Open questions / follow-ups

- Kimi K3 slipped its predicted May window (74% prediction-market odds); credible rumors point to Q3 2026 launch with 2.5T+ params and Kimi Linear attention — worth tracking for the next refresh.
- MiniMax-M3 is not yet in vLLM 0.24.0; verify next release adds it, and confirm SGLang support status.
- llama.cpp GLM-5.2 support (issue #24730) is still open — the RPC/sparse-attention story determines whether GLM-5.2 becomes a practical local target for prosumer hardware.
- Phi-5 references are surfacing in secondary sources but Microsoft has not published a primary blog/model card as of July 4, 2026 — treat existing "Phi-5" claims skeptically until confirmed.
- Continue.dev's acquisition by Cursor (June 2026) leaves the open-source repo read-only; unclear who forks the maintenance load — potential replacement candidates: Roo Code, Cline, Void.
- vLLM MCP support is currently via the Semantic Router; no confirmed native MCP client server-side. Track whether the "vLLM ResponsesAPI & Tool Calling H1 2026" roadmap (issue #34857) delivers a native path.
- Benchmark drift: BFCL v4 vs τ²-Bench Telecom vs real MCP-server workloads still disagree meaningfully — no single number captures agent-tool-call reliability for local models.
