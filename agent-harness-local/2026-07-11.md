# Agent Harness (Local) — 2026-07-11

## Summary

Between the April report and today, the biggest shift is that the "harness gap" is now a first-class concern for model vendors themselves — DeepSeek publicly stood up a dedicated Harness team and Moonshot shipped Kimi Work, a local desktop agent driven by a K2.6 300-sub-agent swarm. On the OSS harness side, OpenCode completed its move to Anomaly (repo now `anomalyco/opencode`, ~165k stars) after the January Anthropic sub-login dispute, Charm's Crush hardened its MCP transport story (stdio/HTTP/SSE) but remains FSL-1.1-MIT, Pi migrated with Mario Zechner to Earendil (`earendil-works/pi`), and Block's Goose is now shipped by the Linux Foundation's Agentic AI Foundation as v1.38.0. Inference backends narrowed the gap: llama.cpp's built-in MCP host (merged March 2026) is now the standard bridge for any GGUF model, vLLM's Kimi-K2 tool-call parser was re-verified against Moonshot's K2-Vendor-Verifier, and SGLang's RadixAttention is delivering 40–60% TTFT wins on shared-prefix agent workloads. MCP itself is on a 2026-07-28 RC that flips the transport stateless and promotes Tasks to a first-class extension. Two new open-weight arrivals reshape the model-plus-harness picture: MiniMax M3 (1M ctx, native multimodal, June 1) and Kimi K2.7 Code (June 12, 30% fewer thinking tokens than K2.6).

## Harnesses

### OpenCode (Anomaly)

- Source: <https://github.com/anomalyco/opencode>, <https://opencode.ai/>
- License: MIT

Repo rebrand from `sst/opencode` to `anomalyco/opencode` is complete — old Docker image references will break. Reported ~165k GitHub stars, 75+ provider integrations, and unique-in-2026 LSP feedback loop (compiler diagnostics fed to the model after every edit). Local models supported via any OpenAI-compatible endpoint (Ollama, LM Studio, llama-server). After the January Anthropic dispute, Claude Pro/Max sub-login was removed; ChatGPT sub-login now works natively via an OpenAI partnership (secondary coverage: Pinggy / Developers Digest).

### Crush (Charm)

- Source: <https://github.com/charmbracelet/crush>
- License: FSL-1.1-MIT (converts to MIT after 2 years) — not fully open source today

Single-binary Go TUI. Multi-provider (Anthropic, OpenAI, Gemini, Groq, Bedrock, Azure, any OpenAI/Anthropic-compatible endpoint including local llama-server / LM Studio / Ollama), mid-session model switching, LSP context, MCP over stdio/HTTP/SSE, per-project agent config, fine-grained permissions. Still pre-1.0 as of July 2026.

### Pi (Earendil)

- Source: <https://github.com/earendil-works/pi>, <https://lucumr.pocoo.org/2026/1/31/pi/>
- License: MIT

Repo moved from `badlogic/pi-mono` to `earendil-works/pi` after Mario Zechner joined Armin Ronacher's Earendil PBC in April 2026. Minimal harness: <1,000-token system prompt (vs 7–10k for Cline/OpenCode/Claude Code) via "lazy skills" (one-line descriptions in context, full instructions/schemas load on invocation). Core model gets four tools (read/write/edit/bash). Ships CLI, unified LLM API, TUI/web UI libs, and MCP client. Now also the harness inside OpenClaw (per the Syntax podcast episode with Zechner and Ronacher).

### OpenHarness (HKUDS)

- Source: <https://github.com/HKUDS/OpenHarness/releases>
- License: MIT (per README)

Post-April cadence: v0.1.8 (2026-05-06, stabilization + provider expansion adding NVIDIA NIM, ModelScope, Qwen, MiniMax, Gemini; MCP stability fix so failed servers no longer abort startup) and v0.1.9 (2026-05-07, bundled `skill-creator` skill and user-invocable slash commands). Reported active issue traffic through June (issues opened 6/17, 6/19, 6/22, 6/23) but no tagged release visible in June/July on the releases page.

### Plandex

- Source: <https://github.com/plandex-ai/plandex>, <https://plandex.ai/>
- License: MIT (agent), AGPL (server)

At v2.2.1 in Q2 2026. Hosted Plandex Cloud continues winding down (started 2025-10-03) in favor of self-hosted/local modes. New Ollama quickstart plus built-in model packs for Qwen 3 (8B–235B) and DeepSeek R1 distilled (8B–70B) via the Ollama provider.

### Aider

- Source: <https://github.com/Aider-AI/aider/releases>, <https://aider.chat/HISTORY.html>
- License: Apache 2.0

Recent additions: `/think-tokens` and `/reasoning-effort` slash commands with human-readable budgets (8k, 10.5k, 0.5M), `--auto-accept-architect` flag (default true), and tree-sitter-language-pack for broader language coverage. Ollama remains the standard path for local models via `--model` against any OpenAI-compatible endpoint.

### Goose (Block → Agentic AI Foundation)

- Source: <https://github.com/block/goose>, <https://block.xyz/inside/block-open-source-introduces-codename-goose>
- License: Apache 2.0

Now hosted by the Linux Foundation's Agentic AI Foundation (contributed Dec 2025 alongside Anthropic's MCP and OpenAI's AGENTS.md). Reported v1.38.0 on 2026-06-17 as a Rust CLI + desktop app with 15+ LLM providers (including Ollama) and 70+ MCP extensions.

### Hermes Agent (NousResearch)

- Source: <https://github.com/nousresearch/hermes-agent>
- License: MIT

Ships 60+ built-in tools plus MCP server support; requires a model with reliable function-calling and ≥64K context. Backend-agnostic against Ollama, LM Studio, vLLM, llama.cpp, KoboldCpp, or any OpenAI-compatible endpoint. May/June 2026 saw a dev.to community challenge with dozens of published implementations, including Raspberry Pi deployments.

### llama-agent (Gary149)

- Source: referenced by <https://huggingface.co/docs/hub/agents-local> ("Local Agents with llama.cpp")
- License: unverified (fork of llama.cpp)

Reported fork that embeds the entire agent loop directly into the llama.cpp binary — no Node process, no HTTP hop between agent and model, one compiled binary handles inference, tool calls, subagents, and optional HTTP API. Reported, not independently verified for July 2026.

## Backends

### llama.cpp

- Source: <https://github.com/ggml-org/llama.cpp>, PR #18059 (webui client-side tool calling), March 2026 MCP merge

Since April: web-UI-side MCP host is stable — any local GGUF model can call MCP tools via the SvelteKit chat interface, no bridge app. MCP wiring lives browser-side; the server's only MCP-specific piece is the optional `--webui-mcp-proxy` CORS proxy. Note MCP client is NOT in the C++ server — an important limitation for headless CI-style agents that want to talk MCP directly to llama-server. Build cadence stayed roughly weekly (b9917 on 2026-07-08, b9951 on 2026-07-10). Ollama's tool-parser fixes (June 2026) also flow upstream since Ollama tracks llama.cpp.

### vLLM

- Source: <https://docs.vllm.ai/en/latest/features/tool_calling/>, <https://vllm.ai/blog/2025-10-28-kimi-k2-accuracy>, issue vllm-project/vllm#34857
- License: Apache 2.0

Tool-call parser matrix expanded meaningfully: dedicated `kimi_k2` tool parser and reasoning parser, `glm4_moe` tool parser with incremental string streaming, and the pythonic parser (Python-list-as-tool-calls, which sidesteps JSON schema ambiguity and natively expresses parallel calls). vLLM + Moonshot jointly debugged K2 tool-call accuracy using the K2-Vendor-Verifier benchmark and shipped fixes for three compatibility issues (chat_template ID format `functions.func_name:idx`). MCP support for gpt-oss shipped via `ParsableContext`, with work ongoing to generalize MCP to all models — today, browser/python/container MCP tools are the supported subset (per the H1 2026 lookahead issue).

### SGLang

- Source: <https://github.com/sgl-project/sglang/releases>, <https://docs.sglang.io/advanced_features/tool_parser.html>
- License: Apache 2.0

v0.5.x is the current line (v0.5.7 tagged; v0.5.13 extends DeepSeek-V4 to context-parallel serving with sparse-attention kernels). HiCache-for-hybrids launched by default, adding hierarchical KV-cache offload to sliding-window and Mamba hybrids. First-class model launch commands published for MiniMax-M3 and Kimi K2.6/K2.7 Code. Community reports for K2.6 agent workloads with a fixed tool schema cite 40–60% TTFT reductions vs vLLM at scale from RadixAttention shared-prefix caching (Lushbinary / Codersera write-ups — secondary coverage). Tool-call parsers exposed via `--tool-call-parser` (qwen25, pythonic, glm4_moe, kimi_k2, etc.).

### Ollama

- Source: <https://docs.ollama.com/capabilities/tool-calling>, <https://ollama.com/library>
- License: MIT

Parallel tool calls are supported at the API level; `OLLAMA_NUM_PARALLEL` (default 4) governs concurrent request handling. Late-June 2026 llama.cpp bump fixed a tool-call parser bug (braces inside JSON strings were incorrectly detected as end-of-tool-call). MCP still not native — you need a bridge (`ollmcp`, `MCPHost`, `ollama-mcp-bridge`, or a custom SDK client), which remained the same limitation flagged in the April report. Feature request open.

### LM Studio

- Source: <https://lmstudio.ai/changelog>, <https://lmstudio.ai/docs/app/advanced/parallel-requests>
- License: proprietary (free for local use)

The April report's "no streaming tool calls / no parallel calls" gap has closed. Changelog now documents: streamed tool-call argument tokens as they're generated; a fix for parallel tool calls split across multiple SSE chunks being dropped; a fix for root-level `$defs` being stripped from tool definitions; parallel requests via continuous batching (also enabled for MLX backend). Python SDK `.act()` supports auto-scaling parallel tool calls to a multiple of CPU core count.

### TensorRT-LLM

- Source: <https://github.com/NVIDIA/TensorRT-LLM/releases>
- License: Apache 2.0 (fully open-sourced in 2026)

Latest tagged release 2026-04-20 (per release page). Fully open-source now with development on GitHub. Tool-calling is per-model via chat templates; no first-class MCP integration is documented. Practical role in local agent stacks is still "throughput backend for a fixed model," not "agent loop host."

### LocalAI

- Source: <https://github.com/mudler/LocalAI>
- License: MIT

Continues as an OpenAI-compatible facade over multiple backends. No specific tool-calling / MCP milestone stood out in the sources since April. Reported active maintenance; specifics unverified for July 2026.

### KTransformers

- Source: <https://github.com/kvcache-ai/ktransformers>
- License: Apache 2.0

The pragmatic path for running 100B+ MoE models locally on a single RTX 5090 (32GB VRAM) via CPU/GPU heterogeneous inference with AMX-specialized kernels. Called out by name as a supported K2.6/K2.7 deployment path alongside vLLM and SGLang. GOSIM Paris 2026 "Agentic AI on Edge" track.

### MCP protocol

- Source: <https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/>

Not a backend, but the RC published for 2026-07-28 is the biggest revision since launch: stateless core (initialize handshake and `Mcp-Session-Id` removed — any request can land on any instance), new `Mcp-Method`/`Mcp-Name` headers so routers don't have to parse bodies, Tasks graduated to a first-class extension (`tasks/get`, `tasks/update`, `tasks/cancel`), six SEPs of OAuth 2.0 hardening (RFC 9207 `iss` validation), and a formal Active→Deprecated→Removed lifecycle policy with a 12-month floor. Notably, the RC blog does NOT mention parallel tool calls — that remains a client-side concern.

## Model + Harness Combinations That Work Well

### Tiny (≤4B)

- **Gemma 4 E2B / E4B (2B / 4B effective)** with **Pi** on **llama.cpp** or **Ollama**. Reported strong function-calling in a footprint that fits a 24GB M4 Pro laptop with room to spare, useful as an on-device edit-and-verify loop for constrained tools. Source: <https://gemma4-ai.com/blog/gemma4-benchmark>, <https://patloeber.com/gemma-4-pi-agent/>

### Small (4B–14B)

- **Qwen3-Coder-Next-A3B (3B active / 80B total)** with **OpenCode** on **Ollama** or **LM Studio**. 46GB unified memory at Q4, reported >70% SWE-Bench Verified with the SWE-Agent scaffold; the standout April pick still standouts in July with no direct competitor at 3B active. Source: <https://qwen.ai/blog?id=qwen3-coder-next>, <https://unsloth.ai/docs/models/qwen3-coder-next>

### Medium (14B–32B)

- **Devstral Small 24B** with **Cline** (VS Code) on **Ollama**, context set to ≥32K. Purpose-built for agentic multi-file edits; the community recommends it against qwen2.5-coder:32b hallucinating tool calls. Source: <https://ollama.com/library/devstral>, <https://mistral.ai/news/devstral/>
- **Gemma 4 26B MoE** with **Codex CLI** on **llama.cpp**. Benchmarked on a 24GB M4 Pro MacBook Pro at 77.1% LiveCodeBench v6 and 86.4% τ2-bench agentic tool use (12 April 2026 runs, Codex CLI v0.120.0). Source: <https://gist.github.com/danielvaughan/9c414ce1b49b1940dfc87bb9d7534a55>

### Large (32B–70B)

- **Qwen 3.5-27B / Qwen 3.6-27B dense** with **Hermes Agent** on **Ollama** or **LM Studio**. Community rec for "best local model with 16+GB VRAM"; the thinking-off variant reported stable for 30+ sequential tool calls on a single RTX 3090. Source: <https://unsloth.ai/docs/models/qwen3.6>, <https://www.buildmvpfast.com/blog/qwen-3-5-non-thinking-mode-local-agent-deployment-stable-2026> (secondary)
- **Qwen3.6-35B-A3B MoE** with **Qwen-Agent** (native MCP + function-calling framework from Alibaba) on **vLLM** or **SGLang**. Explicitly trained/evaluated on MCP-based agentic tasks. Source: <https://github.com/QwenLM/Qwen-Agent>

### XL / MoE (>70B total, incl. 100B+ MoE)

- **Kimi K2.7 Code (1T / ~32B active)** with **OpenCode** or **Crush** on **vLLM 0.10.x with `--tool-call-parser kimi_k2`**, **SGLang** (Radix-friendly for repeated tool schemas), or **KTransformers** (single-node CPU/GPU hybrid). Modified MIT weights, released 2026-06-12; Moonshot says K2.6 deployment patterns reuse cleanly, and improves K2.6 while cutting thinking tokens ~30%. Source: <https://kimik2ai.com/k2.7/>, <https://openclawlaunch.com/blog/kimi-k2-7-release>, <https://lushbinary.com/blog/kimi-k2-6-self-hosting-guide-vllm-sglang-ktransformers/>
- **Kimi K2 Thinking (native INT4)** with any harness driving long tool chains via **vLLM** or **SGLang**. Moonshot reports state-of-the-art on HLE and BrowseComp with 200–300 sequential tool calls held stable at 256K context, INT4 gives ~2× generation speed. Source: <https://huggingface.co/moonshotai/Kimi-K2-Thinking>
- **MiniMax M3 (open weights)** with **Hermes Agent** or **OpenCode** on **SGLang** (official launch command published). 1M context, native multimodal, sparse attention; trained specifically for long-horizon tool loops. Both OpenAI-compat and Anthropic-compat endpoints. Source: <https://huggingface.co/MiniMaxAI/MiniMax-M3>, <https://lushbinary.com/blog/hermes-agent-minimax-m3-setup-guide/>
- **GLM-4.6 (355B / 32B active MoE)** with **Crush** or **OpenCode** on **vLLM** using `glm4_moe` tool parser. Apache 2.0, 200K context, reported 15% fewer tokens per CC-Bench task vs GLM-4.5. Source: <https://cirra.ai/articles/glm-4-6-tool-calling-mcp-analysis>, <https://github.com/zai-org/GLM-4.5/blob/main/resources/glm_4.6_tir_guide.md>
- **DeepSeek V4-Flash (284B / 13B active, 1M ctx)** with any OpenAI-compatible harness on **vLLM** or **SGLang**. Native tool calling with up to 128 parallel function calls per turn, Anthropic-compatible endpoint. Local via KTransformers reported feasible for V4-Flash tier only; V4-Pro (1.6T) remains a multi-node deployment. Source: <https://lushbinary.com/blog/deepseek-v4-ai-agents-function-calling-mcp-guide/>, <https://techjacksolutions.com/ai-tools/deepseek/deepseek-v4-coding-and-agentic-workflows/>

## Open questions / follow-ups

- OpenHarness has no tagged release visible for June or July 2026 despite active issue traffic — worth confirming whether they've moved to trunk-tracking or whether v0.2 is imminent.
- The MCP 2026-07-28 spec ships in ~2 weeks: after release, re-check which local backends (llama.cpp web UI, Goose, Crush) update their MCP client to the stateless transport and Tasks extension, and how quickly parallel-tool-call orchestration lands client-side.
- llama.cpp's MCP host is still webui-only; if a native C++ MCP client lands in llama-server, that removes the browser dependency for headless agents and unblocks a large class of CI/server agents.
- vLLM's "MCP for all models" via `ParsableContext` is claimed as in-flight in the H1 2026 lookahead; verifying which non-gpt-oss models actually work at July 2026 would matter for Kimi K2.7 / GLM-4.6 / DeepSeek V4 agent workloads.
- The `llama-agent` (Gary149) fork is reported by secondary sources but a maintained repo could not be verified — worth pinning down whether this is still active or superseded.
- The prior report's headline numbers (vLLM ~3.9× TTFT vs Ollama; SGLang ~29% shared-prefix win) weren't reproduced in current sources; the current secondary claim is SGLang 40–60% TTFT reduction on shared-prefix agent workloads with K2.6 — worth an apples-to-apples benchmark run to update the number.
