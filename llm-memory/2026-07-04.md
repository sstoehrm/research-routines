# LLM Memory — 2026-07-04

## Summary

The last ten weeks have been dominated by two threads. First, a wave of arXiv work explicitly training memory rather than just wiring it: Supersede, Mem-π, Memory-R1 follow-ups and Letta's "memory-native RL" position piece all treat memory-management as a policy to be learned with GRPO/PPO on top of small open models (Qwen2.5-3B/7B, Qwen3-8B, Llama-3.1-8B). Second, a shift away from atomic-fact stores toward multi-granularity, context-preserving memory (TriMem, RaMem, ByteRover) after several papers documented that fact-shredding memory loses temporal/episodic context. Mem0 shipped a token-efficient algorithm update (single-pass ADD-only extraction plus multi-signal retrieval) that pushed reported LoCoMo scores up sharply. ICLR 2026's MemAgents workshop drew ~110 submissions and formally introduced BEAM, a 10M-token conversation benchmark that current stacks do not saturate. Titans-style test-time memory remains largely stalled on the closed-source side; the only public open-weight attempt in-window is the Grafted-Titans blog (Qwen-2.5, single-GPU), and there is still no strong peer-reviewed reproduction.

## Letta — "Memory Models: Towards Agents That Learn"

- Source: <https://www.letta.com/blog/towards-agents-that-learn/>
- Date: 2026-06-25

### Why it matters for local models

Letta (the MemGPT successor) is laying out a public thesis that "token-space" memory — memory as editable text rather than weight updates — is the practical continual-learning substrate for the next generation of agents, and that the memory manager itself should be a small model trained with RL on memory-shaped rewards. This is directly relevant to local deployments: the target artifact is a small, specialized "memory model" that curates context for a larger frozen policy, which is much cheaper to run and re-train than adapting the base LLM. It also formalizes the abstraction now shared by Letta Code, Claude Code, DeepAgents, and OpenClaw.

### In-depth insights

The post argues that in-context learning has become the de facto continual-learning mechanism for agent harnesses (agentic memory management, "agent dreaming," skill learning) but that LLMs are bad at *producing* durable context for future tasks. Their proposed answer is "memory models": models specialized to create and curate token-space memory, trained with memory-native RL where the reward is derived from downstream task success on unseen episodes. Not open-sourced as of the post; the blog is a position/roadmap rather than a released model or training recipe, and no benchmark numbers are attached.

## Supersede — Diagnosing and Training the Memory-Update Gap in LLM Agents

- Source: <https://arxiv.org/abs/2606.27472>
- Date: 2026-06-25 (arXiv v1)

### Why it matters for local models

Supersede is one of the first concrete, open RL environments where the reward specifically targets *temporal fact-currency* — answering with the current value of a fact and not a superseded one — and shows the gap can be trained down on a 3B open model. Everything (env + recipe) is aimed at small open weights, so anyone running a local agent stack can plug this in.

### In-depth insights

Author: Vedant Patel. The paper isolates "supersession" (a fact was previously true, is now false) as a distinct failure mode on real multi-session conversational data and releases an RL environment where the agent is rewarded for using current values and penalized for stale ones. GRPO fine-tuning of Qwen2.5-3B nearly doubles held-out supersession accuracy on unseen conversations (9.0% → 16.7%, single run). Absolute numbers are still low, and results are from a single seed, but this is the first trainable environment whose reward is temporal fact-currency. License/repo details not clearly stated in the abstract; the environment is described as "released" and open.

## RaMem — Contextual Reinstatement for Long-term Agentic Memory

- Source: <https://arxiv.org/abs/2606.22844>
- Date: June 2026 (arXiv 2606.22844)

### Why it matters for local models

Directly evaluated on Qwen3-8B (in addition to GPT-4.1-mini) and reduces the context-token budget needed at retrieval time by roughly half at matched accuracy. That's exactly the axis local deployments care about — fewer tokens per query is fewer FLOPs on-device.

### In-depth insights

Diagnoses "context collapse": retrieved memories drop the surrounding episode context (time, participants, session span), so semantically-similar memories from different situations look interchangeable. Four-stage pipeline: (1) Episodic Memory Anchoring attaches each memory to event time, mention time, session span, participants; (2) Recall Condition Induction decomposes the query into information need + contextual recall frame; (3) Validity-Aware Retrieval prioritizes memories whose episodic coordinates match the frame; (4) Context-Preserved Synthesis passes memories with their structured context intact into the generator. Empirically RaMem with K=10 matches or beats SimpleMem with K=20 on both GPT-4.1-mini and Qwen3-8B. Results are on their own diagnostic setup; no LoCoMo/LongMemEval headline numbers surfaced in the abstract.

## Mem-π — Adaptive Memory through Learning When and What to Generate

- Source: <https://arxiv.org/abs/2605.21463>
- Date: 2026-05-20

### Why it matters for local models

Rather than retrieving from an external store, Mem-π uses a small dedicated LM/VLM as an on-demand "guidance generator" that decides *whether* to speak at all and *what* to say to the acting agent. That decoupled small model is a natural fit for local co-deployment alongside a frozen big base model, and it is trained with RL rather than distillation from a frontier model.

### In-depth insights

Two-headed decision-content RL objective: the model jointly learns (i) when to intervene (abstain vs. produce guidance) and (ii) what guidance to produce. Trained on web-navigation, terminal tool-use, and text embodied benchmarks. Reported >30% relative improvement on web navigation over retrieval-based and prior RL-optimized memory baselines. The naming is close to but distinct from earlier Mem-α (arXiv 2509.25911), which used similar RL-for-memory-construction ideas on Qwen3-4B and reported 0.389 → 0.642. Neither paper releases a full weights checkpoint explicitly in the abstract, but recipes target open small models.

## TriMem — Rethinking How to Remember: Beyond Atomic Facts in Lifelong LLM Agent Memory

- Source: <https://arxiv.org/abs/2605.19952>
- Code: <https://github.com/tmlr-group/TriMem>
- Project: <https://tmlr-trimem.github.io/>
- Date: May 2026

### Why it matters for local models

Fully open code from TMLR Group. Argues the industry default (compress dialogues into atomic facts, throw the raw turns away) is discarding exactly the information needed for multi-hop reasoning. This is a practical replacement recipe for the "atomic-fact" schemes at the core of mem0-style memory layers.

### In-depth insights

Authors: Jingwei Sun, Jianing Zhu, Jiangchao Yao, Tongliang Liu, Bo Han. Maintains three coexisting granularities in memory: raw dialogue segments (fidelity), extracted atomic facts (fast retrieval), and synthesized profiles that aggregate facts (deep reasoning). Uses TextGrad-based prompt optimization to iteratively refine extraction and profiling prompts against downstream response quality. Because it is prompt-optimization rather than weight training, it is trivially portable to any open-weight base model — but the flip side is that its numbers depend on the base model's instruction-following.

## EvoMemBench — Benchmarking Agent Memory from a Self-Evolving Perspective

- Source: <https://arxiv.org/abs/2605.18421>
- Date: May 2026

### Why it matters for local models

The most rigorous new memory eval this quarter. Its headline finding — no single memory scheme wins across settings, and long-context baselines are still hard to beat — is a useful sanity check before anyone spends compute finetuning a "memory model" onto a 7-8B local base.

### In-depth insights

Two axes: memory scope (in-episode vs. cross-episode) × memory content (knowledge-oriented vs. execution-oriented), giving four settings. Compares 15 representative memory methods against strong long-context baselines under one standardized protocol. Key findings: (i) current memory systems are far from a general solution, (ii) memory helps most when context is insufficient or the task is difficult, (iii) no single memory form works consistently across the four settings, (iv) compression memory can actively *hurt* execution tasks by dropping fine-grained detail. Standardized protocol is a big deal — previous claims across mem0 / Zep / MemOS / Letta were run under different prompts and rarely reproducible.

## Mem0 Token-Efficient Algorithm Update

- Source: <https://mem0.ai/blog/mem0-the-token-efficient-memory-algorithm>
- Coverage: <https://agentry.press/news/mem0-algorithm-update-hits-91-6-on-locomo-94-8-on-longmemeval/>
- Date: April 2026 (right at edge of window)

### Why it matters for local models

Mem0 is one of the most widely deployed open-source memory layers with local models. The April rewrite is a materially different algorithm — not a knob tweak — and it drops mean per-query token cost to ~6.7-7.0K vs. 25K+ for full-context, which is meaningful when the underlying LLM is a 7-13B local model.

### In-depth insights

Three architectural changes: (1) Single-pass ADD-only extraction — each new turn goes through one LLM call, no UPDATE/DELETE; (2) Entity extraction, embedding, and linking across memories so retrieval can boost on entity match; (3) Multi-signal retrieval fusing dense semantic similarity, BM25, and entity match in parallel. Reported LoCoMo 91.6 and LongMemEval 94.8. Largest gains vs. the older algorithm are on temporal queries (+29.6 pts) and multi-hop (+23.1 pts). Caveats: benchmarks are run and reported by Mem0; EvoMemBench-style third-party evaluation of this exact version has not landed yet. Docs describe a v2→v3 platform migration path.

## ICLR 2026 MemAgents Workshop — Outcomes

- Source: <https://sites.google.com/view/memagent-iclr26/>
- Coverage: <https://mcml.ai/news/2026-05-06-mem-agents-workshop-at-iclr-2026/>
- Date: 2026-04-27 (Rio de Janeiro, Room 205)

### Why it matters for local models

This is the field's coordination point right now. ~110 submissions and four keynotes explicitly framed memory as a first-class research topic distinct from long-context or RAG. Multiple accepted papers target small open models — the workshop is where recipes like Supersede, Memory-R1 follow-ups and Mem-π were showcased together.

### In-depth insights

Keynotes: Aditi Raghunathan (CMU) — "Architecting Controllable Parametric Memory in Language Models"; Chelsea Finn (Stanford) — "Scaling Text Optimization for Reasoning and Agentic LLMs"; Weiwen Liu (SJTU) — "Toward the Next Generation of Personalized, Proactive, and Self-Evolving Agents"; Fred Sala (Snorkel.AI) — "Data-Centric Memory: Improving LLM Agents Through Better Data". Also invited: Volker Tresp, Jeff Clune, Mengye Ren, Jeff Pan. Central new benchmark presented was BEAM ("Beyond a Million Tokens", ICLR 2026, code <https://github.com/mohammadtavakoli78/BEAM>, MIT/CC-BY-SA 4.0): 100 conversations at 128K / 500K / 1M / 10M tokens, 2,000 probing questions, LLM-as-judge scoring across 10 memory abilities. No stack (long-context Gemini/Claude, or agentic memory) saturates BEAM-1M (64.1) or BEAM-10M (48.6). The complementary LIGHT method reported +3.50%–12.69% average over the strongest baselines. No public "best paper" announcement is discoverable yet.

## Open questions / follow-ups

- Is there a peer-reviewed, open-weights reproduction of Titans/MIRAS yet? So far only the "Grafted Titans" substack (Qwen-2.5, single consumer GPU, 44.7% on their task) and the earlier "Titans Revisited" preprint from before this window; no in-window arXiv reproduction surfaced.
- The Letta "Memory Models" post is a vision — is a training recipe or checkpoint coming? Worth watching Letta's GitHub for a matching release in July/August.
- Third-party reproduction of Mem0's LoCoMo 91.6 / LongMemEval 94.8 — EvoMemBench's methodology suggests these numbers may not survive a fully standardized eval. Track whether the next EvoMemBench update includes the new Mem0 algorithm.
- KV-cache compression is moving fast (StructKV, InfoKV, FreqKV, Meta-Soft, AnTKV) but has not yet been tied to agentic-memory eval — nobody is measuring what a 4-bit KV cache does to LoCoMo/LongMemEval on Qwen3-8B. This is a natural piece of local-first work.
- claude-mem crossed ~46-65K stars and hit v12.6.4 (May 2026) under AGPL-3.0 — the pragmatic "capture everything, compress, replay" pattern is now the dominant OSS approach for coding-agent memory, but there is no controlled benchmark comparing it to Letta/mem0/MemOS on the same task.
