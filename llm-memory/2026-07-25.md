# LLM Memory — 2026-07-25

## Summary

The May–July 2026 cycle was dominated by **evaluation and critique
papers** rather than new frameworks. MemFail, MemTrace, MINTEval,
MemoryArena, LongMemEval-V2, and MemLens all attack the same problem:
existing memory benchmarks report aggregate QA accuracy and miss where
memory systems actually break (retrieval misalignment, interference,
cross-session drift, visual fidelity under compression, coupled
memorize-then-act settings). A CMU/MBZUAI paper ("Beyond Perplexity")
also directly critiques test-time-training claims — a shot across the
bow of the Titans/MIRAS line. On frameworks, **MemOS** shipped weekly
v2.0.19–v2.0.25 with a fully on-device plugin, **supermemory**
open-sourced a self-hostable server with pluggable local embeddings,
and **mem0**'s Node SDK v3.1.0 added 17 vector stores and 5 LLM
providers. New architectural ideas worth reading are **MeMo** (a
separate small memory model with a frozen executive LLM), **MemForest**
(parallel-extracted hierarchical temporal index), **MemoPilot**
(multi-turn GRPO over a frozen LLM's memory-update policy), and
**C²KV** (composable KV-cache reuse). Google Cloud published **OKF
v0.1**, a vendor-neutral Markdown spec for portable agent knowledge,
and Anthropic launched **Dreaming** for Managed Agents — background
consolidation during idle time that Letta/mem0 will almost certainly
copy. A parallel security thread appeared: FARMA and the "Always-On
Agents" survey (AOEP-v0) both flag persistent memory as an emerging
attack surface.

## MeMo — Memory as a Model

- Source: <https://arxiv.org/abs/2605.15156>
- Date: 2026-05-14 (NUS / MIT CSAIL / A*STAR / SMART)

### Why it matters for local models

MeMo trains a small dedicated Memory model on synthesized reflection
QA from a target corpus; a **frozen** Executive LLM queries it through
a 3-stage protocol. No LLM weight access, no logits required — so it
composes with any open or closed backbone. Retrieval cost is
**independent of corpus size** at inference time, which is a big deal
for local deployments where re-embedding growing histories is the
bottleneck.

### In-depth insights

- Evaluated on BrowseComp-Plus, NarrativeQA, MuSiQue.
- Robust to retrieval noise; avoids catastrophic forgetting.
- Because the LLM is frozen, this is the closest 2026 has come to a
  clean "memory as a plug-in module" pattern that a llama.cpp /
  vLLM / SGLang user can drop in front of an existing serving stack.

## MemForest — Hierarchical Temporal Memory with Parallel Extraction

- Source: <https://arxiv.org/abs/2605.23986>
- Code: <https://github.com/Concyclics/MemForest>
- Date: 2026-05-16 (NUS + Zero Gravity Labs)

### Why it matters for local models

Breaks the "sequential extraction" bottleneck: memory chunks are
extracted in parallel and organized as time-ordered trees rather than
flat global summaries. Useful for local stacks where LLM calls to
build the memory index are the dominant cost.

### In-depth insights

- **79.8% pass@1 on LongMemEval-S** — best among stateful baselines
  at the time of publication.
- Trees are per-time-window, which makes eviction and re-indexing
  trivially local operations.

## MemoPilot — Test-Time RL over a Frozen LLM's Memory Policy

- Source: <https://arxiv.org/abs/2606.08656>
- Date: 2026-06-07

### Why it matters for local models

Trains the **memory-update policy** with multi-turn GRPO while keeping
the LLM itself frozen. The "memory copilot" is the trained artifact,
so this is a clean fit for open-weight backbones you don't want to
fine-tune.

### In-depth insights

- Elo 1762 (Limit Hold'em) and 1590 (Rock-Paper-Scissors) — beats
  DeepSeek-V3.2 and all baseline memory methods in-game.
- Introduces a turn-wise reward and a context-independent turn-level
  advantage estimator.
- Establishes a template ("train a small memory-policy model on top of
  a frozen backbone") that Letta/mem0-style frameworks could plausibly
  integrate as a swappable policy component.

## MemPro — Memory Systems as Evolvable Programs

- Source: <https://arxiv.org/abs/2606.00619>
- Code: <https://github.com/wanghai673/MemPro>
- Date: 2026-05-30

### Why it matters for local models

Treats the whole memory construction + retrieval pipeline — not just
the memory bank — as an evolvable program with a version tree.
Failure-mode-guided edit-debug refinement. For local deployments,
this is the first published attempt to *evolve* the memory stack in
place rather than hand-tuning a hierarchy.

### In-depth insights

- Beats static and prompt-level-evolving baselines on LongMemEval,
  LoCoMo, HotpotQA, and NarrativeQA.
- Because evolution is program-level, the released artifact is a
  concrete set of pipelines rather than weights — reproducible on
  local hardware.

## MemFail — Stress-Testing Memory Failure Modes

- Source: <https://arxiv.org/abs/2605.26667>
- Code (MIT): <https://github.com/ishirgarg/MemFail>
- Date: 2026-05 (Garg, Kolhe, Song, Zhao — UC Berkeley)

### Why it matters for local models

Formalizes memory systems as summarization + storage + retrieval and
provides 5 adversarial datasets across 4 tasks to attribute errors to
specific operations. Practical value: when your local stack fails,
this is how you find out *which* stage is at fault.

### In-depth insights

- Evaluates 4 SOTA memory systems.
- Complements MemTrack from the previous cycle by focusing on the
  operational decomposition rather than the state-tracking axis.

## MemTrace — Tracing and Attributing Memory Errors

- Source: <https://arxiv.org/abs/2605.28732>
- Code (MIT): <https://github.com/zjunlp/MemTrace>
- Date: 2026-05-27 (ZJU-NLP)

### Why it matters for local models

Executable memory-evolution graphs to trace failures across
Long-Context, RAG, Mem0, and EverMemOS. Attribution is automatic and
feeds back into prompt optimization.

### In-depth insights

- MemTraceBench collected from four production-shaped configurations.
- Reports up to **+7.62% end-task lift** when the attribution signal
  is fed back into a closed prompt-optimization loop.

## MINTEval / LongMINT — Long-Horizon Memory under Interference

- Source: <https://arxiv.org/abs/2605.18565>
- Code: <https://github.com/amy-hyunji/MINTEval>
- Date: 2026-05 (UNC — Lee, Chen, Singh, Khan, Stengel-Eskin, Bansal)

### Why it matters for local models

The most punishing published long-context / long-history benchmark to
date: **15.6k QA pairs**, contexts averaging **138.8k** tokens and
running up to **1.8M**. Best system: **33.4% avg accuracy** — far
from saturated. If you're claiming your local memory stack "handles
long context," this is the benchmark that will refute it.

### In-depth insights

- Four domains: state tracking, multi-turn dialogue, Wiki revisions,
  Git commits.
- Interference is the axis: every question has plausible distractors
  from earlier state that a naive RAG will retrieve.

## LongMemEval-V2 — Agent Memory in Web Environments

- Source: <https://arxiv.org/abs/2605.12493>
- Site: <https://xiaowu0162.github.io/longmemeval-v2/>
- Code: <https://github.com/xiaowu0162/LongMemEval-V2>
- Date: 2026-05

### Why it matters for local models

Shifts LongMemEval from *user-history* to *environment-experience*
memory. 451 questions with trajectories of **25M–115M tokens** over
customized Magento shopping, forum, and ServiceNow-style
environments — memory that a local agent must maintain over long
sessions in a real UI.

### In-depth insights

- Five abilities: static state recall, dynamic state tracking,
  workflow knowledge, environment gotchas, premise awareness.
- Answers the criticism that LongMemEval-v1 was too dialogue-centric.

## MemoryArena — Interdependent Multi-Session Agent Memory

- Source: <https://arxiv.org/abs/2602.16313v1>
- Site: <https://memoryarena.github.io/>
- Data (701 tasks): <https://huggingface.co/datasets/ZexueHe/memoryarena>
- Date: Feb 2026 arXiv, cited heavily May–July 2026

### Why it matters for local models

Agents that near-saturate LoCoMo perform **poorly** here — the
benchmark exposes the evaluation gap in coupled memorize-then-act
settings. Include when comparing frameworks; expect the gap between
"filesystem baseline" and "fancy memory" to be much larger than on
LoCoMo.

## MemLens — Multimodal Long-Term Memory Benchmark

- Source: <https://arxiv.org/abs/2605.14906>
- Date: 2026-05-14

### Why it matters for local models

The first serious multimodal long-term memory benchmark. Long-context
LVLMs win at short contexts but degrade with length; memory agents
are length-stable but lose **visual fidelity** under storage
compression. This defines the tradeoff local multimodal stacks now
have to argue about.

### In-depth insights

- 789 questions, 5 memory abilities, contexts from 32K to 256K
  tokens.
- 27 LVLMs + 7 memory agents evaluated.
- Ablation: removing evidence images drops frontier LVLMs below **2%**
  accuracy — a strong signal against text-only compression of visual
  histories.

## Beyond Perplexity — Behavioral Eval for Test-Time-Training Memory

- Source: <https://arxiv.org/abs/2607.00368>
- Date: 2026-07-01 (CMU + MBZUAI — Song, Zhang)

### Why it matters for local models

Direct critique of Titans/MIRAS-style test-time-training memory
papers, which rely on perplexity/loss as proxies for "deployed
memory." Introduces a claim-calibrated evidence ladder plus matched
explicit-memory baselines: paraphrase robustness, retention, locality,
conflict handling. If you are choosing between a TTT-style memory
approach and an explicit-memory framework for a local deployment,
this is the paper that tells you what to measure.

## MemMachine — Ground-Truth-Preserving Memory

- Source: <https://arxiv.org/html/2604.04853v1>
- Date: late April 2026 (heavy May–July uptake)

### Why it matters for local models

Stores **raw episodes** and minimizes routine LLM extraction — a
counter-current to the "always compress" school. Contextualized
retrieval that expands nucleus matches. Reports **~80% fewer input
tokens than Mem0** while landing at 0.9169 on LoCoMo with
gpt-4.1-mini. 93.0% on LongMemEval-S with retrieval-stage
optimizations. For local models where inference cost dominates, the
"store more, extract less" tradeoff is directly relevant.

## From Storage to Experience — Evolutionary Memory Survey

- Source: <https://arxiv.org/abs/2605.06716>
- Companion list: <https://github.com/FeishuLuo/Evolving-LLM-Agent-Memory-Survey>
- Date: 2026-05-07 (ACL 2026 Findings)

### Why it matters for local models

Proposes a 3-stage evolutionary framework (Storage → Reflection →
Experience) and reviews active-exploration + cross-trajectory
abstraction as the frontier. A useful indexing document for what to
read next; the companion GitHub is regularly updated.

## C²KV — Composable KV-Cache Reuse

- Source: <https://arxiv.org/abs/2607.17715>
- Code: <https://github.com/s7a9/C2KV>
- Date: 2026-07 (KDD 2026)

### Why it matters for local models

Existing KV compression schemes produce caches that are tightly
coupled to their original context — non-composable, so you cannot
reuse them across sessions. C²KV separates sequence-level compression
from layer/head-dependent selection, which makes composed reuse
possible. Directly relevant to any local stack that wants persistent
KV as a memory substrate (see LMCache below).

## Framework releases

### MemOS 2.0.19–2.0.25

- Releases: <https://github.com/MemTensor/MemOS/releases>
- Paper (updated): <https://arxiv.org/abs/2507.03724>
- Dates: 2026-06-12 through 2026-07-24 (roughly weekly)

Weekly-cadence release train. Highlights:

- **Local plugin**: 100% on-device SQLite + hybrid FTS5 / vector
  search — no cloud dependency.
- Preference-memory model independence.
- Configurable CJK tokenization.
- Data export from the memos-local variant.
- Reports **88.83 LoCoMo / 89.20 LongMemEval**; agent tasks in the
  OpenClaw suite improved from **36.63% → 50.87%** average.

### supermemory — self-hosted server

- Releases:
  <https://github.com/supermemoryai/supermemory/releases>
- Dates: 2026-06-04 → 2026-07-22 (0.0.1-rc.6 → 0.0.7-rc.2)

Notable in the window:

- **2026-07-10 (v0.0.5)**: pluggable embeddings for self-hosted —
  local ONNX or remote (OpenAI / Google).
- **2026-07-19 (v0.0.6)**: Windows self-hosted server.
- **2026-07-22 (0.0.7-rc.2)**: self-hosted large-document ingestion.
- Reported **95% Recall@15**; aggregation adds only ~720 tokens
  (99.4% context reduction on the tested workload).
- MemoryBench evaluation framework remains open source and is the
  most self-contained way to A/B memory frameworks on a local model.

### mem0 SDK expansion

- Releases: <https://github.com/mem0ai/mem0/releases>

Windowed highlights:

- **Node SDK v3.1.0 (2026-07-13)** — **17 new vector stores**, 5 new
  LLM providers, 4 new embedders, reranking.
- Python v2.0.13.
- OpenCode plugin v0.2.2 (2026-07-22) — see the agent-harness report
  for context.

The Node-side expansion in particular is a large multiplier for local
stacks: the friction of pointing mem0 at whatever local vector store
you already run is now near-zero.

### Cognee v1.4.0

- Source: <https://github.com/topoteretes/cognee/releases>
- Date: 2026-07-17 (Apache 2.0)

Self-hostable knowledge-graph memory. v1.4.0 adds a dataset-level
overview index, faster large-file ingestion, improved search
ranking, and 14 retrieval modes. Still one of the strongest choices
when you specifically want a *graph* memory backend rather than
vector-only.

## Infrastructure & standards

### OKF v0.1 — Open Knowledge Format (Google Cloud)

- Announcement (June 2026)
- Coverage:
  <https://www.marktechpost.com/2026/06/16/google-cloud-introduces-open-knowledge-format-okf-a-vendor-neutral-markdown-spec-for-giving-ai-agents-curated-context/>

Vendor-neutral Markdown-with-YAML-frontmatter spec: every concept is
one file. Formalizes Karpathy's "LLM Wiki" pattern into something
portable across agents; there is no proprietary lock-in. For local
users, this is the first credible interchange format for hand-curated
memory / knowledge bundles. Adoption outside Google's own tools is
still an open question.

### Anthropic "Dreaming" for Managed Agents

- Source: <https://claude.com/blog/new-in-claude-managed-agents>
- Date: 2026-05-06 (Code with Claude event)

Closed today, but the pattern is reproducible: background memory
consolidation during idle time — merge duplicates, prune stale
entries, extract cross-session patterns. Harvey (legal AI) reports
**6× task-completion gain**. Watch Letta / mem0 / MemOS for an open
equivalent; a "Dreaming" pass over MemOS's local plugin is the
obvious next step.

### LMCache — production-tier KV-cache substrate

- Blog: <https://blog.lmcache.ai/en/2026/06/02/a-new-chapter-for-lmcache-and-the-kv-cache-community/>
- Repo: <https://github.com/lmcache/lmcache>

Community/production milestone announced 2026-06-02: multi-node P2P
CPU-memory sharing moved from experimental to production earlier in
the year. Storage backends include CPU RAM, local disk, Redis /
Valkey, Mooncake, S3, GDS. 220+ contributors. Read together with
C²KV — LMCache is where the KV-as-memory idea actually gets to run
in a local cluster.

### NVIDIA Nemotron 3

- Announcement:
  <https://nvidianews.nvidia.com/news/nvidia-debuts-nemotron-3-family-of-open-models>
- Tech blog:
  <https://developer.nvidia.com/blog/inside-nvidia-nemotron-3-techniques-tools-and-data-that-make-it-efficient-and-accurate/>
- Date: 2026-06-04

550B MoE (55B active/token), **1M context window**, native NVFP4
4-bit checkpoint. Nemotron 3 Super is hybrid Mamba-Transformer MoE;
Nemotron 3 Nano is tuned for agentic reasoning at 1M context. All
open weights. Not a "memory system" per se, but 1M native context on
open weights changes the baseline any memory framework must beat.

## Security & governance

### FARMA — Forged Amplifying Rationale Memory Attack

- Source: <https://arxiv.org/abs/2607.05029>
- Date: 2026-07

Poisons an agent's remembered **reasoning** rather than factual
knowledge — a new attack surface local memory frameworks (Letta,
mem0, MemOS) need to defend against. Persistence turns a one-shot
compromise into a permanent behavioral change.

### Always-On Agents Survey & AOEP-v0

- Source: <https://arxiv.org/abs/2606.30306>
- Date: 2026-06

435-work coded corpus. Six diagnostic axes for persistent-memory
agents: authority, scope, mutability, provenance, recoverability,
actionability. Introduces AOEP-v0 (Always-On Evaluation Protocol),
which scores state-mutation and recovery obligations — not just
answer quality. Complements FARMA on the defensive side.
