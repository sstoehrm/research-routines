# LLM Memory — 2026-05-30

## Summary

The five weeks since the last report were dominated by a wave of new
benchmarks (Memora/FAMA, GroupMemBench, SocialMemBench) that move the
field beyond LongMemEval/LoCoMo-style single-user fact recall toward
forgetting-aware, multi-party, and social-group evaluation — and they
show today's open frameworks (Mem0, Zep/Graphiti, LangMem, Cognee)
clustering far below full-context baselines. On the framework side,
**Mem0** shipped its first explicit recency/decay primitive and a
`delete_linked` SDK, **MemOS** pushed three v2.0.x point releases
adding a hook-based plugin system and Reflect2Evolve, and
**Supermemory** publicly claimed ~99% on LongMemEval_s by replacing
vector search with an active search agent. New arXiv papers cluster
around two themes: self-evolving / AutoResearch-driven memory
architectures (EvolveMem, Omni-SimpleMem v2) and biologically-motivated
consolidation (TriMem, Microsoft's Human-Inspired Memory Architecture).
The Titans / MIRAS official open-source release is still scheduled for
Q4 2026; lucidrains' unofficial PyTorch port remains the only practical
option for local experimentation. **Mamba-3** (ICLR 2026 oral) has
direct implications for persistent-state-in-SSM thinking even if not
branded as "memory."

## EvolveMem — Self-Evolving Memory via AutoResearch

- Source: <https://arxiv.org/abs/2605.13941>
- Code: <https://github.com/aiming-lab/SimpleMem/blob/main/EvolveMem/README.md>
- Date: 2026-05

### Why it matters for local models

The first openly described system where the *retrieval pipeline itself*
(scoring fusion, signal weights, even new configuration dimensions) is
autonomously evolved by an LLM-driven diagnostic loop rather than
hand-tuned. For local-model setups that can't afford manual sweeps,
this is the closest thing to AutoML for memory — and the diagnoser can
run on a smaller LLM than the primary agent.

### In-depth insights

- Wraps a per-question failure-log reader that proposes targeted
  configuration adjustments with a guarded meta-analyzer (auto-revert
  on regression, explore on stagnation).
- Reported gains: +25.7% relative over the strongest baseline on
  LoCoMo and +18.9% on MemBench, starting from a minimal baseline that
  itself improves by +78% relative through self-evolution.
- Released as part of the SimpleMem repo (Apache 2.0).
- Limitation: the diagnostic loop uses LLM calls and adds wall-clock
  cost during the evolution phase.

## Omni-SimpleMem v2 — Autoresearch-Guided Multimodal Memory

- Source: <https://arxiv.org/abs/2604.01007>
- HF paper page: <https://huggingface.co/papers/2604.01007>
- Repo: <https://github.com/aiming-lab/SimpleMem>
- Date: 2026-04-02 (v0.2.0 multimodal release)

### Why it matters for local models

First open-source memory system that handles text + image + audio +
video uniformly, discovered by the same AutoResearch flow as EvolveMem.
The "memory abstraction unit" (MAU) abstraction plus hybrid
dense-sparse-graph retrieval with pyramid expansion is straightforward
to bolt onto a local VLM stack.

### In-depth insights

- Pipeline filters multimodal inputs for novelty, compresses to MAUs,
  retrieves via dense + sparse + graph fusion.
- The autonomous research loop ran ~50 experiments across two
  benchmarks, fixing data-pipeline bugs and proposing architectural
  changes without human intervention.
- Reported jumps on LoCoMo F1 from 0.117 → 0.598 (+411%) and
  Mem-Gallery +214%. The mem0 ecosystem blog quotes more conservative
  numbers (LoCoMo F1=0.613 +47%, Mem-Gallery F1=0.810 +51%) — likely
  under different comparison conditions; **verify against the actual
  paper tables before citing**.
- Code Apache-style under aiming-lab/SimpleMem.

## TriMem — Rethinking How to Remember

- Source: <https://arxiv.org/abs/2605.19952>
- Project page: <https://tmlr-trimem.github.io/>
- Date: 2026-05

### Why it matters for local models

Direct critique of the "extract atomic facts and throw away the
dialogue" pattern that mem0 / Zep / LangMem all use. TriMem keeps three
coexisting granularities (raw segments, atomic facts, synthesized
profiles) and uses TextGrad to evolve the extraction prompts at run
time. This is a drop-in conceptual change for any local memory backend
without parameter updates.

### In-depth insights

- Three granularities: raw dialogue segments anchored by source IDs
  (fidelity), atomic facts (retrieval efficiency), synthesized profiles
  (deep reasoning).
- Extraction and profiling prompts iteratively refined via TextGrad
  with response-quality feedback.
- Evaluated on LoCoMo and PerLTQA across multiple backbones; claims
  consistent gains over strong baselines. Specific deltas not stated in
  available excerpts — verify in the PDF.
- Project page exists; code release status unverified.

## Memora benchmark + FAMA metric

- Source: <https://arxiv.org/abs/2604.20006>
- Date: 2026-04 (late April)

### Why it matters for local models

Most current open memory frameworks are tuned for "find the fact in
the past" — Memora measures the opposite: do they correctly *forget*
invalidated facts? This is the right benchmark to evaluate Mem0's
brand-new Memory Decay feature against.

### In-depth insights

- Weeks-to-months synthetic user conversations covering three tasks:
  remembering, reasoning, recommending.
- Introduces **Forgetting-Aware Memory Accuracy (FAMA)** which rewards
  correct use of valid memory and penalizes reliance on obsolete or
  deleted memory.
- Evaluation of 4 LLMs and 6 memory agents shows "frequent reuse of
  invalid memories and failures to reconcile evolving memories" —
  i.e. the existing leaderboard ordering on LongMemEval does **not**
  carry over.
- Data quality enforced via automated memory-grounding checks plus
  human eval. Code/dataset release status unverified.

## GroupMemBench + SocialMemBench

- Sources: <https://arxiv.org/abs/2605.14498>,
  <https://arxiv.org/abs/2605.17789>
- Date: 2026-05 (May 19 and May 23, approximately)

### Why it matters for local models

Both benchmarks expose the dyadic-conversation assumption baked into
Mem0 / Zep / LangMem / Cognee. For local deployments targeting team
chat, Discord/Slack assistants, or family/household agents, these are
the first targeted evaluations.

### In-depth insights

- **GroupMemBench** measures three properties:
  1. group dynamics beyond concatenated one-on-one chats,
  2. speaker-grounded belief tracking,
  3. audience-adapted language (Theory-of-Mind effects on vocabulary).
  Uses a graph-grounded synthesis pipeline conditioning messages on
  per-user personas and target audiences.
- **SocialMemBench** spans five social archetypes (close friends,
  family, recreational, interest community, acquaintance) and three
  group sizes (4–30 members), 430 personas / 348 sessions /
  7,355 turns / 1,031 QA pairs.
- Reference numbers: a full-context Gemini 2.5 Flash only reaches
  0.721 vs a blind-critic mean of 0.98 on small networks — benchmark
  is hard even with full access.
- Across 43 networks the four open frameworks (Mem0, LangMem,
  Graphiti, Cognee) cluster at **0.12–0.18 question-weighted score**
  with overlapping 95% CIs, vs an uncompressed retrieval reference of
  0.345 and a matched full-context GPT-4o-mini reference of 0.369.
  Clear "current generation is not ready for groups" message.

## Human-Inspired Memory Architecture for LLM Agents (Microsoft)

- Source: <https://arxiv.org/abs/2605.08538>
- Date: 2026-05-08

### Why it matters for local models

A blueprint for a memory backend that runs entirely offline cycles
(sleep-phase consolidation every ~6 hours by default) and has clear
ablation results on a realistic developer dataset.

### In-depth insights

- Six cognitive mechanisms:
  1. **sleep-phase consolidation** modeling biological sharp-wave
     ripples via scheduled batch processing,
  2. **interference-based forgetting**,
  3. **engram maturation** — newly integrated memories start in a
     "silent" low-activation state,
  4. **reconsolidation upon retrieval**,
  5. **entity knowledge graphs**,
  6. **hybrid multi-cue retrieval**.
- Synthetic calibration methodology derives all pipeline thresholds
  without exposing benchmark data — directly addresses the
  benchmark-leakage critique from arXiv:2510.27246 in the prior report.
- On a VSCode issue-tracking dataset (13K issues, 120K events):
  **97.2% retention precision with 58% store reduction** via
  deduplication-based consolidation.
- Code/license status unverified.

## Mem0 — Memory Decay + Token-Efficient Algorithm

- Sources: <https://mem0.ai/blog/introducing-memory-decay-in-mem0>,
  <https://github.com/mem0ai/mem0/releases>
- Date: April 2026 (token-efficient algorithm) and 2026-05-08 (Memory
  Decay)

### Why it matters for local models

First explicit recency-aware re-ranking primitive shipped in a
mainstream open memory layer. The April algorithm changes are
particularly relevant for self-hosted deployments because they remove
the per-turn UPDATE/DELETE LLM calls — a real cost on local hardware.

### In-depth insights

- **April algorithm**: single-pass ADD-only extraction (no per-turn
  UPDATE/DELETE), entity linking, multi-signal retrieval that fuses
  semantic similarity + BM25 + entity matching. Largest gains over
  previous Mem0 algorithm: temporal queries +29.6 points, multi-hop
  reasoning +23.1 points (baseline is Mem0's own previous version).
- **Memory Decay (May 8)**: recency-aware ranking — recently accessed
  memories get a soft boost, idle memories drift lower. Configurable;
  opt-in.
- **SDK churn (May 7–28)**: Python v2.0.2–2.0.4, Node v3.0.4–3.0.5 add
  `delete_linked` / `deleteLinked` (transitive removal of superseded
  memories), richer PGVector filter operators
  (`eq, ne, gt, gte, lt, lte, in, nin, contains`), security fixes
  against SQL / prompt injection, a new `mem0 whoami` CLI command, and
  a first OpenCode plugin (v0.1.1).
- 41K GitHub stars / 14M downloads as of May 2026. Apache-2.0.

## Supermemory — ~99% on LongMemEval_s + Tools v2.0

- Sources:
  <https://blog.supermemory.ai/we-broke-the-frontier-in-agent-memory-introducing-99-sota-memory-system/>,
  <https://supermemory.ai/blog/introducing-supermemory-tools-v2-0-0/>,
  <https://github.com/supermemoryai>
- Date: 2026-04-27 (tools v2.0.0); late April / early May (99% blog)

### Why it matters for local models

They ditched vector embeddings entirely in favor of an "active search
agent" — i.e. a tool-using LLM that drives retrieval. If the approach
generalizes, it gives smaller local models a path to long-memory
competence that doesn't require a fancy embedding stack; the trade-off
is more LLM calls per query.

### In-depth insights

- Self-reported ~99% on LongMemEval_s (115k+ token conversation
  histories, contradictory information, cross-session events).
- Explicitly described as an *experimental agentic flow*, not
  production. Baselines and exact comparison conditions are not fully
  transparent — **treat the headline as marketing-adjacent until
  independently replicated**.
- supermemory/tools v2.0.0 unified the API across AI SDK, Mastra,
  Claude Code, OpenClaw; made conversation identity a first-class
  concept; `addMemory` now defaults to `always`.
- TypeScript SDK updated 2026-05-29, Python SDK 2026-05-22.
- License: open repos under supermemoryai org (mix of MIT / Apache —
  verify per package).

## MemOS v2.0.15 / v2.0.16 / v2.0.17 (MemTensor)

- Source: <https://github.com/MemTensor/MemOS/releases>
- Date: 2026-05-11, 2026-05-19, 2026-05-26

### Why it matters for local models

MemOS is explicitly positioned as a "self-evolving memory OS" with
local plugins; the v2.0.15 introduction of a hook-based plugin system
makes it the easiest of the OS-style memory frameworks to extend
without forking. The May 9 memos-local-plugin 2.0 announcement targets
Hermes Agent / OpenClaw — both runnable fully on-device.

### In-depth insights

- **v2.0.15 (May 11)**: hook-based plugin system, Reflect2Evolve
  architecture inside memos-local-plugin, per-turn memory grouping,
  "hermes thinking capture," native memory import flows, overview
  dashboard upgrades.
- **v2.0.16 (May 19)**: renamed `web → viewer`, added reranker and
  `mem_feedback` test coverage.
- **v2.0.17 (May 26)**: Hermes viewer probe, node resolution, bridge
  hardening, "lightweight memory mode," memory self-evolution opt-in,
  refinements to reflection synthesis and skill triggering.
- Cloud-plugin claim from earlier release notes: 72% lower token usage
  and multi-agent memory sharing.

## Letta — Sleep-time Compute Formalized

- Source: <https://www.letta.com/blog/sleep-time-compute>
- Docs: <https://docs.letta.com/guides/agents/architectures/sleeptime/>
- Date: 2026-05-06

### Why it matters for local models

Letta is making "sleep-time compute" a first-class concept: a
background agent that shares a memory block with the foreground agent
and asynchronously reorganizes memory. For local stacks this neatly
maps to overnight batch jobs that consolidate the day's interactions
without blocking inference latency.

### In-depth insights

- Sleep-time agents are a multi-agent architecture where all agents
  share one or more memory blocks. They produce "learned context" via
  reflection on prior conversations or codebases.
- Operationally distinct from MemGPT's bundled approach because memory
  management runs out-of-band.
- Tied to Letta's earlier Context Repositories announcement
  (git-versioned memory in Letta Code).
- Note: WebFetch was blocked by Letta's site; date confirmed via
  secondary sources but worth verifying.

## Mamba-3 (ICLR 2026 oral)

- Source: <https://arxiv.org/abs/2603.15569>
- ICLR 2026 oral: <https://iclr.cc/virtual/2026/oral/10010353>
- OpenReview: <https://openreview.net/forum?id=HwCvaJOiCj>
- Date: arXiv 2026-03-16; ICLR 2026 oral presentation

### Why it matters for local models

Not branded as "memory" but it is. Mamba-3 halves the state size
needed to match Mamba-2 perplexity — directly a memory-efficiency win
for long-context local inference — and the MIMO variant gives +1.8
points downstream accuracy at 1.5B. Relevant for anyone considering an
SSM as the substrate for a persistent-state agent.

### In-depth insights

- Three improvements:
  1. trapezoidal discretization replacing Euler's method,
  2. complex-valued state update enabling richer state tracking,
  3. MIMO formulation that increases arithmetic intensity without
     raising decode latency.
- At 1.5B: +0.6 pts avg downstream over Gated DeltaNet; MIMO variant
  +1.2 more for +1.8 total.
- Comparable perplexity to Mamba-2 with **half the state size**.
- Princeton PLI authors. Open-weights / code expected on the lab's
  usual cadence — verify.

## Other notable May 2026 arXiv posts (flagged, not deeply expanded)

- **From Storage to Experience: A Survey on the Evolution of LLM Agent
  Memory Mechanisms** — <https://arxiv.org/abs/2605.06716> (May 7).
  Three-stage evolutionary framework (Storage → Reflection →
  Experience). Repo:
  <https://github.com/FeishuLuo/Evolving-LLM-Agent-Memory-Survey>.
- **A Survey on the Security of Long-Term Memory in LLM Agents:
  Toward Mnemonic Sovereignty** — <https://arxiv.org/abs/2604.16548>
  (Apr 17). Six-phase memory lifecycle
  (Write / Store / Retrieve / Execute / Share / Forget-Rollback) × four
  objectives (integrity, confidentiality, availability, governance).
  Important for production threat-modeling.
- **MemMachine** — <https://arxiv.org/abs/2604.04853>,
  <https://github.com/MemMachine/MemMachine>. Apache-2.0
  "ground-truth-preserving" memory system from MemVerge. LoCoMo
  0.9169 with gpt-4.1-mini; LongMemEval 93.0% overall; claims ~80%
  fewer input tokens than Mem0 in matched mode.
- **δ-mem: Efficient Online Memory for LLMs** —
  <https://arxiv.org/abs/2605.12357>.
- **Thinking Ahead: Prospection-Guided Retrieval (PGR)** —
  <https://arxiv.org/abs/2605.14177>. Decouples retrieval from how
  memories are stored.
- **Is Agent Memory a Database? (Governed Evolving Memory / GEM)** —
  <https://arxiv.org/abs/2605.26252>. State-level operators
  (ingestion, revision, forgetting, retrieval) replacing record-level
  CRUD.
- **MemIR — typed memory representation** —
  <https://arxiv.org/abs/2605.25869>. Treats source-monitoring as a
  structural constraint to address "provenance-role collapse."
- **Memory in the LLM Era: Modular Architectures and Strategies in a
  Unified Framework** — <https://arxiv.org/abs/2604.01707> (Apr 2).
  Modular architecture survey + benchmark.
