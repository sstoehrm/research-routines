# LLM Memory — 2026-06-06

## Summary

Since the 2026-04-23 report, the field has moved from "memory plumbing"
to two distinct frontiers. First, evaluation has matured: ICLR 2026 ran
the MemAgents workshop on April 27, two new benchmarks
(MemoryAgentBench at ICLR 2026, MemoryArena at ICML 2026) replaced
single-pass long-context tests, and Arc Computer's CL-Bench
(arXiv 2606.05661, June 4) showed that dedicated memory frameworks
(Mem0, Zep, Letta-style) can actually underperform naive in-context
learning on stateful tasks. Second, open-source memory architectures
are explicitly competing with closed offerings: mem0's new
token-efficient algorithm reaches 91.6 on LoCoMo / 93.4 on LongMemEval
at ~7K tokens/call; LightMem (ICLR 2026) cuts tokens 117× on
LongMemEval using a sleep-time consolidation loop on Qwen and GPT
backbones; MemTensor's MemOS shipped a v2 local plugin for
Hermes/OpenClaw on May 9; and Letta refocused around git-versioned
"Context Repositories" with Letta Code as its open runtime. On the
architecture side, NVIDIA showed (Feb 2026, arXiv 2602.21204) that
Titans-style test-time training with KV-binding reduces to learned
linear attention, and follow-ups GradMem (2603.13875) and SR-TTT
(2603.06642) push gradient-based test-time memory writes onto open
backbones. Memory security has crystallized as a sub-field with
MPBench (2606.04329), MemLineage (2605.14421), and a survey on
"mnemonic sovereignty" (2604.16548). Note also that Anthropic shipped
"Dreaming" for Claude Managed Agents on May 6 — closed-model, but it's
the architectural reference that open implementations are now chasing.

## CL-Bench: Continual Learning Bench (Arc Computer)

- Source: <https://arxiv.org/abs/2606.05661>,
  <https://github.com/Arc-Computer/CL-Bench>,
  <https://continual-learning-bench.com/>
- Date: 2026-06-04

### Why it matters for local models

This is the first benchmark designed to actually isolate "did the
agent learn online" from "did a strong base model already know it" —
and the headline result is that purpose-built memory systems (mem0,
Zep, Letta-style harnesses) do not beat naive in-context learning on
six expert-validated stateful domains (software engineering, signal
processing, outbreak forecasting, DB querying, strategy games, demand
forecasting). For local-model users, this is a strong signal that
swapping in a memory framework is not a free win and that evaluation
on a benchmark like CL-Bench should precede deployment.

### In-depth insights

- Introduces a "gain" metric that subtracts stateless capability from
  stateful capability, so a memory system only scores by what it adds.
- Tasks are designed so a shared latent structure can be discovered
  online; stateless agents can't access it.
- Frontier models tested across architectures from naive ICL to
  dedicated memory systems; finding: agents frequently overfit
  immediate observations and fail to reuse knowledge across instances.
- Code MIT-licensed, runs against any model with the appropriate API
  client; useful as a regression harness for Llama/Qwen-based stacks.

## mem0 Token-Efficient Memory Algorithm — Temporal-Reasoning Upgrade

- Source:
  <https://mem0.ai/blog/mem0-the-token-efficient-memory-algorithm>,
  <https://mem0.ai/blog/the-token-efficient-memory-algorithm-now-has-temporal-reasoning>,
  <https://github.com/mem0ai/mem0>
- Date: April 2026 (initial); temporal-reasoning update May 2026.

### Why it matters for local models

mem0 is one of the few production memory systems with first-class
local/self-hosted support (Ollama, vLLM, local vector stores). The
new algorithm replaces multi-pass LLM extraction with single-pass
hierarchical extraction plus multi-signal retrieval, halving
extraction latency — meaningful when the extractor is a small local
model.

### In-depth insights

- Reported numbers: 91.6 on LoCoMo (+20 over previous mem0), 93.4 on
  LongMemEval (+26), with <7K tokens per retrieval call vs. 25K+ for
  full-context baselines.
- Largest gains on temporal queries (+29.6) and multi-hop reasoning
  (+23.1).
- Algorithm published openly via mem0.ai/research; underlying paper at
  <https://arxiv.org/abs/2504.19413> (ECAI 2025) established the
  head-to-head methodology now used.
- Apache-2.0 codebase; 21 framework integrations, 20 vector-store
  backends, local-MCP hosting model supported.

## LightMem (ICLR 2026): Sleep-Time Memory Consolidation on Open Backbones

- Source: <https://arxiv.org/abs/2510.18866>,
  <https://github.com/zjunlp/LightMem>
- Date: arXiv Oct 2025; accepted ICLR 2026; code active through May 2026.

### Why it matters for local models

LightMem is one of the cleanest demonstrations that a small-model +
sleep-time-consolidation pipeline can beat much more expensive setups
on the standard memory benchmarks — and the eval explicitly uses Qwen
backbones, not just GPT. The "sleep-time" loop decouples consolidation
from online inference, so a workstation GPU only sees lightweight
retrieval at query time.

### In-depth insights

- Three-stage Atkinson–Shiffrin-inspired pipeline: sensory filter
  (lightweight compression + topic grouping) → topic-aware short-term
  consolidation → long-term store updated offline.
- LongMemEval results: up to +10.9% accuracy over baselines, 117×
  fewer tokens, 159× fewer API calls, 12× faster runtime.
- Both GPT and Qwen backbones evaluated; Qwen results confirm the
  approach is not GPT-specific.
- Open source under the zjunlp org with reproduction scripts.

## MemoryAgentBench (ICLR 2026) and MemoryArena (ICML 2026)

- Source: <https://arxiv.org/abs/2507.05257>,
  <https://github.com/HUST-AI-HYZ/MemoryAgentBench>,
  <https://arxiv.org/pdf/2602.16313>
- Date: MemoryAgentBench accepted ICLR 2026 (Jan); GPT-5-Mini results
  and MemoryArena ICML acceptance added May 2026.

### Why it matters for local models

MemoryAgentBench is becoming the standard rubric — accurate retrieval
(AR), test-time learning (TTL), long-range understanding (LRU),
conflict resolution (CR) — and it is what new open-source memory
systems are now publishing against. MemoryArena extends evaluation
into multi-session agentic tasks (web nav, preference-constrained
planning) that better reflect real workstation deployments.

### In-depth insights

- MemoryAgentBench reformats RULER, InfBench, HELMET, LongMemEval
  into incremental multi-turn streams and adds two new datasets
  (EventQA, FactConsolidation).
- "Inject once, query many" design makes large evaluations cheap on
  local hardware.
- May 2026 update added GPT-5-Mini numbers and MIRIX as a head-to-head
  baseline.
- MemoryArena (arXiv 2602.16313) embeds memory inside complete
  agentic tasks rather than QA — closer to how Letta/mem0 actually
  get used.
- MIT-licensed; ~350 GitHub stars.

## EvolveMem: Self-Evolving Retrieval Configuration

- Source: <https://arxiv.org/abs/2605.13941>,
  <https://github.com/aiming-lab/SimpleMem/blob/main/EvolveMem/README.md>
- Date: 2026-05-21.

### Why it matters for local models

Most memory frameworks treat the retrieval pipeline (scoring, fusion,
thresholds) as fixed. EvolveMem makes the entire retrieval
configuration a structured action space that an LLM-driven diagnosis
module mutates based on per-question failure logs. Because it
operates above the model, it works with any local backbone you can
call.

### In-depth insights

- Closed-loop "AutoResearch" process with revert-on-regression and
  explore-on-stagnation safeguards.
- +25.7% relative over the strongest baseline on LoCoMo; +78% over
  the minimal baseline; +18.9% over the strongest baseline on
  MemBench.
- Lives in the same aiming-lab/SimpleMem repo alongside the January
  2026 SimpleMem release, so reproducible end-to-end.
- Open source; suitable for Qwen/Llama backbones.

## NVIDIA: Test-Time Training with KV Binding Is Secretly Linear Attention

- Source: <https://arxiv.org/abs/2602.21204>,
  <https://research.nvidia.com/labs/sil/projects/tttla/>
- Date: 2026-02-24 (referenced because it directly reframes the
  Titans/MIRAS lineage covered previously).

### Why it matters for local models

This paper unifies the Titans / TTT / KV-binding family — exactly the
architectures the prior report flagged — into a learned
linear-attention operator. Practically, that means there's a fully
parallel formulation that preserves performance, which removes the
main blocker (slow sequential training) to running Titans-style
memory on a workstation GPU. lucidrains' titans-pytorch was already
at v0.4.22 as of mid-May 2026, and this analysis is the theoretical
justification for further simplifications.

### In-depth insights

- Shows multiple phenomena that contradict the online-meta-learning
  interpretation of TTT-as-memorization.
- Reduces diverse TTT variants (Titans, KV-binding, Mamba-style fast
  weights) to a standard linear attention form.
- Enables parallel training without losing the per-token "memory
  write" semantics.
- Open-source related implementations:
  <https://github.com/lucidrains/titans-pytorch>,
  <https://github.com/engineerA314/atlas-pytorch> — both updated
  through May 2026.

## GradMem and SR-TTT: Gradient-Based Test-Time Memory Writes

- Source: <https://arxiv.org/abs/2603.13875> (GradMem),
  <https://arxiv.org/abs/2603.06642> (SR-TTT)
- Date: March 2026; both with open-source code.

### Why it matters for local models

Both papers push test-time memory updates into open backbones without
requiring the full Titans neural-memory machinery. GradMem only
optimizes a small set of prefix memory tokens; SR-TTT augments a TTT
backbone with a sparse exact-attention "needle" cache so it doesn't
catastrophically forget rare tokens.

### In-depth insights

- GradMem: meta-learned shared initialization → K gradient steps on
  prefix memory tokens produce example-specific memory; model weights
  frozen. Self-supervised context-reconstruction loss replaces
  forward-only memory writes.
- SR-TTT: loss-gated sparse memory routes only "highly surprising"
  (high-surprisal) tokens to an exact-attention residual cache,
  keeping O(1) memory for low-entropy context. Open-source weights
  and training scripts on GitHub.
- Both are training-time-modest enough to run on a single
  workstation.

## MemTensor MemOS v2 Local Plugins for Hermes / OpenClaw

- Source: <https://github.com/MemTensor/MemOS>,
  <https://github.com/MemTensor/MemOS/releases>,
  <https://arxiv.org/abs/2507.03724> (original MemOS paper)
- Date: memos-local-plugin 2.0 released 2026-05-09; v2.0.13 line
  through May 2026.

### Why it matters for local models

MemOS is the most "OS-shaped" of the open memory stacks — MemCubes
encapsulate content plus provenance/versioning across plaintext,
activation, and parameter memories. The May 2026 Hermes Agent Local
Plugin is 100% local, zero cloud dependency, with hybrid FTS5+vector
retrieval, smart dedup, and tiered skill evolution. Reported 35.24%
token savings and a 159% temporal-reasoning improvement vs. OpenAI's
global memory on LoCoMo (from the underlying paper).

### In-depth insights

- Compatible with HuggingFace, OpenAI, and Ollama out of the box.
- v2 split into local plugin (Hermes/OpenClaw) and cloud plugin
  paths; the local one is the relevant target for self-hosted setups.
- MemCube primitives are versioned and migratable, which gives a
  coherent answer to the "what do we do when memory drifts" question
  that the security papers below raise.

## Letta: Context Constitution + Context Repositories + Letta Code

- Source: <https://www.letta.com/blog/context-constitution>,
  <https://github.com/letta-ai/context-constitution>,
  <https://www.letta.com/blog/context-repositories>,
  <https://www.letta.com/blog/letta-code>
- Date: Context Repositories Feb 12 2026; Context Constitution Apr 2
  2026; Letta Code app Apr 6 2026; "Red-teaming the Context
  Constitution" research May 6 2026.

### Why it matters for local models

Letta has pivoted from "agent server" framing to "git-versioned
memory filesystem + coding-agent runtime that any model can drive."
Letta Code runs locally and exposes the agent's memory as a real
filesystem with git commits per change — the simplest substrate yet
for the "filesystem-baseline" observation from the previous report.
The Context Constitution is a public document defining how an agent
should manage its own context for learning and identity.

### In-depth insights

- Git-backed memory: every change auto-committed with informative
  messages; subagents can branch/merge memory like code.
- Built-in skills: memory initialization, memory reflection
  (background reviews), memory defragmentation.
- May 6 research finding: even with the Constitution, models show
  "deep self-identification with ephemerality" that prompting alone
  can't repair — i.e., post-training help is needed for agents to
  actually treat memory as persistent identity. Honest negative
  result.
- MemGPT (predecessor) remains open-source under Letta's stewardship.

## Memory-Security Wave: MPBench, MemLineage, Mnemonic Sovereignty

- Source: <https://arxiv.org/abs/2606.04329> (MPBench / memory
  poisoning), <https://arxiv.org/abs/2605.14421> (MemLineage),
  <https://arxiv.org/abs/2604.16548> (security survey)
- Date: April–June 2026.

### Why it matters for local models

For anyone running a long-lived local agent that writes to its own
store, these are the new attack-surface papers. A single poisoned
memory write can drive long-term behavior, and existing
prompt-injection defenses don't catch it. Self-hosted operators
inherit responsibility for this surface — no managed-service vendor
between them and the attack.

### In-depth insights

- MPBench identifies four memory write channels and nine structural
  vulnerabilities in model capabilities, prompt design, and agent
  architecture; defines six classes of memory-poisoning attacks.
  Finding: more aggressive memory write/retrieve policies are more
  exploitable. Existing prompt-injection defenses fail.
- MemLineage attaches both cryptographic provenance and LLM-mediated
  derivation lineage to each memory entry; targets defense rather
  than detection.
- Security survey (arXiv 2604.16548) introduces "mnemonic sovereignty"
  — verifiable, recoverable governance over write/read/update/forget.
  Useful conceptual scaffolding when designing local-agent memory
  governance.

## ICLR 2026 MemAgents Workshop — Papers Worth Tracking

- Source: <https://sites.google.com/view/memagent-iclr26/>,
  <https://iclr.cc/virtual/2026/workshop/10000792>,
  <https://openreview.net/group?id=ICLR.cc%2F2026%2FWorkshop%2FMemAgent>,
  <https://mcml.ai/news/2026-05-06-mem-agents-workshop-at-iclr-2026/>
- Date: Workshop held 2026-04-27 in Rio de Janeiro (hybrid); MCML
  recap May 6 2026.

### Why it matters for local models

The workshop accepted >110 submissions and was the de-facto venue for
the work covered above. Several MemAgent papers (e.g.,
arXiv 2603.04549, 2603.24639) directly target open-weight stacks and
admission/policy mechanisms (A-MAC), which are practical for local
deployments.

### In-depth insights

- Confirmed accepted/cited at the workshop: MemoryAgentBench,
  MemoryArena, A-MAC (admission control), LightMem, MemoryCD —
  lifelong cross-domain personalization benchmark
  (<https://arxiv.org/abs/2603.25973> — first cross-domain,
  real-Amazon-Review-derived memory benchmark; finds existing memory
  methods are "far from user satisfaction" across domains).
- Workshop framing complements the prior survey arXiv 2509.18868:
  emphasis on episodic/semantic/working memory and their interface
  with external stores and parametric memory.
- Proceedings linked from the OpenReview group above are the best
  source for the full accepted list.

## Anthropic "Dreaming" (May 6 2026) — Closed-Model Reference Architecture

- Source: <https://www.anthropic.com/> (announced at Code with Claude
  2026); coverage:
  <https://www.techzine.eu/news/devops/141125/anthropic-introduces-dreaming-for-claude-managed-agents/>,
  <https://letsdatascience.com/blog/anthropic-dreaming-claude-managed-agents-self-improving-may-6>
- Date: 2026-05-06.

### Why it matters for local models

Closed-weight, but included because it is now the reference
architecture that LightMem ("sleep-time update"), Letta ("memory
reflection background process"), and the Letta sleep-time-compute
work are all chasing. Useful as a design spec for open
implementations: review session transcripts during idle time, extract
patterns, merge duplicates, replace stale entries, produce a separate
output memory store that humans can inspect/approve.

### In-depth insights

- Background process gated behind a developer application; research
  preview, not GA.
- Original memory store not overwritten — produces a separate
  dream-output store for human review.
- Harvey reported ~6× task-completion rate improvement in internal
  testing once dreaming was enabled.
- Open-source counterparts to track: Letta's sleep-time-compute
  pipeline and LightMem's offline consolidation stage.

## Open questions / follow-ups

- The CL-Bench finding that naive ICL beats dedicated memory
  frameworks on stateful tasks deserves a deeper look — is it the
  benchmark, the frameworks, or both? Run mem0's new token-efficient
  algorithm and LightMem against CL-Bench to see whether the picture
  changes.
- Titans/MIRAS open-source: Google's announced "Q4 2026 open-source
  implementation" hasn't landed; meanwhile lucidrains/titans-pytorch
  and the ATLAS/Omega-rule implementations are diverging. Worth
  tracking whether any of them ships a pretrained checkpoint, not
  just code.
- The Letta "Red-teaming the Context Constitution" result (models
  can't be prompted into treating memory as durable identity) is an
  empirical claim that should be cross-checked on Llama-3/Qwen-3-class
  models — is this an artifact of frontier post-training or
  universal?
- Anthropic Dreaming has no published technical paper; the closest
  open analog is LightMem's sleep-time stage and Letta's
  memory-reflection subagent. Need a head-to-head on a shared
  benchmark.
- MemoryCD is the only benchmark using real (Amazon Review)
  longitudinal user behavior; reproducing its splits and running
  open-source memory stacks on it should be a priority for the next
  report.
- Memory-poisoning defenses (MemLineage et al.) lack published
  numbers against MPBench; check by next cycle.
