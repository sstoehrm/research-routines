# LLM Memory — 2026-04-25

## Summary

Two-week delta since 2026-04-23. The April 2026 arXiv wave landed a cluster
of new memory systems that are explicitly designed for local / open-weight
backbones: **MemMachine** (Apache-2.0, Ollama/vLLM/Bedrock-native),
**ByteRover** (pure-markdown filesystem memory, no vector DB), **HiGMem**
(hierarchical event-turn retrieval with an order-of-magnitude smaller
retrieved context), **HeLa-Mem** (Hebbian associative graph, stress-tested
across small backbones), and **Knowledge Capsules** (KV-injection
nonparametric memory, the closest open analogue to NVIDIA's "context as
training data"). On the framework side **Letta Code** shipped as an
npm-installable agent on 2026-04-06 with first-class Ollama/vLLM provider
configuration, and **mem0 v2.0.0** (2026-04-16) dropped the Neo4j/Memgraph
requirement — mem0 now runs on a vector store alone, which materially
lowers the bar to self-hosting. ByteRover and MemMachine claim new SOTA on
LoCoMo / LongMemEvalS but are not yet apples-to-apples against the Letta
filesystem baseline from the prior report. MemAgents ICLR 2026 accepted
list is still not public.

## MemMachine — Ground-Truth-Preserving Memory System

- Source: <https://arxiv.org/abs/2604.04853>
- Repo: <https://github.com/MemMachine/MemMachine>
- Site: <https://memmachine.ai/>
- Date: arXiv 2026-04-06; repo actively updated through April.

### Why it matters for local models

Apache-2.0, LLM-agnostic, with first-class **Ollama** and **vLLM** backends
plus Python and TypeScript SDKs and an MCP server. The "ground-truth-
preserving" design stores entire conversational episodes rather than relying
on a lossy LLM-based extractor — relevant for self-hosted setups where you
cannot afford to call a heavyweight extractor on every turn.

### In-depth insights

- Storage combines **PostgreSQL + pgvector**, **SQLite**, and **Neo4j**
  (graph long-term memory) behind a single interface.
- Reports **0.9169 on LoCoMo** with gpt-4.1-mini and **93.0% on
  LongMemEvalS** in a six-dimension ablation.
- Companion Retrieval Agent: **93.2% on HotpotQA-hard**, **92.6% on
  WikiMultiHop** under randomised noise.
- License: Apache-2.0; code open.

## ByteRover — Agent-Native Memory via LLM-Curated Hierarchical Context

- Source: <https://arxiv.org/abs/2604.01599>
- Date: 2026-04-02.

### Why it matters for local models

Stores everything as **human-readable markdown files on the local
filesystem** — no vector DB, no graph DB, no embedding service. The most
aggressive "filesystem-as-memory" design in this cycle and a direct
comparison point against the Letta filesystem baseline from the prior
report.

### In-depth insights

- Hierarchical "Context Tree" (Domain → Entry) with explicit relations,
  provenance, and an Adaptive Knowledge Lifecycle (importance + maturity
  tiers + recency decay).
- Five-tier retrieval resolves most queries in **<100 ms without any LLM
  call**, escalating to agentic reasoning only on novel questions.
- Claims SOTA on **LoCoMo**, competitive on **LongMemEval**.
- Code/license: paper states an open implementation is released;
  repo URL not verified.

## HiGMem — Hierarchical & LLM-Guided Memory

- Source: <https://arxiv.org/abs/2604.18349>
- HTML: <https://arxiv.org/html/2604.18349>
- Date: 2026-04-22.

### Why it matters for local models

Two-level event-turn memory that uses event summaries as semantic anchors,
so a **small open-weight model** can predict which fine-grained turns to
read. The authors explicitly position the design as a reproducible baseline
rather than a moon-shot number — it is meant to be re-implemented on local
stacks.

### In-depth insights

- Best F1 on **4 of 5 question categories on LoCoMo10** while retrieving an
  **order of magnitude fewer turns** than the strongest baseline.
- Directly reduces answer-stage context cost, which matters for llama.cpp /
  vLLM users who pay per token.
- Announced as open-source; license not verified.

## HeLa-Mem — Hebbian Associative Memory

- Source: <https://arxiv.org/abs/2604.16839>
- HTML: <https://arxiv.org/html/2604.16839>
- Date: 2026-04-21.

### Why it matters for local models

One of the few new systems explicitly stress-tested across **varying model
sizes**, with the paper reporting consistent gains on small backbones —
i.e. the effect survives at 7B–14B, not just on GPT-4.

### In-depth insights

- Conversation history modelled as a dynamic Hebbian graph; co-activated
  nodes strengthen over time (Online Encoding & Association).
- Reflective Consolidation distils hub clusters into structured semantic
  knowledge to prevent graph explosion.
- Dual-path retrieval (associative + structural). Evaluated on **LoCoMo**.
- Code/license: URL not verified.

## Knowledge Capsules — KV-Injection Nonparametric Memory

- Source: <https://arxiv.org/abs/2604.20487>
- Date: 2026-04-22.

### Why it matters for local models

Builds "capsules" from a corpus using a **frozen base model** (no
fine-tuning) and injects them at inference as attention KV pairs. The
closest 2026 analogue to NVIDIA's "context as training data" line but
without retraining or adapter weights — in principle compatible with
llama.cpp / vLLM as long as attention-time KV patching is exposed.
llama.cpp / vLLM integration is **not yet demonstrated** in the paper.

### In-depth insights

- External Key-Value Injection (KVI) framework.
- Retrieval via graph-guided multi-hop traversal over capsules.
- Dual-channel injection — KV at attention + textual evidence in prompt for
  grounding.
- License/code: URL not verified.

## RoMem — Continuous Phase Rotation for Temporal KGs

- Source: <https://arxiv.org/abs/2604.11544>
- Date: 2026-04-13.

### Why it matters for local models

Drop-in temporal-KG module designed to plug into existing structured
memory stacks (Graphiti / Zep style). The Semantic Speed Gate is a small
pretrained model that runs independently of the base LLM — usable from a
local stack without retraining anything.

### In-depth insights

- SOTA on **ICEWS05-15 (72.6 MRR)**.
- **2–3× MRR** and answer accuracy on **MultiTQ**.
- Dominates **LoCoMo**; zero degradation on DMR-MSC.
- Zero-shot generalisation to unseen financial domains (FinTMMBench).

## Memory in the LLM Era — Unified Framework + New Method

- Source: <https://arxiv.org/abs/2604.01707>
- Date: 2026-04-02.

### Why it matters for local models

First systematic head-to-head of agent-memory methods under the same
experimental harness, with a released code + data bundle (repo URL not
verified). A useful reference architecture to port to Qwen3 / Llama 4.

### In-depth insights

- Modular taxonomy + benchmark harness across two standard suites.
- Lists representative systems (LOCOMO, AMem, MemoryOS, Nemori, MAGMA)
  under one roof; the paper's proposed hybrid beats prior SOTA.
- Open implementation announced; license not verified.

## Letta Code — Memory-First Coding Agent

- Blog: <https://www.letta.com/blog/letta-code>
- App post: <https://www.letta.com/blog/introducing-the-letta-code-app>
- Repo: <https://github.com/letta-ai/letta-code>
- Ollama guide: <https://docs.letta.com/guides/server/providers/ollama>
- Date: app 2026-04-06; underlying Letta server v0.16.7 from 2026-03-31.

### Why it matters for local models

Installs via `npm install -g @letta-ai/letta-code`; provider config
(`OLLAMA_BASE_URL`, vLLM base URL) via env vars, multiple providers enabled
simultaneously. Server now defaults to a **128K global context window**
(up from 32K) and ships an overhauled compaction path — directly relevant
to KV-cache budgets on local hardware. `/init` and `/remember` commands
are explicit handles on the persistent memory block.

### In-depth insights

- Claimed "#1 model-agnostic open-source agent on Terminal-Bench".
- Same three-tier memory story (core / archival / recall) as Letta main.
- Apache-2.0 per the main `letta-ai/letta` repo.

## mem0 SDK v2.0.0

- Changelog: <https://docs.mem0.ai/changelog>
- Releases: <https://github.com/mem0ai/mem0/releases>
- Date: v2.0.0 on 2026-04-16; preceded by v1.0.10 hotfix on 2026-04-01
  (fixed a destructive `vector_store.reset()` and an Ollama URL config bug).

### Why it matters for local models

**Neo4j / Memgraph are no longer required** — entity linking replaces
graph memory, so mem0 now runs on a vector store alone. This removes a
heavy infra dependency for self-hosters and makes mem0 embeddable on a
laptop again.

### In-depth insights

- **Single-pass extraction**: one LLM call per `add()`, ~50% latency
  reduction vs. v1.
- Hybrid retrieval: semantic + BM25 + entity-graph boost.
- Reported **2.59 s p95 latency** for the Mem0g graph-enhanced variant.
- Entities live in a parallel `{collection}_entities` collection inside
  the existing vector store.

## Follow-ups on 2026-04-23 open questions

- **Open-source Titans on Qwen3 / Llama 4**: the relevant project is still
  **TPTT** (<https://arxiv.org/abs/2506.17671>, repo
  <https://github.com/fabienfrfr/tptt>), which evaluates on Llama-1B,
  Qwen2.5-1.5B, OlMoE-1B-7B, Gemma3-270m, OpenELM-1.3B, and Mistral-7B and
  integrates with Hugging Face + LoRA. **No Qwen3 / Llama 4 port has
  surfaced** in this cycle. Qwen3-Next ships native gated DeltaNet linear
  attention (<https://github.com/QwenLM/Qwen3.6>), a Titans-adjacent
  design; llama.cpp support is still maturing — see
  <https://github.com/ggml-org/llama.cpp/issues/15940>.
- **Letta vs. mem0 vs. filesystem on LongMemEval / LoCoMo**: Letta's own
  benchmark (<https://www.letta.com/blog/benchmarking-ai-agent-memory>)
  remains the canonical source — Letta filesystem on gpt-4o-mini = **74.0%
  on LoCoMo** vs. the Mem0 graph variant at **68.5%**. ByteRover and
  MemMachine now claim higher numbers but on different backbones, so a
  direct 2026-04 apples-to-apples is **still not published**. The
  **MemoryAgentBench** (ICLR 2026) harness
  (<https://arxiv.org/abs/2507.05257>, code
  <https://github.com/HUST-AI-HYZ/MemoryAgentBench>) is the most credible
  neutral rig.
- **MemAgents ICLR 2026 accepted list**: workshop site
  <https://sites.google.com/view/memagent-iclr26/> and OpenReview group
  <https://openreview.net/group?id=ICLR.cc%2F2026%2FWorkshop%2FMemAgent>
  are live; submissions closed 2026-02-13; the **accepted-papers list is
  still not public** as of today. Re-check weekly.
- **"Context as training data" adapters compatible with llama.cpp / vLLM**:
  no vendor-published adapter has appeared. **Knowledge Capsules** (above)
  is the closest research analogue but ships no llama.cpp / vLLM kernels.

## Open questions / follow-ups

- Reproduce **MemMachine** against **Letta filesystem** on LongMemEvalS
  using the same backbone (Qwen3-32B or Llama-4-Scout) and record score
  deltas for the next execution.
- Verify **ByteRover**'s "<100 ms without any LLM call" claim on a single-
  node workstation with a local embedder.
- Check whether **mem0 v2.0.0** reproduces its headline latency on a CPU-
  only vector store (e.g. LanceDB) for laptop deployments.
- Track whether **Knowledge Capsules** ships an attention-KV patch
  reference for vLLM or llama.cpp — that's the blocker for local use.
- Re-visit **MemAgents ICLR 2026** accepted list in the next cycle.
