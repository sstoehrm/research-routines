# LLM Memory — 2026-08-22

## Summary

The four-week window since 2026-07-25 was dominated by **August-cycle
arXiv output** (the 2608.* range) rather than by any single blockbuster
framework. Concretely: an unusually large batch of memory-behavior
benchmarks appeared — **MemTrapBench** (cognitive traps flip every
tested memory framework below the no-memory baseline), **StateMemBench**
(agents that near-saturate LoCoMo lose two thirds of their advantage
when the world state actually evolves), **AgentMemBench** (unified
five-strategy comparison), and **MCB** (memory-commitment boundary) all
attack the "aggregate QA accuracy" measurement style that MemFail and
MemTrace opened up in the previous cycle. On frameworks, **Tencent
Cloud open-sourced TencentDB Agent Memory v2.0** on Aug 3 (MIT, four
memory asset types, ACL governance) — the most consequential new
open-source memory hub of the window. **MemOS** shipped
v2.0.27–v2.0.30 with a DeepSeek Harness integration, **supermemory**
issued its first true stable (0.0.7) plus an emergency 0.0.8 patch,
**Cognee** landed v1.5.0 with production-scale migration and the
Ladybug graph adapter, and **mem0** kept its weekly cadence on both
Python and Node SDKs (agent-specific custom instructions, Oracle
vector store). On architecture, a small cluster of papers targets
persistent state and KV reuse for open stacks: **LiveMem** (bounded KV
window plus Gated-DeltaNet-2 memory state), **PRECOG/SMC** (O(1) SSM
state injection for edge devices), **AnchorKV** (20× KV compression at
99% retention on 70B), **CacheScout** (agent-aware KV runtime),
**AATC** (attention-aware transform coding for KV), and a
**cross-model KV cache transfer** paper from NVIDIA that maps caches
across sibling model sizes in closed form. **Alibaba shipped
Qwen3.8-Max** on Aug 3 with 1M context and Aug 12 Hugging Face weights
(2.4T MoE, 95B active) — the new "big open baseline" any memory
framework must beat. Security threads continue: **Proof-of-Execution
Memory** and **SafeCommit** both directly target the FARMA-style
forged-reasoning attack surface from the July cycle. No new Titans /
MIRAS follow-up from Google Research surfaced in this window.

## Benchmarks / evaluation

### StateMemBench + StateMem — tracking evolving world state

- Source: <https://arxiv.org/abs/2608.19652>
- Date: 2026-08-20
- Authors: Fan, Liu, Yang, Ouyang, Han

Why it matters: LoCoMo-style benchmarks reward answering the *last
recorded* fact; StateMemBench penalizes it. This is the "MemoryArena
for evolving state" — expect the same rank-shuffle when applied to
local frameworks.

- 234 multi-session scenarios across two conversation-length regimes.
- **Closed-pool grading**: separates "current state", "superseded
  state", and other errors by construction (not just BLEU / F1).
- StateMem (state-first memory method) reports **1.8× current-state
  accuracy** over strongest same-backbone baseline (0.205 → 0.363 on
  DeepSeek-V4-Flash) and **1.6×** over strongest memory system on
  Qwen-3.5-9B (0.149 → 0.233).
- As a lightweight single-call wrapper on top of existing memory
  systems: **+32 to +67 points** on StateMemBench across six memory
  backends; +15 to +32 of those attributed to the state structure
  itself rather than added context.

### MemTrapBench — cognitive traps in memory use

- Source: <https://arxiv.org/abs/2608.20202>
- Date: 2026-08-21
- Authors: Wang et al.

Why it matters: the paper's punchline is that **every evaluated
memory strategy is worse than no memory** on the trap tasks — a
first-of-its-kind result that reframes what "adding memory" costs.

- 1,050 instances across four scenarios in two categories: Reasoning
  Fixation (Cognitive Bias, Trauma, Task Boundary) and Belief
  Distortion.
- Two model families, five memory frameworks; strongest methods
  suffer **>10% drops** vs no-memory.
- Proposes **AdaptiveMem**, an inference-time instruction ("avoid
  memory traps") that reduces the gap without hurting standard memory
  benchmarks.

### AgentMemBench — five-strategy comparison

- Source: <https://arxiv.org/abs/2608.00009>
- Date: 2026-07-31 / 2026-08-01

Compares five families under identical conditions: in-context
windowing (ICW), external key-value store (EKV), graph-based episodic
memory (GEM), compression-based summarisation (CBS), web-augmented
memory (WAM). Runs on LoCoMo, MultiDoc2Dial, MSC with Recall@k, MRR,
nDCG@k, Answer F1, LLM-judge Faithfulness, Memory Footprint, Latency.
Useful as a *policy* baseline when comparing frameworks that mix
these strategies internally.

### MCB — Memory Commitment Boundary

- Source: <https://arxiv.org/abs/2608.19564>
- Date: 2026-08-20
- Authors: Li, Yao, Zheng

Not "should the agent retrieve?" but "should the interaction be
persisted at all?" — the four legal moves are Remember, Verify, Ask,
or use only in the current context. 140 primary scenarios (70
dev / 70 held-out) plus a 70-item contrast set; independent labelers,
97.1% agreement, Cohen's κ = 0.962. Directly relevant to Letta-style
frameworks that auto-persist by default.

### The Horizon Gap — long-horizon agents survey

- Source: <https://arxiv.org/abs/2608.06663>
- Date: 2026-08-07 (Chen, Wang, Qu)

1,547 arXiv papers (2024–2026) coded across six categories (planning,
memory, execution, training, evaluation, foundations/safety) × three
horizon axes (within-context, within-task-beyond-context, cross-task-
persistent). Explicitly disambiguates **long-horizon** (task
property), **long-context** (model property), **long-term memory**
(system property) — a distinction that keeps getting collapsed in
recent framework marketing. Good indexing document for the next
cycle.

## New memory methods (paper-side)

### MemArbiter — decision-time memory arbitration

- Source: <https://arxiv.org/abs/2608.02113>
- Date: 2026-08-03 (Dong et al.)

Function-aware memory-arbitration framework: decomposes interaction
history into atomic items, organizes them into **five functional
Memory Banks**, and combines bank-level demand, item-level relevance,
focal-ambient representation, and a temporal presentation gate. Names
the "Memory-Action Gap" — retrieved info that fails to guide the
current decision because it is poorly organized/prioritized.

- Evaluated on ALFWorld against Flat Retrieval / Flat Recency at a
  unified per-step memory budget.
- With an **open-weight action-generation model**: success rate
  **82.8%** at 500 tokens and **92.5%** at 750 tokens — beats
  strongest baseline by **+20.9** and **+25.4 pp** respectively.
- Also improves post-failure recovery, reduces failed-action
  repetition and state-action recurrence.
- Directly relevant to local agents where per-step token budget is
  fixed.

### MemSIF — structured interactions → dual-track fact memory

- Source: <https://arxiv.org/abs/2608.01742>
- Date: 2026-08-03

Two ideas: (1) organize raw interactions into **Topical Segments**
and **Event Trajectories** rather than time-ordered logs; (2)
**Dual-Track Fact Memory**: `CoreFact` consolidates stable schema-
guided info at write time; `ActiveFact` forms facts on demand and
promotes those supported by multiple sources / recurring query
demand.

- Addresses Temporal-Structural Misalignment (TSM) and Delayed
  Utility Manifestation (DUM).
- On **LoCoMo**: +2.29 – +8.79% Total ACC over strongest baseline
  across 5 backbones. On **LongMemEval-S**: +2.87 – +6.15%.
- Interesting for local stacks because both tracks are cheap to
  implement over existing vector stores.

### ScrubJay-MEM — type-conditioned temporal decay

- Source: <https://arxiv.org/abs/2608.04746>
- Date: 2026-08-05 (BITS Pilani)

Operationalizes per-memory temporal decay as an auto-classified
coefficient. Each memory is a **What–Where–When** tuple with an
estimated perishability and utility horizon; retrieval scores are
query-adaptive. Also introduces the **Temporal Generalization Test
(TGT)** with held-out retention intervals and a **Generalization Gap
(GenGap)** metric. Independent of any specific store — plug-in
scoring for whatever local memory backend you already run. The most
principled implementation of the Ebbinghaus-decay pattern this cycle.

### The Sleeping Agent — SWC as a diagnostic probe

- Source: <https://arxiv.org/abs/2608.11775>
- Date: 2026-08-15 (Kyrkewood; 7 pages, code released)

**Salience-Weighted Consolidation** (sleep-inspired): score history
by salience, partition into priority tiers, apply structured gist
abstraction to mid-priority content. Used here as a probe rather than
a product.

- Evaluated on all 10 LoCoMo conversations, 1,935 text-only
  questions, 1,501 in the aggregate after excluding adversarial cat.
  5 items, at temperature 0.
- Finding: gist compression **substantially beats truncation on
  multi-hop and single-hop factual** but is constrained on
  **temporal** questions. Concrete guidance for when *not* to compress.

### Structured Memory for Edge — PRECOG + SMC

- Source: <https://arxiv.org/abs/2608.02560>
- Date: 2026-08-03

State-space memory for edge deployment: **PRECOG** (Pre-Computed
Context Injection) collapses prefill from O(L_context) to O(1) per
query by exploiting fixed-size, position-agnostic SSM hidden state;
document corpora are pre-encoded offline as SSM hidden states and
injected at query time. The same mechanism enables **SMC** — a
hierarchical persistent memory with cognitive-domain clustering, an
adjustable fidelity-vs-storage dial, and O(1) session initialization.
The clearest "SSM-as-memory-substrate" paper this window — directly
relevant to Mamba-family local deployments (Nemotron 3 Super,
Qwen3.8-Max).

### LiveMem — persistent state via GDN2 branch

- Source: <https://arxiv.org/abs/2608.02515>
- Date: 2026-08-03 (Liu et al.)

Augments a full-attention pretrained LLM with a **recurrent memory
state** maintained by a parallel branch using **Gated DeltaNet-2** as
backbone; the main attention path keeps a bounded KV window. Combines
context turnover + memory maintenance + memory-oriented post-training
+ state-aware serving so the memory state stays load-bearing after
its tokens are evicted.

- Evaluated on LongMemEval; answers questions whose supporting
  evidence has already been removed from the active window.
- Evidence-distance analysis shows information persists beyond the
  active window (specific numbers not verified from the abstract).

### Agent Memory Distillation (AMD)

- Source: <https://arxiv.org/abs/2608.07169>
- Date: 2026-08-09 (KAIST + DeepAuto.ai)

Training-free transfer of hierarchical memory from a large teacher
agent to a small student agent. Three memory types built from
successful teacher trajectories:

- **Workflow memory** — task-level strategies (proactive injection at
  task start)
- **Subtask memory** — behavioral examples at intermediate granularity
  (proactive)
- **Function memory** — per-function calling conventions and common
  pitfalls (retrieved reactively on tool-calling errors)

Evaluated on three tool-use benchmarks with 4B–8B student models and
GPT-5-mini as teacher. Concrete pattern for local deployments that
want to distill from a cloud teacher without weight access.

### MERIT — causal episodic memory for repair

- Source: <https://arxiv.org/abs/2608.05906>
- Date: 2026-08-07

Training-free text-to-SQL repair agent that keeps an online
**dual-polarity memory**: oracle-verified corrections + observed
unsuccessful directions. Deterministic failure-type classifier
conditions a hybrid lexical-dense retriever before the frozen model
generates each revision. A template for "learning from failure
without weight updates" that could plausibly be lifted into other
tool-use domains.

### StateAuditor — repairing stale-memory failures

- Source: <https://arxiv.org/abs/2608.01619>
- Date: 2026-08-03 (Sun, He)

Identifies a structural weakness: draft-anchored verification checks
what the response *says*, and the stale dependency is usually unsaid.
StateAuditor audits **from stored state to draft** — proposes
candidate old→new transitions, then deterministic code pins each
quotation to a single entry, verifies chronology, and only lets
verified transitions trigger repair.

- On the STALE benchmark (400 scenarios, 50-session histories),
  single-query VTA rises from 0.686 → 0.736 (**+5.0 pp**, 95% CI
  [+2.9, +7.2]).
- Verifies **provenance and chronology** — not semantic supersession
  — which makes it a reasonable candidate for local CI checks.

### Reversible Forgetting for enterprise agents

- Source: <https://arxiv.org/abs/2608.18177>
- Date: 2026-08-18 (Yash, Roy, Bhattacharjee)

Argues plain forgetting is incomplete: enterprise environments
non-stationarily deprecate and *re-activate* knowledge. Proposes
three memory states — **active / dormant / retired** — with an
explicit reactivation transition. Implemented as a **Hysteretic
Reversible Memory Controller**: accumulates relevance evidence,
asymmetric thresholds prevent state oscillation, reactivation tested
in shadow mode, retirement gated through policy. Conceptual paper,
but the state machine is small and directly implementable.

### TTCD — Learning What to Remember via context distillation

- Source: <https://arxiv.org/abs/2608.01672>
- Date: 2026-08-03

Test-Time Context Distillation: long-window teacher supervises the
**fast weights** of a short-window student; hidden-state discrepancy
gives a dense self-supervised signal for what to memorize. Continual-
learning protocol on LLaMA-3.1-8B. First TTT paper this cycle that
directly addresses the "Beyond Perplexity" critique from July by
measuring downstream behavior on continual-learning tasks, not just
loss.

### Mitigating Over-Personalization via structured memory

- Source: <https://arxiv.org/abs/2608.08300>
- Date: 2026-08-11 (Hannoon, Zhao, Narayan, Goyal, Sheth)

Two failure modes named: **cross-domain leakage** (memories from one
life domain reshape responses in another) and **memory-induced
sycophancy** (stored user beliefs make the model more agreeable than
truthful). Fix is a **prompt-only presentation change** — no model or
memory-content edits — which makes it a drop-in for local
personalization stacks. First paper this cycle to treat over-
personalization as a distinct memory failure mode.

### Spatial Memory Agent

- Source: <https://arxiv.org/abs/2608.12743>
- Date: 2026-08-13

Frozen-VLM agent that converts verified spatial experience into
reusable procedural lessons — parameter-update-free spatial-reasoning
self-evolution without depending on external spatial tools at
inference. Complements Sky/GUI memory work from prior cycles.

## KV cache / architectural

### AnchorKV — anchor-residual KV compression

- Source: <https://arxiv.org/abs/2608.02901>
- Date: 2026-08-04 (Khalaf et al.)

Represents the cache by a small set of exact anchors; every other
token is expressed via its most similar anchor; only the tokens
whose approximation most affects the output are refined. **No tokens
are discarded** (unlike eviction schemes) — so ordering and
positional structure are preserved.

- **20× compression, 99% of full-cache accuracy at the 70B scale**
  (Llama-3.1-70B).
- Evaluated on Llama-3.1-8B, Mistral-Small-3.1-24B, Llama-3.1-70B on
  **RULER-32K, RULER-64K, LongBench**. Stays near the uncompressed
  cache as compression increases; eviction baselines degrade sharply.
- Baseline gap over eviction / quantization approaches grows with
  compression ratio.

### AATC — attention-aware transform coding for KV

- Source: <https://arxiv.org/abs/2608.14191>
- Date: 2026-08-14 (Laus, Verdun, Wang, Calmon, Krahmer)

Proves under a white-noise quantization model that expected
attention-aware distortion decomposes additively over keys/values,
tokens, channels. Uses transform coding + reverse water-filling from
rate-distortion theory to allocate bits over a calibration set. First
KV-quantization scheme with a formal attention-aware distortion
model. Directly applicable to the local KV-quantization workflows in
vLLM / SGLang / LMCache.

### Cross-Model KV Cache Transfer (NVIDIA)

- Source: <https://arxiv.org/abs/2608.03893>
- Date: 2026-08-04 (Heo, Shafipour, Zhao et al., NVIDIA)

Cascading/routing across different-sized siblings in the same model
family forces the receiver to repay prefill from scratch. This paper
shows cross-model KV has substantial **linear structure** across
matched-KV pairs.

- On **Qwen3 14B → 32B**: one source layer explains **56%** of
  variance in target keys and **32%** in values; multiple source
  layers push this to **79% / 65%**.
- Closed-form per-head ridge mapper: picks the top-k most predictive
  source layers, strips RoPE from keys before mapping (position-free
  and reusable across context lengths), then applies the fit.
- Enables prefill reuse across siblings — matters for any local
  deployment that runs mixed-size cascades on the same family.

### CacheScout — agent-aware KV runtime

- Source: <https://arxiv.org/abs/2608.14624>
- Date: 2026-08-20 (Zhang, Kim, Feng, Du, Liu, Zhong, Ching, Jiang, Hu
  — UCSC, UW, U Chicago)

Multi-agent LLM serving: each user request is decomposed into
specialized agents, each of which reruns fixed context (system
prompts, tool defs, few-shot). CacheScout adds an **agent-aware KV
runtime layer** that learns agent-execution transitions online — no
predefined workflow graphs, no offline training. Directly relevant to
local multi-agent setups on vLLM / SGLang where standard content-hash
caching wastes potential reuse.

### Mamba with Hierarchical Memory

- Source: <https://arxiv.org/abs/2608.02347>
- Date: 2026-08-03

Adds hierarchical memory to Mamba to relieve the state-size /
long-sequence representation bottleneck. Not deeply examined this
cycle but worth reading against PRECOG/SMC and LiveMem as the third
SSM-memory paper in three days.

## Security & governance

### Proof-of-Execution Memory — defending against FARMA

- Source: <https://arxiv.org/abs/2608.16032>
- Date: 2026-08-17

Direct response to the July FARMA paper (2607.05029). Instead of
detecting forged reasoning entries by content, requires the memory
store to accept only entries that carry a verifiable proof-of-
execution — a witness that the reasoning step *actually happened* in
this session. Different design from SENTINEL (which analyzes entries
structurally). Read alongside SENTINEL — the two are the current
attack/defense frontier.

### SafeCommit — certifying when memory-grounded agents may act

- Source: <https://arxiv.org/abs/2608.04289>
- Date: 2026-08-06 (Akewar, Ranjan)

Risk-controlled layer between reasoning and external side effects.
Constructs a **calibrated set of plausible latent worlds** from
memory / observations / tool outputs / provenance / policy, and
permits a side-effect only when a **conformal action certificate**
shows the action is safe in every retained world. Otherwise: a
low-side-effect probe, or a conservative fallback. Complements FARMA-
style defenses at the *commit* boundary rather than the *storage*
boundary.

## Open-weight model context (adjacent but important)

### Qwen3.8-Max (Alibaba)

- HF release: Qwen3.8-2.4T-A95B on Hugging Face 2026-08-12
- Companion small model: Qwen3.8-27B (local-runnable) also live
- Announcement: 2026-08-03

Not a memory system, but the new open baseline. 2.4T sparse MoE with
95B active per token, **1M-token context**, text-only, new
revenue-share license. Any memory framework that argues "we help you
handle long context on open weights" now has to be evaluated against
this. The Qwen3.8-27B companion is what's actually runnable on a
workstation.

### DeepSeek Harness

- Open-source agent runtime released 2026-08-13 under MIT
- CLI: `dsh`; TypeScript, plugin kernel Cordis

Memory posture: keeps a **forensic record** — every event replayable
and forkable — whereas OpenClaw keeps conversational history and
Hermes keeps learned capability (skills + searchable memory).
Consequential because the three big open agent runtimes now have
three distinct memory philosophies, which will drive the next round
of memory-framework integrations (MemOS already shipped its
integration Aug 17).

### Graph-Memory plugin (adoresever/graph-memory)
