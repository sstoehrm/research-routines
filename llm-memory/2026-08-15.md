# LLM Memory — 2026-08-15

## Summary

The July 26 – August 15 cycle is a **KV-cache-and-security cycle**. A
cluster of `2608.*` arXiv papers push KV compression as the primary
substrate for local long-context memory (**AnchorKV**, **RestoreKV**,
**QEvict**, **Practical Online Compaction**, **LiveMem**) and, in
parallel, hit KV compression with its first faithfulness critique
(**Does Accuracy Equal Evidence?**). Two security papers formalize
what the July report only flagged: **AuthMem-Bench** shows 48 of 49
tested consolidators collapse source authority, and **MemCollusion**
(the "Salami Attack") gets 75% attack success against OpenClaw by
sharding the payload across memory writes. Two new agent-memory
benchmarks — **MemArena** (on-device ego-centric, 50 agents × 15
days) and **AgentMemBench** (five strategies × three datasets) —
extend the eval landscape after last cycle's MINTEval / MemFail /
MemLens wave. Framework-wise, **MemOS** shipped v2.0.27 → v2.0.30
and local plugin 2.0.14/2.0.15 on its usual weekly cadence,
**mem0** shipped Oracle AI Vector Search + `agent_custom_instructions`
across Python/Node SDKs, and **Cognee** shipped v1.4.1 → v1.4.2 with
a v1.5.0 dev preview. **Letta**, **supermemory**, **Graphiti**, and
**MemMachine** were silent in the window. On standards, the
**MCP 2026-07-28** spec went explicitly stateless, which pushes memory
back into the application layer — a design choice worth tracking as
Letta / MemOS / mem0 all expose MCP surfaces.

## AnchorKV — Anchor-Residual KV Cache Compression

- Source: <https://arxiv.org/abs/2608.02901>
- Date: 2026-08-03

### Why it matters for local models

The direct successor question after C²KV: can you get 20× cache
reduction without discarding tokens? AnchorKV keeps a small set of
"anchor" tokens stored exactly and expresses every other token as a
residual against its most similar anchor, so the cache is compressible
*and* addressable at the token level. For local serving stacks (vLLM,
SGLang, llama.cpp) where VRAM is the binding constraint on context
length, retaining 99% of the full-cache score at the 70B scale is the
most aggressive lossless-shaped number of the cycle.

### In-depth insights

- Compression ratio **20×** without token discard.
- Reported to retain **99% of the full-cache score at 70B** across the
  paper's model / dataset matrix.
- Complementary rather than competitive with eviction-based methods:
  because the anchors persist, the compressed cache is more amenable
  to cross-session composition than eviction schemes.
- Code / weights status not confirmed from the abstract.

## RestoreKV — Learned Restoration Under Aggressive Eviction

- Source: <https://arxiv.org/abs/2608.01247>
- Date: 2026-08 (2608.01247)

### Why it matters for local models

Query-agnostic KV eviction (compress once, reuse across queries) is
the setup that any persistent-KV memory substrate — LMCache being the
obvious example — has to survive. RestoreKV takes the losing side of
that setup, trains a **LoRA restore head** that regenerates a compact
context-conditioned complement from the evicted cache. Because it's a
LoRA (0.4% of parameters, self-distilled), it's a realistic drop-in
for a local Qwen3 / Llama serving stack.

### In-depth insights

- Trains only **0.4%** of parameters via self-distillation from the
  frozen full-cache model. No task-specific tuning.
- Improves **59 of 60** paired, budget-matched settings on Qwen3-4B
  across five base eviction methods on four long-context benchmarks.
- Positioned as a *complement*, not a replacement, for selection-based
  eviction — plug it on top of H2O / SnapKV / SinkCache.

## Does Accuracy Equal Evidence? — Reasoning Faithfulness Under KV Compression

- Source: <https://arxiv.org/abs/2608.01631>
- Date: 2026-08-03 (Ai, He, Guo — UIUC)

### Why it matters for local models

Every KV compression paper in this cycle (AnchorKV, RestoreKV, QEvict,
LiveMem) argues from final-answer accuracy. This paper shows that on
reasoning tasks, answer accuracy and the validity of the visible
supporting rationale are preserved at *different* rates under
compression. If you're picking a KV compression scheme for a local
reasoning-heavy stack (math tutoring, clinical calc, long-context
retrieval), this is the paper that says "measure both."

### In-depth insights

- Uses a **controlled fixed-trace replay** protocol: holds reasoning
  content fixed, so compression is the only variable.
- Evaluates **10 token-eviction methods + 1 quantization method** on 3
  models across math reasoning, scientific QA, clinical calculation,
  and long-context retrieval.
- Three metrics: final accuracy, answer-chain consistency, perturbation
  faithfulness. Answer accuracy survives compression; chain support
  degrades.

## LiveMem — Memory State Continuity Under Context Turnover

- Source: <https://arxiv.org/abs/2608.02515>
- Date: 2026-08

### Why it matters for local models

Formalizes "state continuity under context turnover": as chunks age out
of a bounded KV window in long-running inference, the model should
still retain the information they carried. LiveMem does this by
attaching a **parallel Gated DeltaNet-2 memory branch** to a frozen
full-attention LLM, so the working attention path stays bounded while
lifecycle state persists. Directly attacks the case a local always-on
assistant actually runs.

### In-depth insights

- Intrinsic memory (part of the model, not the surrounding stack) that
  augments a **pretrained full-attention LLM** — no from-scratch
  retraining.
- Backbone of the memory branch: **Gated DeltaNet-2**.
- Evaluated on LongMemEval; can answer questions from the memory state
  after the supporting evidence has left the KV window.
- Reads as a lighter-touch continuation of the Titans/MIRAS line
  without requiring the full test-time-training rewrite.

## MemArbiter — Decision-Time Memory Arbitration

- Source: <https://arxiv.org/abs/2608.02113>
- Date: 2026-08-03

### Why it matters for local models

Reframes long-horizon agent memory as an **arbitration** problem at
decision time, not a retrieval problem. Interaction histories are
decomposed into atomic items and routed into five functional Memory
Banks; a bank-level demand + item-level relevance + temporal gate
combine to control what is actually surfaced to the current turn. Uses
an **open-weight action-generation model** in the reported numbers,
which is the fingerprint that this is meant to be reproducible
locally.

### In-depth insights

- Success rate **82.8% at a 500-token budget** and **92.5% at 750
  tokens** — beating the strongest baseline by **20.9 and 25.4
  percentage points** respectively.
- Formalizes the "Memory-Action Gap": accessible ≠ actionable.
- Five functional banks + focal-ambient item representation is the
  concrete new architecture. Bank routing itself is not learned via RL
  (contrast MemoPilot from last cycle).

## When Memory Becomes Authority — AuthMem-Bench

- Source: <https://arxiv.org/abs/2608.01679>
- Date: 2026-08-03

### Why it matters for local models

The first serious benchmark for **authority preservation** during
memory consolidation. When Mem0 / Letta / MemOS collapse a
heterogeneous history into a canonical fact, do they preserve *who
said it and under what constraints*? Answer, empirically: **no**. If
your local agent ever writes user-visible actions from consolidated
memory, this is the failure mode that yields silent unauthorized
behavior.

### In-depth insights

- **7 consolidators × 7 LLM backbones = 49 systems**. Authority
  collapse observed in **48 of 49**.
- Baseline unauthorized-action rate on collapsed memories with no
  authority metadata: **50.3%**.
- With **automatically predicted and persisted authority labels**, the
  unauthorized-action rate drops from **16.9% to 0.0%** — so the
  remediation is a metadata field, not an architectural rewrite.
- Complements FARMA (last cycle): FARMA poisons rationale, AuthMem
  shows the metadata channel that would blunt it is missing by
  default.

## Salami Attack (MemCollusion) — Stealthy Collusive Memory Poisoning

- Source: <https://arxiv.org/abs/2608.01637>
- Date: 2026-08

### Why it matters for local models

Applies salami tactics — slicing an adversarial objective into
individually innocuous fragments — to defeat memory-level defenses.
Includes **MoltLab**, a reproducible environment where crafted content
must first be observed and consolidated into persistent memory before
influencing a *later* session. Any local persistent-memory stack that
survives one-shot FARMA-style poisoning still has to answer this.

### In-depth insights

- Automated red-team framework: 4 design constraints, 5
  theory-informed strategies, a fine-tuned generator.
- Evaluated on **OpenClaw** with two backbones across **48 scenarios**.
- Under the strongest memory-saving setting: **81.3% average Memory
  Save Rate** and **75.0% Attack Success Rate**.
- Effective under benign memory dilution and under existing
  memory-level defenses.

## MemArena — Ego-Centric On-Device Personal Memory Benchmark

- Source: <https://arxiv.org/abs/2608.02613>
- Date: 2026-08 (MBZUAI — Zhang, Ma)

### Why it matters for local models

Explicitly built for **edge-deployed personal memory assistants** with
open-weight models. Fills the gap MemoryArena and LongMemEval-V2 both
leave: activity-dense, ego-centric, multi-session, private
interpersonal — the fingerprint of an actual on-device assistant, not
a web agent.

### In-depth insights

- Constructed with the **MASim** agent simulator: **50 agents × 15
  days**, **10.3M** dialog-text tokens, **24.1K** text-only
  ego-observed tokens per agent per day.
- Six evaluation dimensions across recall, reasoning, trustworthiness.
- Evaluates **5 open-weight readers** with Vanilla context, BM25-RAG,
  Oracle retrieval, **Memobase**, and **MemSearch** as memory
  backends.

## AgentMemBench — Systematic Long-Term Memory Strategy Benchmark

- Source: <https://arxiv.org/abs/2608.00009>
- Date: 2026-08 (Cherif)

### Why it matters for local models

Compares five *strategies* (not five products) under identical
conditions: **in-context windowing, external key-value store,
graph-based episodic memory, compression-based summarisation,
web-augmented memory**. This is exactly the axis a local team needs
to make when picking between mem0-style KV, Cognee-style graph, and
plain summary buffers.

### In-depth insights

- Three datasets: **LoCoMo**, **MultiDoc2Dial**, **MSC** (persona
  multi-session chat).
- Metrics: **Recall@k, MRR, nDCG@k, Answer F1**, plus an LLM-judge
  faithfulness score.
- No single strategy wins — the paper reads as the leaderboard-agnostic
  companion to MemOps from last cycle.

## PGMem — Tightly Coupled Persona–Memory Graph

- Source: <https://arxiv.org/abs/2608.01708>
- Code: <https://github.com/wonjunchoi23/pgmem>
- Date: 2026-08 (Choi, Kim, Lee, Yoon)

### Why it matters for local models

Fixes the "persona as a flat profile detached from the events that
justify it" pattern that mem0 / Letta / MemOS all still have.
Personas become nodes on a **heterogeneous persona-memory graph**,
connected to event nodes by typed provenance and evidence edges;
retrieval expands from query-relevant seeds and ranks by evidential
validity. Reported to work with **small language model backbones**,
which matters for local deployments.

### In-depth insights

- Explicit provenance edges make each persona signal traceable back to
  the event(s) that support or revise it — closes the
  memory-persona validity gap the paper defines.
- Outperforms summary-based, persona-aware, graph-structured, and
  agentic-memory baselines across three benchmarks.
- Code released; license on the repo not verified here.

## Addressable Memory for Video World Models

- Source: <https://arxiv.org/abs/2608.07408>
- NVIDIA research page:
  <https://research.nvidia.com/publication/2026-08_addressable-memory-video-world-models>
- Date: 2026-08-07 (Wu et al., NVIDIA / Princeton / Toronto / Vector)

### Why it matters for local models

Video world models store past frames as a growing KV cache. Once the
rollout exceeds the training horizon, **temporal RoPE offsets fall out
of distribution** and attention can no longer address the stored
frames; naive cache compression corrupts memory by averaging
incompatible positional phases. Same disease that limits long-context
LLMs, but with a visual-fidelity failure mode. Directly relevant to
any local video / multimodal memory stack, and complementary to MemLens
(last cycle) on the evaluation side.

### In-depth insights

- Identifies the two failures explicitly: RoPE-out-of-range
  addressability, and RoPE-phase corruption from naive compression.
- Positions the fix as *addressable*, not merely persistent, memory —
  the compression must preserve retrievability.
- Presented at the ICML 2026 F2S workshop as an oral.

## Practical Online KV Cache Compaction — Empirical Study

- Source: <https://arxiv.org/abs/2608.00902>
- Date: 2026-08

### Why it matters for local models

Most KV compaction papers assume offline knowledge of future queries.
Agents don't have that. This paper studies **online** compaction —
compact before you know what the next tool call will ask — across
token-eviction and attention-matching families, on real agent
benchmarks (**BrowseComp-Plus, WideSearch**). Immediate compaction
often *hurts*; delayed compaction using the agent's own future queries
recovers most of the gap. A concrete deployment guideline for local
agent stacks.

### In-depth insights

- Proxy queries evaluated: **boundary**, **repeat-prefill**,
  **delayed future-generation**.
- Practical finding: **delay > immediacy** under agent workloads.
- Directly complements MemArbiter (this cycle) and Practical Online
  Compaction sits below the memory-arbitration layer.

## An Internet for the KV Cache — Vision Paper

- Source: <https://arxiv.org/abs/2608.01526>
- Date: 2026-08-02 (Ray, Feamster, Jiang)

### Why it matters for local models

Argues that inference infrastructure should decouple compute from KV
storage across cloud and datacenters, treating the network as an
active distribution channel where bandwidth / latency / pricing govern
placement. The direct read for local: this is the pattern **LMCache
already ships**, now written up as a design position by the LMCache
lab. Useful as a reference document when arguing for KV-as-memory in
a self-hosted cluster.

### In-depth insights

- References cache blending/editing, TurboQuant, KVzip, RocketKV,
  ChunkKV as the tool inventory.
- Vision paper, not benchmarks — but it defines the vocabulary that
  will show up in local KV-serving stack conversations next quarter.

## Infrastructure & standards

### MCP 2026-07-28 — stateless core

- Spec announcement:
  <https://blog.modelcontextprotocol.io/posts/2026-07-28/>
- Release-candidate post:
  <https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/>
- Date: 2026-07-28

Largest MCP revision since launch. Retires the
`initialize`/`initialized` exchange and the `Mcp-Session-Id` header
in favor of a request/response stateless core; a remote server that
previously needed sticky sessions can now sit behind a plain
round-robin load balancer. **The spec has no protocol-level memory
or persistent-state primitives** — the maintainers explicitly push
state into application logic via handle-passing (a tool mints an
explicit handle, the model threads it between tool calls). Direct
consequence for the local-memory ecosystem: any MCP-exposed memory
service (Letta, mem0, MemOS, supermemory all expose MCP surfaces)
now owns its persistence contract end-to-end. The Tasks concept
moves out of the experimental core into an `io.modelcontextprotocol/
tasks` extension.

### OpenDream — open-source "Dreaming" implementation

- Repo: <https://github.com/pylit-ai/opendream>
- License: Apache-2.0
- Status: alpha; MCP server planned for v0.5

Reproduces the Anthropic Dreaming pattern from last cycle without
the closed backend. Reads past sessions across Claude Code / Codex /
Cursor / OpenHands / Aider / Copilot, runs a background
consolidation pass, writes the consolidated memory back to
`AGENTS.md` so the next session starts smarter. Local SQLite,
bring-your-own LLM, no SaaS. Notable design choice: "dreaming" is
defined as deliberate memory review with explicit status/skip
reasons, not an opaque model behavior — inspectable enough to run
in a local pipeline. A second implementation (`grandamenium/
dream-skill`, four-phase consolidation with 24 h auto-trigger for
Claude Code specifically) is worth mentioning as a competing
approach. Neither has published benchmark numbers yet, so treat
both as reference implementations to fork rather than validated
gains.

## Security & governance

The security thread from last cycle (FARMA, Always-On Agents survey)
matured this cycle:

- **AuthMem-Bench** (see paper section above) — the diagnostic that
  says which of your consolidator's writes lose source authority.
  48/49 systems fail without a metadata channel; add one and the
  unauthorized-action rate goes to 0.0%.
- **MemCollusion / Salami Attack** (see paper section above) —
  attack framework that shards adversarial payloads across memory
  writes. 75% ASR on OpenClaw, effective under benign dilution and
  memory-level defenses.
- **OWASP Agentic AI Top 10** added *Memory and Context Poisoning*
  as **ASI06** this cycle (secondary coverage), prescribing five
  defense layers: input moderation, memory sanitization with
  provenance, trust-aware retrieval, behavioral monitoring, forensic
  capabilities. The OWASP text should be read as scaffolding for
  local-memory defense-in-depth rather than a validated recipe.

- **SuperLocalMemory v4** (arXiv `2608.08253`, `github.com/qualixar/
  superlocalmemory`, **AGPL-3.0** with a commercial license
  option). Positions itself as a "governed local-first memory

  distinguish product from paper.
- **QEvict** (arXiv `2608.05326`) — recoverable **quantized KV
  eviction** for attention-drift-robust long-context decoding.
  Complements RestoreKV and AnchorKV in the same cycle; not yet
  read in depth.
- **PersonaMem-v2** (arXiv `2512.06688`) — appears in indexes but
  the ID falls outside expected `2608.*` range for this cycle;
  possibly a v2 to the PersonaMem v1 that MemOS tracks.
- **Anthropic Dreaming**: still no open equivalent from
  Letta / mem0 / MemOS beyond community forks (OpenDream,
  dream-skill). If you want the pattern this quarter, you fork
  one of those.
- **No Titans / MIRAS follow-up** from Google Research surfaced in
  this window either. LiveMem (this cycle) is the closest thing to
  a lighter-touch TTT-style memory contribution and it does not
  cite Titans in the results returned by search. Still an open

  shipped its next artifact.
