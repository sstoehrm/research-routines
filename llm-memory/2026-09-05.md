# LLM Memory — 2026-09-05

## Summary

The late-July to early-September 2026 window shifted the field from
pure benchmark critique (May–July) toward **actionable diagnosis and
governance**: TEPA, MemTrapBench, Utility-Under-Attack, MemSecBench,
SafeCommit and the "Memory Trust Gap" paper all attack specific
failure modes (stale-fact revocation, cognitive traps, poisoning at
1.2% corpus contamination, capability-dependent over-trust) rather
than re-scoring end-task accuracy. On the architecture side, **Agent
Zero Memory** posted the strongest LongMemEval / LoCoMo numbers of the
year (95.60 / 93.60) with a three-store provenance-aware design;
**MemArbiter** demonstrated that a small "arbitration" layer between
memory and action can add ~25 points on ALFWorld under tight token
budgets; **Zero-Mem** and **MemCon** independently argued for
LLM-free memory paths that keep retrieval token-cost at zero. On the
runtime side, **MemOS shipped v2.0.30–v2.0.33** with a DeepSeek
Harness adapter (2026-08-13 landing of DSH triggered a wave of memory
integrations), **Cognee's v1.5 line consolidated** (Aug 15 → Sep 4),
**Letta launched an Agents SDK** for stateful cross-machine agents,
and **supermemory 0.0.7/0.0.8** added local console + emergency
vector-store repair. **LMCache 0.5.5rc5** now spans CUDA 12.9/13.0,
ROCm 7.2, Intel XPU and Moore Threads MUSA — the KV-cache-as-memory
substrate is genuinely multi-vendor. Google Cloud updated **OKF to
v0.2** with provenance/trust/freshness fields, and Google Research
published **Nested Learning (Hope architecture, NeurIPS 2025)**, whose
"continuum memory system" is the clearest post-Titans/MIRAS
alternative on the associative-memory-as-optimization line.

## Agent Zero Memory — Provenance-Aware Three-Store Memory

- Source: <https://arxiv.org/abs/2608.29606>
- Date: 2026-08-29

### Why it matters for local models

Sets a new bar on the two headline memory benchmarks — **95.60% on
LongMemEval, 93.60% on LoCoMo** — and does so across **eight backbone
models**. The architecture (three parallel stores: episodic Memory
Events timeline, entity-event knowledge graph, and semantic
citation-locked Hierarchical Documentary Memory) is model-agnostic and
composes cleanly with an open-weight backbone. It's the current
reference for "what serious memory looks like" against which any local
stack should compare.

### In-depth insights

- Three parallel systems (episodic + associative + semantic), unified
  by provenance/citation links so recall can be attributed.
- Robust across 8 backbones — not a one-model result.
- Directly competes with MIRIX / EverMemOS / MemForest on the
  same benchmarks and beats them by wide margins.
- License / code: check the arXiv page — not confirmed in this cycle.

## MemArbiter — Decision-Time Memory Arbitration for Long-Horizon Agents

- Source: <https://arxiv.org/abs/2608.02113>
- Date: 2026-08-03 (Dong, Hu, Fan, Dou, Wu, Zou)

### Why it matters for local models

Formalizes the **Memory-Action Gap** — a post-access failure distinct
from forgetting or retrieval error — and shows that a small
arbitration layer between memory and the LLM action policy is what
actually moves task success under tight token budgets. Directly
usable in front of any open-weight action model without touching the
LLM.

### In-depth insights

- Decomposes histories into atomic items, routes them into five
  functional Memory Banks, and combines bank-level demand, item-level
  relevance, focal/ambient representations, and a temporal gate.
- On ALFWorld with an open-weight action model: **82.8% success at
  500-token budget** and **92.5% at 750-token budget**,
  **+20.9 / +25.4 points** over the strongest baseline (Flat
  Retrieval / Flat Recency).
- The magnitude of the gap under a fixed budget is the point: same
  memory content, radically different action success as a function of
  presentation.

## MemTrapBench — Benchmarking Cognitive Traps in Memory Use

- Source: <https://arxiv.org/abs/2608.20202>
- Code: <https://github.com/zjunlp/MemTrapBench>
- Date: 2026-08-20 (ZJU-NLP)

### Why it matters for local models

The most damning memory benchmark of the year: **every evaluated
memory strategy underperforms the no-memory baseline**, with the
strongest suffering >10% drops. If your local stack turns on a memory
framework by default, this is the benchmark that says "measure the
regression first." Two named trap classes — Reasoning Fixation and
Belief Distortion — give you attackable failure modes rather than
opaque numbers.

### In-depth insights

- Evaluates 2 model families × 5 memory frameworks under
  memory-retrieved settings.
- Introduces **AdaptiveMem**, a mitigation that recovers most of the
  ground on MemTrapBench while preserving standard-benchmark scores.
- Data and code are open (ZJU-NLP repo).

## Zero-Mem — Zero-Token Memory Operations

- Source: <https://arxiv.org/abs/2607.29377>
- Reimplementation: <https://github.com/woolcoxm/zero-mem-pi>
- Alternate impl: <https://github.com/skorotkiewicz/zero-mem>
- Date: 2026-07-31 (Xiao, Zhu, Zhang, Chen, Hong, Zhuang, Zhang, Chen,
  Ouyang, Ren, Huang)

### Why it matters for local models

Every memory op outside final answering runs **zero LLM tokens** —
no extraction call, no reranking LLM. Preserves the raw interaction
trace as source-of-record and organizes it two ways: an entity–context
graph across interactions, and a temporal hierarchy that preserves
conversational locality. For local deployments where LLM inference is
the dominant cost, this is the strongest published "no LLM in the
memory loop" design in the window.

### In-depth insights

- Dual view: graph for cross-session structure, hierarchy for session
  locality; per query, both are weighted and traversed.
- Encoder cost is accounted separately — the "zero" refers to LLM
  input/output tokens for memory ops.
- Community reimplementations already exist (pi coding agent, generic
  Pi) — a positive sign for practical uptake.

## Memory-R1 — RL Fine-Tuned Memory Manager + Answer Agent

- Source: <https://arxiv.org/abs/2508.19828>
- ACL Anthology: <https://aclanthology.org/2026.acl-long.583/>
- HF page: <https://huggingface.co/papers/2508.19828>
- Date: v5 revision landed in-window; ACL 2026 Long

### Why it matters for local models

Two small RL-trained agents — a Memory Manager (ADD/UPDATE/DELETE/NOOP)
and an Answer Agent (pre-select + reason) — sit around a frozen LLM.
Trained with **PPO and GRPO on only 152 QA pairs**, and generalizes
across LoCoMo, MSC and LongMemEval and across **3B–14B backbones**.
Exactly the pattern a local operator wants: keep the big model frozen,
train small controllers that manage its memory.

### In-depth insights

- Outperforms strong baselines with tiny supervision budget.
- Multi-backbone generalization is the load-bearing claim.
- Fits between MemoPilot (July cycle) and MemCon (see below) as the
  "train a small policy, keep the LLM frozen" school.

## MemCon — Learned Adaptive Memory Management (No Extra LLM Calls)

- Source: <https://arxiv.org/abs/2607.13591>
- Date: 2026-07-15 (Jiang et al., UCLA / U-Washington / Northwestern)

### Why it matters for local models

Third design point between "static policy" and "LLM-mediated memory
ops": a **learned but lightweight controller** that adaptively decides
*when, what, and how much* to retrieve — with **no extra LLM calls**.
Frames memory ops as an MDP with an online-learned policy. Same
philosophical camp as Zero-Mem and MemoPilot; different mechanism.

### In-depth insights

- MDP formalism → online policy → adaptive retrieval under context
  budgets.
- Cheap to deploy on top of any backbone; expensive step is training
  the controller, not inference.

## TEPA — Revocable Evidence Memory for Conflict Resolution

- Source: <https://arxiv.org/abs/2608.07429>
- Date: 2026-08-07 (Zhou, Ouyang, Zheng, Xiang)

### Why it matters for local models

Names the failure mode **memory pollution**: active memories that
newer conflicting evidence has already superseded but that still
retrieve. TEPA represents observations as keyed precedents; when new
evidence contradicts an active precedent, it is revoked (not deleted —
history is auditable). Directly applicable to any local memory store
that persists user preferences or environment facts.

### In-depth insights

- Evaluated across three settings: controlled hidden-regime drift,
  file-backed executable drift, and preference-update streams.
- Revocation prevents stale entries from remaining in the retrieval
  set post-reversal.
- Companion to TOKI (bitemporal operator algebra) and MemConflict from
  the previous cycle — all three converge on "explicit validity state,
  not just recency."

## Utility Under Attack — Poisoning at 1.2% of Corpus

- Source: <https://arxiv.org/abs/2608.21230>
- Date: 2026-08-21 (Karunanidhi)

### Why it matters for local models

Concrete numbers on how cheaply memory can be broken: **poisoning
just 1.2% of a LongMemEval corpus drops accuracy from 0.850 to
0.300** with plainly worded false assertions — no triggers, no
optimization. The two obvious defenses fail: content screening flags
0 of 360 poisoned memories, and shipped provenance-weighted retrieval
is statistically indistinguishable from no defense (p=0.80). If you
run a persistent memory store for a local agent, plan for adversarial
writes.

### In-depth insights

- Four-stage write-time content screening reaches 0.832 recall on
  indirect prompt injection while flagging 1.5% benign — but rejects
  0/360 poisoned memories in this setting.
- Stronger provenance weighting only "recovers utility" by excluding
  untrusted content, which is degenerate.
- Read alongside MemAudit (May 2026) and MemSecBench (below) for the
  full attack/defense picture.

## MemSecBench — Write-Execute-Forget Poisoning Benchmark

- Source: <https://arxiv.org/abs/2607.27080>
- Date: 2026-07-29

### Why it matters for local models

The first task-grounded end-to-end memory-poisoning benchmark: 310
Write–Execute–Forget packages across 48 realistic contexts (code /
science / daily life / office). Tests not only whether malicious
semantics **persist**, but whether they translate into a real
**external consequence**, and whether the memory can be
**selectively repaired**. Right level of granularity for CI-style
adversarial testing of a local memory framework.

### In-depth insights

- Seven evidence-based checkpoints across three lifecycle stages.
- Runs each case in an isolated runtime with an explicit
  (agent harness × memory backend × LLM backend) triple, which makes
  cross-framework comparison honest.

## SafeCommit — Certified Safe Action Under Memory Uncertainty

- Source: <https://arxiv.org/abs/2608.04289>
- Date: 2026-08-04 (Akewar, Ranjan — FIU)

### Why it matters for local models

Sits *between* memory and any side-effectful tool call. Formalizes
"premature commitment" (acting before resolving whether the memory
grounding is stale/conflicting/incomplete/corrupted) and gates the
action on a **conformal action certificate**: only permit the action
when it is safe in every plausible latent world the memory could be
consistent with. Otherwise pick a low-side-effect probe or fall back.

### In-depth insights

- Constructs the plausible-world set from memory + observations + tool
  outputs + provenance + policy constraints.
- Complements TEPA on the "stale memory" side and MemSecBench on the
  "poisoned memory" side — all three converge on "don't commit if the
  memory could be wrong."

## Memory Trust Gap — Capability-Dependent Failure in Persistent Memory

- Source: <https://arxiv.org/abs/2609.01852>
- Date: 2026-09 (under review at a NeurIPS 2026 workshop)

### Why it matters for local models

Studies where and when the harm from stale stored facts starts as
model capability increases. Direct evaluation on **Qwen3 at 0.6B /
1.7B / 4B / 8B** — exactly the sizes people run locally. Finding:
smaller models trust a stale document more than a stale memory; at
8B the gap goes away; but across scales, stale-value answering
happens **0.92–1.00 of the time** in the Benefit suite.

### In-depth insights

- Two suites: **Benefit** (unsolvable without stored facts), **Safety**
  (an authoritative tool holds the correct value).
- Mitigation is capability-dependent: exposing metadata helps capable
  models; only pre-resolving the conflict helps the smaller ones.
- Reframes "memory is over-trust, not confusion" — a useful lens for
  local-model deployments.

## Measure Before You Manage — Working Memory in Coding Agents

- Source: <https://arxiv.org/abs/2608.31057>
- Date: 2026-08-31

### Why it matters for local models

Empirical study over **55 archived coding-agent trajectories**
demonstrating that "working memory" is not a uniform blob:
instructions, artifacts, tool outputs, and agent-generated state have
different retention, size, and compression profiles. Direct
consequence for anyone building a local coding agent: **equal token
budgets do not imply equal delivered context**, and calibration on
one task family often fails to transfer.

### In-depth insights

- Two strategies studied: object-aware compression, and
  retrieval-based; neither transfers cleanly across tasks.
- Establishes measurement as a prerequisite to management — an
  attitude that maps neatly onto MemFail / MemTrace from the previous
  cycle.

## Are We Ready For An Agent-Native Memory System?

- Source: <https://arxiv.org/abs/2606.24775>
- Code: repo linked from paper
- Date: 2026-06-23 (Zhou, Zhou, Han, Xu, Li, Li, Xiong, Wu)

### Why it matters for local models

Systematically evaluates **12 representative memory systems + 2
baselines across 11 datasets / 5 workloads**. Headline finding: **no
single architecture dominates**; effectiveness depends on aligning the
memory structure with the workload bottleneck. Practical guide when
choosing between a graph (Cognee/Graphiti), a hierarchical
(MemForest/MemOS), or a flat (mem0) backend for a specific local
deployment.

### In-depth insights

- Analytical framework decomposes memory into four modules:
  representation & storage, extraction, retrieval & routing,
  maintenance.
- Includes system-level concerns (cost, maintenance under updates) that
  end-task benchmarks skip.

## LightMem-Ego — Streaming Multimodal Memory for Wearables

- Source: <https://arxiv.org/abs/2607.11487>
- Code: <https://github.com/zjunlp/LightMem-Ego>
- Date: 2026-07-13 (ZJU-NLP)

### Why it matters for local models

Lightweight streaming multimodal memory, aligned on a shared timeline,
routed across current / short-term / long-term tiers. Demonstrated
deployable on **smartphones and AI glasses**. Fills a gap that MemLens
(previous cycle) identified: text-only compression loses visual
fidelity; LightMem-Ego is one of the first frameworks that argues for
keeping the multimodal trace resident on-device.

### In-depth insights

- Use cases: object finding, conversation recall, life summarization,
  routine discovery, personalized assistance.
- Code released on the ZJU-NLP org.

## CogniFold — Always-On Proactive Memory via Cognitive Folding

- Source: <https://arxiv.org/abs/2605.13438>
- Date: revised 2026-08 (Wang, Duan et al.)

### Why it matters for local models

Extends Complementary Learning Systems theory to a **three-layer**
(hippocampus + neocortex + prefrontal-intent) memory that continuously
folds event streams into self-emerging cognitive structures — proactive
rather than reactive/retrieval-based. Closest open equivalent to
Anthropic's "Dreaming" pattern, but formalized as graph-topology
self-organization: merge on semantic similarity, decay when stale,
relink via associative recall.

### In-depth insights

- Robust across **7 broad-coverage benchmarks** across 5 cognitive
  domains; produces structures that match cognitive expectations.
- A useful pointer for anyone trying to build a "background
  consolidation" pass on top of an existing local memory framework.

## Nested Learning — Continuum Memory System (Google, NeurIPS 2025)

- Blog: <https://research.google/blog/introducing-nested-learning-a-new-ml-paradigm-for-continual-learning/>
- Paper (arXiv): <https://arxiv.org/abs/2512.24695> (2025)
- Author PDF: <https://alibehrouz.com/files/NL.pdf>

### Why it matters for local models

Google Research's post-Titans/MIRAS entry: models are represented as
nested / multi-level optimization problems, each with its own
"context flow" — a **continuum memory system (CMS)** where different
modules update at different frequencies, generalizing the long/short
memory dichotomy. Introduces the **Hope** architecture (self-modifying
sequence model + CMS). Not a memory-framework release, but the
theoretical frame that new architectural memory papers will now be
measured against.

### In-depth insights

- CMS: high-frequency neurons for fast adaption / short-lived memory,
  low-frequency neurons for persistent knowledge.
- Direct lineage from the Titans/MIRAS line (Behrouz is a common
  author).
- Companion arXiv paper: **NestedKV (2605.26678)** applies the same
  CMS intuition to training-free KV compression, using global,
  block-level, and sliding-window key anchors — evaluated on RULER
  (4k–32k), LooGLE, LongBench(-E), InfiniteBench, MMLU-Pro on Qwen3
  and Llama-3.2.

## Security & governance

The August 2026 wave of security papers is the clearest signal in
this cycle: **eight named memory-attack / -defense / -governance
papers landed in one month**.

- **Utility Under Attack** (2608.21230) — see item above; poisoning at
  1.2% breaks LongMemEval; standard defenses ineffective.
- **MemSecBench** (2607.27080) — write-execute-forget lifecycle
  benchmark (see item above).
- **SafeCommit** (2608.04289) — action-time certificate under memory
  uncertainty (see item above).
- **TEPA** (2608.07429) — revocation-based memory pollution defense
  (see item above).
- **Memory Trust Gap** (2609.01852) — capability-dependent trust
  failures (see item above).
- **A Survey on Long-Term Memory Security in LLM Agents** (2604.16548,
  v2 in-window) — proposes **Verifiable Memory Governance (VMG)**
  with five primitives: Write Authorization, Provenance Visibility,
  Principal-Scoped Retrieval, Rollbackability, Verified Forgetting.
  The reference vocabulary for security work in this cycle.
  <https://arxiv.org/abs/2604.16548>
- **Beyond Similarity** (2606.06054) — introduces **MemGate**, a 9M
  parameter (35.1 MB) plug-in for trustworthy memory search: no LLM
  modification, no memory-DB rewrite, no inference-time LLM judge.
  Evaluated against A-Mem / Mem0 / MemOS on the OpenClaw environment
  and flags cross-domain leakage, sycophancy, tool-call drift, and
  memory-induced jailbreaks. <https://arxiv.org/abs/2606.06054>
- **MemAudit** (2605.23723) — post-hoc auditing via causal attribution
  + structural anomaly detection; reduces MINJA attack success rate
  from 70.0% → 0.0% for GPT-4o and to 0.0% on reasoning-agent
  settings across three backbones. <https://arxiv.org/abs/2605.23723>

FARMA (previous cycle) and AOEP-v0 are still the "attack surface" and
"evaluation protocol" pointers; the August cluster fills in the
concrete defenses.

  exploration-intent labels. Filed under "structured graph memory"
  camp with Cognee/Graphiti.
- **MemGraphRAG** (2606.00610, KDD 2026) — global-memory-aware graph
  construction; retrieval at ~0.061s/query, claims to beat HippoRAG2
  and LightRAG on complex reasoning + fact retrieval.
  <https://github.com/XMUDeepLIT/MemGraphRAG>
- **Eywa** (2605.30771) — provenance-grounded memory with immutable
  source evidence + deterministic LLM-free retrieval. Companion to
  Agent Zero Memory.
- **Beyond Semantic Organization / MAGE** (2606.06090) — hierarchical
  state-tree memory (Grow/Compress/Maintain/Revise) for long-horizon
  agents. USTC / Microsoft / NJU / UCSD.
- **MEMPROBE** (2606.24595) — hidden-user-state recovery as a
  post-interaction memory audit; 50 simulated users × 31 dimensions ×
  5 memory systems. Finds task completion saturates while
  state-recovery drops — an important dissociation.
- **When Stale Constraints Go Unchecked** (2608.25553) — controlled
  study over 5,400 episodes; native memory allocation gives
  stale-consistent decisions in 74.7–77.3% of episodes under
  supersession. Full artifact archived to Zenodo.
- **Same Ranking, Different Winner** (2605.24060) — TIAP audit;
  switching the credited target (Raw / Source / Canonical) changes
  nDCG on 83.4–94.0% of shared queries on LoCoMo and LongMemEval-S.
  Meta-critique of memory-benchmark scoring.
- **BEAM** (Mem0's 1M/10M-token benchmark, ICLR 2026) — 64.1% at 1M
  and 48.6% at 10M on Mem0 itself; the volume that "actually reflects
  production." Primary paper not verified in-window.
- **Agent Memory: Characterization** (2606.06448, Stanford / KU
  Leuven / MIT / Independent) — first systems characterization of
  agent memory workloads. Worth a dedicated deep dive next cycle.
- **PROJECTMEM** (2606.12329) — local-first event-sourced memory /
  judgment layer for coding agents; mentioned as a peer to
  Measure-Before-You-Manage.
- **MemArchitect** (2603.18330, revised in-window) — policy-driven
  memory-governance layer with a Triage & Bid economy across
  Lifecycle & Hygiene / Consistency & Truth / Provenance & Trust /
  Efficiency & Safety.
- **Nested Learning / Hope** (arXiv 2512.24695) — Google's post-Titans
  frame; NeurIPS 2025 already, but the Nov 2025 arXiv listing means
  the wider community only started citing it in this cycle. Load-bearing
  for architectural memory work in 2027.
