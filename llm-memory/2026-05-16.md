# LLM Memory — 2026-05-16

## Summary

The three weeks since the 2026-04-23 report were a heavy publication
burst on arXiv (the May 2605.xxxx bucket added ~12 on-topic preprints)
plus two material moves from the dominant open-source frameworks. The
architectural-memory thread split between (a) test-time KV-cache
compression that explicitly targets local hardware (Apple Silicon int4
kernels, KV-Fold's left-fold accumulator, several 2605.xxxx eviction
methods) and (b) Transformer→Hybrid-SSM "priming" that ships an
Apache-2.0 model zoo. **Mem0** published the long-form write-up of its
single-pass hierarchical-extraction algorithm and shipped an OSS v2→v3
migration that removes the external graph-store dependency. **Letta**
shipped *Context Repositories / MemFS* — a git-versioned markdown
filesystem the agent edits via its own bash tools — and a sleep-time
compute deep-dive (May 6). Two new evaluations make uncomfortable
reading: **GroupMemBench** shows the strongest commercial memory
system at 46% accuracy in multi-party chat, and **LongMemEval-V2** is
now environment-grounded (WebArena/WorkArena) rather than user-history
grounded. A recurring finding across the new evaluation work — BM25
matching most agent-memory systems in GroupMemBench, "True Memory"
beating Mem0/Supermemory/Zep with a single SQLite file — keeps echoing
the April baseline result that filesystem memory is hard to beat.

## Items

### Priming: Hybrid State Space Models From Pre-trained Transformers

- Source: <https://arxiv.org/abs/2605.08301>
- Date: 2026-05-12

#### Why it matters for local models

The most concretely useful new architectural-memory work in this
window. Converts an existing Transformer (Qwen, Llama, Mistral; dense
or MoE) into an Attention+SSM hybrid using <0.5% of the source's
pre-training token budget, slashing KV-cache size and pushing decode
throughput up to 2.3× — exactly the bottleneck local users hit.

#### In-depth insights

- Compares Gated KalmaNet (GKA), Gated DeltaNet (GDN), and Mamba-2;
  expressiveness hierarchy GKA > GDN > Mamba-2 directly predicts
  long-context reasoning quality.
- Hybrid GKA-32B improves over Qwen3-32B by +3.8 average reasoning
  points while staying within 1% of a Transformer post-trained on the
  same data.
- Releases a model zoo of primed Hybrids plus Priming training/
  inference code under **Apache-2.0**.

### When Quantization Is Free: An int4 KV Cache That Outruns fp16 on Apple Silicon

- Source: <https://arxiv.org/abs/2605.05699>
- Date: 2026-05-07

#### Why it matters for local models

Fused Metal kernel (sign-randomized FFT + per-channel λ + per-group
abs-max + int4 pack) that makes int4 KV cache *faster* than fp16 on
Mac unified memory. Directly applicable to llama.cpp/MLX users.

#### In-depth insights

- 3× persistent KV-cache memory compression with quality preserved on
  Gemma-3 1B (−3 to −8% ms/tok at 256–4096 tokens) and Qwen2.5-1.5B
  (−0.7 to −2.6% through 1K).
- Closes Qwen's notorious 4-bit-per-token catastrophe: ΔPPL +7975 →
  +638.6 (12.5× reduction).
- SRFT and SRHT shown statistically indistinguishable for KV quality.
- No code/license info in the abstract — verify on the arXiv page
  before integrating.

### KV-Fold: One-Step KV-Cache Recurrence for Long-Context Inference

- Source: <https://arxiv.org/abs/2605.12471>
- Date: 2026-05-14

#### Why it matters for local models

Training-free, model-agnostic protocol that treats the KV cache as a
left-fold accumulator over chunks. Runs on frozen weights and lets a
single 40 GB GPU reach 128K context on Llama-3.1-8B at 100% needle-
in-haystack accuracy.

#### In-depth insights

- 100% exact-match recall across 152 trials, contexts 16K–128K, chain
  depths up to 511.
- Per-step drift saturates into a flat plateau insensitive to a
  10,000× change in numerical precision — robust across chunk sizes
  and model families.
- No architectural changes, no fine-tuning, no extra training data.
  Public code release status not stated in the abstract.

### MemFlow: Intent-Driven Memory Orchestration for Small Language Model Agents

- Source: <https://arxiv.org/abs/2605.03312>
- Date: 2026-05-05

#### Why it matters for local models

Explicitly designed for SLMs that buckle under MemGPT-style open-ended
agentic loops; tested on Qwen3-1.7B — a model that runs on a laptop.

#### In-depth insights

- Training-free three-tier dispatch (Profile Lookup / Targeted
  Retrieval / Deep Reasoning) driven by a Router Agent that
  classifies intent, plus a Validator Agent that retries with a
  heavier tier on unsupported answers.
- Nearly 2× accuracy improvement over full-context Qwen3-1.7B
  baselines on LongMemEval, LoCoMo, and LongBench.
- Authors: NJIT. License/code release not confirmed from the
  abstract.

### Storage Is Not Memory: A Retrieval-Centered Architecture for Agent Recall ("True Memory")

- Source: <https://arxiv.org/abs/2605.04897>
- Date: 2026-05-07

#### Why it matters for local models

The entire "True Memory" system runs as a single SQLite file on
commodity CPU — no vector index, no graph store, no GPU. About as
local as it gets, and it beats most agent-memory frameworks on LoCoMo.

#### In-depth insights

- 93.0% on LoCoMo (1,540 questions, 10 multi-session conversations),
  beating Mem0 (61.4%), Supermemory (65.4%), Zep (~71%); only
  EverMemOS (94.5%) is reportedly higher.
- Six-layer architecture centered on a multi-stage retrieval pipeline
  over **verbatim events** — the thesis being that
  extraction-at-ingestion is the wrong primitive because discarded
  content can't be recovered at query time.
- Theoretical grounding in reconstructive recall, episodic/semantic
  distinction, levels-of-processing effects.

### GroupMemBench: Benchmarking LLM Agent Memory in Multi-Party Conversations

- Source: <https://arxiv.org/abs/2605.14498>
- Date: 2026-05-14

#### Why it matters for local models

Single most important new evaluation in this window. Current memory
systems are built for dyadic chats; GroupMemBench exposes how badly
they fail in groups (workplace, channels, family) — the exact regime a
local household assistant has to handle.

#### In-depth insights

- Graph-grounded synthesis pipeline produces multi-party conversations
  with per-user personas and target audiences; six adversarial query
  categories (multi-hop, knowledge update, term ambiguity, user-
  implicit, temporal, abstention).
- Strongest memory system reaches only **46.0%** average accuracy;
  knowledge update collapses to **27.1%**, term ambiguity to **37.7%**.
- A simple **BM25 baseline matches or exceeds most agent memory
  systems** — echoing Letta's earlier filesystem-as-memory result.

### LongMemEval-V2: Toward Memory That Makes Agents Experienced Colleagues

- Source: <https://arxiv.org/abs/2605.12493>
- Date: 2026-05-14

#### Why it matters for local models

V2 is environment-grounded (Magento, ServiceNow, Postmill, shopping-
admin, etc. from WebArena/WorkArena) rather than user-history-grounded
— relevant for a local agent that has to learn a *specific workflow*.

#### In-depth insights

- 451 manually curated questions across five competencies: static
  state recall, dynamic state tracking, workflow knowledge,
  environment gotchas, premise awareness.
- Two-API formulation (Insert(trajectory), Query → multimodal context
  truncated to a fixed token budget, then a fixed reader LLM answers)
  — clean to plug local models in as the reader.
- First explicit benchmark for "memory that makes agents experienced
  colleagues" rather than a personalized chat assistant.

### Mem0 — Token-Efficient Algorithm + OSS v2→v3 migration

- Source: <https://mem0.ai/blog/mem0-the-token-efficient-memory-algorithm>
- Secondary: <https://docs.mem0.ai/migration/oss-v2-to-v3>,
  <https://github.com/mem0ai/mem0>
- Date: blog late April / early May 2026; v3 GA in this window

#### Why it matters for local models

OSS v2→v3 migration is documented, and built-in entity linking removes
the external graph-store dependency (you can run it without Neo4j).

#### In-depth insights

- 92.5 on LoCoMo, 94.4 on LongMemEval, 64.1/48.6 on BEAM (1M/10M),
  ~6,956 tokens/retrieval — largest gains on temporal (+29.6) and
  multi-hop (+23.1) over the old algorithm.
- Single-pass hierarchical extraction (one LLM call, add-only, every
  fact independent), multi-signal hybrid retrieval (semantic + BM25 +
  entity match).
- **Apache-2.0** OSS; entity linking now built-in via a parallel
  `{collection}_entities` collection.

### Letta — Sleep-time Compute deep-dive + Context Repositories (MemFS)

- Source: <https://www.letta.com/blog/sleep-time-compute>
- Secondary: <https://www.letta.com/blog/context-repositories>,
  <https://github.com/letta-ai/letta-code>,
  <https://github.com/letta-ai/context-constitution>
- Date: sleep-time-compute write-up 2026-05-06; MemFS `/memfs enable`
  rollout to existing agents in this window

#### Why it matters for local models

Letta Code explicitly supports local inference servers; MemFS stores
the agent's memory as a directory of markdown files in
`~/.letta/agents/<id>/memory`, git-versioned and editable by the
agent's own bash tools — model-agnostic and portable across Claude,
GPT, Gemini, GLM, Kimi, and local backends.

#### In-depth insights

- Sleep-time agents share memory blocks with primary agents and run
  asynchronously to consolidate/rewrite memory between tasks
  (offloaded memory management).
- Git-backed MemFS lets concurrent sub-agents write to memory in
  isolated worktrees and merge via standard git conflict resolution
  — a real differentiator vs. Mem0/Zep.
- Letta Code is currently the #1 model-agnostic open-source agent on
  Terminal-Bench (42.5%, 4th overall, 2nd among Claude 4 Sonnet
  agents).

### Survey: From Storage to Experience — Evolution of LLM Agent Memory Mechanisms

- Source: <https://arxiv.org/abs/2605.06716>
- Companion list:
  <https://github.com/FeishuLuo/Evolving-LLM-Agent-Memory-Survey>
- Date: 2026-05-07

#### Why it matters for local models

Provides a clean three-stage framework (Storage / Reflection /
Experience) and an actively maintained paper list — useful for picking
which OSS memory layer to bet on.

#### In-depth insights

- Three drivers identified: long-range consistency, dynamic
  environments, continual learning.
- Two frontier mechanisms in the "Experience" stage: proactive
  exploration and cross-trajectory abstraction.

## Honorable mentions (one line each)

- **MemReranker** — <https://arxiv.org/abs/2605.06132> (May 8): 0.6B/
  4B rerankers distilled from Qwen3-Reranker; the 4B reaches
  0.737 MAP, matching Gemini-3-Flash at 10–20% latency. Drop-in for
  local agent memory pipelines.
- **BeliefMem** — <https://arxiv.org/abs/2605.05583> (May 7):
  probabilistic memory entries with Noisy-OR updates; best avg on
  LoCoMo + ALFWorld.
- **MemORAI** — <https://arxiv.org/abs/2605.01386> (May 2): selective
  filtering + provenance-tracked graph + query-adaptive subgraph
  retrieval with Dynamic Weighted PageRank; SOTA on LoCoMo +
  LongMemEval.
- **MAGE: Shadow Memory for Long-Horizon Threats** —
  <https://arxiv.org/abs/2605.03228> (May 4): security-focused
  "shadow stack" memory for agents.
- **EvolveMem: Self-Evolving Memory via AutoResearch** —
  <https://arxiv.org/abs/2605.13941> (May 13): exposes retrieval
  config as an action space optimized by an LLM diagnosis module;
  +25.7% relative on LoCoMo, +18.9% on MemBench.
- **Circuit Analysis Inside Agent Memory** —
  <https://arxiv.org/abs/2605.03354> (May 4): mechanistic
  interpretability of mem0 + A-MEM across Qwen-3 0.6B–14B; finds
  "control circuitry active at 0.6B but content circuitry needs ≥4B"
  — directly relevant if you're picking a base model for a local
  memory agent. 76.2% silent-failure localization.
- **Not All Thoughts Need HBM** —
  <https://arxiv.org/abs/2605.09490> (May 10): 4-tier (HBM/DDR/
  compressed/evicted) semantics-aware hierarchy avoids the accuracy
  collapse (0–2.5%) conventional eviction causes for reasoning
  models.
- **FibQuant** (<https://arxiv.org/abs/2605.11478>), **LaProx**
  (<https://arxiv.org/abs/2605.07234>), **eOptShrinkQ**
  (<https://arxiv.org/html/2605.02905>), **LKV**
  (<https://arxiv.org/html/2605.06676>): four more 2605 KV-cache
  compression/eviction methods, all targeting long-context inference
  on a single accelerator.
- **Survey: Security of Long-Term Memory in LLM Agents** —
  <https://arxiv.org/abs/2604.16548> (Apr 17, just inside the
  window): "Mnemonic Sovereignty" framing; nine governance
  primitives, no published architecture covers all.
