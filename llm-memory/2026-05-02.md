# LLM Memory — 2026-05-02

## Summary

Nine days after the previous report, the deltas are concentrated in two
areas: (1) the **memory-framework race** has heated up — `mem0` shipped
a v2.x line that collapses graph memory into in-process entity linking,
and `claude-mem` pushed eleven releases including a fix that drops
Chroma-worker CPU from 422% to ~0% on restart; and (2) a wave of late-
April arXiv preprints reframes memory beyond raw retrieval — KV-cache
compression with code-structure priors (CodeComp), continual learning
recast as a retrieval problem (Hu et al.), a personalized memory
benchmark with explicit *forget-on-request* tasks ("From Recall to
Forgetting"), an "Experience Compression Spectrum" that puts skills as
the missing middle layer, and a 7-layer neuroscience-inspired
reference architecture (ZenBrain). The ICLR 2026 MemAgents workshop
also surfaced an oral spotlight (MemAgent: RL-trained memory
controller on a frozen base) that composes with any open backbone. No
open-weight reimplementation of Titans/MIRAS has shipped yet.

## mem0 v2.0.x → ts-v3.0.2: hybrid retrieval + in-process entity linking

- Source: <https://github.com/mem0ai/mem0/releases>
- Date: v2.0.0 line 2026-04-16, v2.0.1 Python 2026-04-25, ts-v3.0.2 in
  the same window.

### Why it matters for local models

mem0 is the default Apache-2.0 memory layer for any local-model agent
loop. v2.0.0 collapses the previous Neo4j/Memgraph graph backend into
in-process entity linking, which removes an external service
dependency for self-hosted setups and makes the framework usable on a
single laptop without a separate graph DB.

### In-depth insights

- Hybrid retrieval = vector + BM25 + entity-graph boost fused into one
  normalized score; all 15 supported vector stores now expose
  `keyword_search()` / `search_batch()`.
- Single-pass extraction collapses two LLM calls per `add()` into one
  (~50% latency reduction, vendor-reported).
- Headline benchmark gains (vendor-reported, **not yet third-party
  reproduced**): LoCoMo 71.4 → 91.6; LongMemEval 67.8 → 93.4. Whether
  these hold against open-weight backbones (Qwen3 / Llama-4) instead of
  GPT-4o is the obvious follow-up.
- 2026-04-29 OpenClaw integration plugin v1.0.11 added dimension-aware
  vector collections for embedder swaps and lowered the default
  similarity threshold from 0.5 to 0.1 — bare default was rejecting
  too many matches.
- License unchanged: Apache-2.0.

## claude-mem v12.3.7 → v12.4.9: 11 releases in the window

- Source: <https://github.com/thedotmack/claude-mem/blob/main/CHANGELOG.md>
- Date: 2026-04-20 through 2026-04-30.

### Why it matters for local models

`claude-mem` is the most-installed Claude Code memory plugin (per the
prior report), but its storage layer (Chroma) and observation pipeline
run locally and can be pointed at any local embedder. Several of the
in-window fixes are practical workstation issues, not Claude-specific.

### In-depth insights

- Watermark caching cut Chroma-worker CPU from 422% to ~0% on restart
  — the kind of fix that makes the local DB usable on a laptop.
- Observation **type isolation** + bearer-auth removal +
  localhost-only CORS hardening (security review of the embed server).
- PID-reuse detection for container / devcontainer workflows.
- Async summarization queue + a Telegram-notifier observation type
  added 2026-04-22.
- License: MIT (unchanged); plugin still depends on
  `@anthropic-ai/agent-sdk` for compression, but storage stays local
  in Chroma.

## CodeComp — Structural KV-Cache Compression for Agentic Coding

- Source: <https://arxiv.org/abs/2604.10235>
- Date: 2026-04-11 (widely circulated through Apr 20–30).

### Why it matters for local models

Training-free, model-agnostic, and explicitly designed to integrate
into **SGLang** — which means it runs against any open-weight code
model under aggressive memory budgets on a single GPU. It is the
first KV-compression method to use code-structure priors, which is
directly relevant to local agentic coding loops where the budget is
tight and the prompt is structured.

### In-depth insights

- Uses Joern's Code Property Graph priors to mark call sites, branch
  conditions, and assignments as eviction-protected spans.
- Two mechanisms: span-level structural protection +
  structure-aware budget allocation per chunk.
- Beats attention-only KV-compression baselines at equal memory and
  matches uncompressed full-context patch quality on bug-localization
  and code-generation benchmarks (paper claims; baselines named in
  the paper).
- Authors: HKU + LMSYS Org. Code expected to land in SGLang plugin
  form per the paper text; no standalone repo visible yet.

## "When Continual Learning Moves to Memory" — Hu et al.

- Source: <https://arxiv.org/abs/2604.27003>
- Date: 2026-04-29.

### Why it matters for local models

Reframes continual learning for agents that *cannot* fine-tune
weights — i.e. the typical local-LLM situation — and shows that the
classical stability–plasticity dilemma re-emerges at the **retrieval
layer**, not at the weight layer. Concrete falsification of the
"dump everything into a memory store and retrieve" default.

### In-depth insights

- Introduces a (k, v) framework decoupling representation form (raw
  trajectory vs. abstracted procedure) from organization (flat /
  clustered / hierarchical).
- Empirical setting: ALFWorld + BabyAI sequential tasks — both small
  enough to run with 7B-class open models.
- Finding: abstract procedural memories transfer more reliably than
  detailed trajectories; negative transfer concentrates on hard
  cases.
- Practical implication: an explicit forgetting / compression policy
  is required, not optional, once you have multi-task agent memory.

## "From Recall to Forgetting" — personalized long-term memory benchmark

- Source: <https://arxiv.org/abs/2604.20006>
  (HTML mirror: <https://arxiv.org/html/2604.20006v1>)
- Date: 2026-04-28.

### Why it matters for local models

New benchmark axis (selective forgetting) that LoCoMo / LongMemEval
do not cover. Evaluable against locally hosted memory stacks (Letta,
mem0, supermemory, OpenMemory). Privacy-aligned by construction.

### In-depth insights

- Targets personalized agents over weeks-to-months conversation
  horizons.
- Three task types: remembering, reasoning, recommending — plus an
  explicit **forget-on-request** evaluation aligned with privacy
  semantics.
- Complements MemoryAgentBench (which covers retrieval / TTL /
  long-range / forgetting at a more abstract level).
- Public dataset release in progress per the abstract; primary author
  roster overlaps with prior MemTrack work.

## "Experience Compression Spectrum" — episodes, skills, rules

- Source: <https://arxiv.org/abs/2604.15877>
- Date: 2026-04-22.

### Why it matters for local models

Provides a design vocabulary for picking storage tiers in a local
agent stack (raw episode store → distilled skill → declarative rule)
and quantifies the compression budget at each tier.

### In-depth insights

- Reports compression ratios: episodic 5–20×, procedural skills
  50–500×, declarative rules 1000×+.
- Argues skills are the **missing middle layer** between Letta-style
  raw episodic stores and DSPy-style hard rules — a useful framing
  given that most existing memory frameworks ignore the procedural
  tier.
- Architecture-agnostic; code release announced but not yet linked
  from the arXiv abstract page.

## ZenBrain — 7-layer neuroscience-inspired memory architecture

- Source: <https://arxiv.org/abs/2604.23878>
- Date: 2026-04-26.

### Why it matters for local models

Reference architecture comparable to MemOS / EverMemOS but more
granular; useful as a checklist when designing a self-hosted stack.
Heavy on theory.

### In-depth insights

- Seven layers: working, short-term, episodic, semantic, procedural,
  core, cross-context — orchestrated by nine algorithms
  (consolidation, decay, salience, etc.).
- Integrates 15 cited neuroscience models. Lighter on benchmark
  numbers than MemOS-class systems.
- Explicitly contrasts itself with two-tier (short / long) systems
  like Mem0 and three-tier ones like MemMachine.

## SuperLocalMemory v3.x — local-only AI memory

- Source: <https://github.com/qualixar/superlocalmemory>
- Date: April 2026 (v3.x line; v2.8.0 baseline 2026-02-26, ~9
  releases since).

### Why it matters for local models

Self-described as "first local-only AI memory" — AGPL-3.0, with no
cloud calls in Mode A. If the numbers reproduce, it's the strongest
zero-cloud baseline.

### In-depth insights

- LoCoMo numbers (vendor-reported): Mode A zero-cloud 74.8%, Mode A
  open-domain QA 85.0%, Mode C with local LLM 87.7% — vs. their
  cited Mem0 baseline 64.2%.
- 1,986 questions across 10 multi-session conversations.
- Backing paper claimed at arXiv 2603.14588 ("Information-Geometric
  Foundations for Zero-LLM Enterprise Agent Memory") with Zenodo DOI
  10.5281/zenodo.19038659. The arXiv page was **not independently
  verified** during this research run; treat numbers as vendor
  claims until reproduced.
- License: AGPL-3.0 (commercial license offered).

## ICLR 2026 MemAgents workshop — MemAgent oral spotlight

- Source: <https://iclr.cc/virtual/2026/oral/10007826>
- Workshop site: <https://sites.google.com/view/memagent-iclr26/>
- OpenReview group: ICLR.cc/2026/Workshop/MemAgent
- Date: workshop late April 2026.

### Why it matters for local models

"MemAgent: Reshaping Long-Context LLM with Multi-Conv RL-based
Memory Agent" was promoted to oral. It is an RL-trained memory
controller that sits on top of a frozen base model, so it composes
with any open-weight backbone without retraining the base weights.

### In-depth insights

- Multi-conversation RL signal (not just single-trajectory) trains
  the controller to decide what to keep across sessions.
- Frozen-base architecture means it works against any local
  llama.cpp / vLLM endpoint without weight changes.
- No comprehensive proceedings dump yet at time of writing; the
  OpenReview group is the canonical source.

## Open questions / follow-ups

- Are mem0's headline LoCoMo (91.6) and LongMemEval (93.4) numbers
  reproducible by a third party against an **open-weight** backbone
  (Llama-3.x / Qwen-3), or are they GPT-4o-bound?
- SuperLocalMemory's arXiv 2603.14588 needs primary verification —
  does the paper exist on arXiv, and do the LoCoMo numbers hold
  without the vendor's own evaluation harness?
- Is there an open-weight reimplementation of Titans / MIRAS that has
  shipped trained checkpoints since the late-2025 critiques? None
  surfaced in this window — re-check after the ICLR proceedings drop.
- CodeComp says it "integrates into SGLang" — is there a public PR /
  branch, and how does it stack against KV-Press / KIVI for long
  agentic coding sessions?
- With Hu et al. arguing retrieval is the new continual-learning
  bottleneck, do mem0's hybrid-retrieval gains actually translate to
  better cross-session task transfer, or just better single-question
  recall?
