# LLM Memory — 2026-04-23

## Summary

Memory is being treated in 2026 as the main bottleneck for agentic
systems rather than raw model capability. The field has split into
three concurrent threads: (1) **architectural memory** that learns at
test time (Google's Titans + MIRAS, NVIDIA's "context as training
data"), (2) **agentic memory frameworks** usable with any open-weight
model (Letta née MemGPT, mem0, MemOS, MAGMA, EverMemOS), and
(3) **rigorous evaluation** on long-horizon benchmarks (LoCoMo,
LongMemEval, MemTrack, MemoryBench). The ICLR 2026 **MemAgents**
workshop has become the central venue. A new survey ("Memory in Large
Language Models", arXiv 2509.18868, with updates into early 2026)
consolidates five mechanism families: context-resident compression,
retrieval-augmented stores, reflective self-improvement, hierarchical
virtual context, and policy-learned management. For local-model
practitioners the most actionable items this cycle are the Letta vs.
mem0 split, llama.cpp gaining first-class agentic/MCP loops (see the
agent-harness report), and new evidence that a plain filesystem can
match or beat many "smart" memory stacks.

## ICLR 2026 Workshop: MemAgents — Memory for LLM-Based Agentic Systems

- Source: <https://iclr.cc/virtual/2026/workshop/10000792>
- Proposal PDF: <https://openreview.net/pdf?id=U51WxL382H>
- Date: 2026 (ICLR 2026 cycle)

### Why it matters for local models

The workshop has become the default place where open-source memory
frameworks (Letta, mem0, MemOS, Zep) publish next to academic papers,
so the accepted list is a good filter for what is actually being
reproduced on open weights.

### In-depth insights

- Framing: the limiting factor for agentic systems is not raw
  capability but how agents encode, retain, retrieve, and consolidate
  experience.
- Groups five mechanism families (compression, retrieval stores,
  reflective self-improvement, hierarchical virtual context,
  policy-learned management) — a taxonomy that's now being reused in
  follow-up work.
- Strongly overlaps with the survey "Memory for Autonomous LLM Agents:
  Mechanisms, Evaluation, and Emerging Frontiers" (arXiv 2603.07670).

## Survey: "Memory in Large Language Models — Mechanisms, Evaluation and Evolution"

- Source: <https://arxiv.org/abs/2509.18868>
- Companion lists:
  <https://github.com/Shichun-Liu/Agent-Memory-Paper-List>,
  <https://github.com/TsinghuaC3I/Awesome-Memory-for-Agents>
- Date: original Sep 2025, updates into early 2026.

### Why it matters for local models

Covers work from 2022 through early 2026 and explicitly tracks which
techniques have open-source implementations. Useful as a "what to
read first" index when catching up.

### In-depth insights

- Breaks memory into short-term (KV cache, windowing), working memory
  (scratchpads, sketches), long-term (retrieval, parametric edits),
  and procedural (skills, tool-use memories).
- Highlights the move from stateless RAG to "autonomous memory
  orchestration" where the model decides what to store and when to
  retrieve.
- Calls out open evaluation gaps: temporal/causal dynamics, abstention,
  knowledge updates — exactly what LongMemEval and MemTrack target.

## Google Research: Titans + MIRAS — Learning to Memorize at Test Time

- Source (blog):
  <https://research.google/blog/titans-miras-helping-ai-have-long-term-memory/>
- Paper: <https://arxiv.org/abs/2501.00663>
- Date: paper Jan 2025, MIRAS framing and follow-ups 2026.

### Why it matters for local models

Not local today — weights are not released — but Titans-style blocks
are already being re-implemented in open repos (several Hacker News
threads and re-implementations in early 2026). If the approach holds
it changes what "context length" means for small local models, because
long-term memory stops being an external store.

### In-depth insights

- Three components: a short-term **core** using standard attention,
  a **long-term neural memory** that is updated online, and
  **persistent memory** — fixed learned parameters for time-
  independent knowledge.
- Uses a "surprise" signal to gate what gets written to the long-term
  module; only surprising or goal-relevant tokens are consolidated.
- Scales to ~2M-token effective contexts and reports higher retrieval
  accuracy on BABILong than several larger baselines including GPT-4.
- MIRAS is the theoretical umbrella generalizing Titans into a family
  of "test-time memorization" architectures, blending the throughput
  of RNNs/SSMs with the accuracy of attention.

## NVIDIA: "Context as Training Data" — Test-Time Learning

- Source:
  <https://developer.nvidia.com/blog/reimagining-llm-memory-using-context-as-training-data-unlocks-models-that-learn-at-test-time/>
- Date: early 2026.

### Why it matters for local models

Shows an implementation path where a local model runs a lightweight
LoRA/adapter update at inference time over its own conversation
history, turning context into durable memory without re-training the
base weights. Compatible with llama.cpp-style local stacks.

### In-depth insights

- Frames context windows as a transient form of training data that
  can be consolidated via small gradient steps on cached activations.
- Reports gains on long-horizon retrieval tasks vs. fixed-weight
  baselines at equivalent compute.
- Open question the piece does not fully answer: catastrophic
  forgetting on earlier tasks when adapters keep being updated.

## Agentic Memory Frameworks: Letta (MemGPT) vs. mem0

- Letta: <https://github.com/letta-ai/letta>,
  <https://www.letta.com/blog/memgpt-and-letta>
- mem0 comparison:
  <https://vectorize.io/articles/mem0-vs-letta>
- 2026 landscape:
  <https://medium.com/@bumurzaqov2/top-10-ai-memory-products-2026-09d7900b5ab1>
- Date: ongoing through 2026.

### Why it matters for local models

These are the two dominant Apache-2.0 frameworks you can point at a
local Ollama/vLLM/llama.cpp endpoint today. Picking correctly avoids
locking your agent into a particular runtime.

### In-depth insights

- **Letta** is a runtime: agents execute *inside* Letta and use its
  three-tier memory (core / archival / recall) inspired directly by OS
  virtual memory. Good when you want one system of record for the
  agent.
- **mem0** is a memory layer: a drop-in SDK that any framework
  (LangChain, CrewAI, AutoGen, custom loops) can call. Good when you
  already have an agent loop and just need persistence.
- Both are Apache-2.0 and self-hostable. Letta expects a persistent
  backend (Postgres). mem0 is more embeddable.
- Letta's own benchmarking (<https://www.letta.com/blog/benchmarking-ai-agent-memory>)
  found that a **filesystem-backed memory** is surprisingly hard to
  beat — an important baseline when evaluating any fancier system.

## Early-2026 Papers Worth Tracking

- **MemRL: Self-Evolving Agents via Runtime RL on Episodic Memory**
  (2026/01) — uses RL to decide what to promote from episodic to
  long-term memory.
- **MAGMA: Multi-Graph Agentic Memory Architecture** (2026/01) —
  separate graphs for entities, events, and procedures; pluggable
  retrievers per graph.
- **EverMemOS: Self-Organizing Memory Operating System** (2026/01) —
  memory reorganization as a background process, inspired by OS
  paging/compaction.
- **Agentic Memory: Unified Long- and Short-Term Management**
  (2026/01) — single policy learned to schedule reads/writes across
  tiers.
- Source list:
  <https://github.com/Shichun-Liu/Agent-Memory-Paper-List>

### Why they matter

These are the first papers that treat the memory *policy* itself as a
first-class learned component, rather than a fixed heuristic. All four
claim to work with open-weight backbones in their eval setup.

## Benchmarks: LoCoMo, LongMemEval, MemTrack, MemoryBench

- LoCoMo: <https://snap-research.github.io/locomo/>
- LongMemEval: <https://arxiv.org/pdf/2410.10813>,
  <https://openreview.net/forum?id=pZiyCaVuti>
- MemTrack: <https://arxiv.org/pdf/2510.01353>
- MemoryBench: <https://github.com/supermemoryai/memorybench>
- Benchmark meta-critique:
  <https://arxiv.org/pdf/2510.27246>

### Why it matters for local models

These are the standard evaluations for claiming "our memory works".
Running a local stack against them is the cheapest way to know whether
a framework is worth adopting.

### In-depth insights

- **LoCoMo**: 10 multi-session dialogues, ~198 QA items each across
  ~27 sessions, ~588 turns. Tests QA, event summarization,
  multi-modal generation.
- **LongMemEval**: 500 questions grouped into five abilities —
  information extraction, multi-session reasoning, temporal
  reasoning, knowledge updates, abstention. Average ~115K tokens of
  history per question.
- **MemTrack** (2025) targets *state tracking* specifically, not just
  retrieval — important for agent workflows.
- **MemoryBench** (supermemoryai) is a unified harness that runs
  multiple datasets through the same interface; useful if you want
  apples-to-apples numbers across frameworks.
- Meta-critique "Benchmarking and Enhancing Long-Term Memory in LLMs"
  (arXiv 2510.27246) documents that even RAG-augmented models still
  lag humans badly on temporal / causal reasoning, and that score
  deltas between frameworks are small relative to backbone choice.

## Open questions / follow-ups

- Reproduce Titans on an open backbone (Qwen3 / Llama 4) and confirm
  the BABILong numbers; track any open implementations.
- Run LongMemEval and LoCoMo against Letta + mem0 + a filesystem
  baseline on the same local model and record score deltas for the
  next execution.
- Watch MemAgents ICLR 2026 accepted list for any framework with
  better-than-filesystem results.
- Decide whether "context as training data" style adapters are
  compatible with llama.cpp / vLLM serving without retraining the
  base model.
