# LLM Memory — 2026-05-09

## Summary

The two and a half weeks since the last report were dominated by the
**ICLR 2026 MemAgents workshop** (held April 26–27 in Rio de Janeiro)
and a wave of new arXiv preprints that orbit the same themes:
graph-structured agentic memory, KV-cache compression for on-device
inference, and theoretical critiques of "RAG-as-memory". Notable new
papers include **HeLa-Mem** (Hebbian associative memory), **OCR-Memory**
(rendering trajectories to images for VLM retrieval), **ContextWeaver**
(dependency-graph reasoning memory), and a NTU position paper arguing
that moving continual learning from weights into memory just relocates
the stability-plasticity dilemma into retrieval contention. **mem0**
shipped a patch series (v2.0.1/2.0.2 Python, v3.0.2/3.0.3 Node) that
fixes a real PGVector distance-math bug, plus an OpenClaw plugin update
adding dimension-aware collections — important for users who swap local
embedding models. **Cognee** cut a 0.5.8rc1 release. **Letta** had no
release in window. No new benchmark releases of note.

## HeLa-Mem: Hebbian Learning and Associative Memory for LLM Agents

- Source: <https://arxiv.org/abs/2604.16839>
- Date: late April 2026.

### Why it matters for local models

Pure graph + activation logic, no proprietary embedding tricks. The
dual-store design lets a small open-weight backbone offload associative
recall to a cheap external graph and stay inside a tight context
budget.

### In-depth insights

- Models conversational history as a dynamic Hebbian graph; uses online
  co-activation to strengthen edges.
- "Hebbian Distillation" consolidates hub clusters into a semantic
  store; retrieval is a dual path (spreading activation + semantic
  lookup).
- Reports best average rank (1.25) across LoCoMo question categories
  with significantly fewer context tokens than embedding-only baselines.
- Code/license: not verified from the abstract page; check repo before
  adopting.

## OCR-Memory: Optical Context Retrieval for Long-Horizon Agent Memory

- Source: <https://arxiv.org/abs/2604.26622>
- Date: April 29, 2026.

### Why it matters for local models

Routes long agent histories through a cheap open VLM (Qwen2-VL,
InternVL) instead of growing the LLM context. Compresses agent history
far beyond what a 4–32K-context Llama can hold without re-training the
backbone.

### In-depth insights

- Renders historical trajectories into images annotated with visual
  identifiers.
- Retrieval is "locate-and-transcribe": a visual anchor selects a
  region, OCR returns verbatim text — avoids free-form generation
  drift.
- Trades token budget for pixels; reports consistent gains on
  long-horizon agent benchmarks under strict context limits.

## ContextWeaver: Selective and Dependency-Structured Memory Construction for LLM Agents

- Source: <https://arxiv.org/abs/2604.23069>
- Date: April 24, 2026.

### Why it matters for local models

Token efficiency is the binding constraint for local coding agents
(DeepSeek-Coder, Qwen2.5-Coder, Qwen3-Coder-Next). Structured
dependency memory reportedly improves SWE-bench pass@1 without
needing a frontier-context model.

### In-depth insights

- Builds a dependency graph over reasoning steps rather than flat
  retrieval; emits compact root-to-step summaries.
- Lightweight execution-feedback validator gates which steps are
  promoted into long-term memory.
- Outperforms sliding-window baselines on SWE-Bench Verified and Lite
  at higher pass@1 with fewer reasoning steps and tokens (concrete
  deltas in the paper, not yet reproduced externally).

## When Continual Learning Moves to Memory: Experience Reuse in LLM Agents

- Source: <https://arxiv.org/abs/2604.27003>
- Date: April 29, 2026 (NTU Singapore).

### Why it matters for local models

Concrete guidance for what to actually store in mem0 / Letta when
wrapping a small open model: prefer abstracted procedural memories,
avoid raw trajectories on hard cases.

### In-depth insights

- Argues the stability-plasticity dilemma does not vanish when
  continual learning moves from weights to external memory — it
  relocates to retrieval contention.
- Introduces a (k,v) framework decoupling representation from
  organization.
- Empirically on ALFWorld and BabyAI: abstract procedural memories
  transfer reliably; detailed trajectories cause **negative transfer**
  on hard cases.

## Contextual Agentic Memory is a Memo, Not True Memory

- Source: <https://arxiv.org/abs/2604.27707>
- Date: April 30, 2026.

### Why it matters for local models

Strong theoretical case that the local-LLM + vector-DB stack is
structurally limited. Motivates work on weight-level consolidation
(LoRA-on-the-fly, NVIDIA "context as training data", Titans-style
neural memory) for open backbones.

### In-depth insights

- Position paper: vector stores, RAG, scratchpads, and context
  management are *retrieval*, not memory.
- Proves a generalization ceiling and shows persistent susceptibility
  to memory poisoning.
- Grounds the critique in Complementary Learning Systems theory; calls
  for a missing "neocortical" weight-consolidation half.

## SparKV: Overhead-Aware KV Cache Loading for Efficient On-Device LLM Inference

- Source: <https://arxiv.org/abs/2604.21231>
- Date: late April 2026.

### Why it matters for local models

Hybrid edge/cloud KV cache is a credible path for running 7–14B open
models on phones / Jetson-class devices without prefill stalls.

### In-depth insights

- Cloud partitions KV cache into chunks indexed along token / head /
  layer.
- An on-device scheduler decides per-chunk whether to stream from
  cloud or recompute locally, using an MLP latency predictor and a
  sliding-window throughput controller.
- Reports up to 5.1× lower TTFT and 1.5–3.3× lower per-request energy.

## Adaptive KV-Cache Quantization for Lightweight On-Device LLMs

- Source: <https://arxiv.org/abs/2604.04722>
- Date: early April 2026 — borderline pre-window, listed for completeness.

### Why it matters for local models

Tested directly on **SmolLM-360M**, the canonical on-device open model;
results map cleanly to llama.cpp / MLX deployments.

### In-depth insights

- Learned per-token policy selects from {2, 4, 8-bit, FP16} using
  token frequency, attention variance, and entropy.
- On SmolLM-360M / HellaSwag: **17.75% lower decoding latency** vs.
  static quant, **+7.60 accuracy**, within **0.30 of FP16**.

## Framework releases

### mem0 — Python v2.0.1 / v2.0.2 and Node v3.0.2 / v3.0.3

- Source: <https://github.com/mem0ai/mem0/releases>
- License: Apache 2.0.
- Dates: April 25 and May 7, 2026.

Patch series following the v2.0.0 ADD-only / hybrid retrieval rewrite.

- v2.0.1 / v3.0.2: fix entity filtering, async memory
  `text_lemmatized`, Elasticsearch CA cert support, OpenAI client
  timeout forwarding.
- v2.0.2 / v3.0.3: SQL/prompt-injection hardening, **fix inverted
  PGVector distance math** (real correctness bug for self-hosted
  Postgres + local-embedding stacks), expose `decay` parameter on
  project updates, repair telemetry identity stitching.

### mem0 OpenClaw plugin v1.0.11

- Source: <https://github.com/mem0ai/mem0/releases>
- Date: April 29, 2026.

Adds **dimension-aware collections** that auto-detect embedder swaps
(matters when switching between bge / nomic / mxbai without
reindexing — a frequent local-stack failure mode), automated
triage/recall skills setup, and a much lower default search threshold
(0.5 → 0.1) for broader recall.

### Cognee 0.5.8rc1

- Source: <https://github.com/topoteretes/cognee/releases>
- Date: early May 2026.

Release candidate; adds a Sales Benchmark Demo and "relevancy,
ingestion, and stability" improvements for memory retrieval. Cognee
remains one of the few fully self-hostable graph-memory engines that
works with any LiteLLM-compatible local backend (Ollama, vLLM,
Baseten).

### Letta

- Source: <https://github.com/letta-ai/letta/releases>

No release in window. Latest tagged release remains v0.16.7 from
2026-03-31. The MemGPT vs. mem0 split coverage in the prior report
still applies unchanged.

## Benchmarks

No genuinely new benchmark releases in this window. The **MemMachine**
paper (<https://arxiv.org/abs/2604.04853>, early April) reports new
SOTA-style numbers on existing benches (LoCoMo 0.9169 with
gpt-4.1-mini, LongMemEvalS 93.0% with retrieval-stage tuning) but it's
a method paper using prior benchmarks, not a new evaluation.
