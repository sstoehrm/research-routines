# LLM Memory — 2026-04-24

## Run metadata

- **Date:** 2026-04-24
- **Window covered:** ~Nov 2025 – Apr 2026, with a few earlier anchor works still actively cited.
- **Scope:** Memory solutions relevant to **local / open-weights** deployment.

## TL;DR

Local-LLM memory is bifurcating along two tracks. On the **architectural** side, momentum is toward hybrid attention + recurrent/SSM stacks (Mamba-3, Gated DeltaNet, Titans/MIRAS) and sparser attention (DeepSeek Sparse Attention, MLA) — all attacking the KV-cache bottleneck that made long-context local inference impractical. On the **systems** side, an "agent memory layer" stack has consolidated around Mem0, Letta/MemGPT, MemMachine, HippoRAG 2, and A-MEM, converging on a common shape (hybrid vector + graph + episodic store, LLM-based consolidation, MCP-style cross-tool sharing) and increasingly treating Ollama / vLLM as first-class citizens. KV-compression research (Expected Attention, KV Cache Transform Coding) is now landing in open runtimes via `NVIDIA/kvpress` and community llama.cpp ports. Two things remain unsolved: how parametric memory (test-time updates) should interact with external non-parametric stores, and a neutral benchmark — LOCOMO / LongMemEval results are still contested between memory-layer vendors.

## Papers

### 1. Titans + MIRAS — Learning to Memorize at Test Time

- **Authors / org:** Ali Behrouz, Peilin Zhong, Vahab Mirrokni et al. — Google Research
- **Date:** arXiv Jan 2025; Google Research blog write-up + MIRAS unification Dec 2025 (NeurIPS 2025)
- **URLs:** [arXiv:2501.00663](https://arxiv.org/abs/2501.00663) · [Google Research blog](https://research.google/blog/titans-miras-helping-ai-have-long-term-memory/)

Titans adds a neural long-term memory module trained **at test time** — the model learns which tokens to persist as it streams them. The follow-up MIRAS framework reframes Transformers, Mamba, RetNet, DeltaNet and Titans as instances of one associative-memory optimization problem, giving local-model builders a principled knob set (memory capacity, forgetting gate, update rule) that transfers across architectures. Reported to scale past 2M-token contexts and beat Transformers and linear RNNs on needle-in-a-haystack and BABILong. No official open-weight Titans release yet, but the recipe is reproducible on Llama-class backbones.

- **Key mechanism:** Test-time gradient updates to a compact neural memory module, unified under MIRAS.

### 2. Mamba-3 — Improved Sequence Modeling using State Space Principles

- **Authors / org:** CMU, Princeton, Cartesia AI, Together AI (Goomba Lab) — ICLR 2026
- **Date:** Paper + code released ~Mar 17, 2026 (Apache 2.0)
- **URLs:** [Together AI blog](https://www.together.ai/blog/mamba-3) · [OpenReview (ICLR 2026)](https://openreview.net/forum?id=HwCvaJOiCj)

A drop-in Transformer-backbone replacement that keeps a **fixed-size recurrent state** instead of a growing KV cache — particularly attractive for local deployment where VRAM is the binding constraint. Adds a more expressive recurrence, complex-valued state tracking, and a MIMO variant to close the quality gap with attention. Reported to beat Llama-3.2-1B on prefill+decode latency across all sequence lengths at 1.5B scale, with ~4% better LM quality and up to 7× faster long-sequence inference vs. Mamba-2. Kernels (Triton / TileLang / CuTe) are open-sourced — the piece most relevant for wiring into llama.cpp-style runtimes.

- **Key mechanism:** Linear-recurrence SSM with complex-valued state and MIMO channels, replacing attention KV cache with a compact fixed state.

### 3. DeepSeek-V3.2 — DeepSeek Sparse Attention

- **Authors / org:** DeepSeek-AI
- **Date:** arXiv Dec 2025; V3.2-Exp open weights released late 2025
- **URLs:** [arXiv:2512.02556](https://arxiv.org/abs/2512.02556) · [GitHub](https://github.com/deepseek-ai/DeepSeek-V3.2-Exp)

Introduces **DeepSeek Sparse Attention (DSA)**, pairing a "lightning indexer" with fine-grained token selection to drop attention cost from O(L²) to O(L·k) while preserving quality. Built on top of MLA, so KV-cache savings compound. Because weights and technical report are both open, this is one of the cleanest recent references for long-context memory at reasonable local hardware cost — relevant for anyone running large MoE models locally who wants 128K+ context without blowing up memory.

- **Key mechanism:** Lightning indexer + top-k token selection layered on MLA.

### 4. Mem0 — Production-Ready AI Agents with Scalable Long-Term Memory

- **Authors / org:** Prateek Chhikara et al. — Mem0 (mem0.ai)
- **Date:** arXiv Apr 2025; ongoing benchmark updates through early 2026
- **URLs:** [arXiv:2504.19413](https://arxiv.org/abs/2504.19413) · [GitHub](https://github.com/mem0ai/mem0)

Reference paper for the most widely-adopted open-source memory layer (MIT-licensed). Mem0 extracts and consolidates salient facts from conversations into a hybrid vector+graph store; the Mem0g variant uses a graph backbone for relational reasoning. Reported LOCOMO 91.6, LongMemEval 93.4, BEAM — with ~90% lower token cost vs. full-context baselines. For local deployment, the key property is LLM-agnosticism: Mem0 works with Ollama / vLLM / any OpenAI-compatible endpoint, so extractor and serving model can both be on-prem.

- **Key mechanism:** LLM-based fact extraction + consolidation into hybrid vector/graph/KV store, scoped by user/session/agent.

### 5. A-MEM — Agentic Memory for LLM Agents

- **Authors / org:** Wujiang Xu et al. (Rutgers / AGI Research) — NeurIPS 2025
- **Date:** arXiv 2025; NeurIPS 2025 camera-ready
- **URLs:** [arXiv:2502.12110](https://arxiv.org/abs/2502.12110) · [GitHub](https://github.com/agiresearch/A-mem)

Applies **Zettelkasten**-style organization to agent memory: every new memory gets auto-generated tags, keywords, and contextual links to prior notes, forming an evolving knowledge graph rather than a flat vector index. Good fit for local deployments because the ChromaDB backend supports Ollama and vLLM out of the box and works with modest 7–8B open models. Reported gains on six foundation models over prior memory baselines; the adaptive linking is what distinguishes it from RAG pipelines with fixed schemas.

- **Key mechanism:** Zettelkasten-inspired notes with LLM-generated attributes and dynamic inter-note links.

### 6. HippoRAG 2 — From RAG to Memory: Non-Parametric Continual Learning for LLMs

- **Authors / org:** OSU-NLP Group (Ohio State + UIUC) — ICML 2025
- **Date:** arXiv Feb 2025; repo actively maintained into 2026
- **URLs:** [arXiv:2502.14802](https://arxiv.org/abs/2502.14802) · [GitHub](https://github.com/OSU-NLP-Group/HippoRAG)

Extends HippoRAG's neurobiologically-inspired retrieval (**Personalized PageRank** over an LLM-extracted knowledge graph) to do better factual recall, sense-making, and associative memory than GraphRAG, RAPTOR, and LightRAG — while being cheaper to index. Reports ~7% gain on associative-memory tasks over leading embedding models. Local-stack fit: offline pipeline is just an LLM + open KG, so Llama-3 / Qwen-class models can do the triple extraction.

- **Key mechanism:** Personalized PageRank over an LLM-built knowledge graph bridging a "parahippocampal" encoder and an "artificial neocortex" LLM.

### 7. MemMachine — Ground-Truth-Preserving Memory for Personalized AI Agents

- **Authors / org:** MemVerge, Inc.
- **Date:** arXiv Mar 2026 (see caveat below)
- **URLs:** [arXiv:2604.04853](https://arxiv.org/abs/2604.04853) · [GitHub](https://github.com/MemMachine/MemMachine)

Open-source memory stack that stores **raw episodes** rather than lossy LLM summaries, then adds short-term, long-term episodic, and profile memory on top. Reports 0.9169 on LOCOMO (with gpt4.1-mini) and 93.0% on LongMemEval-S, claiming ~80% fewer input tokens than Mem0 under matched conditions. "Preserve the ground truth, retrieve smarter" is the main differentiator vs. Mem0 / Zep, which extract facts upfront. Apache-licensed, intended to run alongside local inference backends.

- **Key mechanism:** Episode-preserving store with contextualized nucleus-expanded retrieval + separate profile memory for user preferences.

### 8. Expected Attention — KV Cache Compression by Estimating Attention

- **Authors / org:** NVIDIA / kvpress contributors
- **Date:** arXiv Oct 2025; integrated into NVIDIA kvpress
- **URLs:** [arXiv:2510.00636](https://arxiv.org/abs/2510.00636) · [NVIDIA/kvpress](https://github.com/NVIDIA/kvpress)

Compresses the KV cache by **estimating which entries future queries are likely to attend to**, then evicting low-expected-attention tokens. Evaluated on Qwen3-8B and Llama models; outperforms most prior eviction baselines on LongBench at aggressive compression ratios. Directly applicable to local serving because it plugs into NVIDIA's kvpress library, which already supports HuggingFace Llama / Qwen / Mistral and is the cleanest open-source home for KV compression right now.

- **Key mechanism:** Predictive importance scoring of KV entries using expected future attention, followed by eviction.

### 9. KV Cache Transform Coding

- **Authors / org:** ICLR 2026 (see OpenReview for author list)
- **Date:** ICLR 2026 camera-ready
- **URLs:** [OpenReview PDF](https://openreview.net/pdf/1cef9774f0f0cf7bb9e4b167882e3ad3ef8cde16.pdf) · [llama.cpp TurboQuant discussion](https://github.com/ggml-org/llama.cpp/discussions/21526)

Applies classical **transform-coding** ideas ("JPEG for KV") to compress the cache with learned orthogonal transforms + quantization, evaluated on Qwen-2.5 and Llama-3.1-8B. Complements the TurboQuant line (2-/3-/4-bit KV types landing in llama.cpp via community ports). Practical takeaway: aggressive 2–4 bit KV quantization now has solid theoretical footing and is actually being merged into open-source runtimes.

- **Key mechanism:** Learned orthogonal transform + quantization of KV tensors before caching.

## Releases / news

### 10. Letta V1 + Letta Code

- **Org:** Letta (letta.com); absorbed the MemGPT open-source project
- **Date:** Letta V1 agent architecture + Letta Code coding agent launched early 2026
- **URLs:** [Letta V1 blog](https://www.letta.com/blog/letta-v1-agent) · [GitHub](https://github.com/letta-ai/letta)

Letta is the MemGPT successor and is now a full stateful-agent runtime with the OS-inspired **three-tier memory model** (core / archival / recall). The V1 rewrite drops MemGPT-era heartbeats / send_message in favor of native reasoning, and adds "Letta Evals" for benchmarking stateful agents. Directly relevant for local use: self-hosted Letta is free, runs via Docker, is fully model-agnostic, and natively supports Ollama / vLLM / any OpenAI-compatible local endpoint. Letta Code is positioned as a memory-first local coding agent (reportedly #1 open-source agent on Terminal-Bench at release time).

- **Key mechanism:** OS-style tiered memory (RAM / disk / conversation log) inside a stateful agent server with a new V1 reasoning loop.

### 11. Sebastian Raschka — "A Dream of Spring for Open-Weight LLMs: 10 Architectures from Jan–Feb 2026"

- **Author:** Sebastian Raschka
- **Date:** Feb 2026
- **URL:** [Ahead of AI](https://magazine.sebastianraschka.com/p/a-dream-of-spring-for-open-weight)

Not a paper, but the single best meta-source for how memory/attention choices are evolving across the fresh open-weights cohort. Highlights convergence on MLA (Kimi K2.5, GLM-5, Ling 2.5), DeepSeek Sparse Attention (GLM-5), and Gated DeltaNet / linear-attention variants (Qwen3.5) — the mechanisms that determine how much context a local deployment can realistically carry. Useful as the "where is the architectural frontier moving" anchor in any digest. (Note: some of the specific model names referenced in this post — GLM-5, Qwen3.5 — may differ from final vendor naming; treat model-version references as approximate.)

### 12. Mem0 — "State of AI Agent Memory 2026"

- **Org:** Mem0
- **Date:** Early 2026
- **URL:** [Mem0 blog](https://mem0.ai/blog/state-of-ai-agent-memory-2026)

Running benchmark comparison between Mem0, Zep, Letta, LangMem, OpenAI Memory, Memobase, and others on LOCOMO and LongMemEval. Useful because it surfaces the ongoing **token-efficiency vs accuracy trade-off** — e.g. Zep's temporal KG scores ~63.8% on LongMemEval (GPT-4o) vs. Mem0's ~49%, but at reportedly ~340× the tokens per conversation. Those numbers are actively contested (Zep has published a rebuttal), so treat as disputed rather than settled. The LOCOMO-vs-LongMemEval split is a useful frame for readers choosing a memory layer for local deployment.

### 13. LongMemEval — still the default long-term-memory benchmark

- **Authors / org:** Wu et al.
- **Date:** ICLR 2025; heavily used through 2026
- **URLs:** [arXiv:2410.10813](https://arxiv.org/abs/2410.10813) · [GitHub](https://github.com/xiaowu0162/LongMemEval)

500 curated questions over long multi-session chat histories covering information extraction, multi-session reasoning, temporal reasoning, knowledge updates, and abstention, with ~115K-token (S) and ~1.5M-token (M) variants. Long-context LLMs show a 30–60% drop on the S split, and frontier commercial systems cap at 30–70% accuracy — a strong signal that raw long context is **not** a substitute for a real memory layer. Ships with a vLLM-based evaluation harness, so open-weight readers are first-class.

- **Key mechanism:** Multi-session chat benchmark with distractors and five memory-ability categories.

## State of the field

Architectural memory is converging on "attention + compact recurrent state" hybrids (Titans, Mamba-3, Gated DeltaNet) plus sparser attention (DSA, MLA). External memory systems are converging on hybrid vector+graph+episodic stores with LLM-based consolidation, and almost all of them now treat Ollama/vLLM endpoints as first-class — meaning a fully on-prem "model + memory layer" stack is finally viable. What still looks unsolved: (1) nobody has a clean story for how parametric test-time memory (Titans-style) should compose with external non-parametric stores, and (2) public benchmark results (LOCOMO, LongMemEval) vary wildly by configuration, so vendor comparisons remain untrustworthy until a neutral reproducible harness exists. Watch for MIRAS-style unification work, more KV-compression kernels landing in llama.cpp / kvpress, and the next memory-layer round trying to beat MemMachine's ground-truth-preserving design on token cost.
