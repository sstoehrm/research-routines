# LLM Memory — 2026-05-23

## Summary

The month between 2026-04-23 and 2026-05-23 was unusually paper-heavy.
Three threads moved at once. **(1) Architectural memory** got its first
genuinely drop-in proposal: *In-Place Test-Time Training* (arXiv
2604.06169) updates the final MLP projection during inference on an
existing pretrained transformer and demonstrates it on a 4B model at
128K context — the first "Titans-style" idea that fits a single 24–48
GB consumer GPU. **(2) Frameworks** consolidated: **mem0 v2.0.x**
shipped a single-pass ADD-only memory algorithm with self-reported
92.5 LoCoMo / 94.4 LongMemEval at ~7K tokens per retrieval call;
**Letta Code v0.24.x** (Apr 25–26) doubled down on local-first
operation with git-backed *Context Repositories* and *Skill Learning*
in token space; **EverMemOS** kept iterating its self-organizing
engram lifecycle. **(3) Evaluation** broadened past LoCoMo/LongMemEval
with three new benchmarks: **Memora** (forgetting/staleness),
**GroupMemBench** (multi-party speaker-grounded memory), and a new
**MemoryBench** revision; the **ICLR 2026 MemAgents workshop**
(Apr 26–27, Rio) became the de facto consolidation venue with >110
submissions. A new security survey ("Mnemonic Sovereignty") flagged
that none of the major OSS frameworks implement its nine memory-
governance primitives — the gap most likely to bite local self-hosters.

## mem0 v2.0.x — single-pass ADD-only memory algorithm

- Source: <https://mem0.ai/blog/mem0-the-token-efficient-memory-algorithm>,
  <https://github.com/mem0ai/mem0/releases> (v2.0.1 Apr 25, v2.0.2 May 7, 2026)
- State-of-memory write-up: <https://mem0.ai/blog/state-of-ai-agent-memory-2026>
- Date: v2.0 blog Apr 17, 2026; in-window point releases through May 7.
- License: Apache-2.0 OSS core (managed cloud also offered).

### Why it matters for local models

mem0 stays the lowest-friction memory layer to bolt onto a local
Ollama / vLLM / llama.cpp endpoint via LiteLLM. The v2.0 change is
specifically aimed at slow local inference: it replaces the old
multi-call ADD/UPDATE/DELETE flow with a single-pass ADD-only
extraction, cutting the per-turn LLM-call budget — material when each
call is a 10–30 s local generation.

### In-depth insights

- Architecture: hierarchical extraction in one pass; multi-signal
  retrieval (semantic + BM25 + entity match fused into one score);
  built-in entity linking; agent-generated facts treated as first-class.
- Reported scores: 92.5 LoCoMo, 94.4 LongMemEval, 64.1 / 48.6 on
  BEAM-1M / BEAM-10M, averaging ~7K tokens per retrieval call vs.
  ~25K+ for full-context baselines.
- Quoted deltas over the v1 algorithm: +29.6 pts on temporal queries,
  +23.1 pts on multi-hop reasoning.
- Limitation: ADD-only means memory grows monotonically. No public
  data yet on retrieval latency at 10⁶-memory scale on a local
  Postgres+pgvector deployment. Benchmark numbers are self-reported.

## In-Place Test-Time Training — arXiv 2604.06169

- Source: <https://arxiv.org/abs/2604.06169>
- HF mirror: <https://huggingface.co/papers/2604.06169>
- OpenReview: <https://openreview.net/forum?id=dTWfCLSoyl>
- Date: v1 April 2026 (in window).

### Why it matters for local models

The most consequential architectural memory idea of the window for
local-hardware users. It is *drop-in*: no architecture surgery, runs
on an existing pretrained transformer, demonstrated at 128K context
on a 4B model — a profile that fits a single 24–48 GB workstation GPU.
This is the first plausible answer to "what would a Titans-style fast
memory look like if you couldn't change the architecture".

### In-depth insights

- Mechanism: chunk-wise update of the *final projection matrix* in
  each MLP block during inference, using an NTP-aligned loss instead
  of TTT's generic reconstruction loss. Compatible with context
  parallelism.
- Claims: a 4B model with In-Place TTT achieves superior performance
  at 128K context as a drop-in retrofit; when pretrained from scratch
  with this objective, it beats other TTT variants.
- Limitations: code release not yet linked at the time of writing;
  per-step fast-weight update has non-trivial cost vs. plain attention.
- License/weights: pending — verify on arXiv abs page.

## KV-Fold — one-step KV-cache recurrence on a single 40 GB GPU

- Source: <https://arxiv.org/abs/2605.12471>
- HTML: <https://arxiv.org/html/2605.12471>
- Date: May 2026 (in window).

### Why it matters for local models

Training-free, model-agnostic, runs Llama-3.1-8B within a single
40 GB GPU. Implementable in a few hundred lines without retraining,
so it is the cheapest path to long-context retrieval on a workstation.

### In-depth insights

- Method: treat the KV cache as the accumulator in a left-fold over
  sequence chunks; each step processes the next chunk conditioned on
  the accumulated cache, appends new KV, passes forward. Pure
  inference-time recurrence.
- Results: 100% exact-match retrieval across 152 trials, contexts
  16K–128K, chain depth up to 511 on Llama-3.1-8B, all within a single
  40 GB GPU.
- Stability: per-step drift saturates into a flat plateau, insensitive
  to a 10,000× precision change, robust across chunk sizes and model
  families.
- Limitation: this is a *retrieval* benchmark — does not test reasoning
  depth or interference under noisy contexts.

## Memora — "From Recall to Forgetting" benchmark

- Source: <https://arxiv.org/abs/2604.20006>,
  HTML <https://arxiv.org/html/2604.20006v1>
- Date: Apr 21, 2026 (in window).

### Why it matters for local models

Fills a gap LoCoMo and LongMemEval don't cover: *invalidated* and
*evolving* memories. Local agents that run unsupervised for weeks
are exactly where stale memory shows up first.

### In-depth insights

- Spans weeks-to-months of conversation; three tasks: remember, reason,
  recommend.
- Introduces **FAMA** (Forgetting-Aware Memory Accuracy), which
  penalises reliance on obsolete/invalidated memory.
- Evaluation across four LLMs and six memory agents finds frequent
  reuse of invalid memories and failures to reconcile updates — i.e.
  current frameworks fail this axis.

## EverMemOS — self-organizing memory operating system

- Source: <https://arxiv.org/abs/2601.02163>, HF
  <https://huggingface.co/papers/2601.02163>
- Code: <https://github.com/EverMind-AI/EverMemOS>,
  <https://github.com/EverMind-AI/EverOS>
- Date: paper Jan 2026; evaluation harness and plug-ins iterated
  Apr–May 2026 (in window). Apache-2.0.

### Why it matters for local models

Self-hostable Apache-2.0 memory layer that sits in front of any LLM
endpoint. The engram-inspired lifecycle (MemCells → MemScenes) is
implementable on a single workstation with a local embedding model.

### In-depth insights

- Three-stage lifecycle: (1) **Episodic Trace Formation** — dialogue
  to MemCells (atomic facts + Foresight signals); (2) **Semantic
  Consolidation** — MemCells clustered into thematic MemScenes;
  (3) **Reconstructive Recollection** — MemScene-guided agentic
  retrieval.
- Reported scores: 92.3% LoCoMo, 83.0% LongMemEval (+5.2 pp over MemOS,
  +15.5 pp on knowledge-update sub-task, +17.9 pp on assistant-actions).
- Limitation: consolidation phase is LLM-heavy; quality depends on the
  backbone. Numbers are author-reported; no independent replication yet.

## Letta — Context Repositories, Skill Learning, Letta Code v0.24.x

- Sources: <https://www.letta.com/blog/context-repositories>,
  <https://www.letta.com/blog/skill-learning>,
  <https://www.letta.com/blog/context-constitution>,
  <https://github.com/letta-ai/letta-code/releases>,
  <https://github.com/letta-ai/letta>
- Date: Letta Code v0.24.3 (Apr 25) and v0.24.6 (Apr 26), plus May
  point releases; Context Constitution red-teaming write-up May 6, 2026.
- License: Apache-2.0.

### Why it matters for local models

Letta Code is explicitly local-first ("works locally on your machine").
Context Repositories store agent context in the local filesystem *as a
git repo* — every change is a commit, every rollback a `git reset`.
Skill Learning improves the agent in token space without backprop, so
it works against any open-weight backbone via LiteLLM/Ollama.

### In-depth insights

- Context Repositories: git-backed memory, descriptive commit messages
  per change, enables concurrent multi-subagent collaboration through
  branch/merge semantics.
- Skill Learning: a `/skill` slash command enters a "skill-learning
  mode" after an interaction; the agent records what it learned in
  token space (no fine-tuning). Pairs cleanly with small local
  backbones that cannot afford LoRA updates.
- Baseline reset just before the window: Letta v0.16.7 (Mar 31) raised
  default global context from 32K to 128K and overhauled compaction.
- Open question carried forward: is in-context skill accumulation
  competitive with LoRA on a local 7B–13B backbone? No public
  head-to-head.

## TriMem — three-tier lifelong agent memory

- Source: <https://arxiv.org/abs/2605.19952>
- Project page: <https://tmlr-trimem.github.io/>
- Date: May 2026 (in window).

### Why it matters for local models

Most local memory systems compress dialogue to atomic facts and lose
fidelity. TriMem keeps three tiers simultaneously, letting a small
local backbone (7B–13B) reason via the profile tier while keeping
cheap retrieval on atomic facts.

### In-depth insights

- Three granularities: (1) raw dialogue segments anchored by source IDs
  (fidelity); (2) extracted atomic facts (efficient retrieval);
  (3) synthesised profiles (aggregated for deep reasoning).
- Construction prompts are continuously optimised via TextGrad from
  answer feedback.
- Reported: consistently outperforms strong memory baselines on LoCoMo
  and PerLTQA across multiple LLM backbones.
- Cost: ~3× storage; profile synthesis is itself an LLM call.

## Memory-R2 — RL credit assignment for memory agents

- Source: <https://arxiv.org/abs/2605.21768>
- HTML: <https://arxiv.org/html/2605.21768>
- Date: May 20, 2026 (in window).

### Why it matters for local models

First serious paper to point out that in multi-session memory
environments, rollouts diverge in *memory state*, so trajectory-level
reward comparisons are unfair — and to propose a fix. Required reading
if you intend to fine-tune a local Qwen/Llama agent with persistent
memory via GRPO/DAPO-style RL.

### In-depth insights

- Insight: memory turns past actions into part of future environment,
  so the standard same-prefix rollout assumption breaks.
- Memory-R2 introduces a credit-assignment scheme that compensates.
- Authors at LMU Munich, TUM, and Huawei Heisenberg Research Center.
- Open: no public training script verified yet; whether it runs on a
  single workstation with vLLM + Qwen3-8B in <80 GB total GPU memory is
  the question that decides reproducibility.

## GroupMemBench — multi-party conversational memory

- Source: <https://arxiv.org/abs/2605.14498>
- Date: May 14, 2026 (in window).

### Why it matters for local models

Real local-agent deployments (self-hosted Slack/Discord bots,
family-shared assistants) are multi-user. Every existing memory
framework (Letta, mem0, EverMemOS, Zep) is single-user by default;
this benchmark is the first to expose where they fail.

### In-depth insights

- Measures group dynamics beyond concatenated 1:1 chats: speaker-
  grounded belief tracking (per-user memory modelling) and
  audience-adapted Theory-of-Mind language.
- Graph-grounded synthesis pipeline produces multi-party dialogue with
  controllable reply structure, conditioned on per-user personas and
  target audiences.
- Authored at Yahoo Research (Yang, Lai et al.).
- Caveat: synthetic data; corpus release status not yet confirmed.

## Human-Inspired Memory Architecture (Microsoft) — arXiv 2605.08538

- Source: <https://arxiv.org/abs/2605.08538>,
  HTML <https://arxiv.org/html/2605.08538v1>
- Date: May 2026 (in window).

### Why it matters for local models

Specifies six concrete cognitive mechanisms with implementable knobs
(sleep consolidation cycles, interference-based forgetting, engram
maturation, reconsolidation on retrieval, entity KG, hybrid multi-cue
retrieval) — designed as a system architecture on top of any LLM, so
it composes with a local backbone.

### In-depth insights

- Six mechanisms: sleep-phase consolidation, interference-based
  forgetting, engram maturation, reconsolidation upon retrieval,
  entity KGs, hybrid multi-cue retrieval.
- Five system primitives: multi-tier storage, offline consolidation,
  adaptive forgetting, gradual maturation, reconsolidation on retrieval.
- Introduces synthetic calibration that derives pipeline thresholds
  without benchmark exposure (anti-leakage).
- Limitation: calibration data is synthetic; no head-to-head numbers
  vs. mem0 / Zep / EverMemOS published yet.

## Mnemonic Sovereignty — security survey of LLM agent memory

- Source: <https://arxiv.org/abs/2604.16548>,
  HTML <https://arxiv.org/html/2604.16548v1>
- Date: Apr 17, 2026 (boundary of window; included because it directly
  affects self-hosting decisions).

### Why it matters for local models

Local self-hosted agents inherit every memory-poisoning, extraction,
and rollback risk from cloud agents, but without an enterprise
security team. The survey defines nine governance primitives and
notes that no published architecture covers all of them — including
the OSS leaders (Letta, mem0, EverMemOS, MemOS, MemPalace).

### In-depth insights

- Threat lifecycle: writing, storing, retrieving, sharing, deleting.
- Current literature concentrates on write/retrieve integrity;
  confidentiality, availability, store/forget, and benign-persistence
  remain under-explored.
- Argues LLM self-introspection for memory security is sparse but
  essential going forward.

## MemPalace 3.x — verbatim spatial memory (and its critical analysis)

- Sources: <https://github.com/mempalace/mempalace>,
  <https://arxiv.org/abs/2604.21284>
- Date: project Apr 2026; critical-analysis paper Apr 30, 2026
  (in window).

### Why it matters for local models

Runs entirely locally with *no LLM API calls at write time* — the
entire memory layer is deterministic regex/keyword + ChromaDB
embeddings. Dependencies are just `chromadb` and `pyyaml`. Exposes 29
MCP tools, so any MCP-compatible local model (including the new
llama.cpp WebUI MCP loop) can use it.

### In-depth insights

- Structure: Wings (domains) → Rooms (topics) → Drawers (memory chunks).
  Verbatim storage, no LLM-side compression.
- Reported: 96.6% Recall@5 on LongMemEval.
- The critical-analysis paper argues the headline number is mostly
  attributable to verbatim storage + ChromaDB's default
  `all-MiniLM-L6-v2` embeddings, *not* the spatial metaphor. Useful
  cross-check.
- ~11K LOC Python, 44 test files. Verify exact license on the repo.

## FibQuant — universal vector quantization for KV cache

- Source: <https://arxiv.org/abs/2605.11478>,
  HTML <https://arxiv.org/html/2605.11478>
- Date: May 12, 2026 (in window).

### Why it matters for local models

Random-access KV-cache compression at *fractional bits* — directly
attacks the memory-bandwidth bottleneck on 24 GB consumer GPUs.
Compatible with the rotation-based KV codec interface already used in
llama.cpp and vLLM, so the integration path is short.

### In-depth insights

- Replaces scalar tables with a shared radial-angular codebook
  combining Beta-quantile radii, Fibonacci / Roberts–Kronecker
  quasi-uniform directions, and multi-restart Lloyd–Max refinement.
- Provably strictly improves on the scalar product specialization at
  matched bit-rate.
- Supports fractional-bit and sub-1-bit operating points without
  calibration or variable-length addressing.
- Authors: Namyoon Lee and Yongjune Kim (POSTECH).

## Survey: "From Storage to Experience"

- Source: <https://arxiv.org/abs/2605.06716>
- Tracking repo:
  <https://github.com/FeishuLuo/Evolving-LLM-Agent-Memory-Survey>
- Date: May 7, 2026 (in window).

### Why it matters for local models

Best 2026 orientation survey. Three-stage evolutionary framework
(Storage → Reflection → Experience) maps cleanly onto what shipping
OSS (Letta, mem0, EverMemOS) is doing — useful citation backbone
when justifying framework choice.

### In-depth insights

- Three stages: (i) Storage (faithful recording of trajectories);
  (ii) Reflection (dynamic evaluation/refinement loop); (iii)
  Experience (abstraction into reusable behaviour patterns).
- Three drivers: long-range consistency, dynamic environments,
  continual learning.
