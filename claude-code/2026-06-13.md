# Claude Code — 2026-06-13

## Summary

The May–June 2026 window was dominated by a steady drumbeat of
weekly Claude Code releases (v2.1.133 → v2.1.176) and three larger
moves around plugins and skills:

1. **The official marketplace grew from ~101 plugins to 223** in
   `anthropics/claude-plugins-official` (35 Anthropic-authored, ~188
   partner-authored when counted from the live `marketplace.json`).
   Notable Anthropic additions in this window include the new
   **security-guidance** plugin and **skill-creator** as a first-party
   plugin, along with a broader **LSP family** (`typescript-lsp`,
   `pyright-lsp`, `gopls-lsp`, `rust-analyzer-lsp`, `ruby-lsp`,
   `php-lsp`, `swift-lsp`, `kotlin-lsp`, `jdtls-lsp`, `lua-lsp`,
   `clangd-lsp`, `csharp-lsp`).
2. **Skills loading and management got serious operational tooling**:
   `/reload-skills`, `SessionStart` hook `reloadSkills: true`,
   `disableBundledSkills`, the new `--safe-mode` flag that disables
   *all* customization for triage, and `claude plugin init <name>`
   scaffolding plugins in `.claude/skills`.
3. **Dynamic Workflows** (v2.1.154) ship as a Research Preview —
   Claude writes an orchestration script on the fly and runs tens to
   hundreds of sub-agents from it. Sub-agents can now spawn their own
   sub-agents up to five levels deep (v2.1.172). This is the natural
   next layer above skills/plugins and shifts where token budget goes.

Two notable third-party developments: **caveman** (output-token
compression) shipped v1.8.2 (May 12) and revised its claim to ~65 %
average output-token reduction (range 22–87 %) across 10 benchmark
tasks; and **Prismatic** launched a first-class partner skills
plugin (May 5).

The Q1-era community marketplace (`jeremylongshore/claude-code-
plugins-plus-skills`, the `ccpi` package manager) grew from
423/2849/177 to **425 plugins, 2,810 skills, 200 agents**; the
README brands itself "tonsofskills.com." Cross-check stars and
last-commit date before installing anything from there — most of the
growth is autogenerated bundles.

## Plugins

### security-guidance — real-time vulnerability review (first-party)

- Source: <https://github.com/anthropics/claude-code/tree/main/plugins/security-guidance>
- Marketplace: `anthropics/claude-plugins-official`
- Install: `/plugin install security-guidance@claude-plugins-official`
- License: not specified in the README at fetch time — Anthropic-published
- Requirements: Claude Code ≥ v2.1.144, Python 3.8+ on `PATH`

Three-layer reviewer:
1. **Pattern warnings** on `Edit`/`Write` — regex matches for ~25
   high-risk constructs (`yaml.load`, `pickle.load`, `torch.load(weights_only=False)`,
   `eval`, `new Function`, `os.system`, `child_process.exec`, raw
   `innerHTML`, hardcoded secrets, etc.).
2. **Stop-hook LLM diff review** after Claude finishes a turn —
   high-severity findings get fed back to Claude in-session for fix.
   Default reviewer model is `claude-opus-4-7`, override with
   `SECURITY_REVIEW_MODEL`.
3. **Agentic commit review** — on `git commit`, an SDK-driven agent
   traces data flow across files for IDOR, auth bypass, cross-file
   SSRF, path traversal.

Anthropic reports a 30–40 % reduction in security-related PR comments
in internal testing. Free on all plans. Kill switch:
`SECURITY_GUIDANCE_DISABLE=1`. Per-layer toggles via
`ENABLE_PATTERN_RULES`, `ENABLE_CODE_SECURITY_REVIEW`,
`ENABLE_STOP_REVIEW`, `ENABLE_COMMIT_REVIEW`. Custom rules via
`claude-security-guidance.md` (user / project / `.local` levels).

**Notes / caveats:** uses Stop and commit hooks, runs additional
inference per turn (extra tokens on the user's account when self-
served), reads files across the repo during commit review. Worth
auditing the per-turn LLM call cost on big diffs.

### LSP plugin family (first-party)

- Source: `anthropics/claude-plugins-official` marketplace
- Install: `/plugin install <lang>-lsp@claude-plugins-official`
- License: see marketplace entries

Twelve language-server plugins authored by Anthropic now sit in the
official marketplace: `typescript-lsp`, `pyright-lsp`, `gopls-lsp`,
`rust-analyzer-lsp`, `ruby-lsp`, `php-lsp`, `swift-lsp`,
`kotlin-lsp`, `jdtls-lsp`, `lua-lsp`, `clangd-lsp`, `csharp-lsp`.
Each one hooks the appropriate language server so Claude gets
real symbol lookups, go-to-definition, and diagnostics instead of
grep heuristics. v2.1.145 added LSP-server visibility in the
`/plugin` Discover/Browse pane.

### skill-creator — meta-skill, now packaged as a plugin (first-party)

- Source: `anthropics/claude-plugins-official` marketplace
- Install: `/plugin install skill-creator@claude-plugins-official`
- Previously surfaced only in the docs (see 2026-04-23 baseline)

Scaffolds new skills, A/B-tests variants, and produces frontmatter

`claude plugin init <name>` for a project-local skill.

### ralph-loop, hookify, mcp-tunnels, mcp-server-dev (first-party)

- Source: `anthropics/claude-plugins-official`
- Install: `/plugin install <name>@claude-plugins-official`

Four utility plugins authored by Anthropic that landed in the
official marketplace during this window:

- **ralph-loop** — long-running task loop (background "Ralph"
  pattern that keeps Claude on one outcome).
- **hookify** — scaffolds and validates hooks for
  `settings.json` / plugin `hooks/`.
- **mcp-tunnels** — tunnels local MCP servers through Claude Code
  Remote sessions so an `stdio` server on your laptop is reachable
  from a cloud session.
- **mcp-server-dev** — boilerplate / scaffolds for building MCP
  servers, complementing `agent-sdk-dev`.

**Notes:** `hookify` modifies `settings.json`. Read its diff before
accepting — hooks are load-bearing.

## Skills

### Dynamic Workflows (first-party, Research Preview)

- Source: <https://claude.com/blog/introducing-dynamic-workflows-in-claude-code>
- Ships with Claude Code v2.1.154 (2026-05-28)
- Manage runs with `/workflows`; trigger by including the word
  "workflow" in a prompt

Claude writes an orchestration script on the fly that spawns dozens
to hundreds of parallel sub-agents and consolidates their results.
v2.1.172 (June 10) lifts the nested-sub-agent cap to **5 levels
deep**. This sits one layer above skills/plugins: a workflow can
chain many `/skill-name` invocations or partition a `/code-review`
across files.

**Notes:** Research Preview; token cost is real because each
sub-agent consumes its own context. Use `/usage` (v2.1.149+) to
inspect per-plugin / per-subagent breakdown before scaling.

### caveman v1.8.2 — output-token compression (community)

- Source: <https://github.com/JuliusBrussee/caveman>
- Released 2026-05-12
- License: see repo

Updated benchmark claim: **~65 % average output-token reduction
(range 22–87 %)** across 10 benchmark tasks — a softer figure than
the ~75 % cited in the April baseline. Adds six intensity levels
(`lite`, `full`, `ultra`, `wenyan-lite`, `wenyan-full`,
`wenyan-ultra`) toggled by `/caveman`.

**Notes:** generated code is left untouched, but review commit
messages and PR bodies before they go to external reviewers —
caveman-style brevity reads as terse. Same caveat as the baseline.

### /code-review (first-party slash command + plugin)

- Source: <https://claude.com/plugins/code-review>
- Plugin: `code-review@claude-plugins-official`
- Renamed from `/simplify` in v2.1.147 (2026-05-21); `/simplify`
  now delegates to `/code-review --fix` (v2.1.152, 2026-05-27)

Runs 4 review agents in parallel, scores each issue for confidence,
posts only issues with ≥ 80 confidence. Two notable flags:
- `--fix` applies the findings to the working tree (v2.1.152).
- `--comment` posts findings as inline PR comments via `gh`.

This is the local sibling of cloud `/ultrareview`.

### /goal — completion-condition autopilot (first-party)

- Source: <https://code.claude.com/docs/en/whats-new/2026-w20>
- Available since v2.1.139 (2026-05-11)

User defines a completion condition; Claude keeps planning, editing,
and testing across turns until the condition holds. Works in
interactive, `-p`, and Remote Control modes; tracks elapsed time,
turns, and tokens. **Notes:** long unattended runs — set
`/usage` budgets and consider `--safe-mode` for first runs to be
sure customizations aren't compounding spend.

### /usage, /plugin list, /reload-skills — operational tooling (first-party)

- `/usage` (v2.1.149) — per-category breakdown across skills,
  subagents, plugins, and per-MCP-server cost; v2.1.152 added large
  session-file streaming. This is the cheapest way to find a noisy
  skill or runaway MCP server.
- `/plugin list` (v2.1.163) — list installed plugins with
  `--enabled`/`--disabled` filters.
- `/reload-skills` (v2.1.152) — re-scan skill directories without
  restarting. Pairs with `SessionStart` hook returning
  `reloadSkills: true` to make a freshly installed skill available
  in the same session.

### Skill listing budget (mechanic, not a skill)

- Source: <https://claudefa.st/blog/guide/mechanics/skill-listing-budget>

Each loaded skill costs ~75–150 tokens for its frontmatter. Default
budget = 1 % of context. On the 200 K models that's ~15–25 skills
before listing truncation; on 1 M it's ~75–125. The `/skills` menu's
token-count sort (introduced in Q1) is the way to prune. Worth
re-evaluating per project — a "kitchen-sink" community marketplace
quickly eats this budget.

## Open questions / follow-ups

- Re-benchmark **caveman v1.8.2** locally — the author's revised
  ~65 % figure is closer to plausible than the ~75 % claim from Q1.
  Worth measuring at intensity `full` vs `ultra` on the same
  workload.
- Whether **`disableBundledSkills`** + a curated marketplace is a
  defensible base config for org rollouts (locked context budget,
  predictable token spend).
- Real production token cost of **dynamic workflows** at 100+
  sub-agents — Anthropic surfaces `/usage` breakdowns now, but
  there's no public benchmark per task class yet.
- Test **`security-guidance`** on a representative repo to validate
  the 30–40 % PR-comment reduction. Specifically: does the
  per-turn Stop-hook LLM call materially raise spend, and what's
  the false-positive rate on commit review?
- Track how partner plugins use the new `defaultEnabled: false`
  flag — useful for plugins that need explicit opt-in (auth tokens,
  side-effecting MCP servers).
- Audit **`hookify`** before recommending — it modifies
  `settings.json`, which is exactly the kind of edit the
  guidelines flag.
- Stability of community marketplace counts (`jeremylongshore`,
  `claudemarketplaces.com`): claimed 2,810 skills vs default skill
  listing budget of ~15–125 — the gap means most catalogue entries
  will never load. The marketplaces are now search/discovery
  surfaces, not bundle indices.
