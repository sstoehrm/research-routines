# Claude Code — 2026-05-16

## Summary

Three weeks of substantial activity, mostly inside the official
Anthropic-managed marketplace rather than via headline-grabbing
third-party launches. Anthropic merged ~10 new plugins into
`claude-plugins-official` (notably **AWS Agent Toolkit**,
**code-modernization**, airtable, mercadopago, clickhouse, dash0,
sap-fiori-mcp-server, qdrant-skills, zilliz, pigment, outputai) and
removed several lower-quality entries. Two notable independent skills
launched: **Prismatic Skills** (May 5) and Signadot's
**`/signadot-validate`** (May 12). The Claude Code CLI itself shipped
significant plugin / skill plumbing across versions 2.1.118 → 2.1.143,
including `claude plugin tag`, `claude plugin prune`, `--plugin-url`,
`.zip` archives in `--plugin-dir`, root-level `SKILL.md` surfacing,
projected token cost in the `/plugin` browser, dependency enforcement
on disable/enable, and the new `claude agents` Agent View plus
`/goal` command. The most-watched community plugin, **claude-mem**,
jumped from the v12.x line to v13.x with a major **AGPL-3.0 →
Apache-2.0 relicense** and a new server-beta event pipeline; cavekit
had no new releases in this window.

## Plugins

### code-modernization (Anthropic)

- Source: <https://github.com/anthropics/claude-plugins-official/tree/main/plugins/code-modernization>
- Install: `/plugin install code-modernization@claude-plugins-official`
  (Anthropic-managed marketplace)
- License: Apache-2.0
- What it does / why it matters: structured workflow plugin for
  modernizing legacy COBOL / Java / C++ / monolith web apps. Enforces
  an `assess → map → extract-rules → brief → reimagine|transform →
  harden` pipeline with seven slash commands
  (`/modernize-assess`, `/modernize-map`, `/modernize-extract-rules`,
  `/modernize-brief`, `/modernize-reimagine`, `/modernize-transform`,
  `/modernize-harden`) and five specialist agents (`legacy-analyst`,
  `business-rules-extractor`, `architecture-critic`,
  `security-auditor`, `test-engineer`).
- Notes / caveats: hardened on May 11 to generate **patches** rather
  than directly editing legacy code. Produces artifacts under
  `analysis/` and `modernized/`; review them. The `security-auditor`
  agent emits `SECURITY_FINDINGS.md` and CVE-checked diffs.

### AWS Agent Toolkit (eight bundles)

- Source: <https://github.com/aws/agent-toolkit-for-aws>,
  <https://github.com/awslabs/agent-plugins>; PR #1756 merged into
  `claude-plugins-official` on May 7

  `aws-amplify`, `aws-data-analytics`, `aws-serverless`,
  `aws-agents`, `aws-dev-toolkit`, `databases-on-aws`,
  `deploy-on-aws`)
- License: Apache-2.0 (per AWS repos)
- What it does / why it matters: eight AWS-supported bundles
  delivering AWS MCP servers + curated skills + agent definitions

  34 skills and 11 agents.
- Notes / caveats: first-party AWS support; recommended for any AWS
  work. Bundles append to a CLAUDE.md rules file at install time —
  diff before committing.

### Prismatic Skills for Claude Code

- Source: <https://github.com/prismatic-io>; announcement
  <https://prismatic.io/blog/introducing-prismatic-skills-for-claude-code/>
  (launched 2026-05-05)
- Install: open-source GitHub repo + paired with the Prism MCP dev

### /signadot-validate (Signadot)

- Source: <https://www.signadot.com/docs/tutorials/rapid-local-debugging-claude-code>
  (launched 2026-05-12)
- Install: skill + Signadot MCP server + CLI; install via Signadot
  docs (not in the official Anthropic marketplace as of May 16).
- License: not explicitly stated in coverage — check Signadot repo
  before relying on it.
- What it does / why it matters: lets Claude Code validate code
  changes against a **live Kubernetes cluster** by creating an
  isolated Signadot Sandbox containing only the modified service
  while sharing dependencies (Postgres, Kafka, Redis, downstream
  services) from the baseline cluster via a unique routing key. The
  agent iterates locally with live log streaming rather than
  rebuilding container images.
- Notes / caveats: requires a Signadot account, a Kubernetes
  cluster, and a production-like baseline. The skill is the
  "closing the agent loop" pattern Anthropic has been promoting;
  expect more vendor-shipped validation skills to follow.

## Changelog items affecting plugins / skills (since 2026-04-23)

Sources: <https://code.claude.com/docs/en/changelog>,
<https://github.com/anthropics/claude-code/releases>,
<https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md>.

- **v2.1.143 (May 15)** — `claude plugin disable` now refuses when
  another enabled plugin depends on the target (with disable-chain
  hint); `claude plugin enable` force-enables transitive deps;
  `/plugin` browse pane shows projected per-turn / per-invocation
  token cost; LSP servers now listed in `/plugin` details.
- **v2.1.142 (May 14)** — plugins with a root-level `SKILL.md`
  (and no `skills/` subdir) are now surfaced as a skill —
  collapses the plugin/skill distinction for single-file workflows.
  Fixed plugin-cache cleanup deleting active version dir; fixed
  `/plugin` browse showing "0 installs" for new plugins.
- **v2.1.141 (May 13)** — `CLAUDE_CODE_PLUGIN_PREFER_HTTPS` env
  var to clone GitHub plugin sources over HTTPS (no-SSH
  environments).
- **v2.1.139 (May 11)** — `claude agents` Agent View research
  preview; new `/goal` command; `--agent <name>` finds plugin-
  contributed agents without the `plugin:` prefix; `claude plugin
  install <name>@<marketplace>` auto-refreshes the marketplace and
  retries before reporting not-found; `/context` now shows the
  providing plugin's name for plugin-sourced skills; fixed
  `Skill(name *)` wildcard permission rules.
- **v2.1.136 (May 8)** — fixed MCP servers from `.mcp.json`,
  plugins, and connectors silently disappearing after `/clear`;
  fixed plugin uninstall/enable/disable matching slugs
  case-insensitively; fixed plugin slash commands with spaces not
  resolving to namespaced form.
- **v2.1.129 (May 6)** — new `--plugin-url <url>` flag fetches a
  plugin `.zip` from a URL for the current session; `skillOverrides`
  setting now functional (`off` / `user-invocable-only` /
  `name-only`); plugin manifests now require `themes` and
  `monitors` under `"experimental"`.
- **v2.1.128 (May 4)** — `--plugin-dir` now accepts `.zip`
  archives; fixed `/plugin` Components panel showing "Marketplace
  'inline' not found" for `--plugin-dir` loads.
- **v2.1.126 (May 1)** — `claude_code.skill_activated` OTel event
  now fires for user-typed slash commands and carries an
  `invocation_trigger` attribute (`"user-slash"`,
  `"claude-proactive"`, `"nested-skill"`); new `claude project
  purge` command.
- **v2.1.121 (Apr 28)** — `claude plugin prune` removes orphaned
  auto-installed plugin deps (`plugin uninstall --prune` cascades);
  `/skills` gains a type-to-filter search box;
  `--dangerously-skip-permissions` no longer prompts for writes to
  `.claude/skills/`, `.claude/agents/`, `.claude/commands/`; MCP
  `alwaysLoad: true` per-server setting to skip tool-search
  deferral.
- **v2.1.120 (Apr 28)** — `claude ultrareview [target]` subcommand
  to run `/ultrareview` non-interactively from CI; skills can
  reference `${CLAUDE_EFFORT}`; `claude plugin validate` now
  accepts `$schema`/`version`/`description` at top level of
  `marketplace.json`.
- **v2.1.119 (Apr 23)** — `--print` mode honors agent `tools:` /
  `disallowedTools:` frontmatter; `--agent <name>` honors built-in
  agent `permissionMode`; plugins pinned by another plugin's
  version constraint now auto-update to the highest satisfying git
  tag; `blockedMarketplaces` correctly enforces `hostPattern` /
  `pathPattern`.
- **v2.1.118 (Apr 23)** — `claude plugin tag` subcommand to create
  release git tags with version validation; plugins can ship
  themes via a `themes/` directory; hooks can invoke MCP tools
  directly via `type: "mcp_tool"`.
