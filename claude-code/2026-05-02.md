# Claude Code — 2026-05-02

## Summary

Nine days after the previous report, Claude Code shipped **five
releases** (v2.1.118 → v2.1.126) and the official marketplace grew by
roughly seventeen plugins (~101 → ~117–120, unverified exact count).
Headline platform changes: hooks can now invoke MCP tools directly via
`type: "mcp_tool"`, plugins can ship custom themes, the new
**`claude ultrareview`** non-interactive subcommand makes ultrareview
usable from CI, MCP server config gained an **`alwaysLoad`** option
that bypasses tool-search deferral, and **PostToolUse hooks can
replace tool output for any tool** (was MCP-only). On the partner
plugin side, several major-vendor plugins landed: **desktop-commander**
(broad shell/filesystem access — review before recommending),
AWS Dev Toolkit, Adobe for Creativity, Snowflake Cortex Code,
ServiceNow SDK, JFrog, Logfire, FullStory, Aiven, 42Crunch API
Security Testing, DataRobot, You.com Agent Skills, SAP MDK Server,
Oracle Data Platform, CrowdStrike Falcon Foundry. Skill semantics got
a `${CLAUDE_EFFORT}` template variable, a `/skills` type-to-filter
search box, and three meaningful bug fixes (deferred tools available
on turn 1 in fork-context skills; auto-compaction no longer re-runs
the most recent skill; `/skills` Enter no longer closes the dialog).
A new OTel attribute `invocation_trigger` distinguishes
user-slash / claude-proactive / nested-skill activations.

## Skills

The Apr 20 → May 2 window did not introduce notable new first-party
shipped skills beyond updates to existing ones, but skill **semantics
moved meaningfully**:

- **`${CLAUDE_EFFORT}` variable in skill content** — v2.1.120
  (Apr 28). Skills can now reference the current effort level
  inline, enabling token / effort-aware skill behaviour. Open
  question: full set of valid values and interaction with the older
  `effort.level` status-line JSON.
- **`/skills` type-to-filter search box** — v2.1.121 (Apr 28). UX
  improvement for discovering skills in long lists.
- **Deferred tools on turn 1 in fork-context skills** — v2.1.126
  (May 1). Previously WebSearch / WebFetch and similar were missing
  on the first turn of `context: fork` skills, silently breaking
  them.
- **Auto-compaction re-run bug** — v2.1.119 (Apr 23). Skills invoked
  just before auto-compaction were being re-executed against the
  next user message. Fixed.
- **`/skills` Enter key behaviour** — v2.1.119 (Apr 23). Was closing
  the dialog instead of pre-filling `/<skill-name>`. Fixed.
- **OTel:** `claude_code.skill_activated` event now fires for
  user-typed slash commands and includes a new
  **`invocation_trigger`** attribute (`"user-slash"`,
  `"claude-proactive"`, `"nested-skill"`) — v2.1.126 (May 1).
  Useful for measuring how skills actually get invoked.

### skill-creator (no `ANTHROPIC_API_KEY` requirement)

Synced from `anthropics/skills` on Apr 23. Friction reduction —
small change but meaningful for marketplace adoption.

## Changelog items that affect plugins / skills

Sources:
<https://code.claude.com/docs/en/changelog>,
<https://github.com/anthropics/claude-code/releases>.

### v2.1.118 (Apr 23)

- Vim **visual** and **visual-line** modes.
- Merged `/cost` + `/stats` into **`/usage`**.
- **Custom themes** via `~/.claude/themes/` JSON files; **plugins
  can ship themes** via a `themes/` directory.
- **Hooks can invoke MCP tools directly** via
  `type: "mcp_tool"`. Significant for plugin authors building
  reactive workflows.
- `DISABLE_UPDATES` env var (stricter than `DISABLE_AUTOUPDATER`).
- WSL `wslInheritsWindowsSettings` policy.
- `autoMode.allow` / `soft_deny` / `environment` accept
  `"$defaults"` to **extend** instead of replacing.
- **`claude plugin tag`** — create release git tags.

### v2.1.119 (Apr 23)

- `/config` settings now persist to `~/.claude/settings.json` with
  project / local / policy precedence.
- `prUrlTemplate` setting; `--from-pr` accepts GitLab / Bitbucket /
  GHE.
- `--print` honours agent `tools:` / `disallowedTools:` frontmatter.
- `--agent <name>` honours `permissionMode`.
- PowerShell auto-approval.
- `PostToolUse` hook input gains `duration_ms`.
- `blockedMarketplaces` correctly enforces `hostPattern` /
  `pathPattern` (was buggy — admins relying on this for policy
  should re-verify configs now actually block).
- `${ENV_VAR}` placeholders in MCP `headers` now substitute
  properly.

### v2.1.120 (Apr 28)

- Windows: PowerShell becomes the shell tool when Git Bash is
  absent.
- **`claude ultrareview [target]`** — non-interactive subcommand
  for CI (`--json`, exit codes 0 / 1). Makes the cloud
  multi-agent review usable from pipelines.
- `${CLAUDE_EFFORT}` variable in skills (see Skills section).
- `claude plugin validate` accepts `$schema` / `version` /
  `description` at the top level of `marketplace.json`, and
  `$schema` in `plugin.json`.
- `/plugin` marketplace failures are now graceful when a single
  entry has an unrecognised source format.

### v2.1.121 (Apr 28)

- **`alwaysLoad` option on MCP server config** — skip tool-search
  deferral and make all tools always available. Significant for
  plugin authors whose tools were getting hidden behind
  `ToolSearch`.
- **`claude plugin prune`** and `plugin uninstall --prune` for
  orphaned auto-installed deps.
- **PostToolUse hooks can replace tool output for *any* tool** via
  `hookSpecificOutput.updatedToolOutput` (was MCP-only). Powerful
  but easy to abuse.
- `--dangerously-skip-permissions` no longer prompts for
  `.claude/skills/`, `.claude/agents/`, `.claude/commands/` writes.
- Transient MCP startup errors auto-retry up to 3×.

### v2.1.122 (Apr 28) / v2.1.123 (Apr 29) / v2.1.126 (May 1)

- Mostly fixes.
- v2.1.126 adds `claude project purge`.
- `--dangerously-skip-permissions` now bypasses `.claude/`,
  `.git/`, `.vscode/`, and shell-config writes (catastrophic `rm`
  still prompts).
- `invocation_trigger` OTel attribute (see Skills section).
